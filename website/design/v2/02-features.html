文档管理

桌面 移动 Web

虚拟磁盘把服务器上的真实目录映射成一块盘，完全依赖文件系统结构， 数据库里不存一份文件目录信息 —— 你在服务器上直接建目录，客户端马上就看得见。 大文件上传 / 下载都支持断点续传，图片、视频、音频、文本、Markdown 都能直接预览。

  • 断点续传跨重启：服务端会话持久化，只有用户主动取消才清理已传分片
  • 合并异步化：后台合并 + 进度轮询，大文件不再因合并耗时长被判失败
  • 流式预览：视频 / 音频零缓存播放，文本逐帧加载不写本地临时文件
  • 隐藏项过滤：. 开头的条目不出现在列表里，程序临时目录不可通过接口访问
实现要点
上传分片默认 512KB / 片，服务端硬上限 1MB
加密分片数据嵌入加密信封，ChaCha20-Poly1305
并发按端配置；服务端合并 / 分片使用保守默认值
续传判据远端文件变化或偏移越界 → 自动从头下载
预览格式图片 8 类、视频 13 类、音频 9 类、文本与代码流式加载
实现要点
存放直接操作服务端 .md 文件，不做私有格式封装
目录隔离每个账号在设置页选自己的笔记目录，互相不可见
默认视图有内容 → 预览；空笔记 → 编辑；手动切换后本页不再自动改写
大纲按标题层级解析，右侧可折叠竖栏，预览 / 分屏均可用
主题跟随系统 prefers-color-scheme 的暗黑模式

笔记本管理

桌面 移动 Web

左边写 Markdown，右边实时成形。代码块有语法高亮，Mermaid 图表渲染成矢量图， 笔记本身就是服务器上的普通 .md 文件 —— 拿走就能用别的工具继续写。

  • 实时预览：GitHub 风格 CSS，表格、代码块、引用都按标准渲染
  • Mermaid 图表：与桌面文本编辑器同一渲染栈，语法错误给中文提示且不白屏
  • 搜索 / 标签 / 收藏：按文件名或内容检索，长笔记库也找得到
  • 新建 / 编辑 / 保存 / 删除：全程直接写服务端文件，没有同步延迟

文本编辑器

仅桌面端
桌面 移动 Web

一个纯本地的多标签编辑器：打开和保存都针对本机文件，编辑器与远端零交互。 登录后断网、服务端没启动也照常可用 —— 它只是借用了这个客户端的窗口。

  • 12 项工具箱：查找替换、行操作、大小写、转义、Base64、JSON、Markdown、CSV、SQL、XML、对比、字号与行号
  • 29 项快捷键：每项都配有快捷键，且只在编辑面板聚焦时生效（焦点在别处既不生效也不被吞）
  • 跨标签查找替换：范围可切到「所有已打开的标签页」，结果按标签页分组，点一条即跳过去选中
  • 多标签状态保持：切换标签保留各自光标、滚动位置与视图模式（编辑 / 预览 / 分屏 / 表格 / 树形）
实现要点
准入登录后入口可见；未登录时入口零存在、快捷键不响应
保存按扩展名识别语言，类型校验先行，标准原子写
状态栏编码 / 换行符 / 语言 / 行列与字符数
右击菜单中文标准编辑菜单，无英文项与浏览器导航项
本地性与远端零交互，不依赖服务端可用性
实现要点
用户管理添加 / 删除普通用户、修改密码、启用 / 禁用账号
磁盘管理添加 / 编辑 / 删除虚拟磁盘，映射服务端真实路径
选路径三端均可「浏览…」从服务器目录树选择（管理员只读接口，只列目录）
鉴权JWT(ES256) 走加密 body；每条带路径参数的路由都校验归属

用户与权限管理

管理员功能
桌面 移动 Web

多账号 + 虚拟磁盘，权限落在磁盘级：读、写、删除三个开关分别授予。 权限不到位的磁盘，用户登录后根本看不到，也就点不进去。

  • 四件事：用户管理、磁盘管理、权限配置、系统设置，三端的管理面板都是这四项
  • 磁盘级授权：读 / 写 / 删分开控制，只读账号也能看，但改不了
  • 目录树选路径：管理员从服务器真实目录树里点，不用手打绝对路径
  • 接口全加密：不暴露任何明文凭据，JWT 通过加密 body 传递

云盘挂载

仅桌面端
桌面 移动 Web

把远端的一个子目录挂成本地的一个挂载点，文件按需下载 —— 用到的才落盘。 多个挂载点之间互不暴露，一个挂载点看不到另一个的内容。

  • 目录级挂载：一个挂载点 = 一个远端子目录，可以同时挂多个
  • 文件级状态：已缓存 / 仅在线，随时释放空间（只删本地缓存）
  • 增量同步：服务端变更日志（rev）为主，全量对账兜底「绕过 API 的直接写入」
  • 永不自动删除远端文件：本地怎么折腾都不会反噬服务器
实现要点
默认态挂载点默认关闭，需手动开启
配置存放只存客户端本地；旧同步配置自动迁移
冲突策略远端优先，本地缓存可随时重新拉取
跨端桌面端专属；Web 端 v1.7.0 起已移除该路由
实现要点
默认设置页开关，默认关闭
分层按 年/月 存放；图片与视频可选
去重先建本地持久化远端索引再上传，命中直接跳过（不读本地文件流）
补传远端文件被删除 → 自动补传
校验SHA256 完整性校验，带百分比、可取消，按「路径+大小+修改时间」缓存

相册自动备份

仅移动端
桌面 移动 Web

手机相册自动往服务器上备份。可以只在 Wi-Fi 下传、只在充电时传， 并且永远不删远端文件 —— 手机上删照片，服务器上的备份还在。

  • 先核对再上传：先建好远端索引，索引命中的文件直接跳过，连本地文件都不读
  • 完整性校验：上传前算 SHA256，服务端合并分片时比对，同一文件重试不重算
  • 进度可见：带百分比、可取消；校验与上一个文件的上传可以重叠
  • 不拉爆机器：未开始传输的任务超过 10 个时本轮不再提交，留到下一轮

媒体修复中心

桌面 移动 Web

损坏或不完整的视频在播放时会被拒绝，这时可以手动发起一次离线修复： ffmpeg 无损重封装（不重新编码），产物验证能播之后才覆盖原文件。

  • 不重编码：只重封装容器，画质与音质一字节不损失
  • 状态可追：pending → running → verifying → success，三端任务列表共享
  • 产物先隔离：落在原文件同目录的隐藏目录 .jflove-repair/，验证通过才二次确认覆盖
  • 权限如实：发起 / 覆盖要求该磁盘的写 + 删权限，只读账号可看不可操作
实现要点
触发播放路径不跑 ffmpeg，只在用户手动发起时执行
并发管理员可配 media_repair_max_concurrent，默认按 CPU 核数推导，硬上限 8
覆盖验证能播后二次确认，原子替换，不留备份
入口文件行内「修复损坏媒体」，仅媒体扩展名可用
实现要点
输入限制仅接受无需登录即可访问的网页；不支持登录态 / Cookie / DRM 流 / 直播
解析三级降级：站点解析 → 静态抓取 → 无头浏览器兜底（末级可全局关闭）
产物视频合并为带音轨 .mp4；音频保留原格式不转码；多图落同名子目录
落点该账号配置的默认目录（必须有写权限），完成后直接出现在「文档管理」
出站安全服务端唯一主动出站通道，逐跳禁内网 / 禁回环

离线下载

桌面 移动 Web

贴一个网址，服务端把里面的视频 / 音频 / 图片列成可勾选的清单， 选中后下载到你自己账号的磁盘目录，完事就在文件管理里。 音视频分离的站点会自动把音轨合回去。

  • 勾选式：先看清清单再决定下什么，不盲目整站拖
  • 自动补音轨：合并失败会明确报错并可重试，绝不产出无声文件
  • 多协议：直链 / HLS / DASH / 批量图片；图片还可以「继续抓下一页」逐页追加
  • 三端可管：新建、勾选、取消、重试、删除，以及配置账号级默认目录

存储与临时文件治理

桌面 移动 Web

断点续传的分片、离线下载的半成品、修复任务的中间文件 —— 都收进统一的隐藏临时根， 用一个期限统一保护，到期安全清理。清理只针对程序自产的、固定命名的文件。

  • 统一临时根：进程级临时目录收拢到 build/tmp；每块磁盘根下只有一个 .jflove-tmp/
  • 一个期限：默认 24 小时，管理员可配 1 小时 ~ 7 天，同时决定续传过期与残留清理
  • 不会误删：只删允许根内、程序自产、固定命名的临时文件，正常文件不碰
  • 三端共享：App / 桌面 / Web 的「系统设置」都有「存储与临时文件」卡片，改完立即生效
实现要点
迁移旧 .jflove-download / .jflove-repair 启动时自动迁移
自动清理开关与周期可配；关闭只停定时任务，「立即清理」仍可手动执行
过期行为客户端从头上传，不报错
升级要求合并协议强制异步，服务端与三端须同批次升级
实现要点
配置位置主机 / 端口 / 账号 / 密码 / 私钥 / 跳板 / 分组 / 连接后执行命令，按账号隔离存服务端
认证密码 / 密钥 / 密码+密钥（双因素）/ 密码+OTP
认证推进严格按 SSH 返回的 authlist 走，不猜方法、不发多余探测
多步认证整次认证只开一次 ssh-userauth，后续步骤同会话内推进
连接路径SSH / SFTP 由客户端直连目标主机，不经过服务端

远程连接

仅桌面端
桌面 移动 Web

内嵌的 SSH 终端与 SFTP，任意级跳板、密钥、OTP 都能配，配置存在服务端、按账号隔离 —— 换台机器也带着走。另有一个只连本机的终端。

  • 任意级跳板：逐跳状态可见，主机指纹首次确认，连接后自动执行命令
  • 凭据状态如实：私钥口令是否设置由服务端布尔标记决定，没设过就显示「未设置」
  • SFTP 同一条连接：与终端共用，浏览 / 上传 / 下载 / 删除 / 新建目录，传输队列可取消
  • 旧服务器兼容：仅当服务器只提供旧算法时启用 ssh-rsa / RSA-SHA1 与 SHA-1 KEX
11 / 11

安全通信

桌面 移动 Web

除三个明文白名单接口外，所有请求、成功响应、错误响应都装进 ChaCha20-Poly1305 信封。 每次会话临时协商密钥，会话密钥只存内存，私钥用完即销毁。

  • 前向保密：X25519 ECDH + HKDF-SHA256（盐 jflove-v1，32B），不落盘
  • 文件流也加密：下载 / 预览按 64KB 分片独立加密，篡改任意一帧都会认证失败
  • 错误响应同样加密：全局异常处理器统一包裹，连 404 与 422 也不漏
  • URL 不带明文参数：业务参数只在加密 body 里；Web 端只读接口 query 中仅含密文
实现要点
明文白名单GET /health、POST /auth/key-exchange、GET /auth/admin-exists
鉴权JWT(ES256)，只从加密 body 的 token 字段读取
帧结构[4B 大端长度][12B nonce][密文 + 16B tag]
三端统一同一套协议：桌面 / 移动 / Web 均可互通
接口规模74 个 API，按 11 个 controller 分组
