# 官网设计规范（已由用户确认，改前必须重新确认）

> 确认日期：2026-11-21｜基准稿：`website/design/v2/`（四页）
> 本文是**可判定的审美判据**，不是风格散文。每一条都能对着截图说"符合 / 不符合"。

## 0. 用户原话（唯一需求来源）

> 「简约，蒂芙尼蓝配色，不要花里胡哨，突出用户想看的重点」
> 「我本意是想用户进来看到的是产品，以及产品介绍……对于安装和文档以及一些产品操作指引文档，
> 留入口就行，入口要放到显眼的位置，总之就是大量的篇幅是产品介绍，少量的面板是其它资料的指引入口」
> 「用橘猫，其它颜色配色不用改」

由此推导出三条不可违反的原则：

| # | 原则 | 判据 |
| --- | --- | --- |
| P1 | **产品优先** | 首页 70% 以上篇幅是产品介绍（场景 / 界面 / 能力），资料入口 ≤ 1 个区块 |
| P2 | **简约克制** | 全站无渐变背景、无发光、无大圆角、无动画炫技（滚动/视差/弹跳一律不要） |
| P3 | **蓝只做强调** | 蒂芙尼蓝只出现在：主按钮、关键数字、强调词、选中态、图标底、链接 hover |

## 1. 色彩

| 用途 | 值 | 用在哪 |
| --- | --- | --- |
| 主色（蒂芙尼蓝） | `#0ABAB5` | 主按钮底、Logo 旁徽章、关键数字、选中态下划线 |
| 主色深 | `#0A8F8B` | 链接、hover、强调文字（正文里的关键词） |
| 主色浅底 | `#E6F7F6` | 徽章底、图标底、当前菜单项底 |
| 正文 | `#12181C` | 标题、正文主色 |
| 次级 | `#3A4650` | 段落、说明文字 |
| 弱化 | `#6B7883` | 元信息、脚注、时间戳 |
| 分割线 | `#E4E9EC` | 1px 边框、表格线 |
| 背景 | `#FFFFFF` / `#F7F9FA` | 白底为主，浅灰只用于**分区块**（相邻区块交替） |

**禁止**：紫色 `#6366f1` 等产品内部主题色出现在官网（那是 App 内配色，不是官网）。

## 2. 品牌

| 项 | 规定 |
| --- | --- |
| Logo | **产品真实橘猫**（`website/public/logo-256.png`，与 `jflove-web/public/` **逐字节一致**，判据⑨会拦） |
| Logo 在顶栏的尺寸 | 24×24，圆角 5px |
| 站名 | `JFLove`（大小写固定为 JFLove，不是 JFLOVE / jflove） |
| 禁止 | 自造字母方块、「JF」字样图标、任何非橘猫的品牌图形 |

## 3. 排版

| 项 | 规定 |
| --- | --- |
| 正文字号 | 14~15px；说明文字 13px；元信息 12~12.5px |
| 标题层级 | H1 40px（首页 Hero）/ 32px（内页）/ H2 24px / H3 15~16px |
| 行高 | 正文 1.65；标题 1.2~1.25 |
| 字体栈 | `-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif` |
| 字距 | 大标题 `-0.02em`；正文 0 |
| 数字 | 一律 `font-variant-numeric: tabular-nums`（版本号、体积、统计） |

## 4. 布局与间距

| 项 | 规定 |
| --- | --- |
| 内容最大宽度 | 1140px，左右内边距 28px（移动端 18px） |
| 区块上下留白 | 桌面 62px，移动 46px |
| 断点 | 980px（主导航折叠）、520px（移动细节） |
| 圆角 | 容器 10px，按钮 7px，小标签 4~5px；**禁止 > 12px** |
| 阴影 | 最多一层极轻投影，或不用；**禁止多层投影堆叠** |
| 网格 | 卡片区用 `repeat(auto-fill, minmax(310px, 1fr))` 或等分列 |

## 5. 各页职责（用户确认的信息架构）

| 页面 | 定位 | 篇幅要求 |
| --- | --- | --- |
| `01-home` 首页 | **产品展示**（主战场） | Hero + 至少 4 个产品场景区块 + 三端概览；资料入口只占 1 个区块（4 卡） |
| `02-features` 功能 | 11 项能力逐条展开 | 每项：左文右图或左图右文**交替**，附「实现要点」表 |
| `03-docs-hub` 文档中心 | **轻量入口页** | 以入口卡为主，不放长正文；顶部一条版本一致性横幅 |
| `04-guide-web` 操作指引 | 逐菜单逐按钮 | 左侧粘性目录 + 右侧「在哪 → 做什么 → 点击什么 + 界面原文」 |

**资料入口必须显眼**：首页底部 4 张卡（快速安装 / 操作指引 / API 文档 / 更新日志），
每张卡有图标 + 标题 + 一句话 + 箭头，**不得缩成一行小链接**。

## 6. 操作指引的图文规范

| 项 | 规定 |
| --- | --- |
| 配图类型 | **真实产品截图**（当前版本实拍），不用手绘示意图代替 |
| 截图来源 | `website/public/screenshots/{web,desktop,mobile}/*.png`（各端尺寸不同：Web/桌面 1440×900，移动 1080×2400） |
| 截图标注 | 每张图下方必须标注「**v<版本号> 实拍**」+ 当前页名称，例如「登录页 · 填服务端地址」 |
| 特殊裁切 | 登录页是居中卡片，上下留白大 ⇒ 用 `aspect-ratio:16/7; object-fit:cover` 只留卡片区 |
| 文案对照 | 每节必须带「界面原文」块，逐字引用 UI 文案（由判据⑦核对） |
| 禁止 | 用旧版本截图；用产品内部紫色主题冒充官网配色 |

## 7. API 文档规范

| 项 | 规定 |
| --- | --- |
| 数据源 | **`website/content/api-openapi.json`**，由 `website/scripts/gen_api_docs.py` 从 `app.openapi()` 生成 |
| 禁止 | 手抄接口清单；从生产服务器在线拉取 |
| 分组展示 | 按 tag 分组，组内按路径排序，显示每组条数与总数 |
| 每条接口显示 | 方法 + 路径 + summary + description（description 里的加密字段说明**原样展示**） |
| 明文标记 | 3 条明文接口必须单独标出，并与 `_PLAIN_PATHS` 一致（判据⑩） |
| 调用流程 | 必须内置「五步调用流程」（密钥交换 → 派生 → 信封 → 登录 → 带 token），见 `website/docs/api-contract.md` |
| 明确说明 | **不提供在线调试**（加密接口无法直接 Try it out）；不提供 SDK；`requestBody` 只有 1/75 有结构，其余靠 description 散文 |

## 9. 可判定的验收清单

发布前逐条核对，任一不符即打回：

- [ ] Logo 是橘猫，与 `jflove-web/public/logo-256.png` 逐字节一致（`check_website_sync.py` 判据⑨ = 0）
- [ ] 全站没有紫色 `#6366f1` 作为主色
- [ ] 没有 CSS 渐变背景、没有多层阴影、圆角 ≤ 12px
- [ ] 蒂芙尼蓝只出现在 P3 列出的 6 类位置
- [ ] 首页产品介绍区块 ≥ 4 个，资料入口 ≤ 1 个区块
- [ ] 每个操作指引配图有「v<版本号> 实拍」标注
- [ ] 数字全部 `tabular-nums`
- [ ] 1440 与 390 两个视口都无横向溢出
- [ ] 四页顶部无 frontmatter 残留、零外部资源引用

## 10. 变更规则

1. 本文任何一条改动，**必须先让用户看新稿并书面确认**（与 Step 2 同一流程）。
2. 改完同步更新 `website/design/v2/` 的四页稿与截图，不留"文档说 A、稿子是 B"。
3. 判据化优先：能写成门禁的（Logo 一致性、文案可溯源、OpenAPI 一致）就不要只写在文档里。
