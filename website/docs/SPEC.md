# 官网标准（骨架 / 布局 / 导航 / 内容规范）

> **本文件是官网的"宪法"**：站点结构已定型，后续更新只改内容、不改骨架。
> 执行体：`.agents/skills/website/SKILL.md`；机器判据：`scripts/check_website_sync.py`。
> 改动本文件任何一条，都必须先让用户确认（与设计确认同一流程）。

---

## 1. 站点骨架（定型，不再增减页面）

固定 **9 个路由**，一个不多一个不少：

| 路由 | 页面 | 定位 |
| --- | --- | --- |
| `/` | 首页 | **产品展示为主**（70% 篇幅讲产品） |
| `/features` | 功能详情 | 11 项能力逐条 |
| `/docs` | 文档中心 | 轻量入口页 |
| `/api` | API 文档 | 五步调用流程 + 接口清单 |
| `/api-announcements` | API 公告 | 接口层变更 |
| `/download` | 下载 | 产物清单 |
| `/install` | 安装指引 | 服务端 + 三端 |
| `/guide/{desktop,web,mobile}` | 三端操作指引 | 逐菜单逐按钮 |
| `/security` | 安全说明 | 协议与边界 |

**增删页面的判据**：只有当用户明确要求「加一个 X 页面」时才动，且要同步更新本表。

## 2. 导航规范（定型）

### 顶栏（全站唯一）

```
[橘猫 Logo] JFLove    产品  功能  文档  下载          v<版本>  [下载客户端]
```

- 固定 **4 项**：产品 / 功能 / 文档 / 下载
- 当前项：蒂芙尼蓝下划线 + 字重 560
- 版本号常驻右侧，来源 `content/meta.json`（禁止硬编码）
- 主按钮永远指向 `/download`

### 页脚（全站唯一）

四列：产品 / 文档 / 指引 / 关于，加一行版权与镜像名。

| 列 | 链接 |
| --- | --- |
| 产品 | 功能特性、下载、安装指引 |
| 文档 | 文档中心、API 参考、API 公告 |
| 指引 | Web 端、桌面端、移动端 |
| 关于 | 安全说明、更新日志 |

### 页内导航

- **文档中心**：6 张入口卡（安装/操作/API/公告/安全/功能）
- **操作指引**：左侧粘性目录（按菜单顺序编号），右侧正文
- **API**：顶部五步流程 → 三处易踩细节 → 明文白名单 → 分组接口清单 → 诚实边界

## 3. 页面布局标准

### 3.1 首页（`/`）

固定 4 个区块，顺序不可变：

```
① Hero        价值主张 + 双 CTA + 4 个真实统计 + 产品界面示意
② 产品场景     4 个（文件 / 笔记 / 离线下载 / 安全），左右交替
③ 三端概览     3 张卡片 + 三端支持矩阵
④ 资料入口     4 张卡（安装 / 指引 / API / 公告）—— 全站唯一入口区
```

**铁律**：资料入口**只能有一个区块**，不得在 Hero 或场景之间穿插。

### 3.2 内页通用

```
PageHead（面包屑 + 大标题 + 导语）
→ 内容区块（每个区块以 SectionTitle 开头）
→ 页脚
```

- 内容最大宽度 **1140px**，左右内边距 28px
- 区块上下留白：桌面 62px / 移动 46px
- 断点：980px（顶栏折叠）、520px（细节）

### 3.3 操作指引页（`/guide/:platform`）

```
PageHead
→ [左] 粘性目录（11 节以内）    [右] 正文
                                  每节 = 在哪 / 做什么 / 点击什么
                                       + 提示条（可选）
                                       + 界面原文表（逐字对齐）
                                       + 真实截图（带「v<版本> 实拍」）
```

## 4. 内容标准（每类页面必须有什么）

### 4.1 首页必须有

- [ ] 一句价值主张（说清「是什么 + 给谁用」）
- [ ] 4 个真实统计（能力数 / API 数 / 端数 / 许可），全部来自 manifest
- [ ] 至少 4 个产品场景，每个配界面示意
- [ ] 三端支持矩阵（11 项 × 3 端）
- [ ] 4 张资料入口卡

### 4.2 功能页必须有

- [ ] 三端支持矩阵 + 合计行
- [ ] 11 项逐条（编号 NN/11 + 名称 + 三端徽章 + 摘要）
- [ ] 数据源脚注（指向 README「功能特性」）

### 4.3 API 页必须有

- [ ] OpenAPI 版本 + 操作数 + 分组数横幅
- [ ] **五步调用流程**（密钥交换 → 派生 → 信封 → 登录 → token）
- [ ] 三处易踩细节（错误也加密 / GET 可 query / 文件分帧）
- [ ] 明文白名单 3 条
- [ ] 按分组展开的接口清单（可折叠，含 description 原文）
- [ ] **"本页不提供什么"**（不提供在线调试 / SDK / 机器可校验结构）

### 4.4 下载页必须有

- [ ] 4 类客户端产物（名称 + 体积 + 一句话用途）
- [ ] 2 个镜像（server / web）+ 端口说明
- [ ] "选哪个端"决策表

### 4.5 安装页必须有

- [ ] 服务端启动命令（含挂载说明）
- [ ] **明文白名单提醒**（反代必须放行这 3 条）
- [ ] Web 端部署（含同源说明）
- [ ] 三端客户端安装步骤
- [ ] "各端怎么填服务端地址"表

### 4.6 操作指引页必须有（每端独立）

- [ ] 本端导航结构（不混入其它端）
- [ ] 每个菜单一节，含「在哪 / 做什么 / 点击什么」
- [ ] **界面原文**表（逐字对齐 UI 文案）
- [ ] **真实截图**（当前版本实拍，带版本标注）
- [ ] 本端**没有**的功能要写明「是设计如此，不是坏了」

### 4.7 安全页必须有

- [ ] 四层协议（密钥交换 / 派生 / 信封 / 文件流）
- [ ] 明文白名单 + 为什么是这三条
- [ ] 前向保密的意义
- [ ] 三条鉴权硬规则
- [ ] **"本项目不做什么"**（不做 pinning / 不明文传输 / 不记日志 / 不交第三方）
- [ ] 用户自查方法

## 5. 内容更新标准（日常维护只做这些）

站点骨架不变，每次项目发版后只更新以下内容：

| 更新对象 | 触发条件 | 命令 |
| --- | --- | --- |
| 功能特性 | README「功能特性」有增删 | `website/scripts/extract_sources.py` |
| 接口清单 | 后端接口有增删改 | `website/scripts/gen_api_docs.py` |
| 版本号 | `version.json` 变了 | `scripts/sync_version.py` |
| 下载产物 | Release 有新资产 | 手改 `DownloadPage`（体积需人工核对） |
| 操作指引 | 三端 UI 有变化 | 先更新事实清单，再改指引 |
| 截图 | UI 有变化 | 重跑截图工具 |
| 更新日志 | 每版必产 | `文档记录/官网记录/<版本>.md` |

**判定顺序（强制）**：先跑抽取 → 再跑门禁 → 红了就修数据源 → 全绿才改页面。

## 9. 截图标准（强制）

**三端都必须有真实截图**，不能用示意图代替。这是用户明确要求的标准。

| 端 | 工具 | 命令要点 |
| --- | --- | --- |
| Web | `website/tools/shoot-product.mjs` | 同会话登录后逐页截；需 `proxy-dist.py` 提供 SPA+反代 |
| 桌面 | `website/tools/shoot-desktop.py` | **必须设干净 `XDG_DATA_HOME`**，否则读到残留旧会话 → 401 |
| 移动 | `scripts/verify/android_smoke.sh` 或 adb screencap | 需 AVD（本机 `jflove-api36`） |

**截图前必做**：

1. 版本对齐：`sync_version.py --check`
2. 重建产物：Web `vite build` / 桌面 `ui/dist` 必须是当前版本
3. 起临时后端（`scripts/verify/server.sh start`，复制 dev 库到 `/tmp`，**绝不碰真实库**）
4. 口令只用于 `/tmp` 副本库，不写入任何入库文件

**截图后必验**：

- [ ] 每张图内容正确（**不是 401 / 加载失败 / 空白页**）
- [ ] 账号与预期一致（不能是残留会话的旧账号）
- [ ] 版本号在当前图上可见
- [ ] 放入 `website/public/screenshots/{web,desktop,mobile}/`

### 9.1 截图版本绑定（硬标准，机器强制）

> **旧版本客户端的截图绝不允许作为操作指引发布。**（用户明确要求）

截图不能自证版本 —— v1.10.17 和 v1.10.21 的界面长得几乎一样。
实测踩过：本地 `app-release.apk` 是 v1.10.17，装上去截的图"看起来完全正确"，但版本过时。

**三道机制**：

| 机制 | 实现 | 失败后果 |
| --- | --- | --- |
| **版本绑定** | `stamp_screenshots.py` 登记每张图的 `version` + `sha256` → `content/screenshots.json` | 图被换但台账没更新 ⇒ ⑫ 红 |
| **版本锚点** | 每端必须有 `settings` 截图（图上直接显示 `JFLove vX.Y.Z`） | 缺锚点 ⇒ ⑫ 红 |
| **升级强制重拍** | 台账版本必须等于 `version.json` | 升版本没重拍 ⇒ ⑫ 红（**故意设计成会红**） |

**截图前的版本核验命令（必须做）**：

```bash
# 移动端 APK
aapt dump badging build/app/outputs/flutter-apk/app-release.apk | grep versionName
#   → 必须等于 version.json，且 versionCode 派生正确（1.10.21 → 1010021）

# Web / 桌面端产物
grep -o '1\.10\.[0-9]*' jflove-web/dist/assets/*.js jflove-desktop/ui/dist/assets/*.js
#   → 必须等于 version.json
```

**重截图后必须跑**：

```bash
python website/scripts/stamp_screenshots.py          # 重生成台账
python scripts/check_website_sync.py                 # ⑫ 必须绿
```

**版本锚点图说明**：

| 端 | 锚点页 | 版本号显示位置 |
| --- | --- | --- |
| Web | `settings.png` | 「关于」分区 → `JFLove v1.10.21` |
| 桌面 | `settings.png` | 「关于」分区 → `JFLove v1.10.21` |
| 移动 | `settings.png` | 「关于」分区 → `版本 v1.10.21` |

> **踩过的坑**：桌面端首次截图全部是「加载失败 [401] 令牌无效或已过期」，
> 根因是 `~/.local/share/JFLove/storage` 里残留 `vmtest` 的旧 JWT。
> 修法：`XDG_DATA_HOME` 指向临时目录。**没有目视检查截图内容，这批图就会被当成"已完成"。**

## 10. 变更规则

1. 本文件是**站点骨架的定型文档**：日常更新只改内容（§5），不改骨架（§1-3）。
2. 要改骨架 / 导航 / 布局，必须先让用户确认，再同步改：本文件 → 页面 → 设计稿 → 截图。
3. 能写成门禁的规则（Logo 一致、文案溯源、OpenAPI 新鲜、设计规范）**不要只写在文档里**。
