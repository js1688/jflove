# JFLove v1.7.0 需求文档 —— 目录级挂载云盘与移动端相册备份

> **本版本是一次「同步模型换代」版本**：桌面端把"整目录双向同步"换成**目录级挂载的云盘**（按需缓存、状态可见、固定/释放），移动端把"同步管理"整体移除、换成**相册自动备份**，Web 端移除不再提供服务的同步面板；服务端新增**变更日志**支撑增量同步。
> **范围**：`jflove-server`（新增 journal + 增量接口）、`jflove-desktop`（挂载内核 + 状态 UI）、`jflove-app`（相册备份 + 删除同步管理）、`jflove-web`（删除同步面板）。
> **数据库**：服务端**新增表**（变更日志），需要 `migrate-1.7.0.sql` / `rollback-1.7.0.sql`。
> 编写角色：product（Phase 1，`AGENTS.md §7.3`）。

## 1. 版本概述

### 1.1 一句话定位

**v1.7.0 让"远端磁盘"第一次在桌面端像一块网盘一样被使用——按目录挂载、看得到全部内容、看得到哪些已缓存、点开才下载；移动端则专心做好一件事：相册自动备份。**

### 1.2 与上一版本（v1.6.2）的差异

| 维度 | v1.6.2 | v1.7.0 |
|------|--------|--------|
| 桌面端同步模型 | 整目录双向 diff（全量扫描 + size/mtime 猜） | **目录级挂载 + 按需缓存 + 状态机 + 增量 journal** |
| 桌面端"同步管理" | 独立页面：配置本地目录 ↔ 远端目录 | 改造为**挂载点管理**（同一入口，语义 = 缓存策略） |
| 状态可见性 | 无（只有传输列表） | **文件级状态**（仅在线 / 已缓存 / 同步中 / 失败 / 冲突）+ 系统云状态列（Windows） |
| 删除行为 | 本地删 → 下一轮从远端拉回 | **永不自动删除**；本地删除仅删缓存/占位，远端不动 |
| 冲突 | 静默按 mtime 覆盖 | **生成冲突副本**，两个版本都保留，用户可处理 |
| 断点 | 无 | **分片续传 + 本地记录已传分片** |
| 移动端 | 同步管理页（1125 行）+ 目录同步引擎 | **删除**；改为设置页相册备份开关 + 传输页进度 |
| Web 端 | 同步面板（82 行说明页） | **删除**（路由 / 菜单 / 页面 / 死代码一并移除） |
| 服务端 | `/sync/snapshot` 全量扫描 | **新增变更日志 + 增量接口**；`snapshot` 保留一个版本兼容 |
| 数据库 | 无变更 | **新增变更日志表**（需迁移脚本 + 回滚脚本） |

### 1.3 版本号、范围与命名

- 版本号：**1.7.0**（唯一真相 `version.json`，由 `scripts/sync_version.py` 同步）。
- 范围：`jflove-server` + `jflove-desktop` + `jflove-app` + `jflove-web`。
- 命名：本次功能在界面统一称「**云盘挂载**」（桌面端）与「**相册备份**」（移动端），不再出现「同步管理」字样（桌面端挂载点列表除外，见 F20）。

### 1.4 范围边界（**明确不做**）

| 不做 | 原因 |
|------|------|
| 服务端 WebDAV / SMB / SFTP 出口 | D1：只为自己客户端服务；标准协议会把 E2E 降级为 TLS-only |
| 第三方工具直连（rclone / 电视 / 第三方文件管理器） | 同上 |
| 移动端系统级挂载（DocumentsProvider / SAF） | 成本高、无缓存状态、且会把内容暴露给任意 App（与"不全量暴露"冲突） |
| iOS / 鸿蒙 | 首版 Android-only（沿用既有平台策略） |
| 通讯录 / 短信 / 通话记录同步 | 用户明确"其它都不改"；隐私敏感 |
| 系统备忘录同步 | 无系统级公开 API，各家私有 |
| Web 端文件同步 / 挂载 | 浏览器无文件系统访问能力 |
| 桌面端"盘符"形态 | CfAPI 给的是带云状态的文件夹（OneDrive 同款）；盘符与云状态在 Windows 上二选一，本版选云状态 |

## 2. 目标用户与使用场景

### 2.1 目标用户

- **桌面端**：需要在电脑上像访问本地磁盘一样访问远端文件、但不想整盘下载的用户（自托管 NAS / 私有云场景）。
- **移动端**：只想让手机照片自动备份到自己的服务器、不想用第三方网盘的用户。

### 2.2 核心场景

**场景 A（桌面端 · 挂载）**：用户把「照片库」这个远端子目录挂载到 `D:\JFLove\照片库`。打开资源管理器，看到所有照片（未缓存的显示云朵图标），双击一张 → 拉取并打开；右键「固定到本地」→ 整个目录离线可用。

**场景 B（桌面端 · 多挂载点隔离）**：用户同时挂载「照片库」和「项目文档」到两个不同本地路径。挂载「照片库」的资源管理器窗口里**看不到**「项目文档」的任何内容。

**场景 C（移动端 · 相册备份）**：用户在设置里打开「相册自动同步」，选择远端目录「手机相册」，开启「仅 Wi-Fi」。之后拍的每张照片在 Wi-Fi 下自动上传；传输页能看到进度与失败项。

**场景 D（移动端 · 关闭）**：用户关掉开关 → 立即停止新的上传，已上传的不受影响；重新打开后从上次中断处继续（不重复传已备份的照片）。

### 2.3 判断这次做成功的标准（用户口径）

1. 桌面端打开挂载目录，**看到的是全部远端文件**，不是"已下载的那部分"。
2. **每个文件的状态一眼可见**：已缓存 / 未缓存 / 同步中 / 失败 / 冲突。
3. 没有缓存的文件**点开才下载**，不点就不占本地空间。
4. 手机上照片**自动上传**，不需要手动操作；失败能看见、能重试。
5. 全程**加密传输**，权限**服务端说了算**。

## 3. 功能需求

### 3.1 F16 桌面端目录级挂载（**新增**）

1. **挂载点定义**：一个挂载点 = `(远端磁盘, 远端子目录, 本地路径, 开关)`。用户可创建**多个**挂载点；同一远端目录可被多个挂载点引用；不同挂载点之间**互不可见**（挂载 A 的目录树里不出现 B 的内容）。
2. **挂载点管理入口**：原「同步管理」页面改造为「云盘挂载」页，列出挂载点（名称 / 远端路径 / 本地路径 / 状态 / 开关 / 缓存占用）；支持新增、编辑、删除、立即同步。
3. **默认关闭**：新建挂载点后开关默认**关闭**，用户手动打开才开始连接（D12）。
4. **系统集成（Windows）**：挂载点启用后，资源管理器中的本地路径显示为**带云状态的文件夹**；状态至少包含「仅在线」「已缓存」「同步中」三种（对应 CfAPI 的 placeholder / hydrated / syncing）。
5. **系统集成（Linux）**：挂载点启用后表现为一个 **FUSE 挂载目录**；可浏览、可按需读取；状态只能在客户端界面查看（Linux 无系统级云状态列）。
6. **越界防护**：挂载点只能指向用户**有读权限**的远端目录；创建时即校验，无权限直接拒绝并给出中文原因。
7. **降级预案**：若 Windows CfAPI 预研不通过，降级为 WinFsp 虚拟盘（**无系统云状态列**，状态改由客户端界面展示），并在发布记录中写明降级事实；**不得**用"假占位"冒充云状态。

### 3.2 F17 缓存状态与固定 / 释放（**新增**）

1. **文件状态**（客户端界面逐文件可见）：`仅在线` / `已缓存` / `同步中` / `上传中` / `失败` / `冲突`。
2. **按需读取**：`仅在线` 的文件在用户打开时才下载；下载完成前不得让目标程序读到半截内容。
3. **固定**：「固定到本地」把文件或整个目录变为 `已缓存`，并**保持**（远端变更时自动更新本地副本）。
4. **释放**：「释放空间」删除本地缓存、保留占位，状态回到 `仅在线`；**不得**影响远端文件。
5. **缓存占用可见**：挂载点列表显示每个挂载点当前缓存占用；提供「清理缓存」动作（只删可释放的缓存，不删已固定的文件，除非用户显式选择）。
6. **删除语义**：删除一个已缓存文件 = 删除本地缓存；远端文件**不受影响**（沿用"永不自动删除"安全约束，见 F22）。

### 3.3 F18 服务端变更日志与增量同步（**新增**）

1. **变更日志**：服务端记录每个虚拟磁盘内的文件变更（新增 / 修改 / 删除 / 重命名 / 移动），带单调递增的版本号（`rev`）。
2. **增量接口**：客户端传入 `disk_id + 子目录 + since_rev`，服务端只返回**该子目录范围内**的增量（不得把其它子目录的变更回传给挂载点，防止越界暴露）。
3. **快照兼容**：旧 `POST /api/v1/sync/snapshot` 本版**保留**（桌面端旧逻辑过渡期使用），下个版本再评估移除。
4. **一致性**：客户端拿到的增量必须与"当前文件状态"一致（不得出现"已删除但仍返回"或"已存在但无记录"）。
5. **性能**：单次增量请求的数据量只与"变更数量"相关，与目录总文件数无关。

### 3.4 F19 移动端相册自动备份（**新增**）

1. **入口**：设置页新增「相册自动同步」分组，包含：
   - 总开关（**默认关闭**）；
   - 远端目标目录选择（只能选用户**有写权限**的目录）；
   - 备份范围：图片（默认开）/ 视频（默认开，可关）；
   - 网络条件：仅 Wi-Fi（**默认开**）/ 仅充电（默认关）。
2. **自动行为**：开关打开后，新增照片在满足条件时**自动上传**（前台服务保活，通知栏可见「正在备份相册」）。
3. **进度与结果**：传输页新增「相册备份」分区，显示：待备份数量、正在上传（含进度）、已备份数量、失败项（可重试）。
4. **不重复**：已备份过的照片不得重复上传（以媒体标识 + 内容哈希判定）。
5. **断点**：上传中断后重新开始，从已上传的分片继续（不整文件重传）。
6. **永不删除**：手机端删除照片**不得**删除远端已备份文件。
7. **管理员警告**：若当前登录账号为管理员，开关旁显示中文警告（"管理员可写入所有磁盘"），但**允许**开启（D10）。
8. **权限引导**：无相册读取权限时，给出中文引导（按 Android 版本区分文案），不得静默失败。
9. **厂商适配**：检测到国产 ROM（小米 / 华为 / OPPO / vivo 等）时，提示用户把本应用加入「自启动 / 后台运行 / 电池优化白名单」，并给出可复制的说明。
10. **关闭即停**：关闭总开关后，立即停止新的上传任务（进行中的可完成或取消，由用户选择）。

### 3.5 F20 删除两端同步管理（**改造 / 删除**）

1. **移动端**：删除「同步」页面、路由、导航入口、同步服务 / 引擎 / 模型 / Provider；**不保留**任何旧同步配置的读写路径（旧配置数据可保留文件但不被读取，不迁移）。
2. **Web 端**：删除 `/sync` 路由、桌面布局与移动布局的「同步」菜单项、`SyncPage` 页面、未被引用的 `sync-service`；删除后全站不再出现「同步管理」入口。
3. **桌面端**：不删除页面，而是把「同步管理」**改造**为「云盘挂载」（F16），保留入口位置与用户既有配置的**迁移能力**（旧同步配置 → 挂载点），迁移失败时必须给出中文说明，不得静默丢弃。

### 3.6 F21 传输与备份进度可见性（**新增 / 改造**）

1. **统一可见**：桌面端挂载产生的下载/上传、移动端相册备份，都必须在传输页可见（任务名、大小、进度、状态）。
2. **失败可处理**：失败任务可**重试**、可**取消**；失败原因用中文展示（不得只给英文异常原文）。
3. **不静默**：任何"提交了但没结果"的情况都不得存在——每个任务必须有终态（成功 / 失败 / 取消）。

### 3.7 F22 冲突与安全约束（**沿用并强化**）

1. **永不自动删除**：任何同步 / 挂载行为都不得删除远端文件；释放空间只删本地缓存；移动端删照片不删远端。
2. **冲突不静默**：同一文件两边都被修改时，**保留两个版本**（生成冲突副本，文件名带可识别后缀），并在客户端标记为「冲突」；不得按 mtime 静默覆盖。
3. **加密不变**：所有传输仍走现有加密信封与分片加密流；本版**不新增**加密算法、不扩大明文白名单、不引入长期密钥。
4. **权限在服务端**：客户端配置（挂载点 / 备份目录）**不构成授权**；服务端对每个请求独立校验读/写权限，越权返回 403。
5. **路径越界防护**：挂载点与备份目录的远端路径必须经过服务端既有路径校验，不得通过 `..` / 符号链接逃逸。

## 5. 非功能需求（体验层面）

1. **不卡 UI**：挂载目录的浏览、状态刷新不得阻塞主界面（长任务在后台线程/进程）。
2. **可见性**：任何挂载点 / 备份任务的状态变化必须在 **2 秒内**反映到界面（不要求实时，但不得需要手动刷新）。
3. **失败可解释**：所有失败必须给中文原因 + 可执行动作（重试 / 检查权限 / 检查网络）。
4. **资源占用**：挂载点不启用时**不得**产生后台网络请求（默认关闭，D12）。
5. **兼容**：旧版本用户升级后，桌面端既有同步配置能迁移为挂载点（F20.3）；移动端旧同步配置不迁移、不报错。
6. **平台**：Windows 10/11（CfAPI）；Linux（FUSE，主流发行版）；Android 8.0+（相册备份，首版）。

## 6. 交互流程

### 6.1 流程 O：桌面端新建挂载点

1. 进入「云盘挂载」页 → 点「新建挂载点」。
2. 选择远端磁盘 → 浏览并选择**子目录**（只能是目录）→ 选择本地路径。
3. 校验：无读权限 ⇒ 中文提示"没有该目录的读取权限"，不允许创建。
4. 保存后开关**默认关闭**；打开开关 → 开始建立连接、拉取增量、生成占位。
5. 失败（网络 / 权限 / 挂载驱动不可用）⇒ 挂载点状态显示「连接失败」+ 中文原因 + 「重试」。

### 6.2 流程 P：打开一个未缓存文件

1. 用户在资源管理器（或客户端文件列表）双击一个「仅在线」文件。
2. 状态变为「同步中」→ 开始下载（可在传输页看到进度）。
3. 下载完成 → 状态变「已缓存」→ 交给系统默认程序打开。
4. 下载失败 → 状态变「失败」→ 中文原因 + 可重试。

### 6.3 流程 Q：固定 / 释放

1. 右键文件或目录 → 「固定到本地」⇒ 下载并保持（远端变更时自动更新）。
2. 右键 → 「释放空间」⇒ 删本地缓存、保留占位，状态回「仅在线」。
3. 释放正在被占用的文件 ⇒ 中文提示"文件正在使用"，不得强行删除。

### 6.4 流程 R：移动端开启相册备份

1. 设置 → 「相册自动同步」→ 打开开关。
2. 首次开启：请求相册权限（Android 13+ 为 `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO`），按授权结果给出中文说明。
3. 选择远端目录（只能选有写权限的）→ 选择范围（图片 / 视频 / 仅 Wi-Fi / 仅充电）→ 保存。
4. 后台服务启动（通知栏「相册备份进行中」）；传输页出现「相册备份」分区。
5. 关闭开关 ⇒ 停止新增任务，通知消失；已备份记录保留。

### 6.5 流程 S：删除两端同步管理

1. app：升级后「同步」入口消失；若用户之前配置过同步，**不迁移、不报错**。
2. Web：升级后菜单里不再有「同步」；访问旧 `/sync` 路由 ⇒ 落到 404/首页（不得白屏）。

## 8. 验收标准（AC-100 ~ AC-135）

### 8.1 F16 桌面端挂载

| AC | 判据 |
|----|------|
| **AC-100** | **挂载点可创建且隔离**：创建挂载点 A（远端目录 X）与 B（远端目录 Y）后，A 的本地路径下**看不到** Y 的任何文件名（逐文件断言）；反之亦然 |
| **AC-101** | **默认关闭**：新建挂载点后开关为关；未打开前**不产生任何网络请求**（断言请求计数 = 0） |
| **AC-102** | **全量可见**：挂载点打开后，本地路径下可见远端子目录的**全部文件**（数量与远端一致），未缓存文件以占位形式存在（文件大小 = 远端大小） |
| **AC-103** | **按需读取**：未缓存文件在被打开前，本地无实体内容（或大小为 0 的占位）；打开后内容可读且与远端 SHA256 一致 |
| **AC-104** | **Windows 云状态**：资源管理器中挂载目录的文件带云状态标识；至少能区分「仅在线」与「已缓存」两种（真机截图或系统 API 读取状态） |
| **AC-105** | **权限校验**：用无读权限的账号创建挂载点 ⇒ 创建失败且提示中文原因；直接构造请求指向无权限目录 ⇒ 服务端 403 |
| **AC-106** | **降级可识别**：若 CfAPI 不可用，客户端明确显示"当前为兼容模式（无系统状态列）"，不得伪装成 CfAPI 模式 |

### 8.2 F17 缓存与固定

| AC | 判据 |
|----|------|
| **AC-107** | **状态齐全**：客户端界面逐文件显示六种状态之一（仅在线 / 已缓存 / 同步中 / 上传中 / 失败 / 冲突），且状态与实际一致（抽查 5 个文件逐一核对） |
| **AC-108** | **固定生效**：对目录执行「固定到本地」后，该目录下所有文件变为「已缓存」，且离线（断网）仍可打开 |
| **AC-109** | **释放生效**：执行「释放空间」后本地实体被删除、占位保留、状态回「仅在线」，**远端文件仍存在**（服务端校验文件数量不变） |
| **AC-110** | **删除不伤远端**：删除本地已缓存文件后，远端同名文件仍存在且内容不变（SHA256 前后一致） |

### 8.3 F18 服务端增量

| AC | 判据 |
|----|------|
| **AC-111** | **增量只返回变更**：先同步一次，再只修改 1 个文件，`since_rev` 请求返回的变更条数 = 1（不随目录总文件数增长） |
| **AC-112** | **范围隔离**：对目录 X 的增量请求**不含**目录 Y 的变更（构造 Y 的变更后断言 X 的结果里没有 Y 的路径） |
| **AC-113** | **一致性**：增量结果与当前目录状态一致（删除的文件不出现在结果中；新增文件必须出现） |

### 8.4 F19 移动端相册备份

| AC | 判据 |
|----|------|
| **AC-114** | **入口存在且默认关**：设置页有「相册自动同步」分组与开关，首次进入时开关为**关**；关闭状态下不产生上传请求 |
| **AC-115** | **自动上传**：开关打开 + 满足条件（Wi-Fi）后，新增照片在 **1 分钟内**开始上传并在传输页出现任务（真机或模拟注入） |

| **AC-117** | **断点续传**：上传中断后重新开始，已上传分片不重传（断言分片请求数 < 总分片数） |
| **AC-118** | **永不删除**：手机端删除已备份照片后，远端文件仍存在（服务端文件数量不变） |
| **AC-119** | **权限引导**：无相册权限时，界面出现中文引导文案（0 命中英文异常原文），且给出可操作的跳转 |

## 10. 安全宪法对齐（`AGENTS.md §9` 逐条）

| 条款 | 本版如何满足 |
|------|-------------|
| §9.1 加密通道 + 文件流加密 | 挂载读 / 相册上传均复用现有加密信封与 `StreamingResponse + encrypt_stream_chunk`；不新增明文路径 |
| §9.2 密钥交换 | 完全不变（X25519 ECDH + HKDF + PFS） |
| §9.3 鉴权与权限 | 所有新接口走 JWT（加密 body 的 `token`）；挂载点 / 备份目录在服务端逐请求校验读写权限 |
| §9.4 不暴露内容 | 响应头不带文件名/路径；日志不记录明文路径（截断或哈希） |
| §9.5 加密原语清单 | 只复用 `middleware.py` / `crypto.py`；客户端只走 `http_service.dart` / `http_client.py` |
| §9.6 角色约束 | 桌面端渲染层无网络出口（挂载在 Python 侧）；移动端 session_key / JWT 不进日志 |
| §9.7 新接口自查 | 每个新接口在设计文档逐条标注：路径参数 / 归属校验 / 加密信封 / 是否文件流 / 响应头 |
