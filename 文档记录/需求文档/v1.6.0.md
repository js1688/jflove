## 1. 版本概述

### 1.1 一句话定位

**v1.6.0 在桌面端新增「文本编辑器」** —— 一个快捷键呼出、可多开、支持矩形块选择、按文档类型差异化、带 12 项文字处理工具箱、**只读写本机文件（与远端零交互）**、**先校验类型再加载内容**、并在异常退出后自动全部还原的**应用内浮动编辑窗格**；同时提供**系统「打开方式」集成（不抢占默认程序）+ 应用内细粒度文件关联**；并**顺手清掉 v1.5.1 遗留的 5 条技术债（BL-1 ~ BL-5）与服务端既有缺陷 BL-8**。

### 1.2 与上一版本的关系

- **v1.5.1**：GitHub issue 实测反馈修复版，**没有新功能**，全部改动指向既有功能的可见差异与浮层缺陷。
- **v1.6.0**：**功能新增 + 技术债清理**。与 v1.5.1 的关系是"叠加而非改写"：
  - 业务语义（加密信封、修复、同步、权限、文件流解密）**一律不变**；
  - **文本编辑器不做任何远端读写** —— 不新增接口调用、不新增路由参数、不触碰虚拟磁盘 / 文件管理 / 笔记的任何数据通道；
  - 数据库**无结构变更**（无迁移脚本需求）；
  - 服务端改动仅两项：**BL-2** 的 OpenAPI 描述文案（**行为不变**）、**BL-8** 的覆盖写原子性修复（**行为按需求修正，见 §4**）。

## 2. 目标用户与使用场景

### 2.1 目标用户

- **程序员 / 开发者**（本产品的使用者本人即是目标用户，不是"泛办公用户"）。
- 使用特征：一天里会反复遇到"手上有一段文本要处理"，但**为它打开 IDE 太重、打开记事本太弱**；同时手上有一个 `.log` / `.json` / `.yaml` 想就地改两行，不想等 IDE 起来。

### 2.2 核心场景

> **处理一段文本、就地改一个本地文件。**

典型触发：

| 场景 | 用户动作 | 现在的替代方案（痛点） |
|------|---------|----------------------|
| 拿到一段 JSON / SQL / 日志，想看清结构 | 粘贴 → 格式化 / 树形视图 / 高亮 | IDEA 打开慢、会污染工作区、可能误建文件 |
| 一堆行要去重 / 排序 / 去空行 / 去首尾空格 | 粘贴 → 工具箱一键处理 | 记事本没有这些工具 |
| 要按列取一段文本（对齐的日志、表格） | 修饰键 + 拖拽 = 矩形块选择 → 复制 | 记事本 / 浏览器不支持列选择 |
| 两段文本看差在哪 | 粘贴两段 → diff（第二段可来自剪贴板 / 另一窗格 / 本地文件） | 要开在线 diff 站点（**要把内容贴出去**） |
| 一段文本要留档 | 粘贴 → 保存 → **首次由我指定路径与文件名** | 存文件要开 IDE / 资源管理器 |
| **本机某个文本 / 日志 / JSON 文件要小改一处** | 在文件管理器里对文件选「打开方式 → JFLove」→ 编辑器窗格直接打开该文件 → 改 → `Ctrl+S` **存回原文件** | 要先用记事本 / IDE 打开，或先把文件拖到编辑器里；大文件还可能把记事本卡死 |
| 手上有一个几 GB 的可执行文件 / 镜像，误点了"用编辑器打开" | 编辑器**先校验类型** → 直接拒绝并说明原因 | 记事本会把 GB 级文件读进来卡死 / 崩溃 |

### 2.3 判断这次做成功的标准（用户口径）

1. 从"想处理一段文本"到"处理完"，**不必离开 jflove**；
2. **内容不出本机**：粘贴进来的内容、打开的本机文件内容、草稿**一律只在本机**；**编辑器与远端零交互**（既不上传、也不下载）—— 任何"远端内容因编辑而落到本机"或"本机内容上行到远端"的路径在本版本中**不存在**；
3. **"要快"**：呼出窗格的等待时间不能让人想回去开记事本（性能目标见 §5）；
4. **不丢内容**：崩溃、被杀进程、误关窗格都不能让粘贴的内容消失；保存失败不得损坏已有文件；
5. **不会被一个文件弄崩**：任何文件在**加载内容之前**先过类型校验，超大 / 二进制文件被明确拒绝或降级为只读；
6. **不依赖账号**：未登录、服务端不可达时，编辑器的全部本机能力照常可用。

## 3. 功能需求

> 需求编号 F1 ~ F10 与 §9 验收标准一一对应。
> **编号变更说明**：原 **F7「文件管理页对接」整节删除**（远端文件不经编辑器打开，见 §7.2）；F7 编号**回收**给新的「本地文件关联」；**新增 F8「类型校验先行」**；原 F8「草稿与还原」→ **F9**，原 F9「状态栏与阅读体验」→ **F10**。

### 3.1 F1 应用内浮动窗格

**用户故事**：作为开发者，我在任意页面按一个快捷键就能拿到一块空白编辑区，随手粘贴处理；我可以同时开好几块，互不干扰；我切到别的页面时它们不会消失。

**功能规则**：

1. **快速创建**：在应用任意路由页面按快捷键 → 立即出现一个新的浮动编辑窗格。
2. **多窗格**：可同时打开多个窗格，**互不干扰** —— 每个窗格各自独立的内容、文档类型/语言、视图模式（编辑/预览/分屏/表格/树形）、几何位置、脏标记、**本地文件目标路径**。
3. **窗格操作**：拖动（改位置）、缩放（改尺寸）、最小化、最大化 / 还原、关闭。
4. **层级聚焦**：点击某窗格使其置于最前；被激活的窗格不被其它窗格遮挡；层级随交互变化。
5. **平铺与层叠**：提供一键"平铺"（所有窗格互不重叠地铺满可用区域）与"层叠"（按固定偏移堆叠）两种排列。
6. **跨路由常驻**：浮动层位于窗口标题栏之下、路由内容之上；**切换路由不销毁窗格**，也不重置其内容与几何。
7. **单窗格关闭**：内容为脏时先询问（见 F9）。
8. 窗格**不是独立操作系统窗口**（该方案已废弃，见 §7.5）。

### 3.2 F2 快捷键体系

**用户故事**：作为开发者，我要的键位跟别人不一样；我要能自己改、能看到每个快捷键是干什么的，而且我不希望它去跟别的软件抢键。

**功能规则（硬性）**：

1. **全部可配置**：文本编辑器的每个快捷键都能改。
2. **有默认值**：出厂即带一套常规默认键位，装完就能用（具体键位由 Phase 2 设计提出，见 §11 U-13）。
3. **有配置界面**：界面中每一项至少显示：**功能名 + 中文功能说明 + 默认键 + 当前键 + 修改入口 + 重置入口**（支持单项重置与一键恢复全部默认）。
4. **有中文功能说明**：每条快捷键都必须有中文说明，不允许只显示键名（用户硬性要求「一定要有配置的地方和功能说明」）。
5. **不做全局热键**：**只在应用窗口激活时生效**；不注册任何操作系统级全局热键，应用失焦时一律不响应，绝不与其它程序抢键。
6. **冲突检测**：把同一个键分配给两个功能时，界面必须提示冲突，**不得静默覆盖**。
7. **不被宿主吞掉**：被页面宿主（WebEngine）默认动作占用的组合键（如打印、打开、跳转焦点等），一旦被分配给编辑器功能，就**必须由编辑器接管并真实生效**，不允许出现"配了但按了没反应"。
8. **持久化**：快捷键改动跨重启保留；重置后回到默认值。
9. **不影响既有页面**：编辑器快捷键只在编辑器窗格获得焦点/与编辑器相关时生效，不得改变既有页面的既有交互（被显式接管的组合键除外，且接管范围必须写进设计文档）。
10. **块选择的修饰键**（F3）同样在本界面可配。

### 3.3 F3 块选择（用户第一优先诉求）

**用户故事**：作为开发者，我要像在 IDEA / VSCode 里那样按住一个修饰键拖鼠标，直接框出一块矩形区域的文本，复制出来是**逐行对齐拼接**的结果。

**功能规则**：

1. **矩形块选择**：默认修饰键 `Alt` + 鼠标左键拖拽 = 矩形块选择（框选的是"列区间 × 行区间"的矩形）；**不按修饰键**时是普通流式选择。
2. **复制口径（IDE 行为）**：块内文本按行提取，**每行取该列区间的字符**；比块宽短的行**右侧补空格**补齐到块宽；行间以换行符连接。
3. **键盘方式**：修饰键 + `Shift` + 方向键也能做块扩展选择（上下按列扩展行、左右按列移动列区间）。
4. **修饰键可配置**：可在快捷键配置界面改（默认 `Alt`）。
5. **不破坏既有能力**：块选择与多光标、语法高亮、折叠、搜索共存，不因此禁用其它编辑能力。

### 3.4 F4 文档类型识别与差异化体验

**用户故事**：作为开发者，同一段文本，我要的是"符合这种格式的编辑体验" —— JSON 要能折叠和看树，Markdown 要能预览，CSV 要能看表格，代码要有括号匹配。

**功能规则**：

1. **类型识别（受 F8 约束）**：**先校验类型、再加载内容**（F8 定义了校验顺序与阈值）；类型判定顺序为 **扩展名白名单 → 二进制嗅探 → 兜底纯文本**。只有通过 F8 校验的文件才会进入本节的差异化体验。
2. **语言可手动切换**：识别错了可以手动纠正（纠正后高亮与该类型的差异化能力随之生效）。
3. **差异化能力表**：

| 类型 | 高亮 | 差异化能力 |
|------|------|-----------|
| json / jsonc | ✅ | 格式化 / 压缩 / **树形视图（只读，U-4）** / 折叠 |
| md / markdown | ✅ | **编辑 / 预览 / 分屏**（复用既有 Markdown 渲染栈） |
| csv / tsv | 表格视图高亮 | **表格视图切换（只读，U-3）**、分隔符识别、列对齐 |
| sql | ✅ | **SQL 美化**（可配置，见 F5 第 9 项） |
| xml / html / svg | ✅ | **格式化 / 压缩**（D15 新增）、折叠、缩进 |
| yaml / yml / toml / ini / conf / properties / css | ✅ | 折叠 / 缩进 |
| py / js / ts / tsx / jsx / sh / bat / ps1 / java / go / rs / c / cpp | ✅ | 括号匹配 / 自动缩进 / 注释切换 |
| log / txt / 无扩展名 | 纯文本 | 等宽字体 / 自动换行 / 大文件保护 |
| diff / patch | ✅ | **只读预览** |
| 未知扩展名（文本内容） | 纯文本 | **按 `txt` 处理**，不报错；可手动切换语言（F8 第 5 条） |
| 未知扩展名（二进制内容） | — | **不加载、不产生窗格**，明确提示（F8） |

4. **编码与换行符**：识别 UTF-8 / UTF-8-BOM / GBK，识别 LF / CRLF；**保存时保留原样**；状态栏显示当前编码与换行符（数据安全口径见 §9.10）。
5. **"只读预览"与"工具箱 diff"是两件事**：`.diff/.patch` 文件以**只读**方式打开；F5 第 11 项的「两段文本对比」是一个**工具**，对任意两段文本可用。二者不得混为一谈。

### 3.5 F5 文字处理工具箱（**12 项**）

**用户故事**：作为开发者，我贴进来的东西十有八九要加工一下才能用 —— 格式化、去重、转义、加解码、对比，我要一键拿到结果。

**功能规则（逐项列清）**：

1. **查找 / 替换（含正则）+ 跳转行**：支持正则匹配与正则替换；支持按行号跳转。
2. **行操作**：排序 / 去重 / 去空行 / 去首尾空格。口径：
   - 以按 `\n` 切分得到的**行数组**为输入，输出为以 `\n` 连接的结果（**不额外补末尾换行**）；末尾换行产生的空行同样算空行；
   - **排序**：按 Unicode 码点升序，**大小写敏感、与本地语言环境无关**；
   - **去重**：完全相等的行视为重复，**保留首次出现**；
   - **去空行**：删除内容为空字符串的行（仅空白字符的行**不算**空行）；
   - **去首尾空格**：对每行做 trim（含 `\t`）。
3. **大小写转换**：大写 / 小写 / 驼峰 / 下划线。口径：
   - 分隔符集合 = 空白符 / `_` / `-` / `.`；
   - **驼峰**：按分隔符切分，首词全小写、其余词首字母大写后拼接；
   - **下划线**：按分隔符切分后全小写，用 `_` 连接。
4. **转义 / 反转义**：JSON / HTML / URL 三组，均需可逆（转义后再反转义 == 原文）。口径：
   - JSON：`"`→`\"`、`\`→`\\`、换行→`\n`（**不含**外层引号）；
   - HTML：`& < > "` → 对应实体；
   - URL：等价于"保留 `A-Za-z0-9-_.!~*'()`、其余按 UTF-8 百分号编码"的口径。
5. **Base64 编解码**：按 UTF-8 编码/解码。
6. **JSON 树形视图 + 格式化 + 压缩**：树形视图可折叠且**只读**（U-4 已定稿）；格式化缩进 2 空格；压缩去掉结构外空白；**非法 JSON 只提示错误，不得修改原文**。
7. **Markdown 编辑 / 预览 / 分屏**：预览渲染 Markdown（复用既有渲染栈）。
8. **CSV / TSV 表格视图切换**：识别分隔符（逗号 / 制表符）、列对齐；表格视图**只读**（U-3 已定稿），**不回写**文本。
9. **SQL 美化（可配置）**：至少可配置 **方言 / 关键字大小写 / 缩进宽度** 三项，配置即时生效。
10. **XML 格式化 / 压缩**（D15 新增）：**必须保留注释与 CDATA 语义**；**压缩不得触碰文本节点内的空白**（只删元素之间的空白）；提供"格式化前预览"。⚠ **R-6 实测（2026-10-12）**：`xml-formatter` 的压缩**做不到**这条（会吃掉「纯空白文本节点」、多行输入会粘词）⇒ **压缩改为自研实现**；"格式化前预览"作为**强制**保护保留。
11. **两段文本对比（diff）**：以行为单位呈现新增 / 删除 / 修改。**第二段文本的来源支持三种**（U-5 已定稿）：**剪贴板 / 另一个编辑器窗格 / 本地文件**。
12. **字号缩放 + 行号 / 自动换行开关**：`Ctrl` + 滚轮缩放字号；行号可开可关；自动换行可开可关。

**明确不做**：**时间戳 ↔ 日期互转**（D10 已裁决，界面与文档中不得出现该功能）。

### 3.6 F6 保存与打开（**纯本地**，标准编辑器语义）

**用户故事**：作为开发者，我随手粘的东西要么不留、要么存到我指定的路径；我已经存过一次的文件，我按 `Ctrl+S` 它就存回去，**别再问我叫什么名字**。而且我不想让"编辑"这件事跟远端有任何关系。

**功能规则（标准编辑器语义）**：

| 场景 | 行为 |
|------|------|
| **新建（草稿形态）→ 首次保存** | **必须**弹出**原生文件对话框**，由用户指定**保存路径与文件名**；用户取消 → 窗格仍为脏、**磁盘上不产生任何文件** |
| 已保存文档 → `Ctrl+S` | **直接更新该文件**，**不再询问位置与文件名**，不出现任何对话框 |
| 已保存文档 → 自动保存（**默认开启**） | 内容变化防抖 **1.5 s** 后**直接写回该文件**，同样不询问；**只对已有目标路径的文档生效**（D21 裁决：默认开启、debounce 1.5 s） |
| 草稿形态文档 → 自动保存 | **永不**自动落盘到用户文件系统（只写本机草稿库，见 F9）；避免"用户不知情地在磁盘上生成文件" |
| 打开本地文件 | **原生文件对话框**打开；打开前先过 **F8 类型校验**；通过后**完整读取**（不截断） |
| 打开（由系统「打开方式」唤起） | 命令行参数传入文件路径 → 校验后进入编辑器窗格（F7） |
| 另存为 | 重新选目标路径与文件名；**原文件不被修改**（内容与 mtime 均不变） |
| 保存失败 | 明确报错；**编辑器内容与草稿不得被清空**；原文件不得被破坏 |

**边界与红线（强制）**：

1. **零远端**：**移除全部远端内容** —— 不保存到虚拟磁盘、不从远端打开、不"保存回原路径（远端）"、不出现远端目录选择器；编辑器任何路径都不读写远端数据。
2. **有路径才自动落盘**：只有用户**显式指定过路径**（首次保存或另存为）的文档，才会被 `Ctrl+S` / 自动保存写回该路径；**从未保存过的文档一律不会被静默写入磁盘**。
3. **原子写**：保存采用"临时文件 + 原子替换"，中途失败不得损坏原文件（§9.10 AC-S1）。
4. **绝不静默截断**：能打开的内容必须完整；超出阈值时按 F8 的规则"拒绝"或"降级只读打开"，**不允许"内容被截断却允许保存"**。
5. **编码原样回写**：见 F4 第 4 条与 §9.10 AC-S4。
6. **字节不经渲染层**：本机文件的读取与写入由原生侧完成，渲染层只拿文本；渲染层**无网络出口**、不接触密钥（`AGENTS.md §9.5/§9.6`）。

### 3.7 F7 本地文件关联（**安装包基础注册 + 应用内细粒度设置**）

> **编号说明**：本编号原为「文件管理页对接」，**该节已整节删除**（见 §7.2），编号回收给本节的**本地**文件关联。

**用户故事**：作为开发者，我在资源管理器里看到一个 `.log`，我希望右键「打开方式」里就有 JFLove，点一下就把编辑器拉起来；同时我不希望 JFLove 把我系统里 `.txt` 的默认程序抢走 —— 什么时候用 JFLove 由我自己决定。

**功能规则**：

1. **安装包基础注册（不抢占默认程序）**：安装包把 JFLove 注册进系统「**打开方式**」候选列表（Windows：`Applications\JFLove.exe` + 支持的扩展名声明；Linux：桌面项 + MIME 关联声明）。
   - **不修改、不抢占任何扩展名的默认程序**；
   - **卸载时清理**注册项，不残留。
2. **应用内「文件关联」设置页**：新增设置页（或设置页内的一个 Section），列出可勾选扩展名的清单，**勾选哪些扩展名用 JFLove 打开**；勾选状态**跨重启保留**。
   - **默认全不勾选**（**D22** 裁决）：安装后 JFLove 只出现在系统「打开方式」候选里，**不替用户决定**任何默认程序，由用户主动勾选。
   - **清单单一真相（强制）**：可勾选项**必须由 F4 的类型表派生**（同一份配置 / 常量），**不得维护第二份手写清单**；将来编辑器新增支持格式时，关联清单**自动同步**，两者**永远一致**（**AC-48a** 锁定）。这条对应**用户原话**：「把文本编辑器支持的格式**全部**都列出来…如果后面文本编辑器支持的格式越多，那么…支持勾选的格式也应该要**对应的增加，要保持一致**」。
   - **清单范围**：编辑器**当前支持的全部格式**（即 F4 类型表的全部条目），本版本**不做自定义输入**（**D23** 裁决）。
   - **「勾选」的实际语义**（**D24** 裁决）：勾选 = **声明 JFLove 支持该类型** + **应用内记住偏好**，**不静默修改系统默认程序**；另在该项旁提供「**设为默认**」按钮（落地方式见 D24）。
3. **被系统作为打开方式调用 → 默认唤起文本编辑器**：命令行参数传入文件路径时，**默认唤起文本编辑器窗格**（而不是首页 / 媒体页 / 文件管理页）。
   - **无论该扩展名是否在勾选清单内，只要用户显式选择了 JFLove，就一律打开**（用户显式选择即明确意图；这同时是 **D23** 要求的「**操作系统层面**手动把任意扩展名绑定到 JFLove」的落地路径）；
   - 打开前**仍先走 F8 类型校验**；被 F8 拒绝时给出明确提示而非静默忽略。
4. **单实例复用**：已有 JFLove 在运行时，再次传入文件 → **在已有实例里打开编辑器窗格**，**不新开进程**；若已有实例处于最小化 / 托盘状态，则先恢复窗口可见。复用请求超时时**不得静默丢弃用户的打开请求**（至少给出提示；超时值由设计文档定义）。
5. **编辑器不依赖登录（用户裁决 A）**：纯本地功能与账号无关 —— **未登录或服务端不可达时，通过「打开方式」唤起、新建、编辑、保存、崩溃还原全部照常可用**，不出现登录拦截。
6. **多路径参数**：一次传入多个文件路径 → 分别打开对应数量的窗格；不存在的路径给出明确提示且不影响其它路径打开。

### 3.8 F8 类型校验先行（**先校验类型，再加载内容**）

> **用户原话**：「你一定要**先校验类型，再加载内容**，我担心加载个几 GB 的 exe 文件把程序弄崩溃了」。
> 本节是**强制顺序约束**：任何入口（应用内原生对话框打开 / 系统「打开方式」唤起 / 命令行参数传入路径）都必须在**读取完整内容之前**完成类型校验。

**功能规则**：

1. **校验顺序（强制）**：
   1. **扩展名白名单**：命中 → 采用对应语言（**不再做二进制嗅探**）；
   2. **未知扩展名 → 二进制嗅探**：读**前 8 KB**；出现 **NUL 字节** 或**非文本字节比例过高** → 判为**二进制** ⇒ **不加载内容、不产生编辑器窗格**，给出明确提示；
   3. **大小阈值**（对**所有**文件生效，白名单命中亦不豁免）：
      - `> 50 MB` → **直接拒绝**并说明原因（含"文件过大"）；
      - `> 5 MB` 且 `≤ 50 MB` → **提示用户**，并**默认以只读方式打开**（编辑动作禁用、保存不可用）；
      - `≤ 5 MB` → 正常打开；
   4. **编码判定**：非 UTF-8 / UTF-8-BOM / GBK / UTF-16 等**可识别编码** → **明确提示**，**不得静默替换**（禁止"按 UTF-8 + 替换字符打开后还允许保存"）。
2. **阈值数值表（用户已确认，写进 AC）**：

| 判据 | 阈值 / 规则 | 超限行为 |
|------|------------|---------|
| 扩展名白名单 | 命中即采用对应语言 | 跳过二进制嗅探 |
| 二进制嗅探 | 读前 **8 KB**；含 **NUL 字节** 或非文本字节比例过高 | **判为二进制 → 不加载、不产生窗格** + 明确提示 |
| 大文件（提示） | **> 5 MB** | **提示用户 + 默认只读打开** |
| 大文件（拒绝） | **> 50 MB** | **直接拒绝** + 说明原因 |
| 编码 | 非 UTF-8 / GBK / UTF-16 等可识别编码 | **明确提示**，**不得静默替换** |

3. **文案要求**：
   - **不识别类型** → 按 `txt` 处理；
   - **`txt` 也打不开**（二进制 / 超大）→ **明确提醒用户**，并且**不加载内容**；
   - 提示必须说明**原因**（"不是可识别的文本文件" / "文件过大（> 50 MB）" / "已按只读打开（> 5 MB）"），且**不得**在提示或日志中打印完整路径与内容片段（`AGENTS.md §9.4/§9.13/§9.14`）。
4. **不可绕过**：校验是先于内容加载的**前置关卡**，不得"先读进来再判断"（判据见 §9.10 AC-S3）。
5. **残余风险（已知、有界、不阻塞）**：扩展名白名单命中时跳过二进制嗅探，因此"把一个小二进制文件改名成 `.log`"这类情形会以文本方式打开（≤ 5 MB，最多显示乱码，不会崩溃；> 5 MB 仍降级只读）。此为该顺序规则的**有意取舍**；如后续要求对白名单命中文件也强制嗅探，另开裁决（不在本版本范围）。

### 3.9 F9 草稿与还原

**用户故事**：作为开发者，我经常粘了一大段还没想好存哪儿就切走了；电脑崩了、进程被我杀了，回来还得有。

**功能规则**：

1. **草稿只在本机**：草稿存放在 `USER_DATA_DIR/storage/scratch/`；**不写入、不上传任何远端**。**本版本为明文存储**，并在设置页提供「**清空草稿**」入口（是否加密见 §11 U-8，当前按推荐值"明文 + 清空入口"定稿）。
2. **自动暂存**：内容变化后在**本机**自动暂存（**只在脏时写**，按防抖间隔合并写入）；暂存内容需足以还原窗格（正文 + 语言 + **本地文件路径（若有）** + 编码 + 换行符 + 几何等）。
3. **异常退出 → 下次启动自动全部还原**：崩溃 / 进程被杀后，下次启动**自动还原全部草稿窗格（不限数量）**为浮动窗格。
4. **正常退出 → 弹确认**：有脏窗格时弹出确认，至少包含「**保存**」「**放弃并退出**」「**取消**」三项；并**让用户选择是否保留下次恢复** —— 该项为**全局一次性选择**，**不是逐窗格选择**（D8 + U-9 定稿）。
5. **最小化到托盘不算退出**：最小化到托盘时**一律不清理**草稿；从托盘恢复后窗格与内容仍在。
6. **关闭单个脏窗格 → 询问**：保存 / 放弃 / 取消；取消则窗格不关闭、内容不变。
7. **干净退出且未选择保留** → 清理草稿，下次启动不还原。
8. **原子写**：草稿与自动暂存的写入**同样采用原子写**；写入过程中断（被杀 / 断电）不得导致草稿库不可加载（§9.10 AC-S2）。
9. **清空草稿入口**：设置页提供「清空草稿」，二次确认后清空全部草稿且**不影响用户已保存到磁盘的文件**。

### 3.10 F10 状态栏与阅读体验

**功能规则**：每个窗格底部状态栏显示：

| 字段 | 口径 |
|------|------|
| 行:列 | 1 基；列为光标所在字符位于该行的第几个字符 |
| 选中字符数 | 无选中时显示 0 |

| 只读标记 | 处于 F8 只读降级 / `.diff` 类只读时显示 |
| 脏标记 | 未保存时有标记，保存后消失 |

| 维度 | 要求 |
|------|------|
| **启动与呼出速度** | "要快"是核心诉求。目标（U-11 已定稿：沿用暂定值）：应用冷启动后**首次**呼出窗格 ≤ 1.5 s（含编辑器内核首次加载）；已加载后再开窗格 ≤ 300 ms；按快捷键到窗格可见**无可感知等待**。测量值必须写进开发记录 |

## 6. 交互流程

### 6.1 流程 A：快捷键呼出新建 → 编辑 → 首次保存 → 之后直接更新

1. 用户在任意页面按默认快捷键（取值以配置界面列出的默认键为准）。
2. 应用内浮层出现新的浮动窗格：标题栏显示"未命名"与脏标记；编辑区获得焦点；语言=纯文本；状态栏显示默认编码（UTF-8）与换行符（LF）。
3. 用户粘贴或输入文本；防抖间隔后自动暂存写**本机草稿**，脏标记保持。此时文档为**草稿形态**（无路径）—— 磁盘上**没有任何**用户文件被创建。
4. 用户按保存快捷键（或点保存）→ 弹出**原生文件对话框**（**必须由用户指定路径与文件名**）。
   - **取消** → 窗格仍为脏，磁盘无新文件；
   - **确定** → 写入完成：脏标记消失；标题栏显示文件名；该窗格记住**本地目标路径**。
5. 再次修改并按 `Ctrl+S` → **直接写回该路径，不再询问**（无任何对话框）；要换位置用「另存为」。
6. 关闭窗格：内容干净 → 直接关闭；内容为脏 → 询问（保存 / 放弃 / 取消）。

### 6.2 流程 B：系统「打开方式」唤起 → 类型校验 → 编辑 → 保存回原文件

1. 用户在文件管理器中对某文件选「打开方式 → JFLove」（或双击，若用户自行把默认程序设成了 JFLove）。
2. **单实例复用**：若已有 JFLove 在运行（含最小化 / 托盘）→ 恢复窗口可见 → 在**已有实例**里继续；否则启动新实例。
3. **类型校验先行（F8）**：扩展名白名单 → 二进制嗅探 → 大小阈值 → 编码判定。校验**在读全文件之前**完成。
4. 分支：
   - **通过校验** → 编辑器窗格打开该文件；状态栏显示编码、换行符、语言；窗格记录**本地文件路径**；
   - **判为二进制 / `> 50 MB`** → **不产生窗格**，给出说明原因的明确提示（提示中不打印完整路径）；
   - **`> 5 MB` 且 `≤ 50 MB`** → 提示"文件较大、已按只读打开" → 窗格**只读**（编辑动作禁用、保存不可用）；
   - **编码无法判定** → 明确提示（可选编码 / 只读），**不静默替换**。
5. 用户编辑；自动暂存持续写本机草稿（不涉及任何远端）。
6. 用户按 `Ctrl+S` → **直接写回该文件**（不询问位置与名称）；成功 → 脏标记消失、文件内容更新。
7. **失败**（路径不可写 / 文件被删 / 磁盘满）→ 保留编辑器内容与草稿、显示明确错误提示、原文件**未被破坏**（原子写保证）；**不得静默失败、不得清空内容**。
8. 若要存到别处 → 用「另存为」，**原文件保持不变**。

### 6.3 流程 C：异常退出 → 重启自动还原

1. 应用运行中开着若干窗格（含未保存内容），草稿已按防抖间隔写入本机。
2. 进程被强杀或崩溃（**未走**正常退出）→ "干净退出"标记保持"非干净"。
3. 下次启动 → 检测到上次非干净退出 → 按草稿库**自动还原全部窗格（不限数量）**为浮动窗格，恢复内容、语言、**本地文件路径（若有）**、编码、换行符、几何。
4. 还原后的窗格仍为"脏"状态（未保存），用户可继续编辑或保存。

### 6.4 流程 D：正常退出确认

1. 用户触发退出（托盘退出 / 窗口退出路径）。
2. 存在脏窗格 → 弹出确认：**保存** / **放弃并退出** / **取消**（+ **全局一次性**的"是否保留下次恢复"选择）。
3. 分支：
   - **取消** → 退出中止，窗格与内容不变；
   - **保存** → 逐窗格按各自目标保存（**草稿形态、无路径的窗格走"另存为"**），全部成功后退出；
   - **放弃并退出** → 丢弃未保存改动，按用户（全局）选择决定是否保留草稿供下次恢复。
4. 退出完成 → 写"干净退出"标记；若未选择保留 → 清理草稿，下次启动不还原。
5. **兜底**：任何一方无响应都**不得导致丢数据或退出卡死**（超时口径由设计文档定义，但"取消/不丢数据"是需求底线）。

### 6.5 流程 E：最小化到托盘（**不算退出**）

1. 关闭主窗口 → 最小化到托盘；**草稿一律不清理**。
2. 从托盘恢复 → 窗格与内容仍在。
3. 此时若进程被杀 → 按流程 C 处理（下次启动仍能全部还原）。

### 6.6 流程 F：单实例复用唤起

1. JFLove 已在运行（窗口可见 / 最小化 / 托盘任一状态）。
2. 用户从系统「打开方式」传入文件 `f`。
3. 第二个进程**不建立新的主窗口**：把请求交给已有实例，自身退出（判据：系统中 JFLove 进程数为 1）。
4. 已有实例：恢复窗口可见 → 走流程 B 的类型校验 → 打开编辑器窗格。
5. 若已有实例在超时窗口内无响应 → **不得静默丢弃**：给出明确提示（新建实例或提示用户），并由设计文档定义超时值与降级行为。

### 6.7 流程 G：类型校验拦截（不加载内容）

1. 用户尝试打开大文件 `big.exe`（二进制，数百 MB）。
2. 应用**在读取完整内容之前**完成判定：大小超 50 MB ⇒ 拒绝。
3. 结果：**不产生任何编辑器窗格**、**不读取完整文件**（进程内存不随文件增长）；出现明确提示（说明"文件过大"），提示中不打印完整路径与内容片段。
4. 用户可改选其它文件继续操作；应用状态不受影响（不崩溃、不卡死）。

## 9. 验收标准（AC-1 ~ AC-n）

> **判定原则**：每条 AC 都必须能被"跑出来" —— 判据是可观测结果（某入口存在、某快捷键生效、某操作后某文件内容等于什么、某命令退出码为 0 / 某 sha256 相同 / 某进程数为 1）。
> **禁止**用"体验良好""足够快""基本可用"充当判据；无头环境无法验证的观感项只能登记为真机观察项。
> **负向对照要求**：括号标注 `[负向对照]` 的条目，Phase 6 必须把"错误的/修复前的实现"注入回去，确认用例**失败**，否则该 AC 视为不可信。
> **编号说明**：本版 AC 编号**重新编排**（与 2026-10-12 第一轮稿的编号映射见 §7.2 的「连带作废的 AC」表）。
> 主序列 **AC-1 ~ AC-62**；数据安全专项 **AC-S1 ~ AC-S4**（单列，**本机文件安全**）；清债 **AC-B1 ~ AC-B9**；范围/门禁/回归 **AC-R1 ~ AC-R6**。**总计 81 条。**

### 9.10 数据安全专项验收（**单列，强制**）

> 本节 4 条是本版本**不可降级**的数据安全判据。任何一条失败 = 版本阻塞项。
> 口径：**本机文件安全**（原第一轮的远端相关条目已作废，见 §7.2）。

| 编号 | 验收标准（可观测判据） | 对应 |
|------|----------------------|------|
| **AC-S1** | **保存采用原子写（临时文件 + 原子替换），中途失败不得损坏原文件**：① 目标文件 `p` 已有内容 `old`（sha256 = `H0`）；在保存过程**中途注入失败**（写入临时文件中途失败 / 进程在替换前被强杀）→ 断言 `p` 的 sha256 仍为 `H0`、内容逐字节不变，且 `p` **不存在第三种状态**（要么完整 `old`、要么完整 `new`）；② 正常保存成功后，保存过程产生的临时文件**不残留**（目录文件数与保存前相同）；③ `[负向对照]`：把实现换成"以写模式直接打开目标文件再写入"（先截断再写）→ ① 必须失败 | F6 红线 3 / R-3 |
| **AC-S2** | **草稿与自动暂存同样原子写**：在草稿写入窗口内连续强杀进程 **≥ 5 次** → 每次重启：① 草稿索引**可正常加载**（应用不因半截 JSON 崩溃、不出现"草稿损坏"阻塞弹窗）；② 最多丢失最后一次自动暂存窗口内的内容（此前已写入的窗格内容可还原）；③ 草稿目录中**不出现被覆盖成半截的旧草稿**（旧草稿要么完整、要么不存在）。`[负向对照]`：改成"直接覆盖写草稿文件"→ ①②③ 至少一条必须失败 | F9.8 / R-3 |
| **AC-S3** | **二进制 / 超大文件在读取内容之前被拦住**：① 打开 200 MB 的二进制文件（如把某大 exe 复制为 `big.exe`）→ 出现明确提示 / 拒绝，**不产生任何编辑器窗格**；② 打开 60 MB 的 `.txt` → 拒绝，**不产生窗格**；③ 打开 20 MB 的 `.log` → 提示后**只读**打开（编辑被拒、保存不可用）；④ 上述三种情形**从触发打开到提示出现 ≤ 1 s**，且应用进程**私有内存增量 ≤ 50 MB**（判据：任务管理器或 `Get-Process` 的 `PrivateMemorySize64` 前后差值），即**未把文件读入内存**（⚠ **第三种 20 MB 只读打开不适用内存判据** —— 它本就需要完整加载；对该情形只要求「提示出现 ≤ 1 s 且只读态生效」）。`[负向对照]`：去掉大小阈值校验（先读全文件再判断）→ ④ 的内存判据必须失败 | F8 / R-1 / R-2 |
| **AC-S4** | **编码不被静默替换（本机文件）**：① GBK 文件（内容 `中文测试`）打开后**正确显示** `中文测试`，无替换字符 `U+FFFD`，状态栏编码为 GBK / GB18030 类；② **不做修改**直接保存 → 保存后字节**仍可被 GBK 解码**得到 `中文测试`，且**不是** UTF-8 字节；③ UTF-8-BOM 文件保存后 BOM（`EF BB BF`）保留、CRLF 保留；④ **无法判定编码**的样本（如 Latin-1 混排且无 NUL 字节）→ 出现编码提示 / 选择界面，**禁止**静默按 UTF-8 处理并允许保存。`[负向对照]`：把编码处理换回"固定 utf-8 + `errors="replace"`"→ ① 出现 `U+FFFD`、② 保存后变 UTF-8 ⇒ 本条必须失败 | F4.4 / F8.1.4 / R-2 |
