# JFLove 1.1.0 需求文档

## 0. 与 v1.0 的差异说明

本版本仅迭代「在线预览」体验，所有 v1.0 的现有需求保持不变。变更项：

| 项 | v1.0 行为 | v1.1.0 期望行为 |
|---|---|---|
| 视频预览 | 整文件下载完毕后才能开始播放，大文件等待时间长 | 边下边播；点击预览到看到画面 ≤ 3 秒；可拖动进度条任意位置，跳转后开始播放 ≤ 3 秒 |
| 音频预览 | 同上 | 同上 |
| 大文本/日志预览 | 整文件加载完才能开始浏览 | 边下边显示；首屏可见内容 ≤ 3 秒；超大日志（GB 级）也能立即开始查看 |
| 图片 / 矢量图 / Markdown / PDF 预览 | 整文件下载后渲染 | 维持 v1.0 行为（这些格式天然不适合流式） |
| 预览数据本地落盘 | 写入本地 tmp 文件再交给播放器 | 不再写本地 tmp 文件，预览过程中**资料不留任何本地副本**；关闭预览即销毁内存缓冲 |
| 关闭预览窗口 | 后端可能仍在传输 | 立即停止媒体播放与后端传输，不浪费带宽 / CPU / 服务器资源 |
| 预览中文件被服务端删除 | 行为不明确 | 立即弹错并关闭预览 |
| 网络抖动 | 行为不明确 | 短暂中断（几秒）期间预览暂停等待，恢复后继续；持续中断超出阈值时报错关闭 |

## 1. 项目概述

JFLove 是一款面向个人使用的私有桌面与服务端协同管理软件，主要服务于文件文档管理和笔记本管理场景。v1.1.0 版本继续以"端到端加密 + 私有部署"为核心定位，重点提升大文件在线预览的体验。

## 2. 目标用户

与 v1.0 保持一致：

- 个人用户，追求本地与私有服务器数据管理一体化
- 需要统一管理文档、笔记与容器服务的技术爱好者
- 希望通过加密通信保障配置参数与响应数据安全的用户

新增重点关注的使用场景：

- **媒体爱好者 / 摄影师 / 视频剪辑师**：在远程私有盘上存放大体积音视频素材，希望像本地播放器一样快速打开和拖动
- **运维 / 开发者**：远程查看 GB 级日志文件、源码包，希望首屏立刻可滚动

## 3. 核心价值变化

新增价值主张：

- **远程即本地的预览体验**：文件即便存放在远程服务器、即便是几个 GB 的视频或日志，从点击预览到看到内容、到能拖动跳转的等待时间，都控制在「秒级」
- **隐私优先**：预览过程中文件内容不在客户端本地落盘，关闭即销毁内存缓冲；用户宁可重新拉取也不接受本地缓存

## 4. 功能需求

### 4.1 流式预览（新增 / 替换 v1.0 第 5.1 节中预览部分）

#### 4.1.1 流式预览支持的格式

- **视频**：mp4 / mkv / avi / mov / webm / flv / wmv / m4v / mpg / mpeg / ts / 3gp
- **音频**：mp3 / wav / ogg / flac / m4a / aac / wma / opus
- **大体积文本与日志**：txt / log / json / xml / yaml / ini / csv / 常见编程语言文件等

#### 4.1.2 维持 v1.0 行为（不做流式）的格式

- **图片**：png / jpg / jpeg / gif / bmp / webp / tiff / tif / ico
- **矢量图**：svg
- **Markdown**：md / markdown / mdown / mkd
- **PDF**（如 v1.0 已实现，则维持；未实现的本版不引入）

理由：这些格式必须完整解析才能正确渲染，强行流式反而增加复杂度且体验不优。

#### 4.1.3 流式预览的用户故事

**故事 A：远程视频快速预览**

> 作为媒体爱好者，我把若干个数 GB 的 4K 视频素材存在私有盘上。
> 我在客户端目录里点击"预览"按钮，**3 秒内**应该看到画面开始播放。
> 我能拖动进度条到 50%、70%、95% 的任意位置，每次拖动后**3 秒内**画面应当从那个位置开始播放。
> 我能正常控制播放/暂停/音量。
> 我看完前面 30 秒后关掉预览窗口，**后端的传输应当立即停止**，不应继续浪费带宽。

**故事 B：远程音频试听**

> 与故事 A 行为一致，体验阈值相同。

**故事 C：远程大日志检索**

> 作为运维，我有一个 2 GB 的应用日志放在远程私有盘上。
> 我在客户端点击"预览"，**3 秒内**应当看到日志开头的几屏内容并能开始向下滚动。
> 我能滚动到任意位置（包括末尾）查看，跳转响应**3 秒内**。
> 我关掉预览，后端传输立即停止。

**故事 D：网络抖动**

> 作为正在远程办公的用户，我的网络偶尔会有几秒中断。
> 视频/音频在抖动期间应当**暂停等待**而不是直接报错关闭；网络恢复后应当**自动继续播放**。
> 持续中断超过较长时间时（例如 30 秒），允许报错并关闭预览，提示我重试。

**故事 E：文件被删除**

> 我正在预览一个视频，恰好此时管理员或我的另一台设备删除了这个文件。
> 客户端应当**立即弹出明确错误并关闭预览窗口**，不要让我对着已经无法继续的画面发呆。

#### 4.1.4 用户体验阈值（验收标准）

| 场景 | 期望阈值 | 说明 |
|---|---|---|
| 视频 / 音频首屏（点击到出画面/出声） | ≤ 3 秒 | 在带宽充足的本地局域网下视为基线；公网受网络条件影响可适当放宽 |
| 视频 / 音频跳进度后首屏 | ≤ 3 秒 | 拖动进度条到任意点后，从该点开始呈现 |
| 大文本/日志首屏可见 | ≤ 3 秒 | 不要求看到全文，只要求首屏能看且可立即滚动 |
| 大文本/日志跳转到任意位置 | ≤ 3 秒 | 滚动到末尾或拖动滚动条任意位置 |
| 关闭预览到后端传输停止 | ≤ 1 秒 | 不允许后端继续往客户端推数据 |
| 网络短暂抖动恢复 | ≤ 几秒 | 抖动期间暂停等待，恢复后自动继续 |
| 网络持续中断报错 | 30 秒级阈值 | 超出后弹错关闭，允许用户重试 |

> 备注：分块大小、传输协议细节、缓冲区策略由设计阶段决策，本节只规定体验阈值。

### 4.2 隐私与本地缓存策略（新增）

- 流式预览过程中，已下载的字节**只允许在内存中缓冲**，**不允许写入本地文件系统的任何位置**（包括但不限于 `/tmp`、用户主目录、应用 storage 目录）
- 关闭预览窗口或预览异常结束时，**内存缓冲必须立即释放**
- 客户端不提供"预览缓存"开关，**不留口子**让用户在 UI 中开启本地缓存
- 用户再次预览同一文件，应**重新通过加密通道下载**——这是显式的体验取舍：以"再下一遍"换"绝不留痕"

### 4.3 不做的事（明确划清边界）

- **不做后台预加载**（不预读"前一张/后一张"、不预拉相邻文件）。理由：浪费用户带宽与服务器资源，体感收益与复杂度不成比例
- **不做断点续看**（关闭预览不记忆播放位置）。理由：与 4.2 的"不留痕"冲突，且媒体本身的进度记忆属于播放器集成功能，不在本版本范围
- **不做格式转码 / 缩略图生成**。客户端按文件原貌流式拉取，不要求服务端做媒体转码；不能直接播放的格式（如 wma / wmv 在 macOS）由播放器自身能力决定，本版本只解决传输流式化问题

## 5. 非功能需求（体验感知层面）

### 5.1 体验感知

- **首屏速度**：见 4.1.4 阈值
- **流畅度**：视频播放过程中不应出现频繁的"圆圈加载图标"；音频不应出现可感知的爆音/断断续续
- **跳进度的"反应感"**：用户拖动进度条时，进度条应当给出"加载中"的视觉反馈（圆圈、光晕等），等待 3 秒内画面到位
- **关闭即停**：用户关掉预览那一刻起，不应再有任何流量产生（既是体验也是安全边界）

### 5.2 隐私感知

- 用户在预览过程中可能查看敏感视频 / 文档；该过程中**没有任何文件副本留在本地磁盘**
- 卸载客户端不会在 storage 目录残留过往预览过的内容
- 系统层面（如 OS 的内存压缩交换分区 swap）的兜底由部署环境承担，本需求只约束应用层

### 5.3 部署场景与版本策略

**部署场景**：

- 主要使用环境为**公网 IPv6**（个人用户从家庭 / 移动网络访问私有服务器）
- 网络抖动、瞬时延迟相对局域网会更频繁，§4.1.4 的体验阈值需在该场景下持续可用
- 测试与开发验收以**本地 100 Mbps 局域网**作为基线即可，达到基线视为合格

**版本策略（硬升级）**：

- 本版本**不做向下兼容**：服务端升级到 v1.1.0 后，v1.0 桌面端将无法继续使用预览功能（必要时不能继续使用其它功能也接受）
- 用户必须**同时升级**服务端与桌面端到 v1.1.0
- devops 阶段需在版本发布记录中**明确提示用户「本版本为硬升级，请同步更新桌面端」**

## 6. 交互流程描述

### 6.1 视频/音频流式预览流程

1. 用户在文件列表里双击或右键点击「预览」一个视频/音频文件
2. 客户端弹出预览窗口，**3 秒内**画面开始播放（或音频开始发声），同时显示标准的「播放/暂停/进度条/音量」控件
3. 用户拖动进度条到任意位置，**3 秒内**画面/声音从该位置开始
4. 用户关闭预览窗口（点 X 或按 ESC）：
   - 媒体立即停止
   - 后端传输立即终止
   - 内存缓冲立即释放
5. 期间若网络短暂抖动，进度条上呈现「加载中」反馈，恢复后自动继续
6. 期间若文件被删除，弹错误对话框并关闭预览窗口

### 6.2 大文本/日志流式预览流程

1. 用户双击或右键预览一个大文本文件（无大小限制）
2. 客户端弹出文本预览窗口，**3 秒内**显示首屏内容，可立即向下滚动
3. 用户滚动到末尾或任意位置，**3 秒内**呈现该位置内容
4. 关闭预览：与 6.1 第 4 步行为一致

### 6.3 不流式格式（图片/SVG/Markdown）

维持 v1.0：整文件加密下载后渲染。但**与 v1.1.0 的隐私策略对齐**——下载过程中不写本地 tmp 文件，所有字节在内存中缓冲，关闭即释放。

## 7. 错误与异常处理（体验层面）

| 异常 | 期望体验 |
|---|---|
| 文件不存在 / 已被删除 | 弹错误对话框「文件已不存在或被删除」，自动关闭预览窗口 |
| 服务端不可达 | 弹错误对话框「与服务端连接已断开，请检查网络」，提供「重试」按钮 |
| 网络持续中断超出阈值 | 同上 |
| 用户权限不足（仅普通用户） | 弹「无权预览此文件」，关闭预览 |
| 不支持的文件格式 | 退化到「下载到本地后用系统默认应用打开」的提示，不强行预览 |
| 客户端版本旧，服务端新 | 视频/音频自动退化为 v1.0 的「整下后预览」，不阻断功能 |

## 8. 不变的内容（沿用 v1.0）

- 加密通信、密钥交换、JWT 鉴权、URL 不带业务参数、错误响应加密 — 全部沿用 v1.0
- 用户角色（管理员 / 普通用户）、虚拟磁盘、笔记功能、上传/下载、同步 — 不变
- 数据库结构、客户端持久化字段范围 — 不变
- 桌面端 v1.0.1 的服务端地址历史下拉、权限管理 UI 修复 — 沿用

## 9. 验收要点

本版本验收必须覆盖：

- **首屏阈值**：在 100 Mbps 局域网下，4K 视频从点击到画面 ≤ 3 秒；2 GB 日志从点击到首屏 ≤ 3 秒
- **跳进度阈值**：视频拖到 80% 处，3 秒内开始从该位置播放
- **关闭即停**：关闭预览窗口 1 秒内观察网络流量为零
- **零落盘**：预览过程中扫描客户端 storage 目录、系统 tmp 目录，**找不到任何与该文件相关的临时副本**
- **隐私验收**：在客户端用进程工具或文件监控工具实时观察预览过程中的磁盘写入路径，确认仅有内存缓冲，无文件创建

## 10. 待设计阶段决策的事项（不在本文档范围）

以下交给 designer 阶段：

- 流式协议的具体形式（如 HTTP Range、自定义分片协议等）
- 分块大小（影响首屏与 seek 响应时间）
- 客户端内存缓冲上限（防止用户拖动太频繁吃光内存）
- 服务端响应是否需要新增端点 / 是否复用现有下载端点
- 关闭即停的具体取消机制（HTTP 主动断流、客户端心跳、超时清理）
- 与 §9 安全宪法的契合方式：流式协议下的帧加密、错误响应加密、URL 零泄漏

product 阶段不对以上做任何技术承诺，仅承诺第 4 / 5 节列出的用户体验目标。
