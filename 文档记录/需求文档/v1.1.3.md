# JFLove 1.1.3 需求文档

## 0. 与 v1.1.2 的差异说明

| 项 | v1.1.2 行为 | v1.1.3 期望行为 |
|---|---|---|
| 重命名 | 不支持，用户必须删除再重新上传 | 右键菜单新增「重命名」，弹输入框，支持文件和目录 |
| 移动 | 不支持，用户必须删除再重新上传 | 右键菜单新增「移动到…」，弹目录选择器，支持文件和目录 |
| 复制 | 不支持 | 暂不在本期引入（大文件复制涉及服务端重新读写，性价比评估后列入 v1.2.0 候选） |
| 文件树多选 | 不支持（SingleSelection） | 暂不在本期引入，保持单选；多选移动/删除留 v1.2.0 候选 |

**保持不动的事项**：

- v1.1.2 及以前全部功能行为（上传、下载、预览、删除、新建目录、磁盘选择）不变；
- 端到端加密协议、加密信封格式、流式帧格式不变；
- 数据库表结构不变；
- ECDH 静默续约、JWT 有效期配置逻辑不变。

---

## 1. 项目概述

v1.1.3 是 v1.1.2 的小迭代版本，补全文档管理页最基础的两项缺失操作：**重命名**和**移动**。

现状痛点：用户要给文件改个名字，必须先下载到本地、删除服务端原文件、再重新上传——三步操作换一个名字，体验极差。移动文件同理。

涉及模块：

- **jflove-server**：新增重命名接口、移动接口；
- **jflove-desktop**：右键菜单扩充「重命名」「移动到…」；新增目录选择弹窗（用于移动目标路径选取）。

---

## 2. 目标用户

与已有版本一致，主要受益人群：

- **重度文档整理用户**：日常需要整理服务端文件结构，频繁遇到"想改名却只能删了重传"的阻力；
- **目录结构迁移用户**：把已有文件从一个目录批量迁移到新位置，目前只能手动一个个下载再上传。

---

## 3. 核心价值变化

- **减少无意义的"删+传"操作**：重命名/移动在服务端原地操作，不产生重复传输，速度快（仅改元数据 / 操作系统 rename/move）；
- **让文档管理页功能完整**：上传、下载、删除、新建目录都有了，缺的就是重命名和移动，补上后文档管理的基础 CRUD 才算齐全。

---

## 4. 功能需求

### 4.1 重命名

#### 4.1.1 用户故事

> 作为一名重度使用者，我想在文档管理页右键选中某个文件或目录，直接输入新名称完成改名，不需要下载再上传。

#### 4.1.2 交互流程

1. 用户在文件树中右键点击某个**文件或目录**；
2. 右键菜单出现「重命名」选项（在「删除」之前）；
3. 点击后弹出输入对话框，标题为「重命名」，预填当前名称，全选状态（方便直接覆盖输入）；
4. 用户输入新名称，点确认 / 按回车；
5. 客户端调用重命名接口；
6. 成功：原地刷新文件列表，在右上角显示「已重命名」成功提示；
7. 失败（名称冲突、非法字符等）：弹出错误提示，保留对话框，用户可重新输入或取消。

#### 4.1.3 规则约束

- 新名称不能为空，不能包含路径分隔符 `/`、`\`，不能包含 `.`（单点）或 `..`（双点）作为完整名称；
- 新名称与旧名称相同时，静默跳过（不发请求，不报错，不刷新）；
- 目标名称已存在：服务端返回错误，客户端提示「该名称已存在，请更换」；
- 对文件和目录均支持；
- 操作范围限当前目录（重命名不改变所在目录）。

#### 4.1.4 权限

- 用户必须对该磁盘有**写权限**（管理员默认有；普通用户需有写权限授权）；
- 无写权限时：右键菜单中「重命名」显示为灰色不可点击（或不显示）。

---

### 4.2 移动

#### 4.2.1 用户故事

> 作为一名重度使用者，我想把某个文件或整个目录从当前位置移动到另一个目录，整个过程在服务端完成，不用经过本地。

#### 4.2.2 交互流程

1. 用户在文件树中右键点击某个**文件或目录**；
2. 右键菜单出现「移动到…」选项（在「重命名」之后，「删除」之前）；
3. 点击后弹出「目标目录选择器」弹窗：
   - 弹窗标题：「选择目标目录」；
   - 内容：展示当前磁盘的目录树（只显示目录，不显示文件）；
   - 默认展开到当前所在目录层级；
   - 根目录 `/` 可选，表示移动到磁盘根目录；
   - 底部：「确认移动」（主按钮）+ 「取消」（次按钮）；
4. 用户选定目标目录后点「确认移动」；
5. 客户端调用移动接口；
6. 成功：刷新当前目录文件列表（被移走的文件消失），右上角提示「已移动」；
7. 失败：弹出错误提示。

#### 4.2.3 规则约束

- 目标目录不能是被移动项自身或其子目录（避免循环嵌套）；
- 目标目录与当前所在目录相同时，静默跳过（不发请求）；
- 目标路径下已存在同名文件/目录：服务端返回错误，客户端提示「目标位置已存在同名项，请换一个位置或先重命名」；
- 移动目录时，其下所有内容随之迁移（服务端原地操作，OS 层面的 rename/mv）；
- 跨磁盘移动：**本期不支持**（目录选择器只展示当前磁盘的目录结构）。

#### 4.2.4 权限

- 用户必须对该磁盘有**写权限**；
- 无写权限时：「移动到…」显示为灰色不可点击（或不显示）。

---

### 4.3 右键菜单整体调整

调整后右键菜单条目顺序（以文件为例）：

```
下载
预览
───────────（分隔线）
重命名
移动到…
───────────（分隔线）
删除
```

目录项右键菜单（目录无下载/预览）：

```
重命名
移动到…
───────────（分隔线）
删除
```

无写权限时，「重命名」「移动到…」「删除」均灰色不可点击（或隐藏）。

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 重命名 / 移动是服务端 OS 层面的 rename 调用，不涉及文件内容读写，应在 1 秒内完成（正常磁盘 I/O 下）；客户端操作完成后立即刷新文件列表，总体感知 ≤ 2 秒 |
| 安全 | 新名称 / 目标路径走加密请求体传输，不在 URL 中暴露；服务端做路径合法性校验（防路径穿越攻击，如 `../../../etc`）；写权限校验在服务端执行，不仅依赖客户端灰色按钮 |
| 兼容性 | 不变更数据库表结构，不影响已有上传/下载/删除接口；新接口为新增，老客户端不调用即可 |
| 体验 | 重命名输入框预填当前名称并全选；目录选择器层级结构清晰，懒加载（点击展开再请求子目录）；操作结果（成功/失败）有明确的界面反馈 |
| 错误处理 | 所有错误均通过右上角 InfoBar 展示（与现有风格一致），不阻断整页；目录选择器内的错误单独在弹窗内显示 |

| AC-4 | 新名称与当前名称相同，静默跳过不报错 | 是 |
| AC-5 | 新名称已存在，提示「该名称已存在」 | 是 |

| AC-7 | 右键文件/目录 → 「移动到…」可见且可点击（有写权限） | 是 |
| AC-8 | 「选择目标目录」弹窗展示当前磁盘目录树（仅目录） | 是 |
| AC-9 | 选定目标目录确认后，当前列表中该文件/目录消失（已移走） | 是 |
| AC-10 | 目标目录与当前目录相同时，静默跳过 | 是 |
| AC-11 | 目标位置已有同名项时，提示「目标位置已存在同名项」 | 是 |

## 7. 不在本期范围

- 复制文件/目录（服务端需重新读写内容，留 v1.2.0 评估）；
- 跨磁盘移动（权限模型复杂，留 v1.2.0 评估）；
- 文件树多选批量操作（留 v1.2.0 评估）；
- 移动后撤销（文件系统无原生事务，留 v1.2.0 评估）；
- 拖拽移动（实现成本高，留 v1.2.0 评估）；
- 修改文件内容（不在本产品文档管理范畴内）；
- 变更数据库表结构；
- 变更加密协议。
