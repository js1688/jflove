# JFLove v1.6.1 需求文档

> **本版本是一次"形态改写"版本**：把 v1.6.0 刚交付的桌面端「文本编辑器」从**应用内浮动窗格**改为**左侧主导航里的整页编辑工作区 + 顶部固定标签页（tab）**，并把编辑器的**准入条件**从"与账号无关"改为**"必须登录后才能使用"**。
> 计划与决策来源：`plans/desktop-v1.6.1-editor-workspace-tabs.md`（用户 2026-10-14 裁决）；基线：`文档记录/需求文档/v1.6.0.md`。
> **范围**：仅 `jflove-desktop/`（`ui/` 为主）。**服务端 / Web 端 / 移动端零改动**，**数据库无结构变更** ⇒ 本次**没有 Phase 3 / Phase 4b / Phase 4c**。
> **合并收尾**：v1.6.0 尚未执行的 **Phase 7（PMO）/ Phase 8（发布）** 并入本版一次完成（用户裁决，D26）。
> 编写角色：product（Phase 1，`AGENTS.md §7.3`）。

#### 0.5.4 需求约束（本轮，不占 AC 编号）

> 挂约束而不新开 AC 编号的理由：它是既有 **AC-34②**（diff 第二段来源三种均可用）在"平台不允许"情形上的**降级分支**，不改变 AC-34①/③ 的判定；为不占用后续编号（**AC-80 起留给下一轮**）而以「约束 + 判据」形式登记，Phase 6 按本行判据出用例。

**C-1 工具箱「两段文本对比」的剪贴板来源不可用时的降级口径**

- **需求**：当「从剪贴板导入」这一来源在**当前平台 / 外壳不允许读取剪贴板**时，必须 —— ① 给出**可读的中文提示**（**不得**把 `NotAllowedError` 之类的原文直接抛给用户，**不得**静默无反应）；② **保持原有内容与对比结果不变**（**不得**把空串当成"第二段文本"，**不得**清空既有对比结果）；③ 提示中**指明可改用的替代来源**（「另一个编辑器标签页」/「本地文件」）。
- **可判定判据**：在剪贴板读取被拒绝的环境下点击「从剪贴板导入」→ ① 界面出现**中文**提示文本（非空白字符串，**0 命中** `NotAllowedError` / `NotAllowed` 原文）；② 第二段文本框内容与对比结果**逐字符不变**；③ **正向对照**：改用「本地文件」来源时同一对比功能**正常产出对比结果**。
- ⚠ **验证状态（诚实登记）**：该来源在 QtWebEngine 下**很可能一直不可用**（外壳未开 JS 剪贴板读取权限）—— 这一点**尚未真机确认**（见 §0.5.5 B3）。Phase 6 **必须先真机取证"是否确实抛错"**，再按本条判据判定；若取证显示实际可用，本条降级为"常规来源"，不新增判据。

## 2. 目标用户与使用场景

### 2.1 目标用户

**沿用 v1.6.0 §2.1**（程序员 / 开发者；"处理一段文本、就地改一个本地文件"；重、弱两极都不合用）。

### 2.2 核心场景

> **处理一段文本、就地改一个本地文件；登录之后，在一个工作区里用标签页来回切换。**

| 场景 | 用户动作 | 痛点 / 说明 |
|------|---------|-----------|
| **本机文件要小改一处**（**改写**） | 在文件管理器里对文件选「**打开方式 → JFLove**」（或双击，若已设为默认）→ **未登录则先登录** → 应用**自动**切到文本编辑器工作区并**把该文件开成一个标签页** | 用户原话："**登录成功之后再把左侧的菜单切换到文本编辑器，在右边的面板显示刚刚打开的内容，在 tab 页上加上刚刚打开的那个结果**"；登录**不能**让用户事后自己去把文件重开一遍 |
| **多份文档来回看**（**改写**） | 顶部标签条点一下 / `Ctrl+Alt+←/→` 切换 → 编辑面板换成对应文档；`Ctrl+W` 关掉不再需要的 | 替代 v1.6.0 的"开多个浮动窗格、自己摆位置"；用户原话："**在右边的显示面板上方有多个 tab 页，这样可以来回切换**" |
| **新开一份草稿**（**沿用**） | 已登录状态下按快捷键（或点左侧菜单「文本编辑器」）→ 工作区新增一个标签页 | 未登录时该快捷键**不响应**、菜单项**不可见** |
| 其余场景 | **沿用 v1.6.0 §2.2**（看清 JSON 结构、批量行操作、按列取文本、两段对比、留档存盘、超大/二进制文件被拦） | 只是"窗格"一律读作"标签页" |

### 2.3 判断这次做成功的标准（用户口径）

1. **"该登录就登录，登录完接着干"**（**本次核心**）：未登录时点不到编辑器、按不响快捷键；一旦通过「打开方式」唤起，登录完成后**刚才那个文件已经打开在工作区里**，用户不需要再找它一次。
2. **"就像 VSCode 的标签页，而不是一堆小窗"**：顶部一排固定标签、下面一块编辑区；切换标签即切换文档；不需要拖动、排列、最小化任何东西。
3. **"始终在那儿"**：文本编辑器是应用右侧工作区里的一个功能页，左侧菜单控制切换；从它切走再切回来，**刚才的标签页一个不少、内容一字不差**。
4. **内容不出本机**：**沿用 v1.6.0 §2.3 第 2 条**（编辑器与远端零交互；登录门**不得**成为任何远端读写的借口）。
5. **要快**：标签切换与工作区进入无可感等待（性能目标见 §5）。
6. **不丢内容**：**沿用 v1.6.0 §2.3 第 4 条**，并新增一条 —— **登出 / 会话失效也不得丢**（内容留在本机草稿库，重新登录可还原）。
7. **不会被一个文件弄崩**：**沿用 v1.6.0 §2.3 第 5 条**（类型校验先行）。
8. **登录之后不依赖服务端**：**沿用 v1.6.0 §2.3 第 6 条的内核**（断网 / 服务端未启动时本机能力照常），但**前置条件改为"已登录"**。

## 3. 功能需求

> 需求编号 F1 ~ F10 沿用 v1.6.0 的编号体系。**F1 整节改写**；F2 调整条目集；F7 第 3/5 条、F9 第 3 条改写；**F3 / F4 / F5 / F6 / F8 / F10 口径不变**（全文见 `文档记录/需求文档/v1.6.0.md` 同名章节）。

### 3.1 F1 编辑器准入与工作区形态（**改写 v1.6.0 F1 整节**）

**用户故事**：作为使用者，我要动我的本机文件时，希望是在我登录之后的环境里；登录完我不想再手动把刚才那个文件重新打开一遍。同时我讨厌一堆需要自己摆位置的浮动小窗 —— 我要的是 IDE 那种"上面一排标签、下面一块编辑区"，它就待在应用右边，用左边菜单切过去就能用。

#### 3.1.1 F1-A 登录准入（**新增**）

1. **未登录时零存在**：无有效会话时 —— ① 左侧主导航**不出现**「文本编辑器」项；② 编辑器的快捷键**一律不响应**（不新增标签页、不进入工作区）；③ 工作区与标签条**不渲染**。
2. **已登录时可用**：左侧主导航出现「文本编辑器」项（点击进入工作区）；快捷键可新建标签页 / 进入工作区。
3. **外部唤起先过门（核心）**：在未登录状态下经系统「打开方式」/ 命令行参数 / 单实例转发传入文件路径时 ——
   ① **先进入登录面板**（此时**不**打开文件、**不**新建标签页）；
   ② **登录成功后自动**：把左侧菜单切到「文本编辑器」→ 打开原文件为一个标签页 → 该标签页获得焦点，**内容等于该文件内容**；
   ③ 请求**不得丢失**（用户在登录面板上完成登录后必须看到它被打开）。
4. **排队与去重**：登录完成前到达的多个唤起请求**按到达顺序排队**，登录成功后依次打开；**同一路径在队列内只保留一个**。
5. **放弃登录**：用户始终未登录（关闭登录面板 / 一直停在登录页）时，请求**只留在内存队列**（**不持久化**，应用退出即丢弃）；**下次登录成功后不补开**（避免"登录后突然冒出一堆旧文件"；口径见 §11 U-2）。
6. **登出 / 会话失效**：编辑器入口随即不可见、工作区不再渲染；**未保存内容仍在本机草稿库**，**重新登录后**按 F9 规则可还原（**不丢内容**）。
7. **未登录不还原草稿**：本机草稿的自动还原**推迟到登录之后**；未登录时草稿仍在磁盘上，**不清理、不上传、不还原**。
8. **登录只是准入**：登录成功后，即使**断网或服务端不可达**，编辑器的全部本机能力（新建 / 打开 / 编辑 / 保存 / 另存为 / 标签页切换与关闭 / 草稿还原）照常可用，**不出现登录拦截**、**不因服务端不可达而禁用编辑器**。

#### 3.1.2 F1-B 编辑器工作区（**改写**）

1. **整页工作区**：编辑器占据应用**右侧内容区**（左侧主导航与窗口标题栏保持不变）；进入后顶部为**固定的标签条**（不随内容滚动），下方为**编辑面板**。
2. **一个文档一个标签页**：新建或打开一个文件 = **新增一个标签页**；**同一路径只存在一个标签页**（重复打开 = **聚焦已有标签页**，**不覆盖其未保存改动**）。
3. **切换标签 = 切换编辑面板**：点击标签（或使用切换快捷键）即切换显示对应文档；切换**保留**各标签页的内容、光标位置、滚动位置、**视图模式**（编辑 / 预览 / 分屏 / 表格 / 树形，JSON 树形与 CSV 表格仍**只读**）、本地目标路径与脏标记。
4. **标签操作**：关闭（脏标签先询问：保存 / 放弃 / 取消）、**拖拽排序**、**溢出可及**（标签数超出可见宽度时，可通过滚动或**下拉列表**定位并选中任一标签页）。
5. **未保存标记**：标签上有未保存标记，保存成功后消失。
6. **关闭最后一个标签页**：**留在编辑器工作区**并显示**空态**（空态提供"新建""打开"入口），**不自动跳回**其它页面。
7. **不再是浮动窗格（取代 v1.6.0 F1 第 3 / 4 / 5 条）**：**不存在**拖动、缩放、最小化、最大化 / 还原、平铺、层叠、层级 / z 序、窗格几何；工作区矩形随窗口尺寸**自动铺满内容区**。
8. **切换左侧菜单不销毁标签页**（承接 v1.6.0 F1 第 6 条的"不丢内容"内核，**2026-10-15/16 就地写实**）：从编辑器切到设置 / 文件管理 / 笔记再回来，**标签页一个不少**，且**每个标签页的正文逐字符不变**（含**未落盘**的编辑、含在自动暂存防抖窗口（1.5 s）内切走的情形）、顺序 / 当前激活项 / 光标位置 / 滚动位置 / 视图模式 / 脏标记保持不变（判据见 **AC-5 / AC-77**）。
9. **编辑器不是独立操作系统窗口**（v1.6.0 D1 的"独立 OS 窗口已废弃"继续有效），也**不是**浮在路由之上的常驻浮层（本轮新增约束）。
10. **快捷键与菜单双入口**：任意已登录页面按新建快捷键 → 切到工作区并新增标签页；左侧菜单点击「文本编辑器」→ 进入工作区（已有标签页时保持原状）。

3. **其余条（第 1 / 2 / 4 / 6 条）不变**；「打开前仍先走 F8 类型校验」的约束在登录前置下**依然成立**（登录完成后、加载内容前执行）。

#### 3.3.3 F9 草稿与还原（**第 3 条与时序改写**）

**沿用**：草稿只在本机（`USER_DATA_DIR/storage/scratch/`、明文 + 设置页「清空草稿」入口）、自动暂存（只在脏时写、防抖合并）、正常退出弹确认（保存 / 放弃并退出 / 取消 + **全局一次性**的"是否保留下次恢复"）、最小化托盘不算退出、关闭单个脏标签页先询问、干净退出且未选择保留则清理、**原子写**、清空草稿不影响已保存文件。

**改写点**：

1. **第 3 条（异常退出 → 下次启动自动全部还原）**：还原对象由"浮动窗格"改为"**标签页**"；且 —— **还原时机 = 登录成功之后**（未登录时不还原、不清理、不上传草稿）。

3. **登出 / 会话失效不是"退出"**：不得清理草稿（承接"登出也不丢内容"，F1-A 第 6 条）。

## 6. 交互流程

### 6.1 流程 A：**已登录** → 呼出工作区 → 新建 → 编辑 → 首次保存

1. 用户在任意页面按「新建标签页」快捷键（或点左侧菜单「文本编辑器」）。
2. 编辑器工作区打开；若无标签页则显示**空态**（新建 / 打开入口）。
3. 新建标签页：标题显示"未命名"与脏标记；编辑区获得焦点；语言 = 纯文本；状态栏显示默认编码（UTF-8）与换行符（LF）。
4. 用户粘贴或输入；防抖后自动暂存写**本机草稿**，脏标记保持；此时为**草稿形态**（无路径）—— 磁盘上**没有任何**用户文件被创建。
5. 用户触发保存 → 弹出**原生文件对话框**（**必须由用户指定路径与文件名**）：取消 → 标签页仍为脏、磁盘无新文件；确定 → 写入完成、脏标记消失、标题显示文件名、该标签页记住**本地目标路径**。
6. 再次修改按 `Ctrl+S` → **直接写回该路径，不再询问**（无任何对话框）；换位置用「另存为」。
7. 关闭标签页：干净 → 直接关闭；脏 → 询问（保存 / 放弃 / 取消）。

### 6.2 流程 B：**未登录**经「打开方式」唤起 → 登录 → 自动打开（**本版核心流程**）

1. 用户在文件管理器对文件 `f` 选「打开方式 → JFLove」（或双击，若已把默认程序设为 JFLove）。
2. **单实例复用**：已有实例（含托盘 / 最小化）→ 先恢复窗口可见，在**已有实例**里继续；否则启动新实例。
3. **登录门**：应用检测到**无有效会话** ⇒ 显示**登录面板**（左侧菜单中「文本编辑器」项此时**不可见**；`f` **尚未**被打开，也**不产生**标签页）。
4. 用户在登录面板完成登录。
5. **登录成功后自动衔接**：左侧菜单切到「文本编辑器」→ 工作区打开 `f` 为一个标签页 → 该标签页获得焦点、内容等于 `f` 的内容、状态栏显示其编码 / 换行符 / 语言。
   - **类型校验先行**：若 `f` 被判为二进制 / `> 50 MB` → **不产生标签页**，给出说明原因的明确提示（提示中不打印完整路径）；`> 5 MB` 且 `≤ 50 MB` → 提示后**只读打开**；编码无法判定 → 明确提示（不静默替换）。
6. 用户编辑 → `Ctrl+S` 直接写回原文件；失败（不可写 / 被删 / 磁盘满）→ 保留内容与草稿、明确报错、**不静默失败**（原子写保证原文件不被破坏）。
7. **多请求排队**：若登录期间又传来 `g`、`h`，登录成功后按到达顺序依次打开（同一路径去重）。
8. **放弃登录**：用户始终未登录 → 请求只留内存队列，应用退出即丢弃；下次登录成功**不补开**。

### 6.3 流程 C：已登录 + 服务端不可达

1. 用户已登录（会话有效），随后断网 / 服务端未启动。
2. 新建 / 打开本机文件 / 编辑 / 保存 / 另存为 / 标签页切换与关闭 / 草稿还原 —— **逐项照常可用**。
3. **不出现**登录拦截、**不出现**阻塞式错误弹窗；编辑器功能不因服务端不可达而降级或禁用。
4. 会话在离线期间自然过期（token 失效）时：**编辑器当前已打开的内容与编辑动作不受影响**（不触发强制登出、不丢内容）；其余需要服务端的功能按既有口径处理。

### 6.4 流程 D：多标签页切换与关闭

1. 工作区已开 3 个标签页（`A` / `B` / `C`，其中 `B` 为脏且已保存过路径）。
2. 点击标签 `A` → 编辑面板切换为 `A`，内容 / 光标 / 滚动 / 视图模式与上次离开时一致。
3. `Ctrl+Alt+→` → 激活下一个标签页（按标签条顺序）。
4. 在 `B` 上按 `Ctrl+W` → 因 `B` 为脏，先询问（保存 / 放弃 / 取消）：取消 → `B` 仍在且内容不变；保存 → 写回其路径后关闭；放弃 → 直接关闭且该草稿被清理。
5. `Ctrl+W` **不得**触发页面宿主（WebEngine）的默认动作（如关闭宿主窗口）；被接管的组合键必须真实生效。

### 6.5 流程 E：关闭最后一个标签页（空态）

1. 工作区只剩 1 个干净标签页。
2. 用户关闭它 → 标签条清空，工作区显示**空态**（含"新建""打开"入口）。
3. **不自动跳转**到其它页面（仍停留在文本编辑器）；用户可继续新建 / 打开，或点左侧菜单去别处。

### 6.6 流程 F：登出 / 会话失效

1. 工作区开着若干标签页（含未保存内容），草稿已按防抖间隔写入本机。
2. 用户登出（或会话失效触发登出）。
3. 结果：左侧菜单「文本编辑器」项**消失**、工作区**不再渲染**、快捷键**不再响应**；**不弹**"是否保存"式的阻塞流程（内容已在本机草稿库）。
4. 用户重新登录 → 编辑器入口恢复 → **按 F9 规则还原**此前的标签页（内容 = 登出前最后暂存的状态）。

### 6.7 流程 G：异常退出 → 重新启动 → 登录 → 还原

1. 应用运行中开着若干标签页（含未保存内容），草稿已写入本机。
2. 进程被强杀或崩溃（**未走**正常退出）→ "干净退出"标记保持"非干净"。
3. 下次启动 → 检测到非干净退出；**若未登录则不还原**（草稿不动）。
4. 用户登录成功 → 自动还原**全部**草稿标签页（不限数量），内容 / 语言 / 本地路径（若有）/ 编码 / 换行符 / 视图模式 / **标签顺序与激活项**均恢复；还原后仍为"脏"状态，可继续编辑或保存。

### 6.8 流程 H：单实例复用唤起

1. JFLove 已在运行（可见 / 最小化 / 托盘任一状态）。
2. 用户从系统「打开方式」传入文件 `f`。
3. 第二个进程**不建立新的主窗口**：把请求交给已有实例，自身退出（判据：JFLove 进程数为 1）。
4. 已有实例：恢复窗口可见 → **若未登录则先走流程 B 的第 3 ~ 5 步**；已登录则直接走类型校验 → 打开为标签页。
5. 已有实例在超时窗口内无响应 → **不得静默丢弃**（至少给出提示；超时值与降级行为由设计文档定义）。

### 6.9 流程 I：类型校验拦截（**沿用 v1.6.0 流程 G**）

用户尝试打开 `big.exe`（二进制数百 MB）→ **在读取完整内容之前**判定（`> 50 MB` ⇒ 拒绝）→ **不产生任何标签页**、**不读取完整文件**（进程内存不随文件增长）、出现说明原因的提示（不打印完整路径与内容片段）；应用状态不受影响。

## 9. 验收标准（AC）

### 9.1 判定原则

> **沿用 v1.6.0 §9 的判定原则**：每条 AC 必须能被"跑出来"（可观测结果）；禁止"体验良好"类判据；标注 `[负向对照]` 的条目，Phase 6 **必须**把"错误实现"注入回去并确认用例**失败**，否则该 AC 视为不可信；无头环境无法验证的观感项只能登记为真机观察项。
> **编号体系**：v1.6.0 的主序列（AC-1 ~ AC-62）、数据安全专项（AC-S1 ~ AC-S4）、清债（AC-B1 ~ AC-B9）、范围与门禁（AC-R1 ~ AC-R6）**全部沿用编号**；本版**新增 AC-63 ~ AC-79**（其中 **AC-73 ~ AC-79 为 2026-10-15/16 用户实测反馈追加**，条文与依据见 **§0.5**）；被取代或需收窄的条目**就地改写**（§9.3）、确实不再成立的**作废**（§9.4）。

### 11.1.2 2026-10-16 的就地更正留痕（**AC-75 / AC-78 两处成因改写**）

> 本节是 §11.1.1 的**更正留痕**：两条 AC 在 2026-10-15/16 定稿时的**成因描述有误**，2026-10-16
> 实跑/单变量对照后**就地改对**（遵循 §0.4 纪律 1「改写而非追加」：被取代的说法不保留为并列条文，
> 只在此处留痕）。**判据本身（AC-75 的"逐项真的生效"、AC-78 的"逐字符等于剪贴板纯文本"）不变。**

| # | 被更正项 | 原写法（**已作废**） | 更正后（**现行有效**） | 更正依据 |
|---|---------|--------------------|----------------------|---------|
| **AC-75①（`view.diff` 的值）** | `view.diff` = `Ctrl+D` | `view.diff` = **`Ctrl+Shift+D`** | **实跑冲突**：CM6 `searchKeymap` 的 `Mod-d`（Windows = `Ctrl+D`）处理器**就是** `selectNextOccurrence`（"选中下一个相同词"），是各家编辑器通用键位；我们的运行时在 **window 捕获阶段** `preventDefault + stopPropagation` ⇒ 配成 `Ctrl+D` 会**抢掉**编辑器那个功能。而 `Ctrl+Shift+D` 在**全部 8 张 keymap** 里 **0 命中**。**用户裁决**：把 `Ctrl+D` 让回 CM6，`view.diff` 改 `Ctrl+Shift+D` | 设计 §15.3.3（2026-10-16 更正）；`jflove-desktop/ui/src/config/shortcuts.ts` 的 `view.diff` 条目；回归守门断言见 `ui/src/config/__tests__/shortcut-normalize.test.ts`（「`Ctrl+D` 不得被任何默认键位占用」） |
| **AC-78（缺陷成因 + 修法）** | 成因 = 「外部剪贴板为 AWT / Java 风格 **`CF_HTML`**（有数字偏移、无 `<!--StartFragment-->` 标记）」；引用上游 **QTBUG-118121** 为本缺陷上游；修法 = **渲染层** `paste` 事件接管（只取 `text/plain`） | 成因 = 「剪贴板上存在 **`UniformResourceLocator`**（`CFSTR_INETURL`，Qt 侧 `text/uri-list`）**时 QtWebEngine 的 `Ctrl+V` 贴出 0 字符**」；**与 `CF_HTML` 的标记 / 偏移无关**，**QTBUG-118121 已排除**（不是本缺陷成因）；修法 = **外壳（Python）侧在粘贴时归一化剪贴板**，**不由渲染层接管**（CM6 本来就只读 `text/plain`）。**判据不变**：外部来源粘贴后**逐字符等于 `CF_UNICODETEXT`** | **单变量对照矩阵**（逐项单独增删剪贴板格式，只有 `UniformResourceLocator` 一项能把粘贴打成空串；`CF_HTML` 有无标记两种情况都复现 ⇒ 与标记无关）；Java/AWT（IDEA）必然写 `UniformResourceLocator`。**用户裁决**：外壳侧归一化，不改渲染层职责面 |

**为什么不保留旧说法**：两条旧说法都会**误导后续实现** —— ① 按旧说法会把 `Ctrl+D` 当成"安全"键位（实际会抢编辑器功能）；② 按旧说法会去改渲染层 `paste` 处理器（实际修不了本缺陷，且会破坏多光标按行分发）。**成因写错 = 修法必错**，故按纪律 1 就地改写。
