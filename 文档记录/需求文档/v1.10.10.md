# JFLove v1.10.10 需求文档 —— 远程连接：去分组表单、断开自动关标签、左侧「会话」节点

> 版本：**1.10.10**（用户 2026-11-16 确认）｜阶段：Phase 1｜角色：product
> 前序基线：`文档记录/需求文档/v1.10.0.md`、`文档记录/桌面端开发记录/v1.10.9.md`
> 影响模块：**仅 `jflove-desktop`（Web UI 层）**；`jflove-server` / `jflove-web` / `jflove-app` 不改。
> 数据库：**无结构变更**；已有分组数据保留，不做迁移。

---

## 0. 背景与需求来源

v1.10.9 发布后用户实测反馈三条问题（原话见下表）。三条都属于「远程连接」页面的交互与状态一致性，
不涉及新的协议、接口或表结构。

| # | 用户原话（摘要） | 本版落地 |
| --- | --- | --- |
| U1 | 当前版本已去掉「新建分组」，但新建/修改/复制配置的表单里还有「分组」配置，应该去掉 | 远程连接表单、本机配置表单、遗留本机终端页全部移除分组字段；树不再按分组过滤 |
| U2 | 终端执行 `exit` 退出后，标签页要自动关闭，已断开的自动关，防止僵死标签占用 | 真正连上过的会话在结束时自动关闭标签并回收终端；失败标签保留错误信息 |
| U3 | 点「远程连接」菜单后，已打开的会话没有入口再进入；希望在「本地/远程」树结构上增加「会话」固定节点 | 左侧树新增置顶「会话」根节点，列出打开中的标签，点击直达会话面板 |

## 1. 目标用户与场景

**目标用户**：使用桌面端远程连接管理多台服务器、经常同时开多个会话的用户。

**典型场景**：

1. 用户打开 3 个 SSH 会话后回到连接列表查配置，再点「远程连接」菜单——左侧「会话」节点直接列出 3 个会话，
   点一下即可回到对应终端，不需要在顶部另找入口。
2. 用户在服务器上执行 `exit` —— 该标签自动消失，标签栏和「会话」计数同步减少，不留一块静止的黑屏。
3. 用户重新编辑一条旧连接 —— 表单里不再出现「分组」，保存后原有分组数据不被清空（只是界面不再展示）。

**非目标**：不做会话持久化/恢复（关闭应用即结束）、不做 SFTP 心跳与掉线检测、不恢复分组管理入口、
不改后端分组接口与数据表。

## 2. 功能需求

### F1 移除分组表单项（仅界面）

- 远程连接「新建 / 编辑」表单不再出现「分组」下拉；提交时不再携带 `ssh_group_id`。
- 本机配置「新建 / 编辑」表单不再出现「分组」下拉。
- 遗留的「本机终端」页（路由 `/remote/local`）同步移除分组侧栏与分组字段，避免同一功能两套界面不一致。
- 左侧「本地 / 远程」树展示**全部**条目，不再只显示 `group_id = 0` 的条目。
- 已有分组数据保留在库中；编辑远程连接时服务端沿用原 `ssh_group_id`，不清空。

### F2 会话结束自动关闭标签

- 会话**成功就绪后**发生以下任一情况，自动关闭对应标签：
  - 远程终端执行 `exit` / shell 结束；
  - SSH 链路断开（远端关闭、网络中断）；
  - 本机终端进程退出。
- 自动关闭时给出短暂 toast 提示（会话名 + 结束原因），不弹确认框。
- 若关闭的是当前标签，自动切到剩余标签的最后一个；没有剩余标签时显示空态。
- **连接失败不自动关闭**：主机指纹拒绝、认证失败、跳板失败等，标签保留并显示失败原因，供用户修正配置。
- 用户停留在「远程连接」列表页、文件页等其他页面时发生的会话结束，同样要关闭标签（事件订阅不能只活在会话页）。

### F3 左侧「会话」固定节点

- 「远程连接」页左侧树第一位新增固定根节点「会话」，位于「本地」「远程」之上。
- 节点右侧显示打开中的会话数量；每个会话行显示状态点（连接中 / 已连接 / 失败）。
- 单击会话行：将该会话设为当前标签并进入会话面板（`/remote/session`）。
- 会话行悬停显示关闭按钮，点击关闭该会话（等同标签栏的关闭）。
- 没有打开的会话时，节点计数为 0，并显示「暂无打开的会话」提示。
- 会话面板为空时提供「返回连接列表」入口，不出现「从左侧选择连接」这类在会话页不成立的引导文案。

## 3. 非功能需求（体验层面）

- 不新增任何网络请求、桥方法或后端接口；不扩大 `api.request` 路径白名单。
- 不改动「远程连接」页与「会话」页的既有布局骨架（左侧树 + 右侧卡片 / 标签栏 + 工具条 + 终端 + 状态栏）。
- 会话事件订阅常驻后，不得因路由切换产生重复订阅、重复关闭或 toast 风暴。
- 自动关闭标签后必须回收 xterm 实例与本地 WebSocket，不能只从界面移除。

## 4. 交互流程

### 4.1 会话结束

```text
用户在终端执行 exit / 链路断开
  → Python 侧发布 closed 状态（remote.session_status 或 local_term.session_status）
  → 常驻同步层判断：该标签已就绪？
      是 → 从 store 移除标签 + toast「会话已结束」→ 回收终端运行时 → 计数/标签栏更新
      否 → 保留标签，等待 session_failed 事件显示失败原因
```

### 4.2 从「会话」节点回到面板

```text
远程连接页 → 左侧「会话」→ 单击某会话
  → setActiveTab(session_id)
  → navigate('/remote/session')
  → 会话面板显示该标签（其余标签常驻 DOM，只切显隐）
```

## 5. 关键决策与最终裁决

| # | 决策点 | 最终结论 | 原因 |
| --- | --- | --- | --- |
| D1 | 「会话」节点位置 | 左侧树**第一位**（本地/远程之上） | 打开中的会话是高频工作集，置顶一眼可见；不新增顶部栏，布局改动最小（用户 2026-11-16 裁决） |
| D2 | 自动关闭范围 | 只关「曾经就绪」的会话；连接失败保留标签 | 失败原因需要可读、可修正；自动关掉会让错误一闪而过（用户 2026-11-16 裁决） |
| D3 | 分组处理 | 仅移除界面入口，保留数据与后端接口 | 避免数据迁移风险；旧分组数据不丢，只是不再展示 |
| D4 | 会话事件订阅位置 | 上移到登录后常驻布局，不再只挂在会话页 | 用户离开会话页时事件无人接收，是僵死标签的另一半原因 |
| D5 | 版本与流程 | v1.10.10 完整小迭代 | 第 3 项属体验变更，按 `AGENTS.md §7.5.2` 升小版本（用户 2026-11-16 确认） |

## 6. 与上一版本差异

| 项 | v1.10.9 | v1.10.10 |
| --- | --- | --- |
| 远程/本机配置表单 | 含「分组」下拉 | 无分组字段 |
| 左侧树 | 本地 / 远程，只列未分组条目 | 会话 / 本地 / 远程，列出全部条目 |

## 7. 验收标准

| AC | 判据（可观测） |
| --- | --- |
| AC-1 | 打开远程连接「新建」与「编辑」表单，页面不存在「分组」标签与分组下拉；新建/保存成功 |
| AC-2 | 打开本机配置「新建/编辑」表单，同样不存在「分组」字段；`/remote/local` 页面不存在「本地分组」侧栏 |
| AC-3 | 左侧「本地/远程」树显示全部条目（含历史上分过组的条目），不再只显示未分组 |
| AC-4 | 在 SSH 终端执行 `exit`：标签自动消失，标签栏不再残留；「会话」计数同步减 1；出现结束 toast |
| AC-5 | 关闭 SSH 服务端/断网导致链路断开：已就绪的标签自动关闭（与前一条同判据） |
| AC-6 | 输入错误密码/拒绝主机指纹：标签**不**自动关闭，显示失败原因 |
| AC-7 | 打开 ≥1 个会话后回到「远程连接」列表页：左侧「会话」节点显示数量与状态点；单击某会话直接进入对应终端 |
| AC-8 | 在「会话」节点悬停点关闭：该会话关闭、计数减 1；会话页标签栏同步消失 |
| AC-9 | 没有任何会话时：节点显示 0 与「暂无打开的会话」；会话页空态有「返回连接列表」按钮且可点击返回 |
| AC-10 | 停留在文件管理页时某个已就绪会话断开，再进入「远程连接」：该标签已自动关闭（事件常驻验证） |
| AC-11 | `npm run lint`、`npm run test`、`npm run build` 全部退出码 0；桌面端实机 e2e 新增用例 PASS |
