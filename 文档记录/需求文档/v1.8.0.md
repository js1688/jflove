# JFLove v1.8.0 需求文档 —— 服务端离线下载（网址分析 + 媒体抓取）

> **本版本是一次「新增能力」版本**：服务端获得**出站抓取**能力——用户给一个**无需登录**的网页地址，
> 服务端代为分析出页面内的**视频流 / 音频 / 图片**，客户端勾选后由服务端**离线下载**到**服务端统一配置的磁盘目录**，
> 文件直接落进现有虚拟磁盘，三端共享同一份任务进度。
> **范围**：`jflove-server`（核心：分析器 + 下载器 + 任务队列 + 配置项）、`jflove-desktop`（完整功能页）、
> `jflove-web`（完整功能页）、`jflove-app`（**只读**任务与进度）。
> **数据库**：服务端**新增表**（离线下载任务），需要 `migrate-1.8.0.sql` / `rollback-1.8.0.sql`。
> 编写角色：product（Phase 1，`AGENTS.md §7.3`）。

## 1. 版本概述

### 1.1 一句话定位

**v1.8.0 让服务端学会"自己上网取东西"：贴一个无需登录的网页地址，它把页面里的视频流、音频、图片分析成一张可勾选清单，下载到**你自己账号配置的**服务器大盘目录（受你的磁盘写权限约束），三端都能看见进度。**

> **口径修订（2026-10-20 第 4 轮，D9）**：早期讨论中的「管理员配置一个全局共享目录」**已被推翻**。
> 现行口径 = **每个账号一份自己的默认目录**（存服务端，各端一致），且该目录必须是**该账号有写权限**的磁盘；
> 账号没有任何可写磁盘 ⇒ 不可配置 ⇒ 不能使用本功能。本文档后续章节**一律按本口径**，不再出现"全局共享目录"。

### 1.2 与上一版本（v1.7.0）的差异

| 维度 | v1.7.0 | v1.8.0 |
|------|--------|--------|
| 文件来源 | 只能由客户端上传 | **新增**：服务端按网址**主动抓取**并落盘 |
| 新增入口 | 无 | 桌面端 + Web 端新增「离线下载」页；移动端新增**只读**任务列表 |
| 服务端网络方向 | 仅被动接收（客户端 → 服务端） | **新增出站**（服务端 → 互联网），必须做 SSRF 防护 |
| 服务端配置 | 媒体修复开关 / 并发 / 重编码 | **新增（管理员级，全局策略）**：总开关 / 深度分析 / 并发 / 体积与项数上限 |
| 个人配置 | 无 | **新增（账号级）**：每个账号的**离线下载默认目录**（存服务端，按账号隔离，受磁盘写权限约束） |
| 任务模型 | 媒体修复任务（单文件产物） | **新增**：离线下载任务（**多产物** + 分段状态：分析 → 待选择 → 下载 → 合并） |
| 依赖 | fastapi / aiofiles / imageio-ffmpeg | **新增**：站点解析与媒体抓取依赖（含可选的无头浏览器运行时） |

| 移动端 | 相册备份 | **只读**查看离线下载任务（不提供创建入口） |

### 1.3 版本号、范围与命名

- 版本号：**1.8.0**（唯一真相 `version.json`，由 `scripts/sync_version.py` 同步）。
- 范围：`jflove-server`（核心）+ `jflove-desktop` + `jflove-web` + `jflove-app`（只读）。
- 命名：界面统一称「**离线下载**」；任务列表页标题「**离线下载中心**」；**不出现**「下载器 / 爬虫 / 抓取器」等技术词。

### 1.4 范围边界（**明确不做**）

| 不做 | 原因 |
|------|------|
| 需要登录的站点 / 会员高清 / 登录态 Cookie 存储 | D1 / D2：用户明确剪掉；避免引入凭据存储这一敏感面 |
| DRM 加密流（Widevine / FairPlay） | D3：法律红线，且需要完整破解链 |
| 服务端代理 / 科学上网配置 | D8：首版不做；出网受限的站点不在验收范围 |
| 直播流录制（m3u8 无限列表 / FLV 直播） | 语义不同（无终点），本版只做**点播** |
| 「边下边看」/ 下载中即可播放 | 成本高（分片级可用性 + Range 语义 + 三端播放器），留待后续 |
| 播放列表（整季 / 整频道）批量一次性全下 | 本版只做**单页分析**；列表页可识别但需用户逐页操作（见 F23.6） |
| 弹幕 / 评论 / 站点私有元数据 | 非用户诉求 |
| 移动端创建任务 / 勾选下载 | 首版只读（D6 授权口径；创建流程在桌面/Web 完成） |
| 解析器在线自更新（运行时拉取新版本代码） | 供应链风险；**解析器随服务端版本升级**（见 I-6） |
| 转码（把 4K 压成 1080P 之类） | 本版只做**无损重封装与合并**，不重编码 |

## 2. 目标用户与使用场景

### 2.1 目标用户

- **自托管用户**：把服务器当私人网盘用，看到一个想留存的公开视频 / 图集，希望「贴个链接就不用管了」，文件最终躺在自己的大盘上。
- **多端用户**：在电脑上建任务、在手机上看进度；目录由管理员统一配置，不用每次挑。

### 2.2 核心场景

**场景 A（HLS 分片视频 · 普通账号）**：普通账号用户第一次进入 Web 端「离线下载」→ 引导里选了自己有写权限的「下载盘 / download」→ 之后粘贴一个公开视频页地址 → 3 秒后出现「1080P · H264 · ≈139 MB」「720P · ≈58 MB」「封面 1920×1080」→ 勾选 1080P → 服务端开始下载 → 文件出现在他自己的那个目录，可直接在文件管理里播放。

**场景 B（音视频分离的高清流）**：某站 1080P 的视频轨和音频轨是分开的。清单里**只出现一条「1080P」**（不是两条轨），勾选后服务端把两条轨一起下、合并成一个**有声的** mp4。

**场景 C（纯图片页）**：用户在桌面端粘贴一个图集页 → 分析出 24 张图 → 全选 → 落进 `<目标目录>/<页面标题>/` 下 24 张图，逐张可预览；另可选「打包为 zip」得到一个 zip。

**场景 D（需要 JS 才出播放地址的站）**：静态分析没结果 → 服务端自动升级为深度分析（无头浏览器）→ 出清单。若管理员关闭了深度分析，则给出中文提示「当前站点需要深度分析，请联系管理员开启」。

**场景 E（无可写磁盘的账号）**：某账号只有某个磁盘的**只读**权限 → 打开「离线下载」看到的是置灰入口 + 「你没有可写入的磁盘，无法使用离线下载」；他仍能在文件管理里看到别人下载好的文件（若有读权限），但**不能**新建任务。

**场景 F（移动端查看）**：用户在手机上看「离线下载中心」，看到桌面端建的任务正在下载、百分比在走；但不能在手机上新建任务。

### 2.3 判断这次做成功的标准（用户口径）

1. 贴一个**无需登录**的公开视频页地址，**能出清单**，且清单里的清晰度是**能直接用的**（选了 1080P 就是有声的 1080P mp4）。
2. 贴一个**图集页**地址，**图片能全抓下来**（不是只抓到第一屏）。
3. **普通账号**（不是管理员）也能用：自己的目录**配一次就够**，换端登录还是它；**没有可写磁盘的账号则明确用不了**（而不是点了才报错）。
4. **三端都能看到**任务与进度；失败原因**看得懂**、能重试。
5. 抓下来的东西**就在自己的磁盘上**，用现有文件管理就能播、能预览、能下载。

## 3. 功能需求

### 3.1 F23 网址分析（**新增，核心**）

**F23.1 输入**：一个 `http(s)` 网址。用户可在桌面端/Web 端「离线下载」页粘贴，也可由文件管理页「用离线下载打开当前网址」带入（后者非必需）。

**F23.2 分析产出「可下载项」清单**，每项至少包含：

| 字段 | 说明 | 示例 |
|------|------|------|
| 类型 | 视频 / 音频 / 图片 / 字幕 | 视频 |
| 显示名 | 人可读的清晰度或尺寸标签 | `1080P · H264 · 5.2 Mbps` |
| 格式 | 落盘扩展名 | `mp4` / `m4a` / `jpg` |
| 时长 | 视频/音频有，图片无 | `3:34` |
| 预估大小 | 无 `Content-Length` 时按码率×时长估算，**必须标注"约"** | `≈139 MB` |
| 分辨率 | 图片必给 | `1920×1080` |

**F23.3 三级分析（自动降级，用户无感）**

| 级别 | 手段（行为层表述） | 覆盖形态 |
|------|------------------|---------|
| ① 站点专用解析 | 用内置的站点解析库直接取媒体清单 | 主流视频站（无需登录即可看的那种） |
| ② 静态抓取 | 抓 HTML / 页面内嵌 JSON / 播放列表文件（m3u8、mpd） | 直链页、播放列表页、图集页 |
| ③ 深度分析 | 启动无头浏览器，拦截页面发出的媒体请求 | 播放地址由 JS 动态注入的站 |

- **启用顺序**：① → ② → ③，前一级**出结果即停**（不叠加，避免慢）。
- **深度分析开关**：管理员可全局关闭 ③。关闭后遇到只能靠 ③ 的站点，必须给**明确中文提示**，不得静默返回空清单。
- **不下载正文内容**：分析阶段只取"清单"，**不得**把媒体分片下载到磁盘（唯一例外：播放列表文件本身，属元数据）。

**F23.4 音频**：视频页里的音轨若可独立获取，清单里**额外**提供「仅音频」项（便于只要声音的场景）；纯音频页（播客/音乐）直接产出音频项。

**F23.5 图片**

- 抓取范围：当前页可见图片（含懒加载属性、`srcset` 取最大、CSS 背景图、以及页面自身 JSON 里的图片地址）。
- **过滤**：去掉尺寸小于 50×50 的图片与明显是统计像素的资源。
- **去重**：同一地址只出现一次。
- **深度可配**：默认**只抓当前页**；若分析发现该页有图集/分页结构，界面出现「继续抓下一页」按钮，用户点了才追加（每次追加都要有**页数与张数上限**，见 F23.8）。

**F23.6 播放列表 / 分P**

- 若地址是播放列表页，分析结果为**分组结构**（列表名 → 各分P），但本版**默认只取第一个分P**，其余需用户逐个展开选择（不做整季一键下载）。
- 清单里每个分P单独可勾。

**F23.7 结果时效**：同址分析结果在服务端**保留 10 分钟**，期间再次打开直接复用（秒出）；超过 10 分钟必须重新分析（因为媒体地址普遍带签名且会过期）。

**F23.8 硬上限**（防止一页把服务端点爆）

| 限制 | 默认值 | 说明 |
|------|-------|------|
| 单次分析整体耗时 | **30 秒** | 含浏览器启动；超时给中文失败原因 |
| 清单最大项数 | **50** | 超出截断并提示"仅显示前 50 项" |
| 单页图片最大张数 | **200** | 超出截断并提示 |
| 分页追加最大页数 | **20 页** | 超出提示"已达抓取页数上限" |

### 3.2 F24 可下载项清单与选择（**新增**）

- **多选**：逐项勾选；提供「全选 / 全不选」。
- **快捷选择**：「只要最高清」「只要音频」「只要图片」。
- **合并展示**：音视频分离的流**必须合并成一条**（用户看到"1080P"，不看到"视频轨 + 音频轨"）——这是本功能最容易做错的地方（见 §7.2 I-7）。
- **汇总**：清单底部显示「已选 N 项 · 约 X GB」。
- **提交**：勾选后点「开始下载」→ 任务进入下载队列。

### 3.3 F25 存放位置（**账号级配置，受磁盘权限约束**）

**F25.1 每个账号一份默认目录**：默认目录 = 「**虚拟磁盘 + 相对路径**」，**按账号隔离**保存在服务端
（既不是全局一份，也不是存客户端本地）。同一账号在桌面端 / Web 端看到的是**同一份**默认目录。

**F25.2 谁能配**：**任何登录账号（含普通账号）**都能配置自己的默认目录。前提是**至少有一个该账号有写权限的磁盘**。
- 可选磁盘列表 = 该账号有 **write** 权限的虚拟磁盘（服务端过滤后下发，客户端不自行判断）。
- 不允许配置到「自己无写权限」的磁盘（服务端 403，不只靠前端拦）。

**F25.3 没有任何可写磁盘 ⇒ 该账号不能使用本功能**（硬门槛）：

| 位置 | 行为 |
|------|------|
| 入口 | 「离线下载」置灰 + 中文提示「你没有可写入的磁盘，无法使用离线下载」 |
| 配置 | 不允许保存任何目录（服务端 403 `no_writable_disk`） |
| 分析 / 下载 | 接口直接拒绝（`no_writable_disk`），**不产生任何出站请求** |

**F25.4 有可写磁盘但未配置时**：首次进入引导配置（选磁盘 → 浏览/新建子目录 → 保存）。
**未配置前不可发起分析**（避免"分析完了发现没处放"），提示「请先设置离线下载目录」。

**F25.5 任务内可临时改**：创建任务时可临时改目录；**临时改不回写默认值**。
默认值只在「离线下载设置」里改。这样"一次性的特殊选择"不会污染账号默认。

**F25.6 权限或目录变化后的失效处理**：
- 磁盘被删除 / 写权限被收回 / 目录被删 ⇒ 该账号配置**自动视为无效**，界面提示「离线下载目录已失效，请重新配置」；
- 失效期间**不能创建新任务**（服务端拒绝），也不能开始下载；
- **已下载完成的文件不受影响**（文件属于磁盘，不属于账号；账号被收回权限就看不到，但文件还在）。

**F25.7 目录合法性**：只接受「虚拟磁盘 + 相对路径」；拒绝绝对路径、`..` 越界、隐藏目录（`.jflove-*`）；
目录不存在时，允许在**该磁盘内**新建（不得借新建越出磁盘根）。

### 3.4 F26 下载执行（**新增，核心**）

**F26.1 后台异步**：提交后立即返回，下载在服务端后台进行；**不得**阻塞任何 API 响应（页面操作始终流畅）。

**F26.2 并发**：默认同时下载 **2** 个任务（可配，硬上限 4）；超出排队。单个任务内部的分片并发受限（不把带宽吃满，见 §5.6）。

**F26.3 断点续传**：相同任务重试时**已完成的片不重下**（判据见 AC-216）。

**F26.4 合并（无损）**：音视频分离的流必须**合并**为一个 mp4；HLS 的 ts/fmp4 分片必须**重封装**为 mp4；**不重编码、不改变画质**。

**F26.5 原子落盘**：下载中产物写在目标目录下的隐藏临时目录 `.jflove-download/`，**成功后才**以原名出现；中途失败/取消**不留下**半成品可见文件。

**F26.6 同名冲突**：目标目录已有同名不同内容的文件 ⇒ 新文件追加**短哈希后缀**（不覆盖、不丢文件）。内容相同则视为重复，直接复用已有文件并标记「已存在」。

**F26.7 磁盘预检**：入队前检查目标磁盘剩余空间；不足「预估大小 × 1.2」时**拒绝入队**并给中文原因（"磁盘剩余空间不足"），不得下到一半失败。

**F26.8 体积上限**：单个文件预估/实际超过上限（默认 **4 GiB**，可配）⇒ 拒绝并提示。

**F26.9 自动重试**：
- 网络类失败（超时 / 连接重置）自动重试 **1 次**；
- 媒体地址过期（401/403 且判定为签名过期）⇒ **自动重新分析一次**后再续传（用户不需要重新贴地址）；
- 其他失败不自动重试，直接给中文原因 + 手动「重试」。

**F26.10 取消**：取消后立即停止网络活动、清理临时文件；**不删除**已完成的其他产物。

**F26.11 服务端重启**：重启时未完成任务标记为**失败**（原因"服务重启导致任务中断"）并清理半成品（沿用 E-1 的做法）。

### 3.5 F27 离线下载中心（**新增，三端可见**）

**F27.1 任务列表**（**按账号隔离**：只显示当前账号自己创建的任务）：

> **口径修订（2026-10-20 第 5 轮，D10）**：早期版本写的"**全平台共享**"**已被推翻**——
> 任务记录会带出来源 URL / 目标目录 / 产物文件名，跨账号可见就是**隐私泄露**。
> 现行口径：**记录默认按账号隔离**，详见 `product/SKILL.md` 纪律 4。

| 列 | 内容 |
|----|------|
| 状态 | 排队中 / 分析中 / 待选择 / 下载中 / 合并中 / 已完成 / 失败 / 已取消 |
| 进度 | 百分比 + 已下载/总大小 + 速度 |
| 来源 | **脱敏展示**：域名 + 路径前若干字符（不展示完整 URL，见 §10） |
| 产物 | 文件名（可点开所在目录） |
| 目标 | 磁盘名 + 相对路径 |
| 时间 | 创建时间 / 开始时间 / 完成时间（本地时间） |
| 失败原因 | 中文，可展开看建议动作 |

**F27.2 操作**：取消 / 重试 / 删除记录 / 「在文件管理中打开」。
- 「删除记录」只删任务行，**不删文件**（删文件走文件管理，语义分开）。
- **只有任务的创建者**能看到并操作该任务；他人任务**不可见**（枚举 `task_id` 也拿不到详情，按"不存在"处理）。
- 创建者对目标磁盘的写权限被收回后：任务仍可见（是他自己的记录），但**不能重试**（中文原因）。

**F27.3 刷新**：**2.5 秒轮询**（沿用 E-7 口径）；页面不在前台/弹窗关闭时**停止轮询**；任务全部终态后停止轮询。

**F27.4 三端一致性（同一账号）**：同一账号在三端看到**同一份**任务列表（服务端按 `user_id` 过滤），状态/进度/产物名一致；Web 端建的任务在桌面端 **2.5 秒内**可见（AC-219）。**看不到别人的任务**（AC-244）。

**F27.5 移动端（只读）**：能看到任务列表与进度；**无**「新建/分析/勾选/开始下载」入口；点「取消/重试」也**不提供**（首版最简）。

> **管理员不能替他人设**，也不进 `config` 表。本节只放**全局策略**（所有账号共享）。

### 3.9 F31 存量记录按账号隔离（**缺陷修复，本版必须**）

> **来源**：用户 2026-10-20 第 5 轮——「修复记录、任务中心、下载记录这些可以产生记录的地方，都应该按账号隔离，
> 否则会导致隐私泄露」。这是一条**已存在于线上代码**的缺陷（修复任务列表对全员可见），本版一并修掉。

**F31.1 修复任务中心改为按账号隔离**：修复任务列表/详情/取消/覆盖/删除记录，**全部只对创建者可见可操作**；
他人即使拿到 `task_id` 也**看不到、动不了**（按"不存在"处理，不泄露存在性）。

**F31.2 离线下载任务中心按账号隔离**：见 F27.1。

**F31.3 保留"全局互斥"，但互斥不得泄露身份**：
同一个文件**仍然只允许同时跑一个修复/下载任务**（互斥是资源保护，不是可见性）；
当文件已被他人占用时，本账号只看到**无身份信息**的提示（如「该文件正在处理中，请稍后再试」），
**不得**出现他人用户名、任务 ID、任务状态。

**F31.4 本版不给普通账号「看全部」**：管理员同样按账号隔离（管理员看到的也只是自己的记录）。
若将来需要全局运维视角，作为**独立能力**另行定义（登记为下个版本候选）。

**F31.5 判据**：同一套记录，A 建、B 查 ⇒ B 的列表 **0 命中**；B 直接请求该 `task_id` ⇒ 404；
管理员的列表同样 0 命中他人记录。

## 5. 非功能需求（体验层面）

1. **不卡 UI**：分析/下载全部后台执行；任何页面操作响应 < 300 ms。
2. **出清单要快**：普通站（①②级）**≤ 5 秒**出清单；需要深度分析的站 **≤ 30 秒**；期间界面必须有"分析中"的明确反馈（不得像卡死）。
3. **进度可见**：状态变化 **2.5 秒内**反映到三端界面（轮询）。
4. **失败可解释**：见 F29；每条失败都有中文原因 + 下一步动作。
5. **不产生幽灵流量**：总开关关闭 / 任务终态 / 页面离开后，**不得**有残留请求与浏览器进程。
6. **资源占用**：单任务分片并发上限 4；同时下载默认 2；浏览器实例**闲置 60 秒回收**；服务端磁盘临时占用不得超过"正在下载的任务数 × 单文件上限"。
7. **兼容**：老库升级后既有功能不受影响；**未配置目录 / 无可写磁盘**时新功能**自动不可用并给出中文原因**，而不是报错或崩溃。
8. **记录可见性**：所有列表/记录默认只显示当前账号自己的（D10）；他人记录既不可见也不可操作，管理员同样不越权。
9. **平台**：与服务端既有平台一致（Docker / Linux / Windows 开发机均可运行；深度分析在无 GUI 环境必须可用——headless 模式）。

## 6. 交互流程

### 6.1 流程 T：分析 → 勾选 → 下载（主流程）

1. 进入「离线下载」→ 粘贴地址 → 点「分析」。
2. 任务出现在列表，状态「分析中」（普通站 3~5 秒；需要浏览器时提示"正在深度分析，最多 30 秒"）。
3. 分析成功 → 状态「待选择」→ 弹出清单：类型图标 + 显示名 + 时长 + 约大小；音视频分离的已合并为一条。
4. 用户勾选（或点快捷选择）→ 底部显示「已选 N 项 · 约 X GB」→ 确认目标目录（预填上次选择/默认目录）→ 点「开始下载」。
5. 状态转「下载中」→ 进度条 + 速度；完成后转「合并中」（若需要）→「已完成」，产物出现在目标目录。
6. 点「在文件管理中打开」→ 跳转文件管理并定位到产物。

### 6.2 流程 U：失败与重试

1. 任一步失败 → 状态「失败」+ 中文原因（F29 分类）。
2. 可重试的类别显示「重试」；不可重试的（DRM / 需要登录）**不显示**重试按钮，只显示说明。
3. 签名过期类失败：服务端先**自动重新分析一次**；仍失败才落到用户可见的失败。

### 6.3 流程 V：账号配置自己的离线下载目录

1. 用户（**任何账号**）第一次进入「离线下载」→ 若从未配置，出现引导：「先设置离线下载目录」。
2. 配置面板只列出**该账号有写权限**的磁盘 → 选磁盘 → 浏览/新建子目录 → 保存。
3. 保存后立即生效：换到别的端（Web / 桌面）登录同一账号，默认目录一致。
4. **没有任何可写磁盘**时：面板不可保存，整页置灰并提示「你没有可写入的磁盘，无法使用离线下载」。
5. **总开关关闭**（管理员级）：三端入口置灰；已在下载的任务**继续完成**，新任务不可创建。

### 6.4 流程 W：图片分页追加

1. 图集页分析出当前页 24 张 → 清单下方出现「继续抓下一页（第 2 页）」。
2. 点击 → 追加该页图片（去重后追加）→ 按钮更新为第 3 页。
3. 达到页数上限（20）或没有下一页 → 按钮消失并提示。

### 6.5 流程 X：移动端只读

1. 手机上打开「离线下载中心」→ 列表显示状态与进度。
2. 点某个任务 → 只读详情（来源域名、产物名、目标目录、失败原因）。
3. **没有**「新建任务」「勾选」「开始下载」「取消」入口。

## 7. 关键决策与最终裁决

### 7.1 用户裁决（D1 ~ D11）

| 决策点 | 最终结论 | 推翻过程摘要 | 原因 |
|--------|---------|-------------|------|
| **D1 登录态站点** | **不支持**，只做无需登录站点 | 初版讨论时曾把「B站高清/抖音无水印需要 Cookie」列入范围；用户第 2 轮明确剪掉 | 范围收敛，避免凭据存储这一敏感面 |
| **D2 Cookie 管理** | **不做** | 随 D1 一并移除 | 同上 |
| **D3 DRM** | **不做**，分析阶段如实告知 | 用户未反对；我方在讨论中即划为红线 | 法律红线 + 技术不可行 |
| **D4 无头浏览器** | **做，仅作兜底**（③级），管理员可关 | 讨论中给出两个选项（只做①② / ①②③）；用户接受"兜底 + 可关" | 覆盖 JS 注入站，同时不让镜像成本变成默认负担 |
| **D5 图片深度** | **可配**：默认当前页 + 「继续抓下一页」 | 讨论中给出 (a)/(b)/(c) 三选；用户接受 (c) | 避免一次把站点点爆 |
| **D6 产物形态** | 视频合并 mp4 / 音频保原格式 / 图片落同名子目录 / zip 可选 | 讨论中我方给默认，用户"按你的建议" | 与现有文件管理的预览能力对齐（zip 不可预览，故不做默认） |
| **D7 版本** | **1.8.0** | — | 用户确认 |
| **D8 代理** | **首版不做** | 讨论中曾提"出网受限站点需要代理"；用户全盘接受收缩 | 降低首版复杂度 |
| **D10 记录隔离** | **记录一律按账号隔离**；管理员不越权看；规则固化进技能 | **推翻了我方原方案**（原方案：任务中心"全平台共享"，与修复中心一致）；用户第 5 轮指出这是隐私缺陷 | 记录必然带内容元数据（URL/文件名/目录），共享即泄露 |
| **D9 谁能用 / 目录归谁** | **普通账号可用**；默认目录**按账号隔离**（存服务端）；**受磁盘写权限约束**；**无可写磁盘 ⇒ 不能用** | **推翻了我方原方案**（原方案：管理员配一份全局共享目录）；用户第 4 轮明确改成账号级 | 不同账号的磁盘权限不同，全局一份必然出现"给 A 配的目录 B 不可写" |
| **D11 总开关默认值与配置入口** | **默认开启**；管理员可在**三端「系统设置」**应急关闭 | **推翻了我方原方案**（原方案：默认关、仅后端配置无 UI）；UAT 首轮用户反馈"三端都找不到开关，无法自行开启" | 开箱即用；保留熔断能力；三端配置入口必须齐备 |

### 7.2 硬不变量（**不可协商**）

| id | 不变量 | 依据 |
|----|--------|------|
| **I-1** | **不做**登录态抓取、**不存储**任何站点 Cookie / 凭据 | D1 / D2 |
| **I-2** | **不碰** DRM 加密流，不做任何密钥获取/解密链 | D3 / 法律红线 |
| **I-3** | 落盘位置**只能**是「虚拟磁盘 + 相对路径」，**永不接受**客户端绝对路径，**永不**越出 `real_path` | `§9.3` / `§9.7` |
| **I-4** | **SSRF 防护不可关闭**：拒绝环回、私网、链路本地（含云元数据地址）、非 http(s) 协议；重定向必须逐跳复检 | 本版新增攻击面 |
| **I-5** | 加密通道**不变**：新接口全部加密信封，明文白名单**仍为 3 条**，不新增加密原语 | `§9.1` / `§9.5` |
| **I-6** | 解析组件**随服务端版本升级**，**不做**运行时在线自更新（不下载执行远端代码） | 供应链安全 |
| **I-7** | **音视频分离的流必须合并为一条可下载项**，产物必须"有声"；不得把裸视频轨当成品交付 | 本功能最易出错处 |
| **I-8** | 所有失败**必须**映射到 F29 的中文类别；**禁止**向界面抛英文异常原文 | 体验底线 |
| **I-9** | 分析阶段**不落盘**媒体内容；下载产物**必须**先写隐藏临时目录再原子改名 | E-11 / 防半成品 |
| **I-10** | 默认目录**只属于账号自己**：一个账号**绝不能**把落点配到自己无写权限的磁盘上；服务端**每次**校验，不信任缓存/客户端 | D9 / `§9.3` |
| **I-11** | 「账号无可写磁盘」时，功能**必须明确不可用**（中文原因），**禁止**静默失败或降级到别人的目录 | D9 |

### 7.3 我方拍板项（用户已授权"按你的建议"，可被用户一句话推翻）

| 项 | 结论 | 理由 |
|----|------|------|
| 任务列表隔离粒度 | **按账号隔离**（D10） | 记录带 URL/文件名/目录，共享即泄露 |
| 全局互斥 vs 可见性 | 互斥保留（同一文件只跑一个任务），提示**不含身份信息** | 互斥是资源保护，不等于允许看到别人 |
| 账号目录配置的存储 | 服务端新表**按账号一行**（不存客户端本地） | D9 明确"各端看到一样"，客户端本地存会各端不一致 |
| 临时改目录是否回写默认 | **不回写**，默认只在设置页改 | 防止一次性选择污染账号默认 |
| 磁盘权限变动后的处理 | 配置**自动失效**，提示重新配置；已下载文件不受影响 | 权限是磁盘的，文件也在磁盘上 |
| 任务状态机 | 排队中 → 分析中 → 待选择 → 下载中 → 合并中 → 已完成 / 失败 / 已取消 | 覆盖"分析完等用户勾选"这一段，语义不留空 |
| 分析结果缓存 | 服务端保留 **10 分钟** | 媒体地址普遍带签名，久放必失效 |
| 隐藏临时目录名 | `.jflove-download/`（位于目标目录内，文件列表不展示） | 沿用 `.jflove-repair` 的先例（E-11） |
| 同名冲突命名 | `<原名>_<8位短哈希>.<ext>` | 不覆盖、可排序 |
| 图片批量子目录名 | 页面标题（清洗非法字符），空则用域名 | 可读、便于定位 |
| 一批图片默认形态 | **不打包 zip**，落子目录；zip 为**可选**勾选项 | zip 在文件管理里不可逐张预览 |
| 下载并发默认 / 硬上限 | 2 / 4 | 家庭带宽与 NAS 磁盘的现实取值 |
| 单文件体积上限默认 | 4 GiB | 覆盖绝大多数 1080P/4K 单文件 |
| 任务「删除记录」是否删文件 | **不删** | 与文件管理语义分开，防误删 |
| 列表刷新间隔 | 2.5s，页面不在前台停止 | 沿用 E-7 |
| 失败自动重试 | 网络类 1 次；签名过期自动重分析 1 次 | 平衡成功率与"重试风暴" |
| 移动端能力 | **只读**（列表 + 详情） | 首版最小可用；创建流程在桌面/Web |
| 桌面/Web 页面形态 | 任务中心 + 新建任务同页（标签/分段） | 与修复中心交互一致 |

### 7.4 与 v1.7.0 的关系

- v1.7.0 的「云盘挂载 / 相册备份」条文**不受影响**，本版为**纯新增能力**。
- 本版**不修改**挂载、相册备份、编辑器、笔记的任何既有行为。
- 与 v1.7.0 的「D12 配置存客户端本地」**不冲突**：v1.7.0 的 D12 只约束"挂载点 / 相册备份"这类**设备本地**偏好；
  离线下载的默认目录按 **D9** 存**服务端、按账号隔离**（因为要求"各端看到一样"）。两套口径的边界写清楚，避免下游误用。

### 8.1 F23 分析

| AC | 判据 |

| **AC-200** | **入口存在**：桌面端与 Web 端各有「离线下载」入口（PC + 移动浏览器布局各一处）；总开关关闭时入口置灰且点开有中文说明（普通用户 0 命中设置项） |

| **AC-205** | **分页追加**：点「继续抓下一页」⇒ 图片数增加且无重复；连续追加到第 21 页时按钮消失并提示页数上限 |
| **AC-206** | **JS 注入页**：本地样本页的媒体地址仅由 JS 在 `XHR` 后注入 ⇒ 开启深度分析时**能出清单**；关闭深度分析时返回**明确中文提示**（不得空清单、不得英文报错） |
| **AC-207** | **超时**：构造一个 30 秒不响应的本地端点 ⇒ 分析在 **35 秒内**结束，状态「失败」，原因为 F29 类别「网络超时」 |
| **AC-208** | **结果复用**：同址连续两次分析，第二次响应 **< 1 秒**且清单完全一致（10 分钟内） |

## 10. 安全宪法对齐（`AGENTS.md §9` 逐条）

| 条款 | 本版如何满足 |
|------|-------------|
| §9.1 加密通道 + 文件流加密 | 新增接口全部 `decrypt_request_body` + `encrypt_response`；产物由客户端经**现有**加密流拉取，不新增明文/裸流路径；明文白名单不扩 |
| §9.2 密钥交换 | 完全不变 |
| §9.3 鉴权与权限 | 全部接口从加密 body 取 `token`；**账号级目录配置按 `user_id` 归属校验**；**记录类接口（任务/修复/下载）一律 `WHERE user_id = ?`**，详情与操作同样校验归属（D10）；落盘前逐请求 `check_disk_permission(write)`；全局策略项仅管理员 |
| §9.4 不暴露内容 | 列表只展示**脱敏来源**（域名 + 截断路径）；响应头不带文件名/路径；日志中 URL 截断/哈希，**不记录**完整 query（可能含签名） |
| §9.5 加密原语清单 | 只复用 `middleware.py` / `crypto.py`；客户端只走既有 `http_client` / `http-client.ts` / `http_service.dart` |
| §9.6 角色约束 | 桌面端渲染层仍无网络出口（新页面走 `api.request` 白名单前缀，E-9）；移动端只读、无凭据入日志 |
| §9.7 新接口自查 | 设计文档需逐接口标注：是否明文白名单 / 加密信封 / 有无路径参数 / 归属与磁盘权限校验 / 是否文件流 |
| **§9 未覆盖的新面** | **出站抓取（SSRF）**：本版**新增**一条宪法外约束，见 I-4 与 AC-234；设计文档必须给出「协议白名单 + 解析后 IP 校验 + 逐跳重定向复检 + 超时/大小限制」的可执行判据 |
