# JFLove v1.1.6 需求文档

## 0. 与 v1.1.5 的差异说明

| 项 | v1.1.5 行为 | v1.1.6 期望行为 |
|---|---|---|
| 同步配置存储位置 | 服务端 `sync_configs` 表 | **客户端本地** `sync_configs.json` 文件 |
| 多客户端同步配置 | 同一用户的所有客户端共享同一套同步配置（`local_path` 冲突） | 每个客户端独立管理自己的同步配置，互不影响 |
| 远端快照接口 | `GET /api/v1/sync/configs/{id}/snapshot`（依赖 config_id） | `POST /api/v1/sync/snapshot`（直接传 `disk_id`+`remote_path`） |
| 同步完成标记 | `POST /api/v1/sync/configs/{id}/touch`（服务端记录 `last_synced_at`） | 客户端本地记录 `last_synced_at` |
| 配置 ID 类型 | 服务端自增 int | 客户端 UUID 短 ID（str） |

**保持不动的事项**：
- v1.1.5 全部功能行为不变（文件管理、笔记、权限、加密协议等）；
- 端到端加密协议不变；
- 数据库其他表结构不变（仅移除 `sync_configs` 表）；
- 桌面端 UI 布局与交互流程不变。

---

## 1. 项目概述

v1.1.6 是需求变更版本（小版本迭代），核心动因是：

**当前服务端存储同步配置的设计存在架构缺陷**：同步配置中的 `local_path`（本地目录绝对路径）是绑定本机物理目录的，但所有客户端共享同一套服务端配置。当同一用户在多台机器上安装客户端时：

- 机器 A 的 `local_path=/home/alice/Photos` 被存储到服务端
- 机器 B 读取到的是机器 A 的路径，与机器 B 的目录结构不匹配
- 机器 B 修改配置后，机器 A 的配置又被覆盖

**解决方案**：服务端完全不存储同步配置，每台客户端在本地 `sync_configs.json` 中独立管理自己的配置。服务端仅提供 `POST /api/v1/sync/snapshot` 接口（直接传 `disk_id`+`remote_path`）用于递归扫描远端目录。

---

## 2. 目标用户

同一用户在不同机器上使用 JFLove 桌面端的场景：

| 场景 | 现状问题 | v1.1.6 解决 |
|---|---|---|
| 家庭电脑 A 和笔记本 B 安装同一客户端 | A 的 `local_path` 被 B 覆盖 | ✅ 各自独立 |
| 公司电脑和私人电脑使用不同同步目录 | 只能共享一套配置 | ✅ 各自独立 |
| 一台机器 AutoSync 开启、另一台关闭 | 自动同步状态共享 | ✅ 各自控制 |
| 不同机器的同步间隔偏好不同 | 间隔值共享 | ✅ 各自设置 |

## 3. 功能需求

### 3.1 同步配置客户端本地化存储

#### 3.1.1 用户故事

> 作为使用多台电脑的用户，我在台式机上配置了照片同步到 `D:\Photos`，在笔记本上想把同一个远端目录同步到 `C:\Users\me\Pictures`。我不希望两台机器互相干扰对方的本地同步配置。

#### 3.1.2 期望行为

| 场景 | 期望行为 |
|---|---|
| 创建同步配置 | 仅写入本地 `sync_configs.json`，不调服务端 |
| 列出同步配置 | 从本地文件读取 |
| 编辑同步配置 | 仅更新本地文件 |
| 删除同步配置 | 仅从本地文件移除 |
| 远端快照 | 调 `POST /api/v1/sync/snapshot` 传 `disk_id`+`remote_path` |
| 同步完成标记 | 更新本地 `last_synced_at` 字段 |

#### 3.1.3 规则约束

- 配置文件路径：`{USER_DATA_DIR}/storage/sync_configs.json`
- ID 生成：使用 `uuid.uuid4().hex[:8]`（8 位 hex 字符串）
- 写文件使用原子写入（tmp 文件 → `os.replace`）
- 不存储 token、session_key、密码等敏感信息

## 4. 非功能需求

| 维度 | 要求 |
|---|---|
| 安全性 | sync_configs.json 仅存配置元数据（不存 token/密码/session_key）；snapshot 接口走加密信封 |
| 性能 | 本地 JSON 文件读写，无额外网络开销 |
| 兼容性 | 旧服务端（v1.1.5）不兼容新客户端，需同步升级 |
| 体验 | 创建/编辑/删除配置为纯本地操作，响应更快 |
| 错误处理 | JSON 文件损坏或不存在时兜底返回空列表 |

---

## 5. 验收标准

| # | 验收点 | 期望 |
|---|---|---|
| AC-1 | 创建同步配置→本地 JSON 文件写入新条目→列表可见 | 是 |
| AC-2 | 编辑配置→本地 JSON 文件更新→列表刷新 | 是 |
| AC-3 | 删除配置→本地 JSON 文件条目移除→列表不可见 | 是 |
| AC-4 | 客户端 A 创建配置→客户端 B 列表为空（各自独立）| 是 |
| AC-5 | 触发同步→`POST /snapshot` 返回文件清单→diff 正确 | 是 |
| AC-6 | 同步完成后本地 `last_synced_at` 更新 | 是 |
| AC-7 | 服务端旧 `GET /sync/configs` 等 6 个接口返回 404 | 是 |
| AC-8 | `POST /sync/snapshot` 请求/响应走加密信封 | 是 |
| AC-9 | `POST /sync/snapshot` 对不存在的 disk_id 返回 400 | 是 |
| AC-10 | v1.1.5 已有功能（上传、下载、笔记、权限等）回归不受影响 | 是 |

---

## 6. 不在本期范围

- 批量同步配置操作
- 同步配置导入/导出功能
- 服务端同步配置历史数据迁移（旧配置已被视为错误的，从零开始）
