## 1. 版本概述

**v1.8.2 把「能下载但没声音」「慢站必超时」「相册备份卡住/重传」「Linux 播放窗口乱飘」这四类 v1.8.1 用户实测问题修到可用。**

## 2. 目标用户与核心场景

### 2.1 目标用户

- 用离线下载保存 B 站/公开视频的普通用户：要**有声音的成片**。
- 网络环境一般、常遇到慢站的用户：希望**慢一点但能成功**，而不是 30 秒就失败。
- 用手机自动备份相册的家庭用户：希望**换手机/重装后不重复传**，卡住时**知道卡在哪**。
- Linux 桌面用户（KDE Wayland 为主）：希望**拖动窗口时播放画面跟着走**。

### 2.2 核心场景

**场景 A（B 站成片）**：粘贴 B 站视频页 → 分析出 1080P/720P → 开始下载 → 完成后本地播放**有画面有声音**；若合并失败，任务明确失败并可重试，不产出无声文件。

**场景 B（慢站）**：一个首字节 20s 的网页 → 分析在 90s 预算内成功；管理员可把预算调到 120s。

**场景 C（相册重装）**：卸载重装 App、重新开启相册备份 → 扫描发现远端已有 1489 个同名同大小文件 → **不再重传**，界面显示「远端已存在跳过 1489 项」，只补传缺失的 150 项。

**场景 D（相册卡住）**：相册中有一个坏视频（MediaStore 记录失效）→ 扫描**跳过它并记为失败**，其余 1638 张继续完成；界面显示「失败 1 项 · 查看原因」，点「重试失败项」可再试。

**场景 E（Linux 拖动）**：Wayland 会话播放视频 → 拖动主窗 200px → 播放画面**同步移动**、不被主窗遮挡、不黑屏；中文输入法不受影响。

**场景 F（管理端超时）**：管理员在任意一端「离线下载设置」把解析超时改为 120s → 三端 `get_meta` 2.5s 内同步 → 该实例后续解析按新值执行；非管理员看不到也改不了。

## 3. 功能需求

### 3.1 F36 离线下载音视频合并（#9，**本版核心**）

**F36.1 合并触发**：清单项 `aux_url` 非空时，下载必须同时获取主轨（`source_url`）与音轨（`aux_url`），并用 ffmpeg `-c copy` 无损封装为一个 `mp4`；不得只下载主轨。

**F36.2 音轨协议**：`aux_url` 为 `.m3u8` / `.mpd` 时按对应流程下载（复用现有 HLS/DASH 逻辑）；其余按直链下载。不新增数据库列。

**F36.3 结果校验**：合并后用 `ffprobe` 断言含 `audio` 流且时长与主轨偏差 ≤1s；不满足即视为失败。

**F36.4 失败口径（不静默）**：
- 音轨下载失败（403/过期/超时）→ 该项失败，错误码沿用 `url_expired` / `net_timeout`，可重试；`url_expired` 沿用现有「自动重分析一次」；
- ffmpeg 不可用或合并失败 → 该项失败，错误码 `merge_failed`，文案「音视频合并失败，可重试」；
- **禁止**在合并失败时静默落一个无音轨文件当成功。

**F36.5 无音轨来源**：若分析阶段该站点本就无独立音轨（`aux_url` 为空且 `acodec` 为空），列表项标注「无音轨」，写入 `offline_download_items.error_message`（列已存在），三端详情可见。

**F36.6 进度**：合并阶段按「主轨字节 + 音轨字节」累计进度；合并本身不重复计字节。

### 3.2 F37 离线下载解析/下载超时可配（#11，**本版唯一新增配置面**）

**F37.1 新增配置项（`config` 表 KV，无 DDL）**

| 键 | 含义 | 默认 | 允许范围 |
|---|---|---|---|
| `offline_download_analyze_timeout_s` | 单次分析总预算（秒） | **90** | 30–180 |
| `offline_download_connect_timeout_s` | 出站连接超时（秒） | **15** | 5–30 |
| `offline_download_read_timeout_s` | 出站读取超时（秒） | **60** | 15–120 |

**F37.2 生效范围**：解析总预算（`asyncio.timeout`）、出站 HTTP 连接/读取、L3 浏览器 `goto` 与整体预算联动；非法/越界值回落默认并夹到边界。**不提供环境变量覆盖**（保持单一来源）。

**F37.3 解析重试**：`net_timeout` / `network_error` 允许**自动重试 1 次**（退避 2s，仍受总预算约束）；重试仍失败才置 `failed`。4xx / SSRF / DRM 不重试。

**F37.4 超时保留部分结果**：总预算耗尽时，若 L1/L2（或 L3）已抓到 ≥1 项，落库并置 `ready`，同时返回 `warnings`（「部分结果，深度分析未完成」）；一项都没有才 `failed`。

**F37.5 文案**：超时错误统一中文且带可操作建议（如「解析超时（90s），可稍后重试或让管理员调大预算」）；不得回显完整 URL/路径。

**F37.6 管理端 UI**：桌面 / Web / 移动「系统设置 → 离线下载」新增三项（数字输入 + 范围校验 + 保存），改动在三端管理员页；非管理员 403，`get_meta` 不含仅管理员可用的写接口。

### 3.3 F38 相册备份远端去重（#8）

**F38.1 远端存在性判断**：每轮扫描前，对本次涉及的每个远端目录（`<root>/YYYY/MM`）拉取一次列表并缓存（同一轮内只拉一次）；本地资源若在目标目录存在**同名且同大小**文件，则标记为已备份，**不再提交上传**。

**F38.2 记录归属**：本地记录以 `(asset_id, disk_id, remote_root)` 为有效键；目标目录或磁盘变更后，旧记录不参与新目标去重（历史资源进入待传队列）。

**F38.3 失败开放**：远端列表拉取失败（网络/权限）时**不阻塞备份**——本轮退回「按本地记录判断」并提示「远端校验暂不可用」。

**F38.4 可见性**：设置页/传输页显示「远端已存在跳过 N 项」；提供手动入口「重新核对远端」（重新扫描一次）。

**F38.5 安全**：只读取当前账号有权限的磁盘列表；文件名不写日志；请求走既有加密通道。

### 3.4 F39 相册备份扫描健壮性（#12）

**F39.1 单资源隔离**：`asset.file`、`length()`、`submitUpload`、`markFailed` 全部纳入单资源 `try/catch`；一个资源失败**不得**中止整轮扫描。

**F39.2 失败可见**：失败项写入 `reason`，界面显示「失败 N 项」并可展开查看中文原因（如「文件不可用（可能仅在云端）」「读取失败」）；`reason` 不得含完整路径。

**F39.3 重试策略**：失败项每轮最多 1 次自动重试、累计 3 次后暂停自动重试；「立即检查」与「重试失败项」均可手动解锁；失败原因区分「永久不可用」与「暂时失败」。

**F39.4 游标推进**：扫描不再固定从 offset 0 扫到 2000；采用「从 0 开始、按页推进、跨轮续扫」的游标，保证超过 2000 张的相册最终全部访问到，且不会因某段已全部备份而反复空转。

**F39.5 计数自洽**：`已备份 + 失败 + 不在范围（视频开关关闭/不支持类型） = 相册总数`；「待备份」= 总数 − 已备份 − 失败 − 不在范围；四类数字均在界面可见。

**F39.6 单测**：相册备份当前 0 用例；本版至少覆盖「坏资源隔离」「视频关闭计数」「>2000 游标」「远端跳过」。

### 3.5 F40 Linux 媒体浮层子窗口化（#10）

**F40.1 结构**：媒体浮层从「独立顶层窗口」改为**主窗的子窗口/子表面**（native child，坐标相对父窗），随主窗移动/缩放自动跟随；不再依赖全局坐标反算。

**F40.2 兼容**：Windows / X11 行为不得回归；若某平台不支持子窗口嵌入，必须**回退到 v1.8.1 行为**并记日志，不得出现无法播放/无法关闭。

**F40.3 层级**：浮层不得被主窗内容盖住；主窗激活、点击、切换页面后仍保持在页面预留区域之上。

**F40.4 安全**：仍由 Python 侧解码、`StreamProxy` 解密；渲染层不接触媒体字节与密钥（宪法 §9.6 不变）。

**F40.5 实机验收（强制）**：Wayland（`kwin_wayland --virtual`）与 X11（Xvnc + kwin）**双会话**各跑一遍拖动/缩放/全屏/托盘恢复；录制 8s 并抽帧判定。

### 3.6 F41 随版小项（v1.8.1 候选台账 C1/C2/C3）

- **C1**：`GET /api/v1/virtual-disks/server-dirs` 响应新增 `limit`（与 `SERVER_DIR_LIMIT` 同源）；桌面 / Web / 移动选择器文案用 `limit` 渲染，缺省回落 2000。
- **C2**：移动端分析轮询改为退避（2.5s → 5s → 10s → 15s，上限 30s）+ 新建页提供「重试分析」按钮；连续失败给出可操作提示。
- **C3**：Phase 2 修订 `文档记录/设计文档/v1.8.1.md` §4.1（成功任务也渲染满进度条），使设计与实现一致。

## 4. 非功能需求（体验层面）

| 项 | 要求 |
|---|---|
| 解析时延 | 默认 90s 预算；正常站点不因预算增大而变慢（仍按实际返回） |
| 下载合并 | 合并为 `-c copy`，1GB 视频合并额外耗时 ≤10s（不含下载） |
| 相册扫描 | 单轮不因 1 个坏资源中断；1639 张规模下每轮推进可见 |
| 远端校验 | 同一轮每个目录最多 1 次列表请求；失败不阻塞备份 |
| 窗口跟随 | 拖动 200px 时浮层与预留区域偏差 ≤1px；无可见黑帧 |
| 隐私 | 相册文件名、URL、路径不进日志；远端校验只读自己的磁盘 |
| 兼容 | Android 10+；Linux Wayland/X11；Windows 不回归 |

## 5. 交互流程

### 5.1 离线下载（合并）

1. 粘贴 URL → 分析 → 清单（视频项显示清晰度；无音轨项标注「无音轨」）。
2. 勾选 → 开始 → 下载主轨（进度）→ 下载音轨（进度合并计入）→ ffmpeg 合并 → `ffprobe` 校验 → 落盘。
3. 任一环节失败 → 任务/该项失败，中文原因 + 「重试」；`url_expired` 自动重分析一次。

### 5.2 管理端超时

1. 管理员进入「系统设置 → 离线下载」→ 见三项当前值 → 修改 → 保存（范围校验）。
2. 三端 `get_meta` 在 2.5s 内反映新值；后续分析按新预算执行。
3. 非管理员：页面不显示该组；直接调接口 403。

### 5.3 相册备份（重装 / 卡住）

1. 开启备份 → 扫描 → 每个目录先取远端列表 → 同名同大小跳过（计数「远端已存在跳过 N」）。
2. 坏资源：记失败并继续；界面「失败 1 项 · 查看原因」。
3. 「立即检查」：推进游标并重试可重试失败项；「重试失败项」：清失败标记后重扫。
4. 计数区展示：总数 / 已备份 / 上传中 / 失败 / 不在范围 / 远端已存在跳过。

### 5.4 Linux 播放跟随

1. 打开视频预览 → 浮层出现在页面预留区域。
2. 拖动主窗 → 浮层同步移动；缩放 → 尺寸同步；全屏 → 铺满；关窗到托盘 → 隐藏；恢复 → 回到原区域。

## 6. 关键决策与最终裁决

| 决策点 | 最终结论 | 推翻过程摘要 | 原因 |
|---|---|---|---|
| 版本号与范围 | **1.8.2；5 个 issue 全做** | 用户 2026-10-24 裁决 | 都是 v1.8.1 实测暴露的可用性问题 |
| #9 合并实现层 | **下载器内 mux，不改库** | 曾考虑加 `aux_protocol` 列 | `aux_url` 已存在；协议按后缀推断足够 |
| #9 合并失败 | **失败可重试，不静默产出无声文件** | 曾考虑保留视频+标记 | 用户诉求是「能听」，无声文件=不可用 |
| #11 超时 | **管理员可配 + 默认调大** | 推荐方案原是仅调大常量 | 用户明确选择可配，覆盖慢站差异 |
| #11 部分结果 | **超时保留已抓到项** | 现状全丢 | 设计 §2.3.3 已要求，属回归修复 |
| #8 去重 | **远端目录比对** | 曾评估服务端记录表 | 避免 DDL 与隐私面扩大；列表接口已具备 |
| #12 失败策略 | **可见 + 有限自动重试 + 手动解锁** | 曾考虑失败即永久跳过 | 需区分永久/暂时，且用户要「知道卡在哪」 |
| #10 结构 | **子窗口嵌入** | 曾评估 xcb 兼容模式 / 渲染层 MSE | xcb 丢中文输入法；MSE 违反安全宪法 |
| 台账 | **C1/C2/C3 随版，C4/C5/C6 顺延** | — | 小改动且与本次验证相关 |

### 6.1 硬不变量

1. **I-1**：不新增加密算法/KDF；所有网络仍走既有加密信封与 `StreamProxy`。
2. **I-2**：渲染层不接触媒体字节、密钥、token；桌面媒体仍由 Python 解码。
3. **I-3**：离线下载任务、相册记录仍按账号隔离；远端校验只读自己有权限的磁盘。
4. **I-4**：新增配置项仅管理员可写；非管理员 403；日志不记录 URL/路径/文件名。
5. **I-5**：超时配置非法值一律夹到边界并回落默认，不得让配置把服务拖死（单次分析 ≤180s）。
6. **I-6**：失败不得静默：任何被跳过的资源/项都必须有可见计数与原因。
7. **I-7**：v1.8.1 的进度条「success 一律 100%」口径不变。

## 7. 验收标准（AC-271 ~ AC-300）

### 7.1 离线下载合并（#9）

## 8. 安全宪法对齐（`AGENTS.md §9`）

| 条款 | 本版落点 |
|---|---|
| §9.1 加密信封 | 新增配置读写、远端列表读取全部走既有加密通道；`server-dirs` 仅加字段 |

| §9.5 加密原语 | 不新增算法；ffmpeg 只吃本地文件，`-protocol_whitelist file,crypto` |
| §9.6 角色约束 | 桌面媒体仍 Python 解码；渲染层无网络出口；移动 token 不进日志 |
