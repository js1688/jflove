# JFLove v1.9.1 需求文档（体验修正）

> 版本：v1.9.1　类型：产品体验修正（承接 v1.9.0 上线后的用户反馈）
> 决策来源：用户 2026-11-10 对话裁决（逐条已确认）

## 1. 背景

v1.9.0 上线后暴露两处体验问题：

1. App「系统设置 → 离线媒体修复」说明文案仍写着「v1.4.2 起…」，与桌面端 / Web 端口径不一致
   （根因：v1.5.0 卡片迁移时照抄旧文案、合并时按文件裁决丢了修复，见对话取证）。
2. v1.9.0 新增的「存储与临时文件」卡片一次性暴露 8 个参数（客户端类型白名单、孤儿保留期、
   会话上限、合并/分片并发、弱服务端模式预设），管理员难以判断哪个真正控制清理。

## 2. 范围与决策

| 项 | 决策 |
| --- | --- |
| 改动范围 | 后端 + App + 桌面端 + Web 端 |
| 保留字段 | 自动清理总开关 / 临时文件期限 / 清理检查间隔 / 立即清理 |
| 删除字段 | 客户端类型白名单、孤儿保留期、每用户会话上限、合并并发、分片并发、弱服务端模式按钮 |
| 删除字段行为 | 固定服务端默认值：全部客户端类型、会话上限 8、合并并发 1、分片并发 2、孤儿期 = 临时文件期限 |
| 手动清理 | 不受「自动清理」总开关限制（总开关只管定时任务） |
| 文案口径 | App 对齐桌面端 / Web 端，UI 文案不出现版本号字面量 |

## 3. 验收标准

- AC-1：App「离线媒体修复」说明不含 `vX.Y.Z 起` 形式版本号，且含「配置存于服务端、三端共享，修改后立即生效」。
- AC-2：三端「存储与临时文件」只展示 3 项 + 「立即清理」；已删除参数在 DOM/组件树中不存在。
- AC-3：关闭自动清理后调用 `POST /api/v1/config/cleanup` 仍执行清理（`enabled=true` 且返回统计）；
  定时任务入口 `run_auto_cleanup` 在开关关闭时返回 `enabled=false` 且统计全 0。
- AC-4：写入 v1.9.0 遗留配置键（客户端类型 / 孤儿期 / 会话上限 / 合并 / 分片并发）不再影响运行时行为。
- AC-5：后端 `flake8` 0 警告、`pytest` 全通过；App `dart analyze` 0 错误、`flutter test` 全通过；
  Web `npm run lint` 0 警告、`npm run test` 全通过；桌面端 `vitest run` 全通过。
