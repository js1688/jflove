# JFLove v1.5.0 需求文档

> 状态：**草稿**（待用户确认后定稿）
> 版本类型：**体验改版 + 能力补齐**（视觉设计系统统一 + Mermaid 图表能力）
> 模块范围：**jflove-web、jflove-desktop、jflove-app 三端**；**jflove-server 不涉及**（用户 2026-07-14 确认）

## 0. 背景说明

用户实际使用后反馈：**「各端 UI 有点太丑了，不够现代化审美」**，并明确提出 **「MD 文档要支持 Mermaid 的预览图」**。

调研三端现状后确认，问题不是「颜色不好看」，而是**缺一套设计系统**：

1. **三端三套视觉语言，互不相干**：Web 端用 `indigo`、桌面端用 Fluent 默认蓝、移动端用 `#1565C0` 蓝——同一个产品在三端看起来像三个产品。
2. **没有设计令牌**：Web 端没有 Tailwind 配置（v4 用 CSS 配置，该项目连配置文件都没有）；桌面端全项目 **0 处样式表、0 处自定义颜色**；移动端主题文件只有 20 行、只给了一个种子色。
3. **视觉层次缺失**：桌面端全项目 **0 处阴影、0 处圆角声明、0 处动效**；Web 端卡片只有一根灰边框，没有层级；移动端把 `Colors.blue.shade100` 之类的硬编码颜色散落了 20 多处。
4. **图标语言不统一**：Web 端**全部用 emoji 当图标**（📁📝🔄 做导航、📭 做空状态），在不同操作系统上渲染出的形状/颜色都不一样，这是「廉价感」的最大来源；桌面端却用的是正规矢量图标（FluentIcon）；移动端用系统图标。三端三种做法。
5. **没有暗色模式**：Web 端完全没有；桌面端只有跟随系统、且 Markdown 预览区永远硬编码白底；移动端有跟随系统但无自定义。
6. **Mermaid 图表三端都不可用**：Web 端把 mermaid 库写进了依赖（3.4MB）却**一行都没用**；桌面端遇到图表块降级成一段源码文字；移动端完全无支持。用户在笔记里画不了图，画了也看不见。

用户决策（2026-07-14 确认）：

- 本次版本**只做三端改版，不动后端**；
- 三端**都要做到效果图的漂亮程度**（效果图见 `设计预览/out/`，设计方案见 `设计预览/README.md`）；
- Mermaid 三端均采用**客户端渲染**方案，其中桌面端启用 WebEngine 渲染（用户接受 Linux 平台风险）。

## 1. 项目概述

### 1.1 目标

1. **建立一套跨端统一的设计语言**：三端从同一份设计令牌派生颜色、圆角、阴影、间距、字体与动效，使同一页面在三端能被一眼认出是同一个产品。
2. **三端观感达到效果图水准**：完成令牌层、组件层、布局层的替换，消除 emoji 图标、硬编码颜色、缺失的视觉层次。
3. **三端支持亮/暗主题**：跟随系统 + 手动切换，切换即时生效、无闪烁。
4. **三端支持 Markdown 内 Mermaid 图表渲染**：笔记与文件预览中的图表代码块渲染为真正的矢量图形，并支持缩放、全屏、导出与错误降级。

### 1.2 核心原则

- **不改后端、不改加密协议**：本次不新增接口、不变更加密信封策略，`AGENTS.md §9` 安全宪法完全沿用。
- **不改变功能语义**：本次是「换皮 + 补图表能力」，不改动任何已有业务的交互结果（修复流程、同步语义、权限判定、加密流程全部保持）。唯一的信息架构调整是移动端底部导航（见 2.5）。
- **令牌是唯一真相**：三端不允许再出现硬编码颜色值；所有颜色/圆角/间距/字号必须引用令牌。
- **效果图为验收基准**：`设计预览/out/` 下的 11 张效果图即视觉验收标准。
- **图表失败必须局部降级**：单张图语法错误只影响那一张，不报错、不白屏、不影响文档其余内容。
- **性能不倒退**：页面首屏、列表滚动、编辑器输入不得因改版变慢。

## 2. 功能需求

### 2.1 设计系统落地（三端）

| 功能 | 说明 |
|------|------|
| 统一品牌色 | 三端统一为品牌紫靛渐变（主色 `#6366F1`，渐变 `#6366F1 → #8B5CF6 → #A855F7`），替换 Web 的 `indigo`、桌面端的 Fluent 默认蓝、移动端的 `#1565C0` |
| 渐变克制使用 | 渐变仅用于「品牌时刻」：应用标识、主操作按钮、激活指示条、进度填充。正文与大面积底色一律中性色 |
| 中性色阶统一 | 三端共用同一套中性色阶（画布 / 卡片 / 内嵌区三级表面），页面底色由冷灰改为带蓝的浅灰，消除「发灰发脏」感 |
| 三级表面 + 五级阴影 | 用「画布 / 卡片 / 内嵌」三级表面加 5 级轻阴影表达层级，替代当前「靠粗边框区分」的做法 |
| 语义色统一 | 成功 / 警告 / 危险 / 信息四类语义色三端取同一色值，用于状态徽标、同步状态、错误提示 |
| 圆角体系统一 | 三端统一圆角阶梯：小控件 8、卡片与图块 12、弹层与模态 16、徽标与头像全圆。消除同一类元素在不同页面圆角不一致的现象 |
| 间距 4pt 栅格 | 三端统一间距阶梯，页面内边距、卡片内边距、元素间隙取值一致 |
| 字体统一 | 三端统一正文字体（中文回退到各平台系统字体）与等宽字体；数字统一等宽对齐（文件大小、进度百分比、时间戳对齐） |
| 动效统一 | 三端统一动效时长与缓动曲线；悬停、展开、开关、弹层有一致的节奏。消除桌面端「0 动效」的僵硬感 |
| 亮暗主题 | 三端均支持「跟随系统 / 亮 / 暗」三态，且都有应用内切换入口；切换即时生效、无闪烁、无需重启 |
| 禁止硬编码 | 三端源码中不允许再出现直接写死的颜色值（十六进制/颜色常量），全部改走令牌；由代码审查逐条核查 |

**用例**：用户白天在 Web 端用亮色写笔记，晚上切到暗色继续；打开桌面端（跟随系统，系统已切暗色）看到同样的暗色视觉；在手机上三端配色、圆角、按钮形态一致，能明显看出是同一个产品。

**AC-1**：三端主色、圆角阶梯、间距阶梯、字体栈完全一致；同一功能页面（如文件列表）在三端视觉语言可辨识为同一产品。
**AC-2**：三端均提供「跟随系统 / 亮 / 暗」三态切换入口，切换即时生效、无白屏闪烁；桌面端 Markdown 预览区随主题变化（不再固定白底）。
**AC-3**：代码审查确认三端源码无硬编码颜色值残留（令牌引用率 100%）。
**AC-4**：卡片、按钮、输入框具备一致的悬停/聚焦/激活反馈（含阴影与过渡），消除「平面无层次」。

### 2.2 组件与布局改版（三端）

| 功能 | 说明 |
|------|------|
| 图标全面矢量化 | Web 端**移除全部 emoji 图标**，改为统一风格的矢量线性图标；三端图标几何语言一致（线宽、圆角端点、视觉重量）。emoji 仅允许保留在正文文本内容里 |
| 导航改版（Web PC） | 侧边栏分区（主功能 / 管理 / 底部固定）、激活项带指示条与浅色底、支持图标态折叠、底部增加存储占用卡与用户卡 |
| 导航改版（桌面端） | 保留现有 Fluent 导航骨架，补齐激活态样式、命令栏、面包屑层级；数据列表（文件树/表格）从「裸控件」改为带图标、状态徽标、悬停高亮的定制行 |
| 导航改版（移动端） | 见 2.5（底部导航结构调整） |
| 统一组件库 | 三端各自补齐统一组件：按钮（主/次/幽灵/危险/图标）、卡片、输入框、开关、徽标、进度条/进度环、标签页、空状态、加载态（骨架屏）、Toast、确认弹窗 |
| 统一空状态 | 三端空状态用统一的插画式图标 + 标题 + 说明 + 行动按钮，替换当前 emoji（📭）与手写居中文字 |
| 统一加载态 | 列表/卡片用骨架屏替代转圈；消除「同一产品里有的转圈、有的骨架、有的空白」的混乱 |
| 统一错误态 | 三端统一错误展示组件（图标 + 说明 + 重试按钮），替换当前各页面各写各的「加载失败: xxx」纯文本 |
| 统计概览层 | 文件管理页增加概览统计（文件总数 / 已用空间 / 同步目录 / 传输任务），用带图标的统计卡呈现 |
| 文件类型色系 | 文件夹/文档/图片/视频/压缩包等文件类型使用统一的图标 + 色彩标识，三端一致 |
| 拖拽上传反馈 | 文件管理页提供拖拽上传提示区（虚线上传框 + 加密/分片说明） |

**用例**：用户打开 Web 端文件管理页，首先看到统计概览卡，下方是文件列表，每行有类型图标色块、大小、修改时间、同步状态徽标；切到桌面端，同样的信息结构与视觉语言；手机上信息被压缩但风格延续。

**AC-5**：三端源码中不再有 emoji 充当控件图标（导航项、按钮、空状态、状态标签全部矢量化）。
**AC-6**：三端空状态、加载态、错误态均有统一组件，且三端表现一致。
**AC-7**：文件管理页具备统计概览层、文件类型色系图标、状态徽标、拖拽上传反馈区。

### 2.3 Mermaid 图表渲染（三端，本次核心新增能力）

| 功能 | 说明 |
|------|------|
| 图表代码块识别 | Markdown 中语言标记为 `mermaid` 的代码块被识别为图表块，不再当普通代码展示 |
| 真图渲染 | 图表块渲染为矢量图形，而非源码文本；笔记预览与文件预览两处都要生效 |
| 支持图表类型 | 至少支持：流程图（flowchart）、时序图（sequence）、状态图（state）、类图（class）、甘特图（gantt）、饼图（pie）、ER 图 |
| 图块外壳 | 图表统一包在「图块」容器里：顶部显示图表类型标识与操作按钮，中部为画布，底部为缩放控件与渲染信息 |
| 缩放 | 支持 50%–400% 缩放，并有「适配宽度」与「重置为 100%」；移动端支持双指缩放 |
| 全屏查看 | 支持全屏查看大图，可拖动平移、滚轮/手势缩放，Esc 退出 |
| 导出 | 支持导出 SVG（矢量，任意倍率不失真）；可选导出 PNG |
| 复制源码 | 一键复制该图表的 Mermaid 源码到剪贴板 |
| 主题跟随 | 图表配色随应用亮暗主题变化（**必须重新渲染，不能靠 CSS 反转**；暗色模式下图表文字与连线需保证可读） |
| 懒加载 | 文档中的图表仅在滚动进入视口时才渲染，避免一页多图同时渲染造成卡顿 |
| 本地缓存 | 已渲染的图表按「源码 + 主题」缓存，同一图表在会话内二次出现不重复渲染；离线状态下已缓存图表仍可显示 |
| 定位回跳 | 图表块提供「跳到源码」入口，从预览区点击可回到编辑器中该图表源码位置 |
| 语法错误降级 | 图表语法错误时**只降级该图块**：显示错误卡片（错误原因 + 出错行号 + 源码 + 「跳到源码」按钮），文档其余内容正常渲染，不整页报错、不白屏 |
| 渲染不可用降级 | 渲染引擎不可用（能力缺失/加载失败）时，图表块自动降级为「带复制与全屏的源码卡」，并给出说明；功能不中断 |
| 插入入口（编辑器） | 笔记编辑器的工具栏提供「插入图表」入口，选择图表类型后插入带注释的模板代码，降低手写门槛 |
| 权限/安全 | 图表渲染只做本地渲染，不发起任何网络请求、不执行图表内的脚本；禁用 HTML 标签与外链点击 |

**用例**：用户在笔记里写下 ` ```mermaid ` 时序图源码 → 预览区立即渲染出矢量图形 → 图表窄于视图时清晰可读 → 点击全屏放大查看细节 → 导出 SVG 发给同事 → 把主题切到暗色，图表配色同步变暗且文字清晰 → 不小心写错一行语法，只有那一张图变成错误卡片并标出行号，其余内容照常阅读。

**AC-8**：三端笔记预览与文件预览中，`mermaid` 代码块均渲染为矢量图形；Web 端 mermaid 依赖由「死依赖」变为实际使用。
**AC-9**：同一份含图表的笔记在三端渲染出的图表**结构与配色一致**（三端视觉一致性验收）。
**AC-10**：图表支持缩放（50%–400%）、全屏查看、导出 SVG、复制源码；移动端支持双指缩放。
**AC-11**：亮暗主题切换后，图表配色同步变化且文字/连线在暗色下清晰可读（非简单反色）。
**AC-12**：语法错误的图表只降级为该图块的错误卡片（含原因与行号，可跳到源码），文档其余内容正常渲染。
**AC-13**：一页含 10 张图表的笔记，仅视口内的图表被渲染（懒加载生效），滚动过程无可感知卡顿。
**AC-14**：渲染引擎不可用/离线时，图表降级为带复制与全屏的源码卡，不报错、不白屏。
**AC-15**：笔记编辑器提供「插入图表」入口，可选择图表类型并插入模板。

## 3. 非功能需求

### 3.1 性能（体验层面）

| 指标 | 目标 |
|------|------|
| 主题切换 | 切换即时生效（无感知延迟），不出现白屏闪烁，不触发页面重载 |
| 图表首次渲染 | 单张图表渲染在 1.5s 内完成（含渲染引擎初始化）；渲染期间显示骨架占位，不引发布局跳动 |
| 图表二次显示 | 命中缓存后即时显示（无可见等待） |
| 一页多图 | 10 张图表的笔记，滚动流畅无卡顿；同时渲染的图表数量受控（不并发渲染全部） |
| 布局稳定性 | 图表从骨架到成图的过程中，文档滚动位置不跳动 |
| 列表与编辑器 | 文件列表滚动、笔记编辑器输入不因改版变慢（无明显掉帧） |
| Web 端体积 | 不因改版显著增大；已声明的图表库应被实际使用而非空占体积 |

### 3.2 视觉与交互质量

- **对比度**：正文与背景对比度满足可读性要求，亮/暗两套主题下均达标；暗色模式图表文字不得发灰难辨。
- **一致性**：同类元素（按钮、卡片、输入框、徽标）在三端及端内各页面形态一致。
- **反馈完整**：所有可点击元素具备悬停/按下/聚焦反馈；长耗时操作有进度或骨架反馈。
- **无 emoji 控件图标**：三端控件图标统一矢量化。
- **可发现性**：图表能力有可发现的入口（编辑器插入按钮 + 图块操作按钮），不需要用户查文档才知道。

### 3.3 兼容性

- 浏览器兼容范围与 v1.4.2 一致（Chrome / Firefox / Safari / Edge 90+）。
- 桌面端主题切换需与系统主题协同（跟随系统时随系统变化实时更新）。
- 移动端保持竖屏锁定与现有路由结构（除底部导航结构调整外，页面路径不变）。
- 移动端图表渲染能力需在 Android 首版可用（iOS/鸿蒙保持预留）。

### 3.4 稳定性与降级

- 图表渲染引擎初始化失败、异常、超时，均不影响页面其他内容。
- 任何单个图表异常不得导致整篇文档渲染失败。
- 桌面端渲染引擎异常需能恢复（不残留异常状态、不导致应用崩溃）。

### 3.5 安全性

- 严格遵循 `AGENTS.md §9`：本次**不新增接口、不变更加密信封策略、不新增明文白名单**。
- 图表渲染为纯本地渲染，不得发起网络请求、不得执行图表源码中的脚本；禁用 HTML 标签与外链点击。
- 预览渲染（含图表）仍须做 XSS 清洗，不允许图表能力成为新的注入面。
- 渲染引擎启用的资源占用需可释放（页面/预览关闭后不长期驻留）。
