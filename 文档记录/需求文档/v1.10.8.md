# v1.10.8 需求：桌面端终端底座可用性修复

> 角色：product　日期：2026-11-15　版本：v1.10.8
> 来源：用户在使用 v1.10.7 桌面端（Linux / Fedora）后的实测反馈
> 关联：`文档记录/桌面端开发记录/v1.10.8.md`、`plans/desktop-terminal-base-v1.10.8.md`

## 1. 背景

v1.10.0 交付的「远程连接 / 本机终端」用的是 xterm.js + Python PTY，功能在，
但底座存在两类问题：**跑全屏 TUI 会卡死**、**多标签/多页面往返会丢画面**。
用户明确要求"彻底改造技术底座"，并强调实机验证要覆盖复杂命令、英文与中文输入。

## 2. 用户可见问题（原始描述 → 归类）

| 编号 | 用户描述 | 归类 |
| --- | --- | --- |
| U1 | 桌面端 Linux 输入 `dsh cli` 后进入终端型智能体对话，**无法输入文字、像卡住** | 代码缺陷（渲染层卡死） |
| U2 | 终端面板观感差 | 体验 |
| U3 | 多个标签来回切换，切回本机终端标签后**面板空白没有文字** | 代码缺陷（生命周期） |
| U4 | 希望实机验证复杂命令、英文/中文输入，不要交付后才发现问题 | 质量要求 |

## 3. 范围

**做**：桌面端终端底座（本机终端 + SSH 终端共用组件）的可用性、生命周期、观感、验证工具。
**不做**：Web 端、App 端终端；SSH/SFTP 协议层；终端回放（跨渲染进程恢复）——后者按 §4 AC-8 明确不承诺。

## 4. 验收标准

| 编号 | 验收标准 | 判定方式 |
| --- | --- | --- |
| AC-1 | 本机终端能正常运行全屏 TUI（dsh TUI / vim），键入字符在 TUI 内可见 | 实机 CDP 用例（截图 + xterm 缓冲区断言） |
| AC-2 | 中文经输入法提交后能进入 shell / TUI，回显正确 | IME composition 注入 + 缓冲区断言 |
| AC-3 | 多标签切换、列表页与会话页往返后，画面与通道都保持（不重建、不清空） | 双标签 + 路由往返用例 |
| AC-4 | 终端配色/能力正常：`TERM` 不为 `dumb`，TUI 有颜色 | 状态栏与截图；`stty`/环境断言 |
| AC-5 | `Ctrl+C` 能中断前台进程（存在控制终端） | `sleep 30` + Ctrl+C 出现 `^C` |
| AC-6 | 复制/粘贴可用（含中文），失败时给出可操作提示 | 选中→复制→粘贴用例 + 空剪贴板提示 |
| AC-7 | 窗口尺寸变化后，PTY 行列数与状态栏一致 | 视口缩放 + 状态栏行列断言 |
| AC-8 | 面板观感重做（标签栏 / 工具条 / 终端卡片 / 状态栏），字号可调 | 截图评审 |
| AC-9 | 大输出（`seq 1 2000`）不丢尾、不卡 | 尾部断言 |
| AC-10 | 上述验证脚本入库、可复跑；打包产物上同样通过 | `scripts/verify/desktop_terminal_e2e.mjs` |

## 5. 明确不承诺

- 渲染进程整体崩溃后的终端画面恢复（不做原始输出回放，原因见开发记录 §1.2）；
- 终端内 `tmux`/`screen` 级别的会话保持（会话在 Python 侧存活，但 App 退出即结束）。
