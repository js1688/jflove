## 3. 严重（9）

### S-1 · [严重] `_safe_join` 的前缀判据可被"同名前缀兄弟目录"绕过（基线既有，本版结项结论有误）

- **位置**：`jflove-server/src/services/file_service.py:106`（`if not str(target).startswith(str(base_path))`）；**同名缺陷另有一份实现** `jflove-server/src/services/sync_service.py:26-39`（`:37` 同一写法）。
- **判据**：设计 §9.1.10 / 安全宪法要求"路径越界一律拒绝"；正确判据应为 `os.path.commonpath` 或 `base + os.sep` 前缀。
- **证据（主对话独立复现）**：
  ```
  >>> _safe_join(r'D:\disks\alice', '../alice2/evil.txt')
  'D:\\disks\\alice2\\evil.txt'                     # 越界放行
  >>> _safe_join(r'D:\disks\alice', '../bob/evil.txt')
  PermissionError: 非法路径访问                     # 对照：不同前缀被拦
  >>> os.path.commonpath([r'D:\disks\alice2\evil.txt', r'D:\disks\alice'])
  'D:\\disks'
  ```
- **影响**：只要基目录存在同名前缀的兄弟目录（`alice` / `alice2` 这种命名在"每用户一个磁盘目录"下很常见），即可读写/删除/重命名该兄弟目录内文件。受影响端点参见 S-2。
- **建议**：抽 `src/utils/path_safety.py` 单一实现（顺带消除 DRY 违反），判据改 `os.path.commonpath([target, base]) == str(base)`，并新增"同名前缀兄弟目录"回归用例。

### S-2 · [严重] `_validate_filename` 只覆盖 `init_upload` 一处，"第二层兜底"对 8 个端点不存在

- **位置**：定义 `file_service.py:115`，**唯一调用** `file_service.py:283`（`init_upload` 内）；`get_stream_range:703`、`download_file:462`、`delete_file:490`、`preview:549`、`rename:591/600`、`move:640-641`、`list:226`、`make_dir:522` 均**只经** `_safe_join`。
- **证据（主对话）**：`grep -rn "_validate_filename" jflove-server` ⇒ 定义 1 处 + 调用 1 处 + 用例若干。
- **影响**：BL-10 的两层防御实际只在"上传初始化"路径成立；其余端点的文件名/路径直取客户端（`file_controller.py:580-581,610-613` 把 `filename` 直接交给 `get_stream_range`），其唯一边界就是 S-1 那条可绕判定。
- **建议**：把文件名/路径的**统一规范化 + 校验**下沉到 `_safe_join` 的调用点或封装 `resolve_within_base(base, rel, *, filename=None)`；并在**计划文件 §17.8 更正**"过了 `_safe_join` ⇒ 不可穿越"这一错误结论。

### S-3 · [严重] 渲染层与桥的暴露面与文档来源无关，外壳无任何导航策略

- **位置**：`jflove-desktop/src/ui/web_shell.py:426-432`（`view.page().setWebChannel(self.channel)`）、`:540-556`（`DocumentCreation` + `MainWorld` 注入 `qwebchannel.js`）；全仓 `src/` grep `acceptNavigationRequest|createWindow|newWindowRequested` = **0 命中**。
- **证据（主对话新增探针 `jflove-desktop/poc/editor-probes/r7-webengine-channel-origin.py`，产物 `out/r7-offscreen.json`，Qt 6.11.0 + offscreen，按外壳原样接线）**：
  - T1 `file://` 页命中桥（对照成立）：`bridge_calls=['origin=file:// scheme=file: tag=T1-file']`
  - **T2 `http://127.0.0.1:56321` 页命中桥**：`['origin=http://127.0.0.1:56321 scheme=http: tag=T2-http']`
  - **T3 `file://` 页 `location.href=<http>` 顶层导航真的发生**：`nav=True`
  - T4 `<a target="_blank">` 点击：`new_window=False`、`same_view_navigated=False`（Qt 默认丢弃）
- **影响**：本版桥包含 `editor.writeText` / `readTextOnly` / `detectAndRead`（`src/bridge/editor.py:333/283/305`）＝**任意路径本地文件读写**。`LocalContentCanAccessRemoteUrls=False` 只约束子资源/fetch，**不约束顶层导航**。安全宪法 §9.6「渲染层无网络出口 + 只加载自家产物」的安全前提**仅靠 Qt 默认行为、未固化**；一旦页面被导航到任意远端（或未来引入其它导航入口），远端文档即拿到文件读写能力。
- **建议**（三处小改，均为加固、无功能代价）：
  1. 覆写 `QWebEnginePage.acceptNavigationRequest`：只放行自家产物目录（`ui/dist`）与 `about:blank`，其余 `False`；
  2. `createWindow` 显式 `return None`；
  3. 外链统一交 `QDesktopServices.openUrl`（顺带解决 L-1：现在点外链毫无反应）。

### S-4 · [严重] AC-46② 未实现：单实例转交路径不恢复窗口可见
