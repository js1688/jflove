## 一、总体结论

设计令牌层、组件层、三端导航收敛与「图表渲染链路」四件事**都真实落地了**，不是纸面交付：三端令牌取值逐值对齐、mermaid 离线包三端同一份（sha256 一致）、主题切换确实触发图表重渲染、单图失败只降级本图块、没有任何新增接口或加密改动——`AGENTS.md §9` 的**通信/密钥/鉴权/原语四条硬规则全部合规，无一违反**。

但本次审查**实测发现 2 个严重问题**，都出在「图 → 屏幕」的最后一步，且都指向同一个技术根因（mermaid 11.16.0 在 `securityLevel:'strict'` 下把 flowchart / state / class / ER 的**节点标签**放进 `<foreignObject>`）：

1. **Web 端**：`sanitizeSvg` 无条件删除 `<foreignObject>` → 节点文字被删掉，最常用的流程图变成「空框连线图」；
2. **桌面端**：`QSvgRenderer`（文档内嵌位图 + 全屏查看器）**直接丢弃** `<foreignObject>` → 同样丢字。

> 讽刺的是：设计文档 §4.3.1 判定「方案 A：`QSvgRenderer` 直接渲染」不可行的**唯一理由**就是这条，实现却仍然在文档与查看器两处用了 `QSvgRenderer` 光栅化。
> 附带说明：设计文档/计划里对这条实测的**方向写反了**（写成「边标签在 foreignObject 内，`htmlLabels:false` 只救回节点标签」）；本次用**三端实际发货的那份 bundle** 复测，结论恰好相反（节点标签在 foreignObject，边标签是 `<text>`），详见 §五 S-1/S-2 的复现命令与输出。

此外有 12 个中等问题（AC-16 桌面图片仍未显示、三端代码块能力不齐、懒加载只在 Web 实现、移动端每图一个 WebView、令牌化残留等）与 11 个轻微问题。

**结论：不通过**，S-1 / S-2 必须修复并复验后才能进入 Phase 6（详见 §九）。

### 🔴 严重（必须修复）

#### S-1｜Web 端流程图等图表的**节点文字被清洗掉**，只剩空框与连线

- **现象**：`sanitizeSvg`（`jflove-web/src/utils/mermaid/sanitize.ts:40`）无条件删除 `<foreignObject>…</foreignObject>`，而 mermaid 11.16.0 在 `securityLevel:'strict'` + `flowchart.htmlLabels:false` 下，flowchart/state/class/ER 的**节点标签就放在 `<foreignObject>` 里**（边标签才是 `<text>`）。清洗后节点文字整段消失。
- **证据（实测，可复现）**：用**三端实际发货的那份 bundle**（`jflove-web/public/vendor/mermaid.bundle.js`，sha256 `be4d8fbd…`）在无头 Edge 中按 Web 端**逐字相同的配置**渲染 flowchart，并套用 `sanitize.ts` 的同一套正则：

  ```
  # 探针页（临时目录，未写入仓库）：window.mermaid 来自 public/vendor/mermaid.bundle.js
  # 配置：securityLevel:'strict', theme:'base', flowchart:{curve:'basis',useMaxWidth:true,padding:12,htmlLabels:false}
  msedge --headless=new --virtual-time-budget=12000 --dump-dom file:///…/jf-mmd-probe2.html
  → {"raw":{"labelClient":true,"labelEncrypted":true,"labelRehandshake":true,"labelSession":true,
            "foreignObject":4,"textNodes":3,"len":14948},
     "sanitized":{"labelClient":false,"labelEncrypted":false,"labelRehandshake":false,"labelSession":false,
            "foreignObject":0,"textNodes":3,"len":13900}}
  ```

  即：原始 SVG 里 4 个节点文字各出现 1 次且**全部位于 `<foreignObject>` 内**；清洗后 4 个字符串**全部不再出现**，只剩 3 个 `<text>`（边标签 yes/no）。逐类统计（同一 bundle、同一配置）：

  ```
  flow_web_cfg : fo=4  text=3   nodeLabel=4   （flowchart → 节点文字被删）
  state_web_cfg: fo=2  text=3   nodeLabel=4   （stateDiagram-v2 → 节点文字被删）
  class_web_cfg: fo=3  text=1   nodeLabel=5   （classDiagram → 节点文字被删）
  er_web_cfg   : fo=2  text=1   nodeLabel=2   （erDiagram → 实体名被删）
  seq/gantt/pie: fo=0                        （不受影响）
  ```
- **影响**：Web 端**最常用的流程图/状态图/类图/ER 图渲染成「只有框和箭头、没有文字」的图**；`MermaidViewer`（全屏）与「导出 SVG」都走同一个清洗函数（`MermaidBlock.tsx:102,121,225`），因此缺陷同时扩散到全屏与导出文件。AC-8 / AC-9 / AC-11（暗色可读）视觉验收不成立，且单测 `tests/utils/mermaid.test.ts:114-124` 恰好把这条行为**锁死**成期望值，缺陷不会被现有测试发现。
- **修复建议**（任选其一，建议 a）：
  a) 清洗时**不做整体删除**，改为「保留 `<foreignObject>` 但剥离其内容里的可执行构造」——把 FO 内的 `xhtml:div/span` 结构保留（mermaid 自己会做 `initialize` 级清洗），只删 `<script>`/`on*`/危险协议；或把 FO 内容转成 `<text>`（保留文字，去掉 HTML 语义）。
  b) 与桌面端统一：不改 SVG，改为在**受控容器**里渲染（`securityLevel:'strict'` 已禁 HTML 标签与 `javascript:` 链接，mermaid 输出本身即受控），仅过滤 `<script>`/`on*`/外部 `href`。
  c) 若坚持删 FO：则必须让 mermaid 输出 `<text>` 标签（实测 `htmlLabels:false` 达不到，需在页面内渲染后做 DOM→`<text>` 后处理），并把 `tests/utils/mermaid.test.ts` 的断言改为「节点文字必须保留」。

#### S-2｜桌面端文档内图表与全屏查看器**同样丢字**（`QSvgRenderer` 丢弃 `<foreignObject>`）

- **现象**：桌面端文档内是「SVG → `QSvgRenderer` 光栅化 → `<img>` 内嵌」（`src/components/mermaid_render_service.py:139-175,440-449`，调用点 `markdown_view.py:354-360`），全屏查看器也用 `QSvgRenderer`（`src/components/diagram_viewer.py:48,95`）。`QSvgRenderer` **完全忽略** `<foreignObject>` 内容 → flowchart/state/class/ER 的节点文字在文档预览与全屏里都不显示。
- **证据（实测，可复现）**：用仓库自带 venv 的 `QSvgRenderer` 分别渲染「原始 SVG」与「删掉 foreignObject 的同一 SVG」，两图**逐字节相同**，墨迹像素差为 0：

  ```
  D:\github\jflove\jflove-desktop\venv-win\Scripts\python.exe probe_qt_fo.py flow_web_cfg_raw.svg
  （flow_web_cfg_raw.svg = 上面 S-1 探针从真实 mermaid 输出里导出的 SVG：fo=4 text=3）
  → foreignObject 元素数=4
    原始 SVG : valid=True size=504x156 ink=108793
    去FO SVG : valid=True size=504x156 ink=108793
    两图逐字节相同（=FO 内容完全未参与渲染）: True
    ink 差值 = 0
  ```
  （同样结论在 `设计预览/svg/flow-strict-hlfalse.svg` 上复现：ink 差值 0。）
- **影响**：桌面端**笔记预览/文件预览/图表查看器**三处对 flowchart 等类型都缺字（与 S-1 表现相同、根因不同）；直接违背 WBS 里「Qt 渲染 mermaid SVG 不可行」的判定，也违背 AC-9。设计文档 §4.3.1 与计划 §0.2 把这条实测的**方向写反了**（写成「边标签在 foreignObject 内」），导致实现期误以为 `htmlLabels:false` 已解决该问题——**文档需一并更正**，否则下一个版本还会踩。
- **修复建议**：
  a) 文档内位图改由**离屏页截图**产出（`QWebEngineView` 离屏 grab / 页面截图路径），而不是 `QSvgRenderer`——这与设计 D5「全屏用 WebEngine 保证矢量」一致；注意本环境无桌面窗口站，需在真机验证（属 Phase 8 冒烟项）。
  b) 或沿用离屏 `QWebEnginePage`，在页面内把 `<foreignObject>` 内的文字**转为 `<text>`** 后再 `runJavaScript` 取回 SVG（保持现有位图管线不变，改动最小）。
  c) 至少在全屏查看器（`diagram_viewer.py`）改回设计 §4.3.6 的 WebEngine 方案；同时更正设计文档/计划的错误结论。

### 2. 问题清单

#### 🟡 M-1｜文件页表头与数据行**没有真正共用一份规格**（实测：名称表头偏 70px、右侧两列偏 7px）

- **位置**：`src/ui/kit/bands.py:189-203`（`ListHeader.__init__` 的 `setContentsMargins(6 + 16, 0, 16, 0)` 与列定义）↔ `src/ui/kit/file_list.py:86-107`（`row_geometry()`）；调用处 `src/ui/pages/file_page.py:307-313`
- **冲突的规范**：`kit/bands.py:179-180` 与 `kit/file_list.py:22-24` 都写明"列定义与 `FileRowDelegate` **共用同一份规格**，否则表头与数据行会错列"；`gate` 实际未成立。**【实测】**（TEMP 只读脚本，offscreen，W=900，逐控件读 `geometry()`，输出见 §4）：

  | 列 | 表头（label） | 数据行（`row_geometry`） | 偏差 |
  | --- | --- | --- | --- |
  | 名称 | `x=22..649` | `x=92..642` | **-70px**（表头压在复选框列上方） |
  | 大小 | `right=741` | `right=734` | **+7px** |
  | 修改时间 | `left=754` | `left=747` | **+7px** |

  根因两条：① 表头**缺设计稿的 16px 复选框占位列**（`设计预览/04-desktop-pyside.html:75` 的第一个 `<span style="width:16px">`）⇒ 名称标签落在复选框列；② 表头左内边距算了行胶囊的 6px 外边距（`6+16`），右内边距只算 16px（`-16`）⇒ 右侧两列恒偏 6px（另 1px 来自 `QRect.right()` 的含端点语义）。
