## 2. 逐项审查

### 2.1 `_authenticate` 是否真的「按列表走」

| 检查项 | 结论 |
| --- | --- |
| 是否先取服务器列表 | ✅ 用 `auth_none`（RFC 4252 §5.2，OpenSSH 同款）；缺该能力时退化为按凭据猜测，且**之后一律以服务器返回为准** |
| 是否可能发送未列出方法 | ✅ 每一轮 `usable ⊆ allowed`；`_choose_method` 只在 `usable` 里选 |
| `rejected` 的处理 | ✅ 视为「该方式不被允许」：当轮从可用集合移除，且**以服务器给出的新列表为准**（即使为空也不沿用旧列表） |
| `failed`（凭据错）的处理 | ✅ paramiko 此时不回列表，沿用上一轮已知集合（协议限制，非猜测） |
| 弹框密码走哪个方法 | ✅ `_ask_password` 的返回值只用于**服务器列出的 `password` 方法**；`keyboard-interactive` 只在服务器列出时使用 |
| 无限循环 | ✅ `MAX_AUTH_ROUNDS=5` + `MAX_METHOD_ATTEMPTS`（publickey 3 / password 2 / kbd 1）+ `MAX_PASSWORD_PROMPTS=2` |
| 密钥重复发送 | ✅ 已被接受的密钥不再重发；仅在「服务器当前只列 publickey 且未试过其它因子」时才补签（旧网关二次签名） |
| 存储密码错重试 | ✅ 存储密码失败一次后不再原地重打，改由弹框重填（避免对服务器做无意义的重复认证） |

## 3. 问题清单

### 3.1 【中等】`auth_none` 依赖 paramiko 版本

`Transport.auth_none` 在 paramiko 4.0 存在；更老版本可能没有 → 已用 `getattr` 保护并退化为按凭据猜测。
判断依据：`_probe_methods` 返回空集时不阻断认证，只是失去「先看列表」的优化。✅ 可接受。

### 3.2 【轻微】存储密码失败后不再重打

用户若在配置里存了错密码，只会看到「账号密码被拒」并提示改用弹框；不会自动重试同一份。
✅ 有意为之（避免对网关做重复失败尝试，可能触发锁定）。

### 3.3 【轻微】SSH 层「没有收到输入」超时仍为 60 秒

文案已写明；后续版本可放宽。

### 3.4 【轻微】测试替身差异

部分老用例的 `_FakeTransport` 不实现 `auth_none`，走的是「猜测起始方法」路径。
已确认这些用例仍覆盖真实分支（`rejected` / `failed` / `partial`），且新增用例用真实 SSH 服务覆盖标准路径。✅ 可接受。

## 5. 与前几版的关系（避免误读）
