- **可复现**（`probe_state2.py` C/I/G 组）：


  ```python
  if self._shell_hidden:

          return

      self._shell_hidden = False
      ...
  ```
  ⚠ 注意：现有用例 `test_矩形被清空后不重新显示`（`tests/test_v151_media_overlay_lifecycle.py:223-234`）**显式断言"关窗态标志仍应被复位"**——
  它锁的是**现状行为**（L11）。若采纳本建议，这条用例的期望值必须一并**反转**，而不是删掉。

## 五、#3 状态机：`refresh_geometry()` 判定顺序逐格推演

判定顺序（`media_overlay.py:262-284`）：

```
0. if self._shell_hidden:                      # 恢复分支（最先）
     self._shell_hidden = False                # ← M-5：无条件清标志
```

## 六、隐藏期间的几何事件护栏：`not self.isVisible()` 会不会误伤正常路径？

护栏（`web_shell.py:290-295`）：

按任务书点名的三个场景逐一推演 + 实测：

1. **从托盘恢复的首帧**——我实测（`probe_state3.py` 第 1 组）：

   **恢复路径不依赖排队机制**（`showEvent` 走直接调用）⇒ 护栏**不误伤**。✅（注：这是 offscreen 实测，真机需复验 → V-10。）
2. **`showEvent` 与 `moveEvent` 的时序**：`showEvent` 走**直接调用**（`:320-330`，不受护栏约束），`moveEvent` 走排队（受护栏约束）。若平台在"窗口尚不可见"时先投递 `moveEvent`、可见后才投递 `showEvent`，那次 `moveEvent` 被丢弃，但**同一批几何变化随后由 `showEvent` 的直接刷新覆盖**；反之若 `showEvent` 先到，`isVisible()` 已为真，正常排队。两种顺序**都不会永久丢失几何**，最坏是多一次/少一次重贴合（视觉不可感知）。
3. **全屏进出**：主窗在全屏切换期间始终 `isVisible()`（全屏不是 hide）⇒ 护栏不介入；浮层几何由 `setFullScreen` 自己管（`:181-195`），且 `refresh_geometry` 在全屏时早退 ⇒ 不会把全屏浮层拉回。✅
4. **我构造过的三个反例，均不构成误伤**：
   - "主窗隐藏期间平台投递几何事件" → 护栏**故意**拦掉，这是**期望行为**（用例 + 开发记录 §6.5 负向对照 7 证明去掉护栏会红）。✅
   - "主窗可见但被其他窗口完全遮挡" → Qt `isVisible()` 不含遮挡语义，不会误拦。✅
   - "主窗最小化到任务栏（而非托盘）" → `on_shell_hidden()` 未被调用，浮层**会留在屏幕上**不与主窗一起离开。但这不在产品语义路径上（需求 §2.5 只定义"关闭 = 最小化到系统托盘"），故**不算缺陷**；建议真机清单补一条"点系统最小化按钮时的表现"（V-13）。

**结论**：护栏**不会**造成"该显示却永久不显示"的误伤；它放弃的是"隐藏期间的几何同步"，而那次同步在恢复时由 `showEvent` 直接调用补偿（我实测补偿成立）。唯一残留风险是 M-5 的"标志提前消费"，与护栏本身无关。

### R1.3 §10.1 的"意图重放"是否真的生效（任务书点名问题）

- **`setFullScreen(true)` 在关窗态记的意图**：`_fullscreen=True` 保存，恢复分支 `:308-312` 读它并 `showFullScreen()`。

- **一个语义收窄，需要口径确认**：AC-11 的"手动切换优先"现在只在**同一 filename 内**有效；用户切走再切回同一篇时，`modeResolvedForRef` 已被新 filename 覆盖 ⇒ **同一篇笔记会被重新判定一次**（回到 `preview`，手动选的 `split` 丢失）。
