## 1. 结论

**通过**：无严重、无中等问题；轻微 5 条（4 条已在实现中处理，1 条记录为已知边界，不阻塞发布）。

审查过程中发现并已修掉的 2 个问题（记录在 §5，供后续追溯）：

- 纯密码认证（无密钥）时 `diag` 只从 `_auth_diag` 生成，失败信息会丢掉远端版本/算法事实；
- `_pick_next_method` 的 docstring 写成「`publickey` 本轮还没试过才再发」，实际重发决策在
  `_continue_auth`（按 `key_accepted`），文档与代码不符。

## 2. 核心行为复核（对照根因）

| 复核点 | 代码位置 | 结论 |
| --- | --- | --- |
| 服务器给出非密钥的下一步时**绝不**回退 `ssh-rsa` 重发公钥 | `_can_retry_legacy_rsa`：`if allowed and not allowed <= {"publickey"}: return False` | 通过（用户报错①的根因已堵） |
| `rejected`（方式不被允许）不重试 | 同上首行 `if status == "rejected": return False` | 通过 |
| 已进入旧式模式不重复进入 | `getattr(transport, "_jflove_legacy_backup", None) is not None` | 通过 |
| 密钥被接受后不再重发 | `_continue_auth`：`skip_key = key_accepted and "publickey" in known and bool(other)` | 通过 |
| 服务器中途换列表时以新列表为准 | `if allowed: known = set(allowed); offered \|= allowed` | 通过 |
| 同一凭据不重复打 | `failed` 集合 + `candidates -= failed` | 通过 |
| `paramiko` 普通失败不回传 authlist 时仍能换因子 | `return allowed or failed or offered` | 通过（用户报错②的根因已堵） |
| 键盘交互无密码也可尝试 | `_pick_next_method` 去掉 `password and` 门槛 | 通过 |
| 诊断行不含凭据 | `_trace_text` 只拼方法名；`_finish_diag` 只拼 `diag` + 序列 + 服务器要求 | 通过（§9.14） |

## 4. 轻微问题与处置

| # | 问题 | 处置 |
| --- | --- | --- |
| L1 | 仍依赖 paramiko 私有属性（`_preferred_pubkeys`、`server_extensions`、`_agreed_pubkey_algorithm`、`_jflove_legacy_backup`） | 依赖已 pin `paramiko==4.0.0`；`test_remote_legacy_ssh_v1_10_14/15` 作为升级门禁（README 已写已知边界） |
| L2 | `_continue_auth` 用 `known` 每轮重建，逻辑较绕（`known` / `offered` / `failed` 三个集合） | 已用注释说明各自职责；三条用例分别钉住「换列表」「不重打」「密钥不重发」 |
| L3 | 服务器若把 `MaxAuthTries` 设得很低，多次认证往返可能被断开 | 本版**减少**往返（密钥只发一次、不重打同一凭据），风险方向已改善 |
| L4 | 真正的「两把不同私钥」网关仍不支持 | 保持明确文案，写进 README 已知边界；需服务器侧改单密钥或用跳板 |
| L5 | 无密码时 `keyboard-interactive` 会阻塞等待弹层（最长 `OTP_TIMEOUT=60s`） | 沿用既有超时；有密码时代答不弹层，不影响正常路径 |
