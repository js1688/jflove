# JFLove v1.8.4 代码审查报告

> 阶段：Phase 5（快速修复通道，`AGENTS.md §7.5.3`）｜ 版本 **1.8.4** ｜ 角色：code-review
> 审查范围：`jflove-app` 上传两段式管线（`file_hash.dart` / `transfer_service.dart`）、传输页与浮动卡片、
> 相册备份 C1/M-1/M-2（`album_backup_store.dart` / `album_backup_service.dart` / `album_backup_card.dart`）、
> `pubspec.yaml` 新增 `crypto`；服务端/桌面/Web 仅版本号同步（无业务改动）。

## 1. 总体评价

**通过（0 阻断、0 严重）**。用户反馈的「1GB+ 卡校验中」根因（无进度 / 不可中断 / 重复哈希 / 3 路并发抢 CPU）
在实现层全部消除，且没有放宽任何加密或鉴权约束：`file_hash` 协议未变、仍由服务端合并时校验，
新增的只是一次**本地** SHA256 的高效实现与缓存。

## 3. 设计与需求偏差

- **AC-282（v1.8.2）语义变更**：旧需求「换目标目录后清空失败记录」被 **C1** 取代（失败记录按目标隔离，
  换目标不清空、回到旧目标仍可重试）。已写入 `文档记录/移动端开发记录/v1.8.4.md §6`，
  下一版需求文档需回写该条。
- 传输页新增「校验中 N%」「已校验 x / y」「等待中」三态展示（原需求只描述「校验中」）。
- 队列上限（M-2）落地为「未开始传输任务 ≥ 10 时本轮不提交」，与审查建议一致。

## 4. 安全宪法核对（`AGENTS.md §9`）

| 条款 | 结论 |
|---|---|
| §9.1 加密信封 / 流式加密 | 未改动；`file_hash` 仍在加密 body 内传输，服务端 `complete_upload` 仍比对 |
| §9.2 密钥交换 / PFS | 未改动 |
| §9.3 JWT 仅加密 body / 路径参数鉴权 | 未新增接口、路由或路径参数 |
| §9.4 不暴露内容 | 新增日志仅含阶段/计数/异常类型；哈希缓存文件只存「路径 SHA256 + size + mtime + 摘要」，**不落原始路径、文件名或内容**；缓存仅存 App 私有目录，不上传 |
| §9.5 加密原语清单 | 未新增算法/模式/KDF；`crypto` 仅用于 **SHA256 完整性摘要**（与 pointycastle 同一算法、同一输出，已用已知向量与交叉比对用例锁定），ChaCha20/X25519/HKDF 全部未动 |
| §9.6 各端延伸约束 | 移动端仍只经 `http_service.dart` 与后端通信；session_key/JWT 未进日志 |

## 5. 回归风险

- 本地库 **v4 → v5** 只 `ALTER TABLE ADD COLUMN`（默认值 0/''），不重建表、不丢数据；
  失败数在升级瞬间会因目标字段为空而降为 0，`init()` 立即 `backfillFailureTarget` 认领到当前目标。
- 传输调度由「单队列 + 计数」改为「校验段 + 上传段」：下载路径不参与校验（直接进上传槽位），
  行为与原实现一致；已有 6 个管线用例 + 18 个相册用例覆盖。
- `crypto` 依赖：`pubspec.lock` 仅一行 `transitive → direct main`（镜像 `PUB_HOSTED_URL=https://pub.flutter-io.cn`）。

## 6. 结论

**允许进入 Phase 6 测试与发布**；M-1（校验并发可调）、M-2（断点续传）登记为下个版本候选。
