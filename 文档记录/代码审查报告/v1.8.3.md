# JFLove v1.8.3 代码审查报告

> 阶段：Phase 5（代码审查）｜ 版本 **1.8.3** ｜ 角色：code-review
> 审查范围：`jflove-app` 相册同步重构、远端索引、传输记录裁剪、UI 精简；服务端/桌面/Web 仅版本号同步。
> 基线：`文档记录/需求文档/v1.8.3.md`（AC-301～AC-320）、`文档记录/设计文档/v1.8.3.md`

## 1. 总体评价

**通过（0 阻断）**。核心风险「大视频哈希阻塞主 isolate」「无索引盲传」「重复按钮」均已消除；安全宪法 §9 未降级，无服务端/接口/DDL 变更。

## 2. 问题列表

### 中等

| ID | 位置 | 问题 | 建议 |
|---|---|---|---|
| M-1 | `album_backup_service.dart` `_ensureRemoteIndex` | 有 pending 上传且索引已过期时，直接沿用旧索引继续扫描，可能把远端删除后新增的文件按旧快照判断 | 本轮先沿用旧索引保证不中断；下轮 pending 清空后强制重建。建议在 UI 明确「有上传任务时索引暂不重建」 |
| M-2 | `transfer_service.dart` `_pruneTasks` | 只裁剪已结束任务；相册每轮最多提交 20 个，上传慢时排队任务可能超过 50，页面仍可能变长 | 若后续出现卡顿，增加「队列上限 + 超限延后提交」；当前不阻断 |

### 轻微

| ID | 位置 | 问题 | 建议 |
|---|---|---|---|
| L-1 | `album_backup_service.dart` `_ensureRemoteIndex` | 建索引进度 `total: 0`，活动卡只能显示已扫描目录数 | 可估算「待扫描目录数」；不影响正确性 |
| L-2 | `album_backup_service.dart` `_handleAsset` | 无扩展名标题按「唯一前缀」匹配远端，若同前缀多文件则匹配失败并重传 | 相机文件名唯一，风险低；后续可加严格扩展名推断 |

## 3. 设计与需求偏差

- 1.8.3 收尾时将「最近上传」「相册页诊断按钮」移除，已同步修订需求 AC-305/AC-310，并登记 C10（全局诊断页，下个版本）；
- 远端索引由「内存 10 分钟缓存」改为「本地 SQLite 持久化，先建索引再上传」，已同步设计文档 §7 与 AC-316～AC-318。

## 4. 安全宪法核对（§9）

| 条款 | 结论 |
|---|---|
| 加密信封/流式加密 | 未改动，客户端仍走 `http_service` / 帧解析 |
| JWT 仅在加密 body | 未改动 |
| 路径参数鉴权 | 未新增接口/路由 |
| 日志脱敏 | 新增日志只含阶段/异常类型/计数；不记录 token、完整路径、文件名 |
| 新增加密原语 | 无 |

## 5. 回归风险

- 远端索引首次建立会递归列目录，目录极多时首轮较慢，但可取消；
- 远端删除自动补传是用户裁决行为，已写入需求；
- 1.8.2 已发布功能回归见测试报告。

## 6. 结论

**允许进入 Phase 6 测试与发布**；M-1/M-2 记录为后续观察项，不阻断 1.8.3。
