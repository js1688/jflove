## 2. 审查发现与处置

| 级别 | 问题 | 处置 |
| --- | --- | --- |
| 中 **M1** | 传输事件不带 `session_id`；所有标签的 `SftpView` 常驻挂载且全局订阅，别的会话事件会在本标签建行并触发目录刷新；行内「取消」还可能误关本标签 client | 三类事件补 `session_id`；前端每个处理器先按 `sessionId` 过滤；effect deps 加 `sessionId`；新增「其他会话事件不建行」用例 |
| 中 **M2** | 取消只能关已存在的 client；开通道窗口 / 排队等锁中的传输取消无效，仍会完成 | `sftp_cancel` 推进「取消代次」；传输线程在开通道前后与读写前检查；取消后失败行显示「已取消传输」；新增两条用例（开通道窗口、共享锁排队） |
| 中 **M3** | 共享回退时整笔传输持 `_sftp_lock`，目录加载无超时等待，可能永久卡住；UI「45s 自动失败」在等锁时不成立 | 元操作统一走 `_sftp_guard`：`lock.acquire(timeout=SFTP_OP_TIMEOUT)`，超时给「有文件正在传输，暂不能加载或修改目录」；前端提示改为「最长等待 45 秒」 |
| 中 **M4** | 批量汇总把「已发起」当「成功」，锁的是现状而非期望 | 文案改为「已发起 N 个，M 个启动失败（最终结果见传输队列）」；用例同步更新 |
| 轻 L1 | 计数先放锁后减、增量/减量无互斥的窄窗口 | 改为**先减计数再放锁**；计数增量在持锁、开 client 之前完成 |
| 轻 L2 | 取消后错误文案是「连接已关闭」，误导用户重连 | 取消代次命中时统一发「已取消传输」 |
| 轻 L3 | 排队期间显示 running 0B，无等待态 | 未改（避免扩大改动面）；记录为后续体验项 |
| 轻 L4 | `done` 的 `bytes_total` 用前端入参，可能 0B | progress 回调里取实际 total 并回传；done/failed 用实际值 |
| 轻 L5 | 计数断言与事件发布存在窄竞态；缺多标签用例 | 改为**清理后再发事件**；新增多标签隔离/取消/等锁用例 |
| 轻 L6 | 开发记录误写新增 `open failed` 映射 | 文档已更正（实际仅 `connect failed` / `channel open failed`） |
| 轻 L7 | 本机 `NODE_ENV=production` 时 React 测试环境失败（既有问题） | 测试统一用 `NODE_ENV=test`；非本补丁引入 |

## 3. 安全宪法核查（§9）

- 渲染层无网络出口：仍全部经 `callBridge`；未新增 fetch/axios/XHR。
- 文件字节与密钥不进渲染层：传输仍在 Python 侧完成，事件只含 `name/session_id/bytes_total/local_path`。
- 无新增加密原语 / 长期密钥 / 硬编码常量。
- 新增日志只记异常类型（`remote.py` 通道回退 WARNING），不打印远端路径或文件名全文。
- 桥白名单未扩大；未新增路由/路径参数。

## 4. 残余与未决

- 排队等待态（L3）与「取消后 UI 状态改为已取消（而不是失败行）」属体验项，未在本补丁扩大处理。
- Windows 真机 VM 未回验（本机无域），按发布回验流程处理。
- 审查期间 `remote.py` 被并发修改过一次（日志脱敏）；本报告以最终工作区为准，关键行号已变化。
