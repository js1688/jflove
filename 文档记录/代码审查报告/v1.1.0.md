## 二、总体评价

**总体质量：良好，可合并。**

v1.1.0 流式预览功能实现完整，架构设计合理，安全宪法合规。主要亮点：

- 端到端加密流程完整正确：服务端用 `encrypt_stream_chunk` 逐帧加密，客户端用 `parse_stream_frame` 逐帧解密，中间无明文暴露窗口
- `StreamProxy` 设计安全：仅绑定 loopback（127.0.0.1），URL 含一次性 UUID4 token，外部进程无法猜测
- `ThreadingTCPServer` + `daemon_threads` 解决了 seek 并发请求的阻塞问题
- suffix range（`bytes=-N`）处理正确，MOV 文件 moov atom 可被 FFmpeg 发现
- `GeneratorExit` 已显式处理，`frame_iter.close()` 在 `finally` 中确保连接及时释放
- 不写临时文件：预览全程基于内存/HTTP代理，满足 §9.1.2 要求

发现问题共 **5 条**：严重 0 条、中等 1 条、轻微 4 条。

### 中等（1 条）

#### M-1：`_build_range_stream_generator` 同步文件 I/O 阻塞 asyncio 事件循环

- **位置**：`jflove-server/src/controllers/file_controller.py:384-435`
- **描述**：`_build_range_stream_generator` 是同步生成器（`def`，非 `async def`），其中包含阻塞式 `open()`、`f.seek()`、`f.read()`。`FastAPI` 的 `StreamingResponse` 在事件循环内迭代此生成器时，每次 `f.read()` 都会阻塞整个 asyncio 事件循环，期间无法处理其他请求。设计文档任务规格中注明"须在 asyncio 生成器中用 `asyncio.to_thread` 或类似方式避免阻塞事件循环"，但实现未满足此要求。

  **注**：v1.0 的 `_build_encrypted_file_stream`（line 234）同样使用同步 I/O，v1.1.0 继承了该模式。这是跨版本存在的已知问题，不是 v1.1.0 新引入。

- **影响**：单服务器多用户并发预览时，大文件流式响应期间其他请求响应延迟。单用户/轻并发场景下不影响使用。
- **修复建议**：将同步生成器改为 `async def` + `asyncio.to_thread` 执行文件读取：

  ```python
  import asyncio

  async def _build_range_stream_generator(
      file_path: str, session_key: bytes,
      file_size: int, eff_start: int, eff_end: int, content_type: str,
  ):
      meta = json.dumps({...}).encode()
      yield encrypt_stream_chunk(session_key, meta)

      remaining = eff_end - eff_start
      try:
          f = await asyncio.to_thread(open, file_path, "rb")
          await asyncio.to_thread(f.seek, eff_start)
          try:
              while remaining > 0:
                  chunk_size = min(STREAM_PLAINTEXT_CHUNK_SIZE, remaining)
                  chunk = await asyncio.to_thread(f.read, chunk_size)
                  if not chunk:
                      break
                  yield encrypt_stream_chunk(session_key, chunk)
                  remaining -= len(chunk)
          finally:
              await asyncio.to_thread(f.close)
      except FileNotFoundError:
          err = json.dumps({...}).encode()
          yield encrypt_stream_chunk(session_key, err)
  ```

  同时需对 `_build_encrypted_file_stream`（下载/预览 v1 接口）做同样改造，建议一并修复。

### 轻微（4 条）

#### L-1：`note_controller.py` `_get_user` docstring 过时

- **位置**：`jflove-server/src/controllers/note_controller.py:23`
- **描述**：函数文档字符串描述"从请求体**或 Authorization 头**中提取 JWT 令牌"，但实际实现（line 31）只读取 `body.get("token", "")`，不读取 Authorization header。该注释为 v1.0 历史残留，与实现不符，可能误导后续维护者误以为 Authorization 头有效（实际上完全被忽略）。
- **修复建议**：
  ```python
  async def _get_user(request: Request, db: aiosqlite.Connection, body: dict) -> dict:
      """
      仅从已解密的请求体中提取 JWT 令牌并解析当前用户。
      （不支持 Authorization 头兜底——避免企业 MITM 代理观察到明文 Bearer token）
      ...
      """
  ```

#### L-2：`preview_dialog.py` `stop_and_release()` 注释过时

- **位置**：`jflove-desktop/src/components/preview_dialog.py:351`
- **描述**：`stop_and_release()` 方法注释写"便于删除临时文件"，但 v1.1.0 已不再写本地临时文件，此描述已无实际意义，可能引起误解。
- **修复建议**：
  ```python
  def stop_and_release(self) -> None:
      """对话框关闭时调用：停止播放并释放 QMediaPlayer，使 StreamProxy 能及时关闭连接"""
  ```

#### L-3：`_ensure_meta()` 持锁期间执行网络 I/O

- **位置**：`jflove-desktop/src/components/stream_proxy.py:57-75`
- **描述**：`_ensure_meta()` 在持有 `_meta_lock` 的同时发起网络请求（`file_service.stream_range`，连接超时 5s + 读取超时 30s）。若网络异常导致首次元数据请求超时，后续所有等待元数据的线程（其他 Range 请求线程）将被阻塞最多 35s。  
  这是设计文档明确说明的权衡（"首次调用时向服务端发 range(0, 0) 请求拿元数据帧并缓存"），实际影响极小（元数据仅在对话框打开时拉取一次），但值得关注。
- **修复建议**：将锁拆分为"检查+标记"（短暂持锁）和"实际请求"（释放锁外执行）的双检锁模式，可消除持锁期间的 I/O 阻塞，但会引入额外复杂度。当前实现在正常网络条件下完全可接受，建议暂不修改，在代码注释中补充该风险说明即可：
  ```python
  # 在锁内发请求，防止多线程重复拉取；
  # 网络超时（≤35s）期间锁会被持有，但元数据只拉取一次，影响可忽略
  ```

#### L-4：`_StreamTextView.append_bytes` 光标定位方式非标准

- **位置**：`jflove-desktop/src/components/preview_dialog.py:403`
- **描述**：`self._edit.moveCursor(self._edit.textCursor().End)` 通过实例访问 `End` 枚举值，而非通过类直接访问 `QTextCursor.End`。虽然在 CPython + PySide6 的 Python 绑定中两者等价，但通过实例访问类枚举值是非标准写法，会引起 IDE 静态检查警告，也不符合 PySide6 官方文档示例的惯用法。
- **修复建议**：
  ```python
  # 在文件顶部 import 处增加：
  from PySide6.QtGui import QTextCursor

  # 将 line 403 改为：
  self._edit.moveCursor(QTextCursor.End)
  ```
