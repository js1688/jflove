### 轻微（3 条）

#### L-1：`_try_resync_ecdh` 等待方在超时后默认重试，可能放大失败请求

- **位置**：`jflove-desktop/src/utils/http_client.py:_try_resync_ecdh`
- **描述**：等待方在 `Condition.wait(timeout=20)` 超时后直接 `return True`，让调用线程继续重发请求。在极端情况下若续约持有方真的耗时 >20s 且**最终失败**，等待方误以为成功，会以旧 session_key 再发一次（必然 401）。当前 `_send_with_auto_resync` 已限制只重试 1 次，等待方第二次仍 401 会直接抛 `ApiError`，**不会无限循环**，整体安全；但日志会出现一次"无意义的 401 重试"。
- **影响**：仅日志噪音，无功能/安全影响。
- **修复建议**（建议在 v1.1.2 处理）：
  ```python
  with self._ecdh_resync_cond:
      if self._ecdh_resync_inflight:
          self._ecdh_resync_cond.wait(timeout=20)
          # 用一个共享标志记录最近一次续约的成功状态
          return HttpClient._last_resync_ok
  ```
  本期不强制修，保留待并发场景验证后再优化。

#### L-2：`stream_text_loader.py:67` 注释提及"loaded"，但代码上下文仅有 emit 一处，可读性可再加强

- **位置**：`jflove-desktop/src/components/stream_text_loader.py:25-27`
- **描述**：docstring 已改为 `loaded()` 但仍可在文件级补一行注释说明"v1.1.0 BUG-1：原 finished 与 QThread 内置信号同名"。当前虽已注释，可再展开 1 行让历史背景更醒目。
- **影响**：纯可读性。
- **修复建议**：当前接受，无须修改。

#### L-3：登录页"登录有效期"下拉缺少 tooltip 解释下拉行为是"上限而非延长"

- **位置**：`jflove-desktop/src/ui/login_window.py:_build_login_page`（下拉控件创建处）
- **描述**：用户文档（需求 §4.1.3 边界）已经说明"实际生效=min(用户选择, 服务端 JWT exp)"，但 UI 上未提示该行为；如果用户在 UI 选择 8 小时却发现 1 小时被踢，可能以为是 BUG。
- **影响**：体验提示，不影响功能。
- **修复建议**（推荐 v1.1.2 顺手补）：在下拉框旁加一行 `CaptionLabel("最长以服务端为准；选择更短的值可强制提前退出。")`。
