## 总体评价

本轮 Web 端改动实现「视频/音频真边下边播 + 拖动 seek」，方案为 **Service Worker 流式代理**
（桌面端 StreamProxy 的 Web 版）+ MSE 回退 + 完整下载兜底。架构分层清晰、加密原语完全复用
既有 `encryptEnvelope` / `decryptStreamChunk` / `parseStreamFrames`，未引入任何新算法。
**安全宪法 §9 逐条核查全部通过**；未发现严重/高危问题，仅 1 个中等（会话过期无自动续约）
与 4 个轻微建议。

## 二、问题列表

### 中等 #1 — 流式路径会话过期无自动续约

- **文件**：`src/sw/index.ts:191`（handleStreamRequest）、`src/utils/stream-frame.ts:143`（openEncryptedStream）
- **描述**：主应用 `http-client` 在 401 时会自动 `resyncSession()` 重发；但 SW 内部向后端 `/stream`
  拉流若遇 401（会话过期/密钥交换过期），`openEncryptedStream` 仅抛「流式请求失败：HTTP 401」，
  SW 将其转成 500 返回媒体元素，播放中断且无自动恢复（需手动重开预览）。
- **影响**：观看中途会话过期会停播；安全无影响（拒绝访问是安全的）。JWT 默认最长 30 天，实际触发概率低。
- **建议**：SW 检测到 401 时 `postMessage` 通知页面触发 `resyncSession()`，页面随后重新 `openStreamUrl`；
  或短期接受现状并在开发记录中说明。非发布阻塞项。

### 轻微 #2 — SW 内存会话在标签页直接关闭时残留

- **文件**：`src/utils/stream-proxy.ts:174`（clearStreamProxySession）、`src/sw/index.ts:136`（clear-session）
- **描述**：登出会调用 `clearStreamProxySession` 清空 SW 内存密钥；但用户直接关闭标签页（未登出）时，
  密钥保留至 SW 被浏览器终止（同源 SW 生命周期由浏览器管理）。
- **影响**：低（密钥仍只在本机内存，页面重启后新登录会覆盖旧会话）。
- **建议**：页面 `pagehide`/`visibilitychange` 时调用 `clearStreamProxySession()`。

### 轻微 #3 — `openEncryptedStream` 直接 fetch（未走 http-client）

- **文件**：`src/utils/stream-frame.ts:143`
- **描述**：流式获取直接 `fetch`，未复用 `http-client.getQueryEncrypted`。
- **说明**：属**可接受例外**——`http-client` 依赖 `session.ts`（使用 localStorage），SW 环境无 localStorage
  无法复用；且信封构造（`?nonce=...&ciphertext=...` + `X-Session-ID`）与 `getQueryEncrypted` 完全一致。
  与旧 MSE 实现同模式。记录为设计取舍，无需修改。

### 轻微 #4 — React StrictMode 下预览 effect 双执行（仅 dev）

- **文件**：`src/pages/FilePreviewPage.tsx:64-121`
- **描述**：StrictMode 下 effect 挂载→卸载→重挂，会 open→close→open 两次流。
- **影响**：仅开发环境；cleanup 已正确关闭首个流，生产无影响。

### 轻微 #5 — 帧缓冲 concat 理论 O(n²)

- **文件**：`src/utils/stream-frame.ts:214`（parseStreamFrames）
- **说明**：`readMetaFrame`/`parseStreamFrames` 用 concat 拷贝缓冲；但帧固定 64KB、单缓冲极小，
  实际无性能问题。记录为可接受。

## 三、设计一致性

- **与设计文档 v1.1.0 `/stream` 接口约定一致**：`path=目录 + filename=文件名`；
  本次新增归一化（`stream-frame.ts:156`）兼容 Web 端「完整路径（含文件名）」传法，修复了
  `os.path.join(path, filename)` 双重拼接导致的 404「文件不存在」。
- **与桌面/移动端 StreamProxy 对齐**：Range 解析（bytes=a-b / a- / -N）、206 + Content-Range、
  Accept-Ranges、HEAD 探测 file_size，行为一致。
- **`parseStreamFrames` 修复**（`stream-frame.ts:222`）：先解析缓冲再读取，修复 meta 帧与数据帧
  同分片到达时丢帧抛错的问题，纯正确性改进，无行为回退。
