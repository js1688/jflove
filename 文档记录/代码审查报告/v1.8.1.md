## 3. 问题列表

### 3.1 中等

#### M-1 移动端分析轮询失败被静默吞掉，页面可能永久停在「正在分析」

- 位置：`jflove-app/lib/pages/offline/offline_new_task_page.dart:217-223`
- 现状：`_pollDetail()` 的 `catch` 只 `log.fine`，不改变 `_phase`、不提示、不重试；
- 影响：网络抖动 / 会话失效时，用户看到无限进度条，违反需求 §4「所有失败必须有中文原因与下一步建议」；
- 证据：单元测试未覆盖「轮询持续失败」分支（现有用例只覆盖成功 ready）；

```dart
} catch (e) {
  if (!mounted) return;
  log.fine('离线下载分析轮询失败：${userFacingError(e)}');   // ← 无 UI 反馈
}
```

- 建议：累计失败次数（如 3 次）后置 `_phase = failed` + 中文提示 + 「重试分析」；或保留 analyzing 但展示「网络异常，正在重试…」。
- **处理：已修复**。新增连续失败计数（3 次）→ 置 `failed` + 中文提示「已重试 3 次，请检查网络后重新分析」；
  新增回归用例 `offline_new_task_page_test.dart`「分析轮询连续失败 3 次」。
- 结论：**中等（已修复）**。

#### M-2 移动端目录选择器在多级进入时缺少「当前路径不可用」的兜底校验

- 位置：`jflove-app/lib/widgets/virtual_disk_dir_picker.dart:122-133`（`_enter` 拼路径）、`:158-176`（`_goBack`/`_goRoot`）
- 现状：`_enter` 用 `name` 拼相对路径，未校验服务端返回的 `path`；若目录名含 `/` 或服务端路径与客户端拼接口径不一致，会拼出错误路径；
- 对比：服务端 `browse` 返回每项 `{name, path}`（相对路径），当前实现只取 `name`，丢弃了 `path`；
- 影响：普通目录名不受影响；异常名称（极少）会进入 404 循环，用户只能返回根目录；
- **处理：已修复**。`_enter(name, serverPath: ...)` 优先使用服务端 `path`，仅在缺失时回退 `name` 拼接；
  `_normalize` 统一去首尾 `/` 与折叠重复 `/`。
- 结论：**中等（已修复）**。

### 3.2 轻微

#### L-1 三端选择器把「2000」硬编码在文案里

- 位置：`jflove-desktop/ui/src/components/ServerDirPickerModal.tsx:141`、`jflove-web/src/components/ServerDirPickerModal.tsx:144`、`jflove-app/lib/widgets/server_dir_picker_dialog.dart:149`
- 服务端上限是 `virtual_disk_service.SERVER_DIR_LIMIT`；若以后调整，三端文案会漂移；
- 建议：接口响应可补 `limit` 字段，或客户端只写「目录过多，请进入更具体的路径」。

#### L-2 移动端「只要音频/图片」无匹配时错误提示位置偏远

- 位置：`jflove-app/lib/pages/offline/offline_new_task_page.dart:321-333`
- `_errorText` 统一渲染在 URL 卡片内（`:447`），而快捷选择在清单卡片内；小屏上提示可能在可视区外；
- 另：选中成功后未清空上一次 `_errorText`，会残留旧提示；
- 建议：在清单卡片内单独展示选择类提示，并在任一快捷选择成功时清空。

#### L-3 Web 端渲染改动超出设计 §4.1，但与 AC-256 一致

- 位置：`jflove-web/src/pages/OfflineDownloadPage.tsx:542-546`、`src/utils/offline-download.ts:232-236`
- 设计 §4.1 写「页面无需改渲染逻辑」，但 v1.8.0 的卡片只在 active 状态渲染进度条，成功任务无法显示 100%；
- 实现改为所有状态渲染进度条 + 成功文案带 `100%`；
- 判定：**设计偏差但必要**（否则 AC-256 无法满足），建议 Phase 2 修订 §4.1 或在发布记录中注明。

#### L-4 服务器目录接口会跟随符号链接

- 位置：`jflove-server/src/services/virtual_disk_service.py:88-101`
- `entry.is_dir()` 默认跟随 symlink；管理员的目录树里若有指向别处的链接，会显示为目录并可继续浏览；
- 影响：管理员本就能注册任意路径，且接口只列目录、不读文件、不返回大小；**无权限提升**，仅信息面扩大；
- 判定：**已知并接受**；如要收紧可改 `entry.is_dir(follow_symlinks=False)`（会改变管理员预期，需需求确认）。

## 5. 安全宪法逐条核查（§9）

| 条款 | 核查点 | 结论 |
|---|---|---|
| §9.1 加密信封 | 新接口 `server-dirs` 在 `_PLAIN_PATHS` 之外；请求 query 信封 / 响应 `encrypt_response` | 通过（`main.py:33` 仍 3 条白名单） |
| §9.1 错误加密 | 400/401/403/404 全部 `HTTPException`，由全局 handler 加密 | 通过（单测断言响应为 `{nonce,ciphertext}`） |
| §9.3 鉴权 | 新路由无路径参数；`_require_admin` 只从解密 body/query 读 token | 通过（普通用户 403、无 token 401 单测） |
| §9.4 不暴露内容 | 只返回目录名/路径，不返回文件名/内容/大小；错误 detail 不含完整路径；新代码不打日志 | 通过（单测断言 detail 不含 tmp 路径） |
| §9.5 加密原语 | 三端未新增算法/密钥/KDF；仍走既有 `http_client` / `http-client.ts` / `http_service.dart` | 通过 |
| §9.6 桌面渲染层 | 新增 `browseServerDirs` 走 `httpClient.get` → Python 桥；未出现 fetch/axios | 通过（`ui/src` 无直连） |
| §9.6 Web | `browseServerDirs` 走 `http-client.ts`；路径仅在加密 query | 通过（浏览器实机请求无明文 path） |
| §9.6 移动 | 7 个写接口全走 `HttpService`；轮询失败只打 `userFacingError`；无 token 日志 | 通过（源码扫描 + 测试） |
| 换 ID 绕过权限 | 新接口无 ID；离线任务仍按 token 归属，服务端二次校验 | 通过 |
