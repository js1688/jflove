## 2. 总体评价

- **根因定位正确**：P1/P2 的关键是 paramiko「partial 认证返回列表」而不是抛异常；旧测试用抛异常模拟，掩盖了问题。本版按真实语义重写，并以**真实 paramiko SSH 服务**（`AUTH_PARTIALLY_SUCCESSFUL` + keyboard-interactive）做端到端用例，判据从「调用了几次」升级为「服务端确实收到账号密码且 `is_authenticated()` 为真」。
- **SFTP 卡死的两层边界都补了**：`invoke_subsystem` 的无超时 `event.wait()` 用定时器关闭 channel 打断；SFTP channel 设置操作超时；元数据操作按会话串行；传输改独立 subsystem 通道，避免与目录浏览共用同一 SFTPClient 的并发同步请求。
- **取消语义拆分干净**：新增 `sftp_abort`（只取消目录加载）避免「取消加载时连带杀掉上传/下载」；`sftp_cancel` 仍负责取消传输。
- **凭据清空是显式协议**：服务端写空串，不是「留空 = 不修改」；口令单独更新/清空补齐。
- **安全口径未被稀释**：未新增 HTTP 路由；渲染层仍无网络出口；错误文案/日志不含凭据或完整路径；`sftp_abort` 只在内网桥白名单中。
- 无严重、无中等问题；轻微问题 5 条，均不阻塞进入测试/发布流程。

### 轻微

**m-1（轻微）`drop_sftp` 与 `open_sftp` 存在极窄的缓存回填竞态**
- 位置：`jflove-desktop/src/services/ssh_session.py`（`open_sftp` 的 `client = paramiko.SFTPClient(chan)` 与 `self._sftp_client = client` 之间；`drop_sftp` 不持 `_sftp_open_lock`）
- 分析：取消发生在「client 构造完成、缓存赋值之前」时，`drop_sftp` 可能看不到新 client；随后 `open_sftp` 会把一个已关闭的 client 写入缓存。窗口为微秒级，且下一次操作失败后桥会 `_drop_sftp` 再重建。
- 建议：给会话加 `_sftp_generation` 计数，`drop_sftp` 自增并在 `open_sftp` 赋值前比对；不在本版阻塞。

**m-2（轻微）SFTP 打开定时器在「成功返回后、cancel 之前」的竞态**
- 位置：`ssh_session.py::open_sftp` 的 `threading.Timer(SFTP_OPEN_TIMEOUT, abort)` + `timer.cancel()`
- 分析：若定时器恰在 `invoke_subsystem` 已成功、`timer.cancel()` 尚未执行时触发，会把刚建好的 channel 关掉。15s 阈值下概率极低。
- 建议：定时器回调先检查 `invoke_done` 事件再关闭；或把整个打开流程放到可中断的显式状态机里。下个版本处理。

**m-3（轻微）keyboard-interactive 密码/验证码判断依赖中英文关键词**
- 位置：`ssh_session.py::_answer_interactive_prompt`（`verification/code/otp/动态/验证码…`）
- 分析：非中英文提示（如纯日文/自定义网关提示）会落到 UI 输入，不会误用账号密码代答（安全方向正确），但用户需要手输；若提示恰好是「密码」的其它语言写法，则不会自动代答。
- 建议：后续在表单/文档给出「服务器要求继续认证时按弹层提示输入」说明（本版已有 UI 说明）；不阻塞。

**m-4（轻微）表单在编辑态允许清空「认证方式必需的密码」**
- 位置：`ui/src/components/remote/RemoteConnectionForm.tsx::submit`（仅创建态校验 `needsPassword && password`）
- 分析：用户可清空密码保存，之后连接失败。属用户显式清空意图，服务端/客户端都会在连接时给出可读原因；不视为缺陷。
- 建议：如需更稳，保存前对「清空后认证方式缺凭据」弹一次确认；下个版本候选。

**m-5（轻微）`openEditor` 增加一次全量连接请求**
- 位置：`ui/src/stores/remote-store.ts::openEditor`
- 分析：打开编辑抽屉时先拉 `listConnections('')` 再拉详情；搜索态下必须如此（否则跳板选项缺失）。单次网络开销，可接受。
- 建议：若后续列表很大，可缓存全量列表与搜索列表两份；不阻塞。

### 已知未覆盖（非缺陷）

- **Windows 多显示器混合 DPI**：本机 KVM 靶机单屏，无法复现「弹层持续变大」。修复是**结构性去掉原生 `<select>`**，需用户真机双屏复验（PMO 候选台账 #2）。
- **本机 sshd 冒烟**：`/tmp/jf-ssh-test/id_ed25519` 未在 `~/.ssh/authorized_keys`，`ssh -i ...` 返回 `Permission denied (publickey,...)`，`scripts/verify/ssh_smoke.py` 未跑通；真实 SSH/SFTP 链路由新增的 paramiko 测试服务用例覆盖（见开发记录 §3）。未擅自改用户 `authorized_keys`。
