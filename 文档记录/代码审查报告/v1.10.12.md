## 2. 总体评价

- **根因定位正确且有证据**：两条用户可见缺陷（SFTP 面板不出目录、选 `.ppk` 无反应）都定位到具体文件:行，
  修复方向与根因一一对应，没有"绕过现象"式的改动。
- **修复方式恰当**：P1 采用"按会话状态门控 + 兜底探活"，把"挂载即请求"这种**时序假设**换成**状态驱动**，
  并且对"就绪事件早于标签创建"这一同类历史坑（`TerminalView.tsx:532` 曾踩过）做了自愈；P2 同时修了
  "选不中"和"看不到提示"两个独立原因，而不是只补文案。
- **测试与实机判据匹配缺陷形态**：pytest 守"过滤器常量确实传给 `QFileDialog.getOpenFileName`"，
  vitest 守"连接中不发请求 / 就绪后自动加载 / 事件丢失可自愈"，实机脚本守"全程不点刷新也出目录"。
  **判据是时序与调用次数，不是"最终有没有内容"**，符合本类缺陷"静默失败"的特征。
- **安全口径未被稀释**：私钥字节仍只在 Python 进程内流转（渲染层只拿 token/文件名），
  新增 UI 代码无网络出口，错误文案不含完整路径（`AGENTS.md §9.13`）。
- 无严重、无中等问题；3 条轻微问题见 §3，均不阻塞发布。

### 轻微

**M-1（轻微）兜底探活有次数上限，链路 >30s 且事件全丢时会停在占位**
- 位置：`jflove-desktop/ui/src/components/remote/SftpView.tsx:142-176`（每 1s 一次，`attempts > 30` 停表）
- 分析：`SshSession` 单跳超时 `CONNECT_TIMEOUT = 15.0`（`ssh_session.py:34`），多跳链路 `MAX_JUMP_DEPTH=16`
  理论上可远超 30s；此时若就绪事件也丢失（仅"事件早于标签创建"这一种），面板会停在「会话正在连接」。
- 影响：极低概率（事件丢失需与建链完赛竞速），且用户可关闭标签重开。
- 建议：后续把上限改为"与跳板数相关"或直接改为"监听 `remote.session_status` 事件 + 探活"双路。

**M-2（轻微）实机脚本与界面文案耦合**
- 位置：`scripts/verify/desktop_sftp_gate_e2e.mjs`（判据含「会话正在连接」「确认主机指纹」「修改时间」等文案与日期正则）
- 分析：文案调整会让脚本失效。失效方式是**脚本报错**（fail-closed），不是静默通过，风险可接受。
- 建议：稳定后给关键节点加 `data-testid`（如 `sftp-placeholder`、`sftp-row`），脚本改断言 testid。

**M-3（轻微，非本次引入）`bridge/remote.py` 的 `logger` 未被使用**
- 位置：`jflove-desktop/src/bridge/remote.py:20-22`（`from src.utils.logger import get_logger` / `logger = get_logger(__name__)`，
  全文件无 `logger.` 调用）
- 说明：`flake8` 不报模块级未使用变量，故长期未被发现；本次未引入也未删除（避免夹带无关改动）。
- 建议：下个版本要么补关键日志（会话打开/关闭、SFTP 错误），要么删除该变量。
