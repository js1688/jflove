#### S-1 · [严重 · 本版引入 · 阻塞] 草稿还原后工作区**不渲染任何面板**（`mounted` 自举死锁）

- **违反条款**：需求 **AC-55**（"登录成功后自动还原 3 个标签页，内容分别等于 A/B/C"）、**AC-60**（10 个标签逐一相等）、**AC-66**（切换保留状态）；设计 §4.5（hydrate 条件）、§4.8（"标签在**首次成为激活项**时 `setMounted(id,true)`"）
- **证据（静态闭合证明 + grep）**：

  - `grep -rn "hydrateFromDrafts|mounted" ui/src/**/*.test.*` ⇒ 用例里**没有**任何"hydrate 之后渲染"的断言（`scratch-save-decision.test.tsx:548` 只有一句注释提到 hydrate）⇒ 该路径零测试覆盖

- **修复建议（二选一，均为一处改动）**：
  ```tsx

  const mountedTabs = tabs.filter((tab) => tab.mounted || tab.id === activeTabId);
  ```
  ```ts
  // 或者 scratch-store.ts hydrateFromDrafts 内：还原后把激活项也算作已挂载
  activeTabId: state.activeTabId ?? preferredActiveId,
  ```

#### M-14 · [中等 · 口径/设计缺口] 读侧兜底（`pickInvalidTabs`）在会话内**实际不可达**；且 `hydrateFromDrafts` 的"按 id 去重"使它救不回"已在内存但正文失效"的标签

**证据**：

- 新判据确实按设计落地：`ScratchWorkspace.tsx:109` `const shouldRead = store.tabs.length === 0 || pickInvalidTabs(store.tabs).length > 0;`（**"内存为空 ⇒ 必须读盘"这半边在**，冷启动 AC-55 / AC-60 不受影响 —— 见 `scratch-workspace-gate.test.tsx:231-256` 通过），`utils/scratch/editor-liveness.ts:59-72` 的三条合取判据与 §15.5.5 逐字一致，`stores/scratch-store.ts:634-636` 的 `existing` 去重（只新增内存里没有的 id）也**按设计的"锁 3"保留**。
- **但** `ScratchWorkspace.tsx:88-94` 在求值新判据**之前**先命中 `if (hydratedThisSession) { flushOpenPaths(); return; }`；而设计 §15.5.5 的表自己就写明「**门 1：`hydratedThisSession`** … 之后路由重挂**永远不会**再读盘 … 门 1 恰好把它锁死」。本轮只改了门 2，**门 1 未动** ⇒ 除"首次 `draftList()` 抛错（L-3 路径）"外，会话内的重挂**根本不会求值** `pickInvalidTabs`。
- 该唯一可达路径正是入库用例的构造方式：`scratch-editor-content-survival.test.tsx:316-341`（先让首次 `draftList` `mockRejectedValueOnce`，再断言"第 2 次调用"= 兜底读盘真的发生）—— 这是**诚实**的证据，也同时证明"常规重挂不会走这条路"。
- 更进一步：即便判据被求值、磁盘上也有**同 id** 的草稿条目，`hydrateFromDrafts` 的 id 去重（`scratch-store.ts:634-636`）会把该条目**整个跳过**（`:353-368` 的 store 层用例正是这条语义）⇒ 对"内存里有标签、正文已失效、且无快照"的标签，**兜底读盘不会给它任何正文**，只会新增内存里没有的 id。

**影响**：AC-77 的**主判据不受影响**（主修复 = 写侧快照，见 §15.5），但设计 §15.5.6 表里"会话内路由重挂（某条无快照） ⇒ 读盘 → 只新增内存里没有的 id … **AC-77⑥ 兜底**"这一行对自己的**目标形态**是空转的；`R-18` 对策②（读侧兜底）在本轮的实际效力仅限"补上内存里缺失的标签"。

**建议做法**（需设计/产品裁决，二选一，**不要**自行改判据）：

1. **文档就地更正**（推荐，成本最低）：在需求 §9.2 AC-77⑥ / 设计 §15.5.5-§15.5.6 写明——"兜底读盘只负责**新增**内存中不存在的标签；'内存里已存在但正文失效'的标签，其正文**只能**来自写侧快照（`snapshotInitialText`），无快照时不保证还原"，并同步 `hydratedThisSession` 早退这一事实（门 1 的定位）。
2. **实现补齐**（若产品要求"无快照也必须能兜底"）：让 `hydrateFromDrafts` 在"该 id 的标签**正文已失效**"时允许写入草稿正文（须严格限定为 `isTabContentInvalid(tab) === true`，否则会破坏 AC-5⑤/AC-77⑥ 的不变量），并补一条负向对照（活会话有快照时不得被草稿覆盖）。

#### M-15 · [中等 · 潜在内容丢失（**推断，未实跑**）] "取走初始正文"与"实例建成"之间存在窗口：此间卸载会丢正文

**证据（逐行）**：

- `ScratchEditorHost.tsx:612`（`pane.id` effect 内）`initialTextRef.current = takeInitialText(paneId) ?? '';` —— `takeInitialText` 是**取走即删**（`scratch-store.ts:186-191`）；

- 设计 §15.5.2 只讨论了该窗口的"**不会写入空串**"（正确），**未讨论**"已取走的正文会丢"。

**状态说明（诚实登记）**：本条为**代码推断**，**我未实跑**（不写任何临时用例；现有入库用例都在 unmount 前把微任务冲干到实例就绪，如 `scratch-editor-content-survival.test.tsx:193/228`）。因此**建议 Phase 6 先补一条"内核加载完成前切走"的用例取证**（可用 `loadEditorBundle` 的替身延迟 resolve 构造），再决定是否算缺陷。

**建议做法**：

1. 把 `takeInitialText` 移到**实例创建成功处**（`loadEditorBundle()` 之后、`EditorState.create` 之前），使"消费初始正文"与"实例存在"同生共死；
2. 或在 `:613-619` 的 cleanup 里补一条"实例从未建成"的分支：`snapshotInitialText(paneId, initialTextRef.current)`（`snapshotInitialText` 现有的 `tabs.find` 守卫已能挡住已关闭标签，故不会引入死标签复活）。
