## 二、问题列表

### 严重

**无。**

### 中等

**M-1：`min-rows` 实机用例失败，属存量缺陷，本版未修**

- 证据（同一构建、连续三次）：

  ```
  FAIL min-rows 窗口偏矮时自动保证 TUI 行数（v1.10.9） —— 恢复窗口后未回到用户字号：
  {"dims":"135×26","font":"⌥ 字号 13→13（自适应）","warn":false}
  ```
- **已排除是本次回归**（审查时独立复跑，不是采信开发记录）：

  ```
  git stash            # 工作区完全回到 HEAD(05187c9)
  npm run build        # exit 0
  node scripts/verify/desktop_terminal_e2e.mjs --only min-rows
  → FAIL（同上）
  ```
  另做一次对照：仅移除本版新增的 `applyFit` 幂等守卫后重跑，**同样失败**。
- 判定：**存量缺陷**（`applyFit` 在"窗口由矮变高"后没有把字号还原的路径）。不构成本版阻塞项，
  但**必须**记入下个版本候选台账，不可静默丢弃。
- 建议（下版）：在 `applyFit` 里对「恢复到大尺寸」显式重算一次候选（当前 `lastFitKey`
  随尺寸变化会变，理论上应当重算，说明问题在候选挑选而非幂等守卫），
  并对 `readAutoFitRows()` 关闭时的分支补一条实机用例。

### 轻微

**L-1：`TIMEOUT` 哨兵与 `null` 的语义只靠注释维系**

`ui/src/utils/clipboard.ts:30-45` 的 `withTimeout` 返回 `T | null | typeof TIMEOUT`，
三态语义（成功 / 任务抛错 / 超时）完全靠调用方正确区分。当前两处调用都正确
（`copyText` 用 `=== true`、`readClipboardText` 先判 `TIMEOUT` 再判 `null`），
但类型层面无法强制后来者。

建议（可选）：改成 `{ ok: true, value } | { ok: false, reason: 'timeout' | 'error' }`
的判别式联合，让 TS 强制收窄。**本版不必改**。

**L-2：`__resetClipboardProbeForTest` 是生产导出的测试口**

`ui/src/utils/clipboard.ts:152` 为模块级可变状态导出了复位函数。这是项目既有惯例
（`terminal-schedule.ts` 的 `__resetSchedulerForTest` 同理），且不影响运行时分枝，
可接受；已在单测 `beforeEach` 中真正使用，不是死代码。

### E-1（必须标注的证据边界）

开发记录里「rAF 掉到 1.5fps / 按键 2~4 秒」那组数据是**无合成器的 Xvnc/Xvfb** 上的结果。
审查员在**用户真实桌面（Wayland + XWayland `:0`）**复核时，同一探针测得 rAF 稳定 60fps，
**未能复现秒级卡顿**。

判定：
- 该边界**已在开发记录 §2.3 的「⚠ 证据边界」中显式声明**，措辞与实测一致，**没有夸大**；
- 用户可感知的主因应归于 **BUG-1（粘贴两次）与 BUG-2（粘贴固定 500ms）** ——
  这两条在真实桌面已直接复现/量化；
- BUG-3 是**"最小化到托盘 / 页面被判隐藏"**场景下的确定性缺陷（`hidden` 时 rAF=0 已实测），
  修复有效但**不能**单独解释日常卡顿。**建议**下个版本专门安排一次「用户真实桌面 × 长时段」
  的延迟采样（带系统负载、多标签、TUI），把剩余体感差异找出来。

> 这一条是本报告最重要的提醒：**贴标签要贴在证据上**。开发记录已按要求标注，审查予以确认；
> 后续对外表述（发布记录/验收结论）**不得**把"无合成器环境的 2~4 秒"写成用户桌面实测。
