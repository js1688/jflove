## 二、测试策略与覆盖点

### 2.1 服务端策略

#### `test_login_ttl_v1_1_2.py`（18 用例）

走完整加密链路（`do_key_exchange` → 加密 body 发起 `/login` → 解密响应），覆盖：

- **默认 TTL（向后兼容）**：不传 `requested_ttl_seconds`，验证签发的 JWT exp = now + 3600，响应 `expires_in = 3600`；
- **合法 TTL 真生效**：参数化 5 个值（1800/3600/7200/14400/28800），验证签发的 JWT exp 与请求一致（误差 ≤ 30s）；
- **超界 clamp**：99999999 → 28800、0 → 60、-100 → 60、刚好上下限值不报错；
- **类型容错**：字符串数字 "3600" 正确解析；非数字字符串 "abc" 视为 None 走默认值；显式 None 走默认值；
- **响应字段**：`expires_in` 存在且为 int；`expires_in` 与 JWT exp 误差 ≤ 30s（同源校验，无算两遍偏差）；
- **安全宪法**：明文 body 仍被拒绝（400）；登录响应仍是加密信封。

### 2.2 桌面端策略

#### `test_login_ttl_request.py`（5 用例）

**mock 掉 `http_client.post` 与 `_save_session`**，专注验证 `auth_service.login()` 是否正确构造请求 body：

- 传入 `local_max_seconds=7200` → payload 含 `requested_ttl_seconds = 7200`（int 类型）；
- `local_max_seconds=None` → payload 不含 `requested_ttl_seconds`（向后兼容）；
- 不传该参数 → payload 不含字段；
- 字符串数字 "3600" → 强转为 int 后上传；
- 登录后 `session_manager.local_session_max_seconds` 同步更新。

#### `test_login_window_layout.py`（3 用例）

实例化 `LoginWindow`（用 qapp fixture），通过 Qt 布局内省验证：

- "登录有效期"标签和下拉控件位于同一个 `QHBoxLayout` 中；
- "返回"按钮和"登录"按钮位于同一个 `QHBoxLayout` 中；
- 下拉默认选中 1 小时档位（`LOCAL_SESSION_TTL_DEFAULT`）。

### 2.3 回归策略

不新增改动的模块（v1.1.0 流式预览、v1.1.1 ECDH 续约 + 单弹窗 + TTL 持久化）全量回归，确认本期改动未引入回归。

### §9 安全宪法合规性回答

**本次 v1.1.2 变更未破坏 §9 安全宪法的任何一条。**

具体确认：
1. login 接口仍走加密信封（请求 + 响应 + 错误均加密），v1.1.2 新增字段 `requested_ttl_seconds` 仍在加密 body 内传输 ✅

3. JWT 仍仅走加密 body 的 `token` 字段；未引入 Authorization header 兜底 ✅
4. 服务端 `JWT_EXPIRE_MAX_SECONDS = 28800` 硬上限保护：客户端无法绕过 8 小时上限 ✅
5. 服务端 `JWT_EXPIRE_MIN_SECONDS = 60` 硬下限保护：防止恶意 0 秒 / 负数 TTL ✅
6. 加密协议 / 帧格式 / ECDH 静默续约 / 加密原语清单 ：完全不变 ✅
7. 桌面端 `services/` `ui/` `components/` 0 处 `import requests` ✅
8. 安全 5 大类用例全部通过（含 v1.1.2 新增的 2 个 TTL 安全宪法专项用例）✅
