## 二、测试策略与覆盖点

### 2.1 桌面端新增用例策略

#### `test_session_expiry.py` —— 验证 `effective_expire_at()`

需求文档 §4.1.3 明确"实际生效时长 = min(JWT exp, key_exchange_time + local_session_max_seconds)"。本组用例独立测试该计算口径，覆盖：
- 字段全空 → 0
- 仅 JWT 有值
- 仅本地上限有值
- 两者都有：本地短 / JWT 短 各一组
- 本地上限 = 0 表示禁用本地上限

#### `test_http_client_resync.py` —— ECDH 静默续约的核心逻辑

测试策略：**用 mock 替换 `requests.Response` 与 `auth_service.resync_session`，把"网络/服务端"侧整个隔离掉**，专注于客户端的状态机。覆盖：

- ECDH detail 字符串识别（5 用例）；
- `_send_with_auto_resync` 状态机（5 用例）：首发 200、ECDH 401 续约重发成功、JWT 401 不续约、续约后仍 401 仅重试 1 次、续约失败仍重发；
- `_parse_response` 401 抛 ApiError 携带 detail（1 用例）；
- 单飞续约：5 个并发线程，`resync_session()` 仅被调用 1 次（1 用例）。

#### `test_login_ttl_persistence.py` —— 持久化偏好

不 mock QSettings，让真实写读发生（fixture 前后清理键），验证 v1.1.1 新增的 `save/load_local_session_max_seconds` 行为，含损坏值回退。

#### `test_logout_idempotent.py` —— `_logout_in_flight` 互斥

最棘手的部分：实例化 `MainWindow` 需要 QApplication 和合法 session 状态。策略：
- 通过 `qapp` fixture 提供 QApplication；
- 在 fixture 中预先填充 session_manager（fake token / role / expires_at）；
- 用 `unittest.mock.patch` 替换 `auth_service.logout` 与 `MessageBox`；
- 直接调用 `_on_logout_requested` 多次 + 多次 `_check_token_expiry`，断言副作用只发生一次。

#### `test_stream_text_loader_signal.py` —— v1.1.0 BUG-1 修复验证

直接对 `StreamTextLoader.__dict__` 做内省，证实类体内不再声明 `finished`，且 `loaded` 信号在加载完成时被 emit。

### 2.2 服务端回归策略

服务端代码 0 改动，运行 `tests/test_security_e2e.py + test_stream_v1_1_0.py` 做"等价复跑"，确认无环境/版本偏差。
