## 1. 测试范围与方法

终端的问题只在"真事件 + 真进程 + 真渲染"下暴露（v1.10.7 就是单测全绿、真机 TUI 卡死）。
本轮采用三层证据：

1. **单元测试**：Python 通道/环境/控制终端；前端 DECRQM 纯函数 + 结构性约束；
2. **实机 E2E**：`scripts/verify/desktop_terminal_e2e.mjs` 经 CDP 驱动真实 QtWebEngine 界面、
   真实 PTY、真实键盘/输入法事件，逐条对 xterm 缓冲区/真实文件内容/状态栏做断言；
3. **交叉验证**：裸 PTY 对照实验 + tmux 参照终端，区分"上位程序缺陷"与"我们渲染错"。

### 2.2 真实 Wayland 会话（补充验证，非发布门禁）

用打包产物在用户的真实 Wayland 会话里再跑一遍（窗口真实、平台插件真实）：

- **9 / 10 PASS**：`/tmp/jf-term-e2e-wl-full/`；
- 唯一失败项 `clipboard`：无人值守注入时窗口**没有键盘焦点**，Wayland 合成器不把选区交给
  未聚焦客户端 ⇒ 复制/粘贴双向为空。用 KWin 脚本把窗口置为活动后，同一用例 **PASS**
  （`/tmp/jf-term-e2e-wl6/`，日志可查 `CLIPTRACE write len=47` → `read` 由浏览器路径读到）。
- 结论：这是平台安全策略导致的**测试环境限制**，不是产品缺陷；真实用户点击窗口即获得焦点。

## 4. 未覆盖与已知问题

1. **SSH 远程终端未接真机**：无可用 SSH 目标与凭据。共用件已覆盖（同一 `TerminalView`/通道），
   SSH 侧只新增 `nudge_redraw` 与状态上报。
2. **Windows TUI 场景未覆盖**：VM 未安装 `dsh` 等全屏 TUI；本轮 Windows 验证覆盖
   终端打开/键盘/复制粘贴/中文输入/多标签，DECRQM 修复的 TUI 场景由 Linux 真机覆盖。
3. **Wayland 剪贴板依赖窗口焦点**（平台策略，已提示用户；Windows 会话内复制粘贴已通过）。
4. **dsh TUI ≤21 行丢输入框内容行**（上位程序缺陷；默认窗口 24 行规避，窗口过矮仍可能遇到）。
5. 终端会话不跨 App 退出保持（与 v1.10.0 设计一致）。

## 5. 发布回验中发现并修掉的验证工具缺陷

| # | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| T1 | `windows_vm_e2e.sh` 版本比对没 trim 空白 | QGA 的 PowerShell 输出按列宽补空格 ⇒ 正确版本被判成"旧包"，白跑一轮 | `sed 's/[[:space:]]//g'` 后再比对 |
| T2 | `windows_vm_e2e.sh` 会"复用上次会话"直接跳过登录 | 旧会话令牌失效时 `/files/disks` 401、磁盘列表为空，脚本却以为已登录 | 启动前清 `%APPDATA%\JFLove`，强制全新登录并断言 login 200 |
| T3 | `android_smoke.sh` 不支持签名变化 | 换构建密钥后 `adb install -r` 报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 命中该错误时卸载重装 |
| T4 | `windows_vm_ui.mjs` 只有点击/填充，没有输入法与坐标点按 | 无法在 Windows 上验中文输入与 xterm 三击选中 | 新增 `--insert-text` / `--click-at --count` |
| T5 | 缺 Windows 终端交互 runner | `windows_vm_e2e.sh` 不碰终端，"Windows 通过"名不副实 | 新增 `scripts/verify/windows_vm_terminal.sh`（4 项交互断言） |
