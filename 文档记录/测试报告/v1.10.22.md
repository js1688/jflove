## 1. 测试范围

1. **粘贴语义**：一次 Ctrl+V 只允许产生一条 `input` 帧（远程 SSH / 本机终端共用同一组件）；
2. **粘贴时延**：桌面端读剪贴板不得再白等浏览器 API 超时；
3. **输入回显时延**：按键 → 画面出现必须 < 200ms；
4. **输出调度**：页面被判隐藏时输出不得堆死在 `requestAnimationFrame` 上；
5. **不回归**：选中复制、Ctrl+C 中断、vim/TUI、大输出、多标签、尺寸变化、会话自动关闭、IME 中文；
6. **跨平台**：同一份 Web UI 代码在 Linux 与 Windows 上一致（flags 侧改由单测锁定）。

### 2.1 新增用例逐条（关键判据）

| 用例 | 判据 |
| --- | --- |
| `不依赖 requestAnimationFrame（页面隐藏时 rAF 停摆也必须执行）` | **把全局 rAF 换成永不回调**，调度器仍必须执行合帧，且 `rafSpy` 未被调用 |
| `同一轮内多次调度只合并成一次执行` | 3 次 `scheduleFlush` → 下一轮按顺序一次跑完 `[1,2,3]` |
| `单个回调抛异常不影响同轮其它回调` | 首个抛错后第二个仍执行 |
| `Ctrl+V 自定义分支必须 preventDefault` | 源码断言 `preventDefault()` 位置在 `pasteClipboard()` **之前** |
| `smart 模式下无选区仍放行 Ctrl+C` | 保住 SIGINT 语义 |
| `输出写屏不再用 requestAnimationFrame 调度` | `flushPending` 与 `enqueueOutput` 均不含 rAF |
| `桌面端（桥就绪）优先走桥` | 浏览器 API **一次都没被调用**，总耗时 < 100ms |
| `浏览器 API 永挂时：第二次直接走桥` | 第二次读 < 100ms（不再 500ms） |
| `剪贴板确实为空时不该被误判成 API 不可用` | API 返回 `''` → 不回落桥、下次仍问 API |
| `test_非_windows_只注入反后台化开关_不碰遮挡特性` | Linux/darwin 必含三开关、必不含 `CalculateNativeWinOcclusion` |

### 2.2 反向验证（用例必须能抓住旧 bug）

**① 去掉 `preventDefault()` ⇒ 粘贴用例必须变红**

```
git diff（仅移除 KeyV 分支的 event.preventDefault()）→ npm run build（exit 0）
node scripts/verify/desktop_terminal_e2e.mjs --only paste-once
→ FAIL：单次 Ctrl+V 产生了 2 条 input 帧
```

恢复该行后同一命令 `PASS`。这是**同机、同构建、同一按键**的单变量对照。

**② 页面隐藏时 rAF 停摆（证明调度器换掉是必要的）**

```
cdp: 最小化到托盘后
{"vis":"hidden","raf":0,"mc":295747}     ← rAF 1 秒 0 帧，MessageChannel 2.5 秒 29 万次
```

**③ rAF 合帧 vs MessageChannel 合帧（最小复现页 A/B 对照）**

| 时刻 | A（rAF）入队/写入/滞后 | B（MessageChannel）入队/写入/滞后 |
| --- | --- | --- |
| t+0s | 241 / **178** / 16.3ms | 241 / **241** / 0.1ms |
| t+8s | 991 / **928** / 14ms | 991 / **991** / 0.1ms |
| t+14s | 1553 / **1491** / 4ms | 1553 / **1553** / 0.1ms |

A 持续积压、B 零积压 —— **判据是「写入数是否追平入队数」，不是"看起来快"**。

```
FAIL min-rows —— 恢复窗口后未回到用户字号：{"dims":"135×26","font":"⌥ 字号 13→13（自适应）","warn":false}
```

**排除本版回归的两条独立证据**（testing 自行复跑，不采信开发记录）：

## 5. 实机延迟实测（用户真实桌面 `:0`，Wayland + XWayland，DPR=2）

| 场景 | keydown → 画面 |
| --- | --- |
| 空闲逐字输入（25ms 间隔） | 6–25ms（中位 19ms） |
| 连续 24 字符快速输入 | 24/24 全部到达，无丢弃 |
| 6 个终端标签并存 | 中位 24.9ms |
| 5MB 持续输出期间 | 中位 24.6ms（无 longtask / 无 LoAF） |
| e2e `input-latency`（12 键） | 最慢 **35.4ms**（阈值 200ms） |
| 本地 PTY 写→回显 | 0.56–0.68ms |

### 5.1 证据边界（必须随结论一起引用）

「rAF 掉到 1.5fps / 按键 2~4 秒」那组数据来自**无合成器的 Xvnc/Xvfb**，
在用户真实桌面 `:0` 上同一探针测得 rAF 稳定 60fps，**未能复现秒级卡顿**。

因此本版对「卡顿」的归因是：

- **已证实的用户可感知主因**：粘贴两次（A/B 实证）+ **每次粘贴固定白等 500ms**（实测 `readText` 永挂）；
- **已证实的确定性缺陷**：页面被判隐藏时 rAF = 0（实测），影响「最小化到托盘再恢复」场景；
- **未能复现的部分**：用户日常输入体感差异，留待下个版本按真实负载长时段采样（已记入台账）。

### 5.3 回验中发现并修正的测试脆弱点

在 CI 产物上首跑 `clipboard` 用例失败，排查后确认**不是产品缺陷**，而是用例对**折行**不健壮：

```
CI 产物的工作目录更长（/tmp/jf-ci-artifacts/extract/usr/lib/jflove$，59 字符 vs 开发版 51 字符），
粘贴的整行在 135 列处折行，把 "SELECT_ME_中文" 拆成 "SELECT_ME_中" + "文"
⇒ 原来用 /SELECT_ME_中文/g 匹配第 3 次，折行后永远匹配不到 ⇒ 假失败
```

已把判据改为「去掉换行后比对、且只要求比粘贴前**新增**一份」，改后 CI 产物与开发版**双端均 PASS**。
（这类"测试依赖环境细节"的脆弱点正是为什么必须用**产物**而不是源码回验。）
