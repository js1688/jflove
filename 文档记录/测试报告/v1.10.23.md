## 4. T-2 结论的独立复核（testing 自行复算，不采信开发记录）

```
终端区 894×552（1180×760 窗口，DOM 实测 containerH=552 / screenH=533）

lineHeight 1.25 → 行高 20.5 × 1.25 = 25.63px → floor(533 / 25.63) = 20 行  < 24 ❌
lineHeight 1.10 → 行高 20.5 × 1.10 = 22.55px → floor(533 / 22.55) = 23 行  < 24 ❌
lineHeight 1.00 → 行高 20.5 × 1.00 = 20.50px → floor(533 / 20.50) = 26 行  ≥ 24 ✅

容纳 24 行舒适档所需终端区高度：ceil(24 × 25.63) = 615px
```

DOM 实测与计算一致：

```json
{"containerH":552,"screenH":533,"renderedRowCount":26,
 "rowHeightMeasured":20.5,"rowsFontSize":"13px","impliedRows":26}
```

⇒ **产品在 1180×760 下压缩是正确的**；旧断言「恢复后不得出现自适应」是**用例假设错误**。
`TUI_MIN_ROWS=24` 的来历（dsh TUI ≤21 行会画丢输入框内容行）见
`ui/src/utils/terminal-prefs.ts` 注释 —— **保住 24 行优先于观感**。
