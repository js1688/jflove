## 2. 新增用例覆盖（`tests/test_remote_gateway_multifactor_v1_10_16.py`）

| # | 用例 | 判据 |
| --- | --- | --- |
| ① | `test_gateway_partial_publickey_goes_straight_to_password` | 密钥被接受后直接走密码：服务端收到序列必须**恰好**是 `publickey#1 → partial(password) → password` |
| ② | `test_gateway_second_factor_only_keyboard_interactive` | 第二个因子只在键盘交互时，客户端必须切到 `keyboard-interactive` 并代答成功 |
| ③ | `test_gateway_wrong_password_message_points_at_password` | 密码错误：文案指向「密码」，诊断含 `认证序列=`，且不含错误密码明文 / 私钥正文 |
| ④ | `test_gateway_never_asked_key_twice_when_password_present` | 有密码时 `publickey_calls == 1`（防止回归到 v1.10.15 的多发一次） |
| ⑤ | `test_legacy_retry_gate_requires_no_next_methods` | 门槛单测：`allowed` 含 password / keyboard-interactive 时**不**回退；裸失败 / 只列 publickey 仍回退；`rejected` 不回退 |

**反向验证**：把 `_can_retry_legacy_rsa` 的 `allowed` 门槛去掉（恢复 v1.10.15 行为）后，
用例 ① 立即失败（序列多出 `publickey#2`）；恢复本版实现后通过 —— 证明用例钉住的是真实行为。

## 3. 安全用例（§9 安全宪法）

本版**未触碰**服务端接口、加密协议、鉴权与文件流，故 §9 的 5 类安全用例沿用
`jflove-server/tests/test_security_*.py` 的全量结果（467 passed 中已包含），未做任何降级。

| 项 | 结论 |
| --- | --- |
| 诊断行不含密码 / 私钥正文 / 口令 | 用例 ③ 断言：错误信息含 `BEGIN RSA PRIVATE KEY` → 失败；含错误密码明文 → 失败 |
| 日志不含凭据 | `SSH 认证失败诊断` / `SSH 认证完成` 只记方法名、序列、算法、版本 |
| 渲染层无网络出口 | 本版未新增 HTTP/桥出口，`ui/` 无代码改动 |
| 加密信封 / 路径权限 / 文件流 / 错误加密 / 白名单 | 未改动；服务端 467 passed 覆盖未回归 |
| 是否破坏 §9？ | **否** |

## 6. 未覆盖与说明

- **用户真实失败网关不在本机网络内**：只能用本地真实 paramiko 服务端复刻两类形态（用例 ②/③ 与
  `/tmp/v11016-gateway.log`），真实复验需用户安装 v1.10.16 后连接该网关。
- **Windows / Android 实机回验已完成**（见「验证证据」表，均为 CI 当前 tag 产物）。
  重跑注意：本机 `/tmp` 是 tmpfs，下载 3 个 CI 产物（约 537MB）后曾写满导致工具链不可用，
  已通过「只按需下载单个产物 + 用完即删」规避；`/tmp` 被系统清理后证据文件需重跑生成。
- **登录 200 而非 401**：本机 dev 库只有 `admin` 一个账号且口令未知，未擅自重置用户口令或写入
  生产库；改以「真实点击 → 加密登录请求 → 服务端 401 回包 → 界面显示 `[401]`」证明链路闭环，
  并在 Windows 回验时用 CI 产物补 `login 200`（该流程内会创建 `vmtest` 账号）。
