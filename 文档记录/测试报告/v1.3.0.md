## 三、安全用例独立小节（§9.6 硬约束）

### ① 加密信封往返

- **覆盖**：`crypto.test.ts` + `http-client.test.ts`
- **用例**：密钥生成 → ECDH+HKDF 派生 session_key → `encryptEnvelope` 加密 → `decryptEnvelope` 解密 → 字段一致
- **结果**：✅ 通过（含 GET 请求也发送加密 body、token 在解密后的 body 内）

### ② 路径参数权限绕过（Web 端路由守卫）

- **覆盖**：`auth-store.test.ts`（认证状态 + token 过期）+ 代码审查（RequireAuth/RequireAdmin 使用 `useAuthStore`）
- **用例**：
  - 无持久化 token 不恢复登录态 → 路由守卫重定向到 `/login`
  - 非 admin 用户 `isAdmin=false` → RequireAdmin 重定向到 `/`
  - token 过期 → `isTokenExpired()` 返回 true → 同步清除会话 → 重定向到 `/login`
- **结果**：✅ 通过
- **说明**：服务端路径参数归属校验（伪造 user_id/upload_id 得 403）属于后端测试范畴，本版本后端无 API 变更，沿用 v1.1.6 已验证的安全测试。

### ③ 文件下载流可解密、篡改后认证失败

- **覆盖**：`stream-frame.test.ts`（5 用例）
- **用例**：
  - 多帧加密 → 流式解析 → 逐字节一致（含中文/二进制）
  - 网络分片（跨帧边界拆包 100B）→ 正确重组
  - 篡改密文帧 → Poly1305 认证失败抛错
  - 错误 session_key → 解密失败
  - 空明文帧边界（32B）→ 正常解析
- **结果**：✅ 通过

### ④ 错误响应加密

- **覆盖**：`http-client.test.ts`「加密错误响应解密后抛出 ApiError」
- **用例**：403 错误响应（加密信封）→ 解密 → `ApiError.status=403`、`detail='对目标磁盘没有读取权限'`
- **结果**：✅ 通过

### ⑤ 白名单边界

- **覆盖**：`http-client.test.ts`「明文 POST（key-exchange）不带加密信封」
- **用例**：`/api/v1/auth/key-exchange` 明文请求 → body 不含 `nonce/ciphertext`，直接携带 `client_public_key`
- **结果**：✅ 通过

### 安全结论

**本次是否破坏 §9？** 否。全部 5 类安全用例通过，加密协议与后端/桌面端/移动端保持一致。
