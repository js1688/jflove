## 二、测试策略与覆盖点

### 2.1 后端集成测试策略

使用 FastAPI `TestClient` + `session` 级 `env` fixture（admin / alice / bob 三用户环境）对 `GET /api/v1/files/stream` 进行端到端测试。重点覆盖：

- **帧协议正确性**：解析响应字节流的所有帧（`[4B len][12B nonce][ciphertext+tag]`），验证帧 0 是元数据 JSON，后续帧拼合后字节级等于原文件。
- **参数规范化**：`range_start < 0`（suffix range）、`range_end = -1`、`range_end > file_size`（越界自动截断）、`range = 0-0`（元数据专用）。
- **权限边界**：无 token → 401、无磁盘读权限 → 403、文件不存在 → 404、空 filename → 400、admin 绕过权限校验。
- **安全宪法**：请求体加密校验、响应原始字节不含明文特征、响应头零敏感字段、帧篡改 → `InvalidTag`、帧截断 → `AssertionError`/`ValueError`、不在明文白名单。

### 2.2 桌面端单元测试策略

#### StreamProxy

使用 `unittest.mock.patch` mock 掉 `src.services.file_service.stream_range`，用真实 `requests` HTTP 库向代理发请求，验证代理行为：
- HEAD / GET 响应状态码与头部字段
- Range 解析（`bytes=X-Y` / `bytes=X-` / `bytes=-N` 三种格式）
- `_ensure_meta` 缓存（多次请求仅一次元数据拉取）
- 安全：只绑定 loopback、token 包含 32 字符 UUID hex、无效 token → 404、代理关闭 → 503

#### StreamTextLoader

使用 `unittest.mock.patch` mock `stream_range`，通过 `QThread.wait() + processEvents()` 等待信号交付，验证：
- `meta_ready` 先于 `chunk_ready` 触发
- `chunk_ready` 多帧数据拼合后字节一致
- `cancel()` 设置标志后不再 emit chunk
- `error` 信号在异常时触发

## 六、缺陷列表

### BUG-1：StreamTextLoader.finished 与 QThread::finished 命名冲突

| 属性 | 描述 |
|---|---|
| **位置** | `jflove-desktop/src/components/stream_text_loader.py:32` |
| **严重级别** | 轻微（功能不受影响，信号语义模糊） |
| **复现步骤** | 运行 `test_stream_range抛出异常_emit_error信号`，观察 `finished` 信号在异常路径中仍被触发 |
| **期望行为** | `finished` 仅在加载成功（`run()` 正常返回到末尾）时触发 |
| **实际行为** | `finished` 无论成功还是失败都被触发，因为 `QThread::finished` 在线程结束时由 Qt C++ 运行时自动 emit，而 `StreamTextLoader.finished = Signal()` 与其发生绑定 |
| **根因分析** | `finished` 是 `QThread` 的内置信号名，子类中定义同名 `Signal()` 不会创建独立信号，而是与 C++ 信号共用触发机制 |
| **修复建议** | 将自定义信号重命名为 `load_complete = Signal()` 或 `loaded = Signal()`，同时更新 `preview_dialog.py` 中的连接代码 |
| **当前影响** | `preview_dialog.py` 未连接 `finished` 信号（只连接 `chunk_ready` 和 `error`），因此不影响实际运行功能 |
