## 2. 策略

1. **反向验证优先**：凡新增回归用例，先证明它在修复前**会失败**（否则等于没测）。
2. **迁移/回滚脚本写反向用例**：坏数据必须拦住、幂等、不丢数据、id 保留（依据 LESSONS L16–L19）。
3. **真机取证**：三端都用当前版本产物 + 真实点击/输入，不留"只读代码"结论。
4. **不动测试期望值**：失败若因实现有 bug → 报出去，不改测试。

## 9. 测试结论

1. **v1.10.25 QA 的 9 条问题全部关闭**（7 条代码修复 + 2 条文档修正）。
2. **无新增缺陷**；四端静态与单测全绿，且 server 单测数从 468 → 475（+7 条针对性回归）。
3. **P1 是本轮最严重的一条**：修复前 token 续期与二次登录**完全不可用**，且影响面比原报告更大
   （不止 refresh）。已用「反向验证」证明回归用例真能拦住同类问题复发。
4. 涉及生产库表结构变更，已交付幂等迁移脚本 + 带冲突检查说明的回滚脚本，
   并跑通「坏数据拦住 / 等价结构放行」的反向验证。
5. **未破坏 §9 安全宪法**：未新增加密原语，`_PLAIN_PATHS` 未变，错误响应仍全加密。

**放行意见**：可以进入发布阶段。
