## 12. 验证教训（本轮）

### 12.1 关键行为必须以**代码行号**为唯一判据，报告结论必须能被 `grep` 复核

**现象**：本轮出现过"两个子代理对同一段代码的行为描述**方向相反**"——
一个说 `refresh_geometry()` 的恢复分支**忽略** `visible=false`；另一个说它**优先尊重** `visible=false`。
两种说法都能写成"我看过代码"，但结论相反；如果照着错的写进报告，下游会做出反向决策（L10 的同型风险）。

**裁决方式（唯一判据）**：只认行号，不认叙述。读 `jflove-desktop/src/ui/media_overlay.py:323-343`：

```
:323  if self._shell_hidden:                                  # 托盘恢复路径
:326      if not self._kind: return                           # 无媒体源 → 不恢复（M-3）
:329      if self._fullscreen:                                # ← 全屏分支在这里
:331          self._shell_hidden = False
:332          self.window.showFullScreen()                    #   直接全屏返回
:334      if not self._rect or not self._rect.get("visible", True):   # ← visible 检查在**之后**
:337          return                                          #   保持 _shell_hidden（M-5）
:344  if self._fullscreen: return                             # 非关窗态：全屏同样在 visible 之前
:350  if not rect.get("visible", True): return                # 非全屏才尊重 visible
```

**结论（唯一版本）**：**全屏路径忽略 `visible=false`；非全屏路径尊重 `visible=false`**。
⇒ 第一个子代理说对了一半（"忽略"只对全屏路径成立），第二个子代理把非全屏路径的语义外推到了全屏路径。
**两个都不算全对，只有行号能定案。**

**写成纪律**（本轮教训，建议纳入本角色后续版本的工作方式）：

1. **凡"某分支的优先级/顺序"这类结论，报告里必须给 `文件:起止行` + 关键行的原文片段**，
   让读者能自己 `grep` 复核；只写"代码里是这样"的结论**不予采信**。
2. **同一事实出现两种相反描述时，不得取"多数"或"更自信的一方"** —— 必须回到代码行号重新判定，
   并把两方说法都留在记录里（本次即如此处理）。
3. **判别优先级/顺序类问题时，"谁在前谁在后"就是正确性本身**（本例 `_fullscreen` 早退与 `visible` 早退的先后），
   这类代码必须带中文注释说明"顺序即正确性"（`media_overlay.py:297-322` 已如此写，值得保持）。
4. **能被 `grep` 复核的结论优先**：能用"命令 + 输出"表达的（哈希、grep 计数、退出码），
   不要用"读代码后的叙述"表达。
