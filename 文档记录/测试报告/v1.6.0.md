**必须处理的 3 条缺陷（详见 §7）**

1. **D-1｜AC-36 / AC-37（保存 / 另存为）整条未实现**：快捷键定义在 `ui/src/config/shortcuts.ts:104-177`，但应用级监听不含 `file.save`，`ui/src/services/scratch-service.ts:117-120` 的 `pickSaveTarget` **全仓无调用方**；真机 OS 级 `Ctrl+S` 到达渲染层后 `defaultPrevented === false`（无对话框、无落盘）。**目前唯一的落盘通路是 1500 ms 防抖自动暂存。**
2. **D-2｜AC-13（Shift 列选择）未实现，且现绑定有破坏性**：真机实测 `Alt+Shift+↓` **每次复制 2 行**（文档 100 → 150 → 200 字节），最终选区是单区间而非跨行矩形；该改动在 1.5~4 s 内被自动保存**写回原文件**（fixture 100 → 200 字节）。整包无任何列/矩形命令（`copyLineDown` 等 4 个 copy/move 命令存在）。
3. **D-3｜M-4 / BL-21 只读目标写失败会残留含新正文的临时文件**（违反 AC-41 ④）：Windows 上 `chmod 0o444` 后 `os.access(W_OK)` 为 False，但 `_read_only_reason` 返回空 → `atomic_write` 的 `copymode` 把只读位复制到 `.tmp` → `os.replace` 抛 `WinError 5` → `_silent_unlink` 删不掉只读 `.tmp`。已用 `xfail(strict)` 留证，修好后会自动变红提醒取消标记。

## 1. 测试范围与策略

### 1.1 范围

本轮是 v1.6.0 的 Phase 6，范围**只限** v1.6.0 的变更面与设计 §14.3 点名的 40 条负向对照：

- **jflove-desktop**：浮动编辑窗格（渲染层 `ui/` + Python 外壳与桥）、保存/自动保存/草稿、块选择与快捷键、离线与未登录、崩溃与半截状态、关联与单实例；
- **jflove-server**：v1.6.0 的清债项（AC-B2 OpenAPI 描述与实现一致、AC-B8 运行依赖不含测试依赖）；
- **jflove-web**：AC-B3（信封解不开 ⇒ 502）、AC-B4（`test:coverage` 命令级）；**不改 Web 端与移动端代码**；
- **跨端门禁**：parity、版本一致性、库结构、关联资产生成物。

**明确不在本轮**：RPM 构建、Android 端、Docker 化的服务端运行态、会改本机注册表/程序目录的安装与卸载验证（见 §9.3）。

### 1.2 策略（四层，逐层加牙）

| 层 | 手段 | 覆盖什么 | 本层判据 |
| --- | --- | --- | --- |

## 10. 验证教训（本轮，供后续版本复用）

1. **`runJavaScript` 的回调通道在 QtWebEngine 上不可靠**：`page.runJavaScript(script, cb)` 的 `cb` 实测**恒为空串**（页面加载、桥调用、拦截器都正常）。改用**标题通道**：JS 侧 `document.title = 'R11#<seq>::' + JSON.stringify(v)`，Python 侧轮询 `page.title()` 解析，并用自增标记防读到陈旧值。
2. **同一次 `runJavaScript` 里"派发事件 + 立刻读 DOM/样式"必然读到旧值**（React 要下一帧才更新；CM6 也要走一次 measure）。所有交互判据都必须拆成"派发一次 → `QTest.qWait` → 读一次"，**逐次派发**；`paneRef.current` 在同一次同步循环里也不会更新（连发 40 次滚轮只会按同一基准算一次）。
3. **采集型探针必须显式传全轴**：给 `QMouseEvent` 传 `QPointF` 会拿到轴值 `0`，而 Windows 上鼠标轴是 `0..65535` ⇒ 必须显式传 `0..65535` 的轴值，否则事件被丢掉一半。
4. **仓库源文件只用 `edit` / `write` 工具变更**：`Get-Content | Set-Content` 的编码往返会写坏文件；本次事故还导致两个测试文件在修复时被漏掉（§4.2 留档）。若已用 PowerShell 触碰过文件，必须逐文件核对存在性 + `npm run test` 的文件数不能掉。
5. **断言"抛了某类异常"往往等于没断言**：`pytest.raises(ValueError)` 会被**另一个** `ValueError` 顶替 —— 变异矩阵（r9）正是为抓这类"判据空转"而建；凡"守卫被关掉就该失败"的用例，必须匹配**错误消息特征**。
6. **静态断言的盲区**：r8 能断言"源码里有 `stepFontSize(paneRef.current.fontSize, ±2)`"，但断言不了"用户真按 Ctrl+滚轮时会不会触发"—— 真机 H4 才证明它成立；反之 r8 断言不了的"Alt+Shift+↓ 会不会改文档"由真机 H3 抓到（**AC-13 的破坏性行为在任何静态断言与 jsdom 用例里都看不见**）。
7. **jsdom 的物理局限要写进注释而不是伪造替身**：`Range.getClientRects` 不存在 ⇒ CM6 的测量路径直接抛 `TypeError`；因此 AC-13 的"几何结果"在无头环境**不可能**判定，用例只断言"扩展被真正装进配置"并注明局限，几何判定交给真机。
8. **fixture 必须与判据同源**：探针若用"合成选区"当"窗口选择"，判据会在错误的前提下通过（本轮 H2/H4 的早期版本正是这样）；真机判据要么走真实交互路径，要么显式声明是"直接注入"。
9. **真机跑要抢前台**：Windows 默认禁止后台进程抢焦点（`document.hasFocus() === false` 会让应用级快捷键自查直接 return）；`AllowSetForegroundWindow(-1)` + `ShowWindow(hwnd, 9)` + `BringWindowToTop` + `SetForegroundWindow(hwnd)` 之后才测得到真实接管行为。同时要**显式清理修饰键**（`keybd_event` 瞬时连发会丢键，曾出现 `Ctrl+Alt+N` 被记成 `shift: true`）。
10. **沙箱要在 import 之前生效**：`APPDATA` / `LOCALAPPDATA` 必须在 `import src.config.settings` 之前改，否则 settings 已经把真实用户目录固化进常量（`LESSONS.md L20` 的同类坑）。
