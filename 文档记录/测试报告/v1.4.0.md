## 四、测试发现并修复的 BUG（5 项）

> 均为纯代码 BUG（需求/设计正确），走快速修复通道，版本号不变（v1.4.0 开发中）。

### BUG-1（严重）codec 裸字符串导致 MSE 失败、回退下载

- **现象**：修复流（time 模式）在 Chrome 中报 `DEMUXER_ERROR_COULD_NOT_OPEN`，最终回退完整下载原文件（MKV 无法被 Chrome 原生解码）。
- **根因**：服务端 meta.codec 返回裸 codec 串（`avc1.64000c`），`media-source-player.ts` 直接将其传给 `addSourceBuffer()`，而该 API 要求完整 MIME 类型（`video/mp4; codecs="avc1.64000c"`），抛 `NotSupportedError`。
- **定位过程**：浏览器实际解密帧为 fMP4 且单独 append 可播放，而播放器路径失败；通过在 `addSourceBuffer` 捕获异常打印 `NotSupportedError: The type provided ('avc1.64000c') is unsupported` 定位。
- **修复**：`jflove-web/src/utils/media-source-player.ts` 将 meta.codec 按是否含视频轨包装为 `video/mp4; codecs="..."` 或 `audio/mp4; codecs="..."`。

### BUG-2（严重）loading 切换导致 video 元素被 React 重建

- **现象**：`sourceopen` 超时，MSE 无法建立，同样回退下载。
- **根因**：`FilePreviewPage.tsx` 中 `{loading && <spinner/>}<video/>` 为无 key 兄弟列表，loading 状态切换时列表由 `[spinner, video]` 变为 `[video]`，React 按 index 匹配卸载重建 video 元素，`playWithMSE` 持有的旧元素引用失效（`video.src = objectUrl` 设置在已脱离文档的元素上，`sourceopen` 永不触发）。
- **修复**：spinner 始终渲染（`hidden` class 控制可见性），保证 video/audio 元素在组件生命周期内稳定。

### BUG-3（轻微）登录页版本号未随版本更新

- **现象**：登录页底部显示 `v1.3.1`。
- **修复**：`jflove-web/src/config/constants.ts` 中 `APP_VERSION` 更新为 `1.4.0`。

### BUG-4（中等）StrictMode 双跑 effect 时旧实例 cleanup 破坏新实例

- **现象**：React StrictMode（开发模式）下预览反复失败重拉（多次 `ERR_ABORTED`），视频最终不可播。
- **根因**：StrictMode 双跑 effect 时，第一次 `playWithMSE` 的 cleanup 无条件执行 `video.src = ''`，把第二次（有效）实例已设置的 MSE objectUrl 清空，导致 MSE 失活。
- **修复**：`media-source-player.ts` 的 cleanup 仅在 `video.src === objectUrl`（仍指向本实例）时清空 src；旧实例只中止自己的 fetch、回收自己的 MediaSource。

### BUG-5（严重）服务端 time 修复流对桌面/移动端零兼容（方案 B 修复）

- **现象**：修复开关开启时，桌面/移动端请求 /stream 同样收到 time 修复流，而 time meta 缺 `file_size`，且桌面/移动是字节 range 模型 → `_file_size=0`、`Content-Length: 0`、seek 反复触发完整转码（回归风险）。
- **修复（服务端）**：
  1. 声明机制：仅请求携带 `range_start_seconds` 字段才启用 time 修复；旧客户端一律 byte 原文件流，零回归。
  2. time meta 补充 `file_size`（原文件大小）与 `duration`（媒体时长）。
- **修复（桌面端）**：`stream_range` 支持时间参数；`StreamProxy` 识别 time 模式（HEAD 不声明 Accept-Ranges、GET 200+chunked、字节 Range 线性映射时间）。
- **修复（移动端）**：`stream_proxy.dart` 同样适配（含 `mapRangeToSeconds` 映射函数）。
- **验证**：后端 120 passed；桌面 102 passed + 真实服务端链路集成验证（HEAD/GET/seek 三种请求均 200 + fMP4）；移动 27 passed + analyze 0。

## 六、遗留说明

1. **HEVC 健康文件**（如 `IMG_0443.MP4`）：byte 模式下 MSE 默认 codec 探测为 H.264/AAC，若实际为 HEVC 会 append 失败并自动回退 Blob 完整下载播放（本机 Chrome 可硬件解码，体验正常）。后续如需 HEVC 边下边播，可让服务端对 byte 模式健康文件也返回真实 codec（非本次范围）。
2. **桌面/移动 time 模式 seek 为线性近似**（平均码率假设）：恒定码率精确、变码率有偏差；seek 后服务端 `-ss` 重拉修复流（符合「每次重新计算、不落盘」约束）。播放器在 time 模式下按顺序流式播放（HEAD 未声明字节 seek）。
3. 移动端因本机无 Android 模拟器未做真机 E2E（此前已与用户确认），以 analyze + 单测 + 与服务端同构的桌面端链路验证保证。
