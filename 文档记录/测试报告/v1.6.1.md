## 10. 验证教训（本轮，供后续版本复用）

1. **"单测绿"不等于"流程通"**：R1 存在时，`editor-open-paths-gate.test.ts` 的断言（订阅回调里调了 `router.navigate('/editor')`）**依然为真** —— 因为缺陷在"谁最后导航"。凡涉及**多个所有者竞争同一结果**（路由落点、焦点、输入归属），必须有一条**端到端全链路**判据，否则单测面再厚也拦不住。
2. **顺序即判据**：`revealOnThisLogin` 必须在 `flushOpenPaths()` **之前**置位（flush 会清空队列），这类"先置位再消费"的顺序要求必须写在代码注释里（本轮已写），否则下一个人"顺手整理"就会把缺陷带回。
3. **探针的"等待"必须验证它真的在等**：`fixture_tab_is_clean()` 读了一个**从未被返回过的字段**，于是"等标签变干净"静默退化为"永远不等"。凡写"等待 X 成立"的判据，都要**故意构造 X 不成立的场景**确认它会超时（本轮由 `221309` 轮意外暴露，代价是两轮真机时间）。
4. **探针在 Qt 主线程里 `time.sleep` 会把自己的被测对象堵死**：被等的桥写入正是由同一主线程处理。轮询一律用 `QTest.qWait`（泵事件循环），并把"被等的调用到底有没有发生"作为**桥调用计数**写进证据。
5. **判据要用增量，不要把别的步骤当前提**：`AC71-3` 期望"绝对标签数 +2"，实际依赖的是"AC71-2 的 OS 按键投递成功"这一无关前提。改为"操作前后 ±1"后，两条判据各证各的。
6. **`--baseline` 是负向矩阵的可信度来源**：11 条里每条都先证"判据在干净源码上通过"，否则"变异后失败"可能只是因为判据本来就是红的。加上"锚点必须恰好命中 1 次"与"按字节还原 + sha 复验 + git status 兜底"，矩阵的结论才敢写进报告。
7. **变异脚本的**自述**也会错**：`r16` 首版把 §14.3 的行号从第 4 行起整体写偏一位（被只读复核子 agent 抓到）。⇒ 涉及"引用了文档哪一行"的字符串，要么不写行号，要么**逐条对照原文**。
