# JFLove 实机验证标准（唯一真相）

> **本文件是“怎么验证”的唯一真相。** `AGENTS.md`、各角色 `SKILL.md`、`scripts/verify/README.md`、
> 测试报告只允许引用本文件章节号，**不得重复写口径**（同一判据在多处出现必然漂移）。
> 修改验证方式：只改本文件 + 对应 runner 脚本。

## 1. 术语

| 术语 | 定义 |
| --- | --- |
| **当前版本** | `version.json` 的值；任何证据必须能回指到它（产物版本 / 界面页脚 / 安装注册表 / APK versionCode） |
| **实机证据** | ①命令 ②退出码 ③产物或截图/日志路径 ④版本号+commit 四项齐全；缺一即“未覆盖” |
| **交互验证** | 真实点击/键盘输入后产生的状态变化（不是仅启动、仅抓帧） |
| **未覆盖** | 明确写“未覆盖（原因+探测输出）”，禁止写“通过” |

## 2. 强制流程（每次验证都按此顺序）

1. `bash scripts/verify/probe.sh` — 输出能力矩阵，禁止用默认命令/默认 URI 判缺失。
2. 确认 `version.json`，并 `python scripts/sync_version.py --check` 通过。
3. 构建**当前版本**产物（源码启动也算产物；安装包必须由当前 commit 构建或 CI 当前 tag 产物）。
4. 跑对应端 runner（见 §5）→ 产出证据。
5. 填 `## 验证证据` 表（端/命令/退出码/证据/版本+commit）。
6. `python scripts/check_verification_report.py --version <版本> --require ...` 退出码 0。

## 3. 能力探测（probe.sh）

输出字段：`windows_vm`、`linux_display`、`linux_wayland`、`linux_ui`、`xvnc`、`ydotool`、`xinput`、`android`、`android_avd`、`offscreen_cdp`。

- Windows VM 必须用 `virsh -c qemu:///system`（默认 session 看不到域）。
- Linux 先看 `linux_display`/`linux_wayland`，**不得只试 `:99`**；`linux_ui=offscreen+cdp` 表示无 X 也能交互。
- 任一“缺失”只有在 probe 有真实输出后才允许写跳过。

## 4. 当前版本一致性（防旧包）

验证前与报告中必须核对（任一不符即失败）：

| 端 | 核对点 |
| --- | --- |
| 源码 | `version.json` == `sync_version.py --check` == `git describe --tags`（发布时） |
| desktop | 界面页脚版本、`src/config/settings.py` |
| desktop Windows | 安装注册表 `DisplayVersion`、`C:\Program Files\JFLove` 内程序版本 |
| Android | `pubspec.yaml version`、APK `versionName/versionCode`、界面关于页 |
| Web | `package.json` / 设置页关于 |
| server | `/docs` 或 `Dockerfile LABEL` |

**禁止**：用上一版本 Release/缓存包、`C:\jf\setup.exe` 旧文件、历史 APK 冒充当前版本。
Windows 安装前必须删除旧安装包并校验 SHA256 与当前版本一致。

## 5. 各端验证矩阵

| 端 | runner | 判据 | 证据 |
| --- | --- | --- | --- |
| server | `scripts/verify/server.sh smoke` + `flake8` + `pytest` | smoke 退出 0；pytest 全过；flake8 0 | 命令输出 + 版本 |
| web | `cd jflove-web && npm run lint && npm run test && npm run build` + `node scripts/verify/web_shot.mjs --click-text '连接服务端'` | 三项 0；截图 + key-exchange 200 | 截图路径 |
| android | `source scripts/verify/env.sh && scripts/verify/android_smoke.sh --stop` | 当前 APK 安装/启动/截图/输入成功；versionCode 匹配 | 截图 + adb 输出 |
| desktop-linux | `scripts/verify/desktop_linux_ui.mjs`（源码启动 + offscreen + CDP）或 `Xvnc` + `xinput.py` | 登录→进入页面→点击/输入生效；终端有输出 | 截图 + `.xterm-rows` 断言 |
| desktop-windows | `scripts/verify/vm-win.sh up` + `windows_vm_e2e.sh VERSION=<当前>` | 安装/登录/上传 + **UI 交互**（终端输入） | 截图 + 注册表版本 + 日志 |
| 版本切换 | 见 §7 | 旧版→新版后版本号与功能都更新 | 注册表/界面/日志 |

**只启动/只抓帧不算通过**；必须至少一次点击或键盘输入产生状态变化。

## 6. 交互验证方式

| 场景 | 方式 |
| --- | --- |
| Linux 桌面 Web UI | `QT_QPA_PLATFORM=offscreen` + `QTWEBENGINE_REMOTE_DEBUGGING=9222` + CDP（点击/`Input.dispatchKeyEvent`/截图） |
| Linux 原生 Qt 部件 | `Xvnc :99` + `xinput.py`（XTest） |
| Linux Wayland 原生 | `ydotool`（需 `/dev/uinput` 权限） |
| Windows VM | CDP over `host:9223`（`windows_vm_ui.mjs` / 自定义 key 脚本） |
| Android | `adb shell input tap/text` |

## 7. 版本切换验证（每次发布前至少做一次）

1. 在目标环境安装**上一个已发布版本**（从 Release 下载）。
2. 确认版本（注册表/界面/APK）。
3. 安装**当前版本**（同一路径、不手动卸载）。
4. 断言：版本号更新、旧配置仍在、核心功能可用。
5. 反向：卸载当前版本 → 安装旧版 → 版本回退正常（可选，视风险）。

Windows 必须覆盖 `setup.exe` 覆盖安装；Android 必须覆盖安装（`adb install -r`）。

## 8. 证据表与门禁

测试报告必须含：

```markdown
## 验证证据
| 端 | 命令 | 退出码 | 证据 | 版本/commit |
```

门禁：`python scripts/check_verification_report.py --version <版本> --require server,web,desktop,android,windows` 退出码 0。

## 9. 跳过与未覆盖

- 跳过条件只认 probe 输出 + 命令输出；写“未覆盖（原因）”。
- 缺一件（命令/退出码/证据/版本）即不通过。
- 禁止“我以为/应该可以”。

## 10. 引用关系

- `AGENTS.md §7.3`：引用本文件，只保留阶段必须执行的命令入口。
- 各 `SKILL.md`：只写本角色要跑哪几行 + 特有判据。
- `scripts/verify/README.md`：只写工具用法。
- 测试报告：只填证据表。
