# JFLove v1.8.4 桌面端开发记录（追加修复）

> 阶段：Phase 4a（快速修复通道，`AGENTS.md §7.5.3`）｜ 版本 **1.8.4** ｜ 角色：cross-platform-desktop
> 范围：仅 `jflove-desktop`；服务端 / Web / 移动端无改动（版本号仍为 1.8.4）。
> 触发：用户反馈「桌面端打开后最小化，再打开，整个面板变空白」（v1.8.3 安装包复现）。

## 1. 缺陷与根因

**现象**：Windows 桌面端最小化 → 恢复后，整个面板空白（DOM 正常、没有像素）。

**根因（分层取证）**：

| # | 取证 | 结论 |
|---|---|---|
| E1 | Linux/X11 真实进程 + `WebShell` 探针跑「`showMinimized()` → `showNormal()`」「`hide_to_tray()` → `restore_from_tray()`」，恢复后像素统计与恢复前一致（`distinct=1222`，主色占比 0.406） | **不是**前端渲染/路由问题，是**平台合成层**问题 |
| E2 | 恢复路径 `restore_from_tray()` 原来只有 `showNormal()` + `activateWindow()` + `raise_()`，`showEvent()` 只重贴合浮层 | 恢复时**没有任何唤醒渲染器/补帧动作** |
| E3 | `changeEvent()` 原来只把「是否最大化」推给页面 | 「最小化 → 恢复」的 `WindowStateChange` **没有**任何渲染处理 |
| E4 | 同源问题在 v1.5.0 已出现过（原生浮层隐藏后 Chromium 不重绘，`LESSONS.md` L40），当时的处置就是显式重绘 | 证明 QtWebEngine **不会**自动补画它认为"不需要重画"的区域 |
| E5 | Windows 上 Chromium 默认启用 `CalculateNativeWinOcclusion`：窗口被判定遮挡/最小化即**停止出帧**；恢复时若无人叫醒，合成层不会自己重建 surface | 这就是"整片空白"的直接机制 |

**一句话根因**：最小化让 Chromium 停了帧，恢复时外壳只说"把窗口显示出来"，**没人叫醒渲染器**。

### 2.1 唤醒动作（`_wake_renderer`）

两步，缺一不可（异常一律吞掉：观感修复不得打断窗口交互）：

1. **页面生命周期拉回 `Active`**：被系统/设备冻结（`Frozen`）的页面永远不会自己出帧，
   用 `QWebEnginePage.setLifecycleState(Active)` 显式唤醒；非 Active 时打一条 INFO 日志便于排障。
2. **1px 尺寸抖动 + `update()`/`repaint()`**：`resize(w+1,h+1)` → `resize(w,h)` 强制合成层重建
   surface；尺寸变化由 Chromium **自己**派发 DOM `resize`，前端随之重新布局。

> **为什么不用 `runJavaScript` 派发 resize**：外壳的"零 JS 执行"是 AC-87 能力面硬约束
> （`tests/test_v162_context_menu.py::test_capability_surface_not_expanded` 用 AST 守着）。
> 尺寸抖动已经天然产生 DOM `resize`，不需要额外开一条执行通道。

### 2.2 触发时机与守卫

| 触发点 | 说明 |
|---|---|
| `showEvent()` | 从托盘/隐藏恢复；**首次显示不唤醒**（页面还没加载，抖动无意义，靠 `_ever_shown` 区分） |
| `restore_from_tray()` | 托盘「显示窗口」/ 双击托盘 / 单实例「用 JFLove 打开」唤起 |
| `changeEvent(WindowStateChange)` | 识别 `最小化 → 非最小化` **边沿**（`_was_minimized`），系统任务栏恢复走这条 |

守卫：
- 仍 `isMinimized()` 或不可见时**放弃**（此时动尺寸会把窗口改坏）；
- 同一轮多次触发**只执行一次**（`_wake_pending` + `QTimer.singleShot(0, ...)` 合帧）；
- 恢复后只做**一次**延迟复查（`WAKE_RENDERER_RETRY_MS = 180ms`），避免反复抖动。

### 2.3 Windows 预防（`webengine_flags.py`）

`CalculateNativeWinOcclusion` 是 Windows 专属的"窗口被遮挡就停止渲染"优化，正是本次空白的触发条件。
在 `QApplication` 之前合并进 `QTWEBENGINE_CHROMIUM_FLAGS`：

```
已有 --disable-features=Foo,Bar  →  --disable-features=Foo,Bar,CalculateNativeWinOcclusion
无该开关                          →  追加 --disable-features=CalculateNativeWinOcclusion
已包含该特性                      →  原样返回（幂等，尊重用户配置）
非 Windows                        →  原样返回（不动）
```

**为什么必须合并而不是覆盖**：Chromium 只认最后一个 `--disable-features`，另写一个会把用户已有的
特性开关吞掉；直接覆盖 `QTWEBENGINE_CHROMIUM_FLAGS` 会吞掉整串用户参数。
代价：窗口被遮挡时仍可能出帧（CPU 略增），换「恢复必有画面」。

## 5. 已知限制 / 待用户确认

1. 本次修复的两个措施都是**通用解**（业界处理 QtWebEngine 空白恢复的常规手段），
   但本机没有 Windows 真机，**空白是否完全消失以用户复测为准**；若仍复现，下一步可考虑
   `view.page().reload()` 兜底（代价是丢失页面内未保存状态，故不作为首选）。
2. wine 覆盖不到 Windows 原生遮挡/合成行为，这一条无法在 CI 里做成门禁。


## 6. 二次修复：恢复后「点了没反应，要再最小化一次才刷新」（2026-10-30）

### 6.1 新症状

首次修复后用户复测：最小化 → 恢复，**画面能显示**，但之后**点击菜单不出画面**
（逻辑已生效），必须**再最小化一次再打开**才刷新成当前状态。

### 6.2 根因（首次修复的缺口，两条叠加）

| # | 缺口 | 后果 |
|---|---|---|
| G1 | 只做了"补一帧"（重绘 + 1px 抖动），**没有纠正页面可见性** | Chromium 仍认为页面不可见/被后台化 ⇒ 之后每次 DOM 变化都不出帧，只有 restore 那一下被强制画了一次 |
| G2 | 硬唤醒（`hide/show` 重建 surface）在 `_do_wake_renderer` 里碰到"窗口还没 map"就 **return 放弃**，后续补帧只有软动作 | 首次恢复很容易错过硬唤醒 ⇒ surface 从未重建，正好对应"要再最小化一次" |

另外缺少 `--disable-backgrounding-occluded-windows` / `--disable-renderer-backgrounding`：
`CalculateNativeWinOcclusion` 只负责**判定**遮挡，真正让渲染进程降频/停帧的是这两个开关。

### 6.3 修复

| 文件 | 改动 |
|---|---|
| `src/ui/web_shell.py` | ① 新增 `_set_page_visible()`：`hide_to_tray()` 时置 `page.setVisible(False)`、恢复时置 `True`（**这是出不出帧的总开关**）；② `_wake_renderer(hard=True)` 增加 `view.hide()/show()` 强制 re-expose；尺寸抖动改到**主窗**（不动布局里的 view，避免 surface 尺寸错配）；③ 窗口未 map 时**按 80ms × 12 次重试**而不是放弃；④ 补帧阶段若本轮还没硬唤醒则**补做一次**；⑤ `restore_from_tray()` 先显式清 `WindowMinimized` 状态位 |
| `src/utils/webengine_flags.py` | 追加两个后台化开关；新增逃生开关 `JFLOVE_WEBENGINE_SOFTWARE_GPU=1` → `--disable-gpu-compositing --disable-gpu`（D3D 设备丢失场景兜底） |
| `tests/test_v184_shell_wake_renderer.py` | 新增 5 条（重试不放弃、余额用尽停止、补做硬唤醒、已硬唤醒时不再 hide/show、托盘恢复清状态位）+ 1 条逃生开关 |

### 6.4 可复现判据（本机终于能复现）

探针 `/tmp/probe8.py`：页面加载后把 `<html>` 滤镜在 `invert(1)` ↔ `none` 间切换，
用 `QWidget.grab()` 采样指纹判断"DOM 变化是否出帧"。

| 时点 | 修复前 | 修复后 |
|---|---|---|
| 正常态改 DOM | 出帧 ✅ | 出帧 ✅ |
| **最小化 → 恢复后改 DOM** | **不出帧 ❌（复现用户症状）** | **出帧 ✅** |

修复后日志可见 `已唤醒渲染器（show）` 与（必要时）`补做硬唤醒（surface 重建）`。
