## 2. 关键实现点

- **终端通道**：`QWebSocketServer` 只绑 `127.0.0.1:0`；每会话随机 token；下行二进制（UTF-8 原始字节），上行 JSON（input/resize/close）；读线程通过 Qt Signal 投递到 GUI 线程。
- **跳板**：`transport.open_channel("direct-tcpip", ...)` 逐跳串联，最多 16 级；链状态通过 `remote.session_status` 事件推给渲染层。
- **主机指纹**：首次暂停认证、发 `remote.hostkey_ask` 事件等渲染层确认（30s 超时拒绝），确认后由 Python 直接写回服务端；已记录指纹不匹配即中止。
- **凭据红线**：`remote.connections_get` 只返回 `has_password` / `has_private_key` 与指纹；打开会话时 Python 直接取全量，不经渲染层。
- **本机终端**：配置存 `LOCAL_STORAGE_DIR/jflove-local.db`；Windows 缺 `pywinpty` 时入口报错但不影响远程终端。

## 4. 已知限制 / 未覆盖

| 项 | 说明 |
|---|---|
| 真实 SSH 服务器联调 | 已用本机 sshd 验证直连/一级跳板/**两级跳板**/启动命令/shell IO；**密码/OTP 认证、跨机跳板未实测** |
| Windows 本机终端 | `pywinpty` 已写入依赖，但本机为 Linux，**未实机验证** |
| SFTP 取消 | 前端未接取消按钮；Python `sftp_cancel` 语义不完整（见审查报告 M-2） |
| 大文件上传 | `SftpView` 上传由 Python 侧完成，渲染层不碰字节；进度按 256KB 节流 |
| 断点续传 | 按设计 v1 不做 |
