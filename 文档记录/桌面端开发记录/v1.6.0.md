## 6. 施工面 4：单实例 + 入口（提交 `19e5506`）

### 6.1 与设计 §6.6.1 的一处**已复现**的修订

设计原定「`listen()` 的返回值即唯一仲裁」。**实测在 Windows 上不成立**：

| 探针 | 实测结果（原始产物在仓库内） |
| --- | --- |
| `poc/editor-probes/r2-local-server-arbitration.py` → `out/r2-arbitration.json` | A（首进程）`listen=True` / `isListening=True` / `errorString=""` / `serverError=UnknownSocketError`；**B 在 A 存活期间对同名 `listen()` 同样返回 `True`**，`errorString()` 与 `serverError()` 与成功时**同值** ⇒ `listen()` 无法仲裁 |
| `poc/editor-probes/r3-single-instance-roundtrip.py` → `out/r3-roundtrip.json` | 三进程真实往返：A `is_primary=True`；B `is_primary=False`（自认第二实例）且 `forwarded=True`（收到 `ack`）；A 收到 `[[["D:\资料\往返 测试.txt"], "single_instance"]]` ⇒ **`all_passed=True`**，中文路径逐字符一致 |

⇒ 实现采用「**连接探测优先 + 自探测**」，并以 `ack` 作为"首实例确实收到"的判据
（设计 §6.6.1 的其余口径：`QLocalServer`/`QLocalSocket`、行分隔 JSON、陈旧 socket 兜底、
