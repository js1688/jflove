# v1.10.11 桌面端开发记录：私钥内容入库 / 密码 + 密钥双因素 / 窗口边缘缩放

> 版本：v1.10.11　角色：cross-platform-desktop　类型：**代码 BUG + 功能缺口**（`AGENTS.md §7.5`）
> 触发：v1.10.10 发布后用户实测反馈（2026-11-17），用户当前对照客户端为 WinSCP
> 影响模块：`jflove-desktop/` + `jflove-server/`（认证方式白名单）；无数据库 DDL

## 1. 问题与根因

| # | 现象 | 根因 |
| --- | --- | --- |
| P1 | 用记事本打开私钥文件、复制**内容**粘贴进表单，连接报「私钥无法解析…not a valid RSA private key file」 | 已与用户确认：那份 `.pem` 的实际内容首行是 `PuTTY-User-Key-File-3: ssh-rsa`（WinSCP 转换后的 PPK），paramiko 不认 PPK，三次尝试后抛最后一条 RSA 异常。另复现出同样报错的 4 种文本形态：每行缩进 / 折叠成一行（或字面量 `\n`）/ UTF-8 BOM / 单行；原实现无任何规范化。用户手里的原始 `-----BEGIN RSA PRIVATE KEY-----` 文件可正常解析 |
| P2 | 「用户名 + 密码 + 私钥 + 私钥口令」无法配置 | `auth_type` 只有 password / publickey / password_keyboard；密钥模式不显示密码，服务端白名单也不认双因素。用户场景是「登录密码 + 私钥口令」两道口令 |
| P3 | 口令错误 / 缺失时提示仍是 paramiko 英文原文 | `load_private_key` 把最后一次尝试的异常直接拼进文案，没有分类 |
| P4 | 部分 `.pem` 解析不了（`BEGIN PRIVATE KEY`） | paramiko 只认 `RSA PRIVATE KEY` / `OPENSSH PRIVATE KEY` 标签；OpenSSL 3 等工具导出的是 PKCS#8 |
| P5 | 私钥文件只能手打/粘贴，且连接时依赖本地文件 | 用户要求（原话）：「读取文件内容，存储到数据库，不要在连接时引用本地文件，我要全放到服务端数据库」。旧实现没有「选择文件」入口，配置里只能存文本或本机路径 |
| P6 | 窗口无法改变大小，只能最大化；拖边缘变成拖窗口 | ① `Qt.Edge` 位值是 **Top=1 / Left=2 / Right=4 / Bottom=8**，前端常量写成了 `left=1 / top=2`，左右与上下热区互换；② 标题栏的 `startSystemMove()` 先于边缘缩放执行，拖上边缘时抢成窗口移动 |

## 2. 方案

### 2.1 私钥：规范化文本 + 选文件读内容入库（P1/P4/P5）

`src/services/ssh_session.py`：

- `load_private_key(source, passphrase)`：
  - 文本先做 `_normalize_pem_text()` 规范化：去 BOM、CRLF→LF、字面量 `\n`→真换行、
    允许整体缩进、单行 base64 重新折行、`Proc-Type/DEK-Info` 头部保留；
  - `.ppk`（内容含 `PuTTY-User-Key-File`）→ 明确提示「这是 WinSCP 转换后的 PPK，请改用原始 PEM，
    或用 PuTTYgen 执行 Conversions → Export OpenSSH key」；
  - `paramiko` 三种 key 类型全失败后，用 `cryptography` 解析 PKCS#8（普通 / 加密），
    再标准化成 OpenSSH 文本交回 paramiko（RSA / ECDSA / Ed25519 共用一条通路）；
  - 异常分类：`PasswordRequiredException` / PKCS#8「Password was not given」→ 提示填口令；
    `Bad password` / `checkint` / `incorrect` → 口令错误或文件损坏；其它保留格式总提示；
  - 兼容旧记录：存量配置若存的是本机路径，仍按「当前目录 → 用户主目录 → 程序目录」解析
    （仅为向后兼容；**新保存的连接不再写路径**）。
- 安全口径（`AGENTS.md §9.13`）：错误文案**不回显完整路径**，只留文件名与查找范围。

`src/bridge/remote.py` 新增：

| 方法 | 作用 |
| --- | --- |
| `remote.pick_private_key` | 原生单文件选择（GUI 线程）→ Python 读取内容 → 预校验（识别 `.ppk` / 是否加密）→ 暂存到内存 `token`，**只回 token + 文件名 + 是否加密**，私钥字节不进渲染层 |
| `remote.validate_private_key` | 保存前校验（文本或 token 对应内容 + 口令），失败直接回可读原因，避免「保存成功、连接才报错」 |
| `connections_create` / `connections_update` | 提交带 `private_key_file_token` 时，桥把文件内容填入 `private_key` 再发服务端；保存成功后清除 token |

渲染层「选择文件…」只拿到 token；保存后服务端数据库里存的是**私钥内容**，
之后连接不再读本地文件。字段里若塞本地路径，桥会拒绝并提示用「选择文件…」。

### 2.2 双因素认证：密码 + 密钥（P2）

- 新增 `auth_type = password_publickey`（「密码 + 密钥」）：
  - 服务端 `AUTH_TYPES` 放开，新建时**密码与私钥都必填**；
  - 表单同时显示「密码」与「私钥（内容/文件）+ 私钥口令」；
  - 列表卡片显示「密码 + 密钥」。
- `SshSession._authenticate` / `_auth_publickey`：
  1. 先 `auth_publickey`；成功即完成；
  2. 服务器回 `PartialAuthentication`（`publickey,password` 顺序）→ 继续 `auth_password`；
  3. 服务器直接不认密钥、只允许密码（`password,publickey` 顺序）→ 先密码，密码 partial 后再补密钥；
  4. 密钥被拒但服务器未给方法列表时，退回密码再试一次（兼容「密码/密钥二选一」的服务器）；
  5. `publickey` 模式若连接里恰好存了密码，也按双因素尝试（兼容旧配置 / API 直写）；
  6. 失败提示带服务器允许的方法（如「服务器允许：password」）。
- **注意**：paramiko 5.x 中 `PartialAuthentication` 与 `BadAuthenticationType` 是**平级**异常
  （partial 不继承 BadAuthenticationType），两者都读 `allowed_types`。

### 2.3 窗口边缘缩放（P6）

`ui/src/components/desktop/TitleBar.tsx`：

- `EDGE = { top: 1, left: 2, right: 4, bottom: 8 }`，与 `PySide6.QtCore.Qt.Edge` 对齐；
- 缩放监听改为**捕获阶段**并 `stopPropagation()`，确保优先于标题栏拖拽；
- 标题栏 mousedown 命中边缘热区时**不再** `startSystemMove()`；
- 窗口按钮（`.win-btn`）优先，避免点按钮上沿 8px 被当成缩放；
- 热区宽度 6px → 8px（更接近原生边框手感）。

## 5. 已知边界

- **PPK 不做解析**（v3 加密依赖 Argon2，引入新依赖与打包风险，且用户手里有原始 PEM）；
  选到 `.ppk` 时会在保存前明确提示改用原始 PEM 或导出 OpenSSH，而不是连接时才报「无法解析」。
- 私钥内容按 D37 用户裁决**明文存服务端数据库**；本版起桌面端不再保存/引用本机路径。
- Windows 真机窗口缩放已在 v1.10.11 安装包上用 **QMP 真实鼠标拖拽**验证：右边缘 1180→1260、
  左边缘 1260→1201、上边缘 760→722（见测试报告 §5）；Linux 无 WM 时 `startSystemResize` 不生效，
  本地只验证热区位值与调用顺序。
- App 端暂不支持 `password_publickey`（模块边界；桌面端创建的该类型连接在 App 端会按密码方式失败）。

### 6.1 P1：SFTP 连上后文件面板不出目录（竞态）

| 项 | 内容 |
| --- | --- |
| 现象 | 标签显示「已连接」，文件面板常驻红字「会话尚未建立」，点「刷新」才有目录 |
| 根因① | 标签在 `session_open` 返回时**立刻**建好并挂载 `SftpView`（`ui/src/stores/remote-store.ts:155`、`ui/src/pages/remote/SessionPage.tsx:395`），此刻 Python 侧还在后台线程建链，`SshSession._transports` 为空 |
| 根因② | `SftpView` 挂载即 `load('.')` 且**只拉一次**（原 `SftpView.tsx:105-107`）；失败后不重试，`remote.session_ready` / `phase=ready` 事件只写进了 store，组件未订阅 ⇒ 红字永久停留 |
| 修复 | `SftpView` 改为按 store 里的会话状态门控：`connecting` 只渲染「会话正在连接，就绪后自动加载目录…」并发起 0 次 `sftp_list`；`ready` 时自动加载一次（`bootedRef` 去重，避免状态抖动覆盖用户当前路径）；`failed/closed` 显示「会话未就绪，请关闭标签后重新连接」；工具条按钮在未就绪时禁用。store 里查不到会话（单测/独立使用）时保持旧行为 |
| 修复（Python） | `ssh_session.py::open_sftp` 未就绪文案改为「会话尚未建立（正在连接中，请稍候）」；`bridge/remote.py::_sftp` 会话不存在时补「可能已断开，请重新打开标签」 |

### 6.2 P2：选 `.ppk` 毫无反应

| 项 | 内容 |
| --- | --- |
| 现象 | 点「选择文件…」，在对话框里点 `.ppk` 没有任何反应（既不显示「已选择」，也没有报错） |
| 根因① | 私钥文件对话框过滤器 `"私钥文件 (*.pem *.key id_rsa* id_ed25519* id_ecdsa*)"` **不含 `*.ppk`**（`bridge/remote.py:175`）⇒ 默认过滤器下 `.ppk` 在原生对话框里是灰色不可选 |
| 根因② | 即使切到「所有文件」选中，拒绝文案写进抽屉**最底部**的 `error`（`RemoteConnectionForm.tsx:314`，在 `overflow-auto` 滚动区内且位于表单末尾）⇒ 用户看不到，观感仍是没反应 |
| 修复 | ① 抽出 `PRIVATE_KEY_FILTER` 常量并补 `*.ppk`、`*.rsa`（`bridge/remote.py:161`）；② 选文件失败时在「私钥内容或文件路径」字段内**就地**显示红色原因并 `toast.error` 一次，再次选择或编辑文本时清除 |
| 保留口径 | 仍**不做 `.ppk` 解析**（v3 依赖 Argon2）。选中 `.ppk` 立即给可执行指引：PuTTYgen `Conversions → Export OpenSSH key` 导出 `.pem`，或 WinSCP 重新导出 OpenSSH 私钥 |
