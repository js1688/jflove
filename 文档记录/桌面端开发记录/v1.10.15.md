# 桌面端 v1.10.15（远程连接：旧服务器 SSH 认证残余失败迭代）

> 分类：**代码 BUG**（`AGENTS.md §7.5.3` 快速修复通道；用户指定新版本号 `v1.10.15`）
> 来源：用户 2026-11-19 反馈 + Windows 端 v1.10.14 实机日志（`%LOCALAPPDATA%\JFLove\logs\app.log`）
> 计划：`plans/v1.10.15-remote-legacy-ssh-residual.md`
> 影响模块：仅 `jflove-desktop/`（服务端 / 数据库 / 加密协议不改）

## 1. 用户日志给出的根因（不再靠猜）

用户日志关键片段（v1.10.14，Windows）：

```text
17:22:59 [INFO] [src.services.ssh_session] SSH 协商完成：远端=SSH-2.0-Maverick_SSHD 主机密钥=ssh-rsa KEX=未知
...
17:29:26 [INFO] [src.services.ssh_session] 公钥认证未通过，尝试旧式 ssh-rsa 签名（远端版本：SSH-2.0-Maverick_SSHD）
```

失败提示形如「服务器未接受当前密钥（私钥；服务器允许：publickey）」。把日志与代码对上后结论是：

| 步 | 发生了什么 | v1.10.14 的处置 |
| --- | --- | --- |
| ① 首轮 publickey（`rsa-sha2-512`） | Maverick 一类 Java SSH 服务端**不认 rsa-sha2**，验签失败 | 回退 **ssh-rsa**（这条日志就是证据） |
| ② 回退 ssh-rsa | 验签**成功**，但服务端回 **部分认证**（`partial=true`，仍只允许 `publickey`） | 回退后**立刻恢复** `rsa-sha2` 算法表；`_continue_auth` 还会再试一次 publickey，但用的是 `rsa-sha2` ⇒ 又被拒 |
| ③ 本应补一轮 `ssh-rsa` | 只有继续用 `ssh-rsa` 才能走完这一步 | `MAX_METHOD_ATTEMPTS["publickey"]=2`：首轮 + 回退已经用满 2 次，**根本不会发第 3 次** |

另有次要问题（同一日志里也有）：

- `server-sig-algs` 与实际能力不符（扩展写 `rsa-sha2-*`，实际只认 RSA-SHA1）时，v1.10.14 的门槛
  「扩展里必须出现 `ssh-rsa`」直接阻止回退；即使强行回退，paramiko 也会因「扩展与本端清单无交集」抛
  `Unable to agree on a pubkey algorithm`，**请求根本没发出去**。
- 失败后没有可复制的协商事实，只能反复靠用户贴日志。
- 服务器要求「两把不同私钥」时，错误文案让用户去查 `authorized_keys`，方向不对。

## 2. 本版修复

### 2.1 ssh-rsa 模式**持续到本轮认证结束**

`_attempt_legacy_rsa` 不再是「发一次就恢复」，而是进入旧式模式：

- `_enter_legacy_rsa()`：暂存 `_preferred_pubkeys` 与 `server-sig-algs`（哨兵区分「扩展缺失」与「值为空」），
  然后置 `("ssh-rsa",)` 并**摘掉** `server-sig-algs`；
- 直到 `_authenticate` 结束（成功/失败/异常）由 `finally` 调 `_exit_legacy_rsa()` 恢复。

这样回退之后的任何一次 publickey（包括服务器「部分认证」后要求补的那一轮）都继续用 `ssh-rsa`。

### 2.2 publickey 最多 3 次

`MAX_METHOD_ATTEMPTS["publickey"] = 3`：首轮 + 回退 + 部分认证后的补一轮。
正是用户这台 `Maverick_SSHD` 需要的三步链（第 1 次算法不匹配、第 2 次才验签成功、第 3 次走完）。

### 2.3 回退门槛解除 `server-sig-algs`

`_can_retry_legacy_rsa` 只在「真实 paramiko transport + RSA 私钥 + 首轮未完成认证 +
transport 仍活着 + 不是 `rejected`」时回退；`server-sig-algs` 不再作为门槛（旧网关该扩展不可信）。

### 2.4 诊断行（不含凭据）

认证失败的错误信息末尾追加：

```text
诊断：远端=SSH-2.0-Maverick_SSHD；主机密钥=ssh-rsa；KEX=diffie-hellman-group14-sha1；
服务器签名算法=rsa-sha2-512,rsa-sha2-256；本次签名算法=rsa-sha2-512；
私钥=ssh-rsa(2048位)；首轮结果=failed；ssh-rsa 回退=ok
```

并写 INFO 日志（`SSH 认证失败诊断：…`）。字段全部来自协商结果，**不含密码 / 私钥正文 / 口令**。
界面（`ui/src/pages/remote/SessionPage.tsx`）把失败条从单行截断改为**完整换行 + 「复制详情」**。

### 2.5 二次密钥认证的明确文案

「已接受密钥、仍要求再一次 publickey 且没有其它方式可选」时说明：

> 服务器已接受密钥，但仍要求再次进行密钥认证（常见于要求两把不同私钥的网关）；
> 当前每条连接只支持一把私钥，请在服务器侧确认是否需要第二把密钥

### 2.6 多跳链路定位

`open()` 里认证/主机指纹失败统一加 `跳板 N / 目标 + host:port` 前缀。

### 4.1 真实 paramiko 服务证据（新增用例）

- **`Maverick_SSHD` 三步链**（真实 paramiko 服务端：拒绝 `rsa-sha2` 签名；第 1、2 次回部分认证，
  第 3 次才放行）：`is_authenticated() == True`，服务端收到的签名算法依次为
  `rsa-sha2-512 → ssh-rsa → ssh-rsa`，密钥类型 3 次均为 `ssh-rsa`。
- **扩展谎报**（`server-sig-algs` 只写 `rsa-sha2-*`，实际只认 RSA-SHA1）：仍能回退并认证成功。
- **部分认证永远不放行**：给出「两把不同私钥」文案，并写出诊断行。
- **密钥被拒**：错误信息含 `诊断：` / `远端=` / `服务器签名算法=`，不含私钥 PEM 正文。
- **断链**：`_can_retry_legacy_rsa` 返回 False（不再无谓回退）。

## 5. 已知边界

- **两把不同私钥的服务器仍不支持**：数据模型每条连接只有一把私钥
  （`ssh_connections.private_key`）；本版只把文案说清楚。
- 只支持 `ssh-dss`（DSA）主机密钥的服务器仍不支持（paramiko 4.0 已移除 DSA）。
- 回退依赖 paramiko 私有属性（`_preferred_pubkeys` / `server_extensions`）；依赖 pin 4.0.0，
  升级前必须跑 `test_remote_legacy_ssh_v1_10_14.py` + `test_remote_legacy_ssh_v1_10_15.py`。
- 若服务器把「部分认证」当作限流手段、`MaxAuthTries` 极小（如 2），本版的三步链可能仍被断；
  此时错误里的 `诊断：` 会如实给出每一步结果。

## 6. 用户复验方式

1. 用 v1.10.15 安装包复连 `Maverick_SSHD` 那台（及另外几台报同样错误的）。
2. 若仍失败：把界面报错里 `诊断：` 开头那一行（或日志里 `SSH 认证失败诊断：` 行）发回来；
   据此可区分「扩展谎报 / 两把私钥 / 凭据不在 authorized_keys / DSA-only」。
