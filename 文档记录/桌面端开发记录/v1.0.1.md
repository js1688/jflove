## 二、改动 1：权限管理页布局修复

### 2.1 问题现象

打开「权限配置」页面时，顶部出现一大片空白，整个 `QSplitter`（包含用户列表与权限表格）被压缩到下半部分，与「用户管理」「磁盘管理」等其它管理页的布局边距不一致。

### 2.2 根因分析

页面根布局只有两个子项：

```python
layout.addWidget(SubtitleLabel("权限配置"))   # 标题
layout.addWidget(splitter)                     # 用户+权限分栏
```

`QSplitter` 在垂直方向的 `sizePolicy` 默认为 `Preferred`，与 `SubtitleLabel`（同样 `Preferred`）相同。Qt 的 `QVBoxLayout` 在两个 `Preferred` widget 之间会按各自的 `sizeHint().height()` 比例分配剩余空间——结果 `SubtitleLabel` 被强行拉伸到接近一半页面高度（实测 1100×700 窗口下 SubtitleLabel 占 328 px），看起来就是"标题与正文之间一大片空白"。

对比「磁盘管理」「用户管理」：根布局尾项是 `QTableWidget`（`sizePolicy=Expanding`），它优先吃掉剩余空间，标题保持 `sizeHint` 高度，因此没有此问题。

### 2.3 修复

[permission_page.py:108](../../jflove-desktop/src/ui/pages/admin/permission_page.py#L108) 把 `splitter` 的 stretch 因子显式设为 1：

```python
# 修复前
layout.addWidget(splitter)
# 修复后
layout.addWidget(splitter, 1)   # stretch=1，吸收所有剩余垂直空间
```

加注释说明动机，避免后续开发者误删。

### 2.4 修复后实测

| 控件 | 修复前高度 | 修复后高度 |
|---|---|---|
| SubtitleLabel | 328 px | 29 px（=单行 sizeHint） |
| QSplitter | 328 px | 627 px（=吸收所有剩余空间） |

视觉上现在与其它管理页边距完全一致。

## 三、改动 2：服务器地址历史下拉

### 3.1 用户故事

- 同一个客户端经常需要切换连接的服务端（开发环境 / 测试环境 / 生产环境 / 多台 NAS）
- 之前只能记 URL 手动输入，每次切换都要打字
- 设置页有一个相同的"服务端地址"输入框，跟登录页是两套独立逻辑

### 3.2 设计

#### 3.2.1 新 service：`src/services/server_history_service.py`

| 接口 | 行为 |
|---|---|
| `list_history() -> list[str]` | 返回历史地址列表，最近使用的在前；无历史返回空 |
| `get_default() -> str` | 历史首项；为空时返回兜底 `http://localhost:8989` |
| `record(url: str) -> None` | 在登录或重连**成功**后调用，写入历史并置顶；自动去重（含末尾斜杠）；超出 10 条按最旧淘汰 |

存储位置：`storage/server_history.json`，与现有 `LOCAL_STORAGE_DIR` 约定一致。

写入策略：

- 仅持久化字符串 URL，不带任何 token / session_key / 用户名等敏感字段
- 用 `os.replace` 做原子替换，避免半写文件污染缓存
- 全部 IO 异常 try/except 吞掉并打日志，不让本地缓存问题阻断登录主流程
- 仅在密钥交换**成功**后调用 `record()`，避免误输入污染列表

#### 3.2.2 UI 控件：`EditableComboBox`

`PySide6-Fluent-Widgets` 自带 `EditableComboBox`，同时具备：

- 下拉选择（项来自 `list_history()`）
- 手动输入（输入新地址时不影响下拉项）
- `currentText()` 取当前文本（无论是选中的还是手输的）

无需引入新依赖。

### 3.3 登录窗口 [login_window.py](../../jflove-desktop/src/ui/login_window.py)

#### 修改前

```python
self._server_url_input = LineEdit()
self._server_url_input.setText("http://localhost:8989")
# ... _on_connect 中：
server_url = self._server_url_input.text().strip()
```

#### 修改后

```python
self._server_url_input = EditableComboBox()
self._refresh_server_history()    # 加载历史 + 设置默认值
# ... _on_connect 中：
server_url = self._server_url_input.currentText().strip()
self._pending_server_url = server_url   # 暂存，连接成功后写入历史
# ... _on_connect_done 中：
server_history_service.record(self._pending_server_url)
self._refresh_server_history()
```

下次启动时，`_refresh_server_history()` 会自动把上次成功连接的地址作为默认值显示。

### 3.4 设置页面 [settings_page.py](../../jflove-desktop/src/ui/pages/settings_page.py)

逻辑与登录页**完全一致**（共用 `server_history_service`），区别仅在显示初值的优先级：

| 优先级 | 来源 |
|---|---|
| 1 | `session_manager.server_url`（当前正在使用的地址） |
| 2 | `server_history_service.get_default()`（历史首项） |
| 3 | `http://localhost:8989`（兜底） |

也即：进入设置页时默认显示当前正在用的地址，而不是历史首项；切换成功后历史会与登录页同步。

`QSettings("server_url")` 仍然保留写入，跟历史并存（不破坏 v1.0 的兼容行为，下次清理时再移除）。

### 3.5 安全宪法对照

- ✓ 历史文件只存 URL 字符串
- ✓ 不存 token / session_key / 密码 / username
- ✓ 不在 URL 上拼接业务参数（地址本身仅是 hostname:port）
- ✓ session_manager 持久化字段未变化（仍只有 token / username / role / user_id / expires_at）
