# 桌面端 v1.10.16（远程连接：网关多因素认证序列修正）

> 分类：**代码 BUG**（`AGENTS.md §7.5.3` 快速修复通道；用户指定新版本号 `v1.10.16`）
> 来源：用户 2026-11-19 在 v1.10.15 Windows 实机上的两种报错（同一台 WinSCP 能连、jflove 不能的旧网关）
> 计划：`plans/v1.10.16-remote-gateway-multifactor.md`
> 影响模块：仅 `jflove-desktop/`（服务端 / 数据库 / 加密协议不改）

## 1. 根因（本地 paramiko 模拟网关复现，不靠猜）

用户 v1.10.15 的诊断行：`远端=SSH-2.0-UNLAWFUL ENTRY…（网关横幅）；主机密钥=ssh-rsa；
服务器签名算法=rsa-sha2-512,…；私钥=ssh-rsa(4096位)；首轮结果=ok（服务器允许：password）；ssh-rsa 回退=ok`。

`首轮结果=ok（服务器允许：password）` 这句话说明：**密钥这一步已经通过**，服务器只差账号密码。
但客户端此时仍做了三件错事：

| # | 错误动作 | 后果 |
| --- | --- | --- |
| 1 | `_can_retry_legacy_rsa(status="ok")` 为真 ⇒ 回退又发了一次 `publickey` | 网关把「已接受密钥后又来一次」当成「还差一把密钥」⇐ 用户报错①「需两把不同私钥」 |
| 2 | `_pick_next_method` 里 `publickey` 与 `password` 同轮竞争，密钥被排在密码之后 | 多打认证往返，且干扰网关状态机 |
| 3 | `password` 被拒后 `allowed` 变空集（paramiko 普通失败不回传 authlist）⇒ 直接放弃 | 第二个因子实际在 `keyboard-interactive` 时永远试不到 ⇐ 用户报错②「账号密码没有被接受」 |

复现（本地真实 paramiko 服务，改造前后对比）：

```text
改造前：publickey#1 → partial(password) → publickey#2 → partial(publickey) → password
改造后：publickey#1 → partial(password) → password                         ← 与 WinSCP 一致
```

## 2. 修复

### 2.1 密钥只发一次（`_can_retry_legacy_rsa`）

回退门槛从「`status != "rejected"`」改为：

- `rejected` ⇒ 不回退（方式本身被拒）；
- 服务器在 `allowed` 里给了 `publickey` 之外的方式（典型 `{"password"}`）⇒ **绝不回退**：
  密钥已过，再发只会被当成「还差一把密钥」；
- 已处于 `ssh-rsa` 模式（`_jflove_legacy_backup` 非空）⇒ 不再重复进入；
- 其余（裸失败 / 只列 `publickey`）⇒ 仍回退，保留 `Maverick_SSHD` 一类旧服务端的兼容性。

### 2.2 按服务器实际列表补齐（`_continue_auth` / `_pick_next_method`）

- 每轮以服务器**最新**的 `allowed` 为准（多因素网关会中途换列表），并另行累计
  `offered`（公布过的方式集合）用于文案；
- `keyboard-interactive` 不再要求本地有密码（网关常把第二因子放在 `Password:` 提示里，
  由 `_make_interactive_handler` 代答；没密码时弹层补）；
- 同一凭据**不重复打**：`status == "failed"` 的方式进入 `failed` 集合，后续换因子；
- `key_accepted=True` 且服务器另列了别的因子时，`publickey` 从候选里移除。

### 2.3 诊断与文案

- 诊断行新增 `认证序列=publickey→password`（只含方法名，不含任何凭据）；
- `_auth_hint` 接收 `trace`，文案里带「本次已发送：…」；
- 「账号密码没有被服务器接受」的文案改为指出**最可能是登录密码不对**，并给出「改用密码 + OTP」
  的下一步；「需两把不同私钥」的文案只在真的重发过密钥时才出现。

网关场景（本地真实 paramiko 服务，断言服务端侧实际收到的序列）：

| 场景 | 结果 |
| --- | --- |
| 密钥一次通过 → 密码 | `publickey#1 → password` ✅ 与 WinSCP 一致 |
| 网关对「第二次密钥」回 partial（复刻用户报错①） | 不再发生第二次密钥 ✅ |
| 第二因子只在 `keyboard-interactive`（复刻用户报错②） | `publickey → password → keyboard-interactive` ✅ 连上 |
| 密码确实错误 | 报「账号密码没有被服务器接受」，带 `认证序列=publickey→password` ✅ |

**已知边界**：真正的「两把不同私钥」网关仍不支持（每条连接只支持一把私钥）；
需要在服务器侧改成单密钥或另用跳板。

## 5. 用户侧复验

装 v1.10.16 后连同一台网关，应直接连通。若仍失败，请把界面整条 `诊断：…`（含新增的
`认证序列=`）发回 —— 它会直接显示「发过哪些认证、服务器最后还要求什么」。
