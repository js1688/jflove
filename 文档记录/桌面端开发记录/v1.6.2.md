## 2. 本版修的两个缺陷（根因与修法都留痕）

### 2.1 工具箱 10 项「点了完全没反应」

- **根因**：`ScratchToolbar` 的"选完即关"挂在弹框容器的 `onPointerUpCapture`。真实浏览器里
  `pointerup` 与 `click` 是**两个 task**，React 在 `pointerup` 之后同步提交 ⇒ 被点的按钮
  **在 `click` 派发之前被卸载** ⇒ Chromium **不再派发**这次 `click` ⇒ 按钮的 `onClick` 永不执行。
  受害面 = `MENU_STAYS_OPEN`（`sql` / `font`）之外的 **10 项、约 29 个按钮**。
- **真机证据**（`r21`，最小 DOM + OS 级真鼠标，不含 React 与应用）：

  | 模式 | `#out` | `window.__log` | 按钮仍挂载 |
  |------|--------|----------------|-----------|
  | `no-close`（守门对照） | `CLICKED` | `['doc-pointerup','doc-click:b','button-click']` | True |
  | `pointerup-capture`（**改前**） | `NOT-CLICKED` | `['doc-pointerup','close']` | **False** |
  | `click-bubble`（**改后**） | `CLICKED` | `[...,'button-click','close']` | False |

- **为什么 v1.6.1 的用例全绿（假通过）**：`__tests__/scratch-toolbar-labels-menu-ac74-ac76.test.tsx`
  的 `pressButton()` 把三事件塞进**同一个 `act()`** ⇒ React 提交被推迟到 `click` 之后。
- **修法**：关框委托搬到容器的 `onClick`（冒泡）—— 被点按钮的 `onClick` 天然先执行，随后关框；
  判定逻辑（白名单 / 非按钮 / `disabled`）**一字未改**，AC-76 语义不变。

### 2.2 两段文本对比「打开也只有一条缝」

- **根因**：工具栏根元素带 `relative` ⇒ 子节点 `absolute inset-0`（对比覆盖层）的包含块是
  **工具栏**（一行高）；而 `EditorPanel.tsx` 的注释本就写明"定位祖先必须是本面板根元素"。
  叠加 2.1 的缺陷（「打开对比」按钮本身在受害面内）⇒ 用户看到的就是"完全没效果"。
- **修法**：根元素去掉 `relative`，把 `relative` 下移到"内容层"（工具箱弹框在该层内定位，
  外观与右侧不裁切行为不变）；两个覆盖层（对比 / 跨标签搜索）挂在**根元素**下 ⇒ 包含块 = 编辑面板根。
- **判据**：真机 `r22.M3`（覆盖层高度 ≥ 面板 90%）+ **注入式变异**（把 `relative` 放回根 ⇒ `M3` FAIL）。

### 7.6 最容易踩的三个坑（本版实测）

1. **事件顺序类缺陷，jsdom 的 `act()` 会掩盖**：工具箱点击类用例**必须**把

2. **Qt 虚函数里的 Python 异常会被静默吞掉**：外壳侧新增任何 `QWebEngineView` / `QWebEnginePage` 覆写时，
   先用 `r22 --diag-menu` 那种"打点"方式确认覆写**真的被调用**、且参数取对了对象
   （`lastContextMenuRequest()` 属于 **View**，不属于 Page）。
3. **新增/修改快捷键必须跑 `r23-keymap-collision.py`**：我们的运行时机在 window **捕获**阶段

## 8. BUG 修复（同日重发 v1.6.2）：Fedora 安装后启动即 SIGSEGV

> 归类：**纯代码 BUG**（`AGENTS.md §7.5.3` 快速修复通道）。需求 / 设计无变化，版本号按用户裁决**保持 1.6.2**；
> 发布方式 = 删除旧 `v1.6.2` tag 与 Release，在新提交上重发同版本产物。

### 8.1 现象与根因

用户 Fedora 装 RPM 后打开即崩（`coredumpctl`：`Signal: 11 (SEGV)`，PID 8560）。主线程关键帧：

| # | 帧 | 说明 |
| --- | --- | --- |
| 1 | `PySide::getWrapperForQObject(QObject*, _typeobject*)` | 崩在 PySide 给 QObject 生成 Python 包装 |
| 4 | `QCoreApplicationPrivate::sendThroughApplicationEventFilters` | **只有装在 `QApplication` 上的事件过滤器**才走这条链 |
| 16 | `QQuickDeliveryAgentPrivate::setFocusInScope` | 窗口激活 / focus 分发时触发 |

全仓库唯一的应用级过滤器 = v1.6.1（提交 `9043458`）为 F6「IDEA 复制代码贴不进来」加的
`_app.installEventFilter(self.paste_normalizer)`（旧 `src/ui/web_shell.py` 安装点）。

**根因**：应用级 Python 事件过滤器让 PySide6 为**每一个**事件接收者生成 Python 包装（含 QtWebEngine /
Chromium 内部对象）；Linux/X11 窗口激活分发 focus 事件时在 `getWrapperForQObject` 段错误。
PySide6 6.8 / 6.11 均有同款最小复现（`QWebEngineView` + `app.installEventFilter(obj)` 必崩；
同一个过滤器改挂普通 `QWidget` 则正常）：<https://stackoverflow.com/questions/79177330>。
Win32 同代码不崩（本机探针：应用级过滤器只看到 `QWidget` / `QWindow` / `QObject` 等已知类型），
因此只在 Fedora/Linux 暴露。

### 8.2 修法（两条，互相独立）

1. **过滤器只挂渲染 widget**：`QWebEngineView.focusProxy()`（按键真正的落点，类型是 `QWidget`）。
   新增 `WebShell._ensure_paste_filter()`（幂等；换目标先摘旧再挂新）与 `_on_view_load_finished()`；
   挂载时机 = `showEvent()`（`focusProxy()` 首次 show 才创建，实测）+ `loadFinished`（页面重载补挂）。
   `eventFilter` 语义、计数、`CLIPBOARD_NORMALIZE_ENABLED` 判据**全部不变**。
2. **平台门禁**：`CLIPBOARD_NORMALIZE_ENABLED=False`（非 Win32）时**一个过滤器都不安装** ——
   F6 在 Linux 本来就不生效（`text/uri-list` 在 X11 是"复制文件"的载体），从构造上排除崩溃路径。

挂不上时**只告警一次**（不允许 BL-51 式"配了没反应"的静默降级）。
