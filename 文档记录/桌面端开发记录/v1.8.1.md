## 2. 进度条终态口径（D15 / AC-255）

### 2.1 根因

`taskPercent()` 只按 `bytes_done / bytes_total`（其次项数）计算，**没有先判断 `status`**：

```ts
// 修复前
const total = Number(task.bytes_total) || 0;
const done = Number(task.bytes_done) || 0;
if (total > 0) return clamp((done / total) * 100);
```

成功任务的 `bytes_total` 是分析阶段的**估算值**，与实际 `bytes_done` 不完全相等，
于是出现「状态已完成、进度 99%」。移动端 `OfflineTask.progress` 第一行就是
`status == 'success' → 1`，所以三端显示不一致。

### 2.2 修复

```ts
export function taskPercent(task: {
  status: string; bytes_done: number; bytes_total: number;
  item_done: number; item_total: number;
}): number {
  if (task.status === 'success') return 100; // 产品口径：已完成一律满格
  // 其余状态保持字节优先、项数次之
}
```

- 调用方 `TaskList.tsx:200` 传的是完整 `OfflineTask`，只改类型签名；
- 失败 / 取消保持现有百分比，不清零。

### 2.3 单测

`offline-utils.test.ts` 新增：

| 用例 | 期望 |
|---|---|
| `success + 99/100` | 100 |
| `success + 0/0` | 100 |
| `success + 1/4 项` | 100 |
| `downloading + 50/200` | 25（旧口径不回归） |
| `merging + 300/200` | 100（clamp 保留） |

## 3. 服务器目录选择器（D14 / AC-257）

### 3.1 接口

`GET /api/v1/virtual-disks/server-dirs`（管理员、只列目录、加密 query 信封）。
桌面端 `diskService.browseServerDirs()` 走 `httpClient.get` → Python 桥 `api.request`
→ `src/utils/http_client.py`，**渲染层不直接出网**（AGENTS §9.6）。

### 3.2 交互

1. 添加 / 编辑磁盘 → 点「浏览…」→ 打开 `ServerDirPickerModal`；
   - 创建：`initialPath = createPath`（空 = 服务端 roots 第一项）；
   - 编辑：`initialPath = editPath`（当前真实路径）。
2. 顶部显示当前绝对路径；「上级」用服务端返回的 `parent`，不客户端拼字符串；
3. 「根目录」跳到 `roots[0]`；roots 快捷按钮（`/`、`~`、`/storage`、`/data`、盘符）；
4. 目录点击进入；「选择此目录」回填并关闭；
5. 加载 / 空 / 错误态中文；错误**不关闭弹窗**，可重试；
6. `truncated=true` 时提示「目录过多，仅显示前 2000 项」。

### 3.3 安全

- 路径只在加密请求体内，不出现在 URL 明文；
- 渲染层无网络出口，没有新增 fetch/axios；
- 组件不缓存文件信息，只消费服务端返回的目录名与路径。
