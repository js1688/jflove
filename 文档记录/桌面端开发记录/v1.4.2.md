# v1.4.2 桌面端开发记录：播放纯净化 + 修复中心 + seek 回归修复

## 一、变更概述

| 编号 | 变更 | 说明 |
|------|------|------|
| DESK-1 | **StreamProxy 纯 byte 化** | 删除 time 分支 / `seek()` / `_seek_seconds` / `_seek_version` / `duration`；URL 不再带 `?v=`；HEAD 恒声明 `Accept-Ranges: bytes`；新增 `repair_task_id` 透传（验证播放）与 `last_error`（识别损坏错误码） |
| DESK-2 | **seek 回归修复（BUG-10b 根除）** | `_on_slider_released` 恢复 `setPosition()` 原生 seek（v1.4.1 曾无条件重拉流导致健康文件拖拽后从头播放）；删除 `_seek_offset_ms` / `_hint_timer` / `_update_duration_hint` |
| DESK-3 | **损坏播放引导** | `_MediaView._on_error` 识别 `[MEDIA_NEEDS_REPAIR]` → 弹「文件已损坏 + 立即修复」MessageBox → 调 create API → InfoBar 提示去修复中心 |
| DESK-4 | **右键「修复损坏媒体」** | 文件页右键菜单（仅音视频文件；要求 can_write 且 can_delete 并存，权限不足不显示）；健康文件由服务端拒绝（「无需修复」） |
| DESK-5 | **修复中心页面（新增）** | 全平台共享任务列表 + 2.5s 轮询 + 按状态操作（取消/验证播放/覆盖[重点二次确认]/删除产物/删除记录）；只读账号按钮禁用 |
| DESK-6 | **设置页改造** | 移除「实时修复总开关」；保留「允许重编码降级」与「修复并发数」（作用于离线队列） |
| DESK-7 | **验证播放** | `PreviewDialog` 新增 `repair_task_id` 参数：经 StreamProxy 走 `/stream?repair_task_id` 加密流播放修复产物 |

## 三、关键设计取舍

1. **seek 回归修复方式 = 删除 time 逻辑而非修补**：v1.4.1 为消费实时修复流引入的「重拉 + 偏移补偿」整体删除，`setPosition()` 恢复字节 Range 原生 seek。服务端 v1.4.2 已无 time 流，两端的复杂度同步归零。
2. **损坏识别走 `StreamProxy.last_error`**：服务端 415 detail 经解密后由 http_client 抛 ApiError，代理线程捕获存入 `last_error`；播放器报错时 `_MediaView` 检查该字段——避免另起一轮服务端探测。
3. **修复入口权限 = 客户端 can_write + can_delete 双重判断**：服务端 disks 接口 v1.4.2 起返回 `can_delete`；客户端两标志并存才显示菜单项，权限不足直接不可见（接口仍 403 兜底）。
4. **验证播放复用 PreviewDialog**：`repair_task_id > 0` 时 StreamProxy 透传参数、服务端流式返回产物（faststart MP4，健康文件直读），零新增播放管线。

## 五、验证方式（用户侧）

1. 本地 `python src/main.py` 启动（或 PyInstaller 产物）。
2. 文件管理右键一个损坏视频 →「修复损坏媒体」→ 提示已入队。
3. 「修复中心」查看进度 → 成功 → 「验证播放」预览产物 → 「覆盖原文件」二次确认 → 原位置为修复版。
4. 健康 MP4 播放拖拽进度条：从目标点继续播放（v1.4.1 回归已修复）。
5. 损坏文件双击预览：弹「立即修复」引导。
