## 四、修改前后的逻辑对比

### 4.1 401 处理路径

**v1.1.0**：

```
任意请求 → 401 → _parse_response 直接抛 ApiError
                  → UI 弹"会话已过期"或显示错误
                  → 用户被强制踢回登录
```

**v1.1.1**：

```
任意请求 → 401 → _send_with_auto_resync 拦截
                  ├── detail 是 ECDH 类 → resync_session() → 重发 → 200
                  └── detail 是 JWT 类  → 抛 ApiError → MainWindow 计时器/调用方触发登出（受 _logout_in_flight 约束）
```

### 4.2 登录到期判定

**v1.1.0**：

```python
if session_manager.token_expires_at and time.time() >= session_manager.token_expires_at:
    弹 MessageBox + logout
```

**v1.1.1**：

```python
if self._logout_in_flight:
    return
effective = session_manager.effective_expire_at()
# = min(token_expires_at, key_exchange_time + local_session_max_seconds)
if effective and time.time() >= effective:
    self._logout_in_flight = True   # 抢占在 MessageBox.exec() 之前
    弹 MessageBox + _do_logout
```

### 4.3 登录窗 / 主窗口切换

**v1.1.0**：直接覆盖全局变量 `_login_window` / `_main_window`，异常路径可能产生短暂双窗口。

**v1.1.1**：每次切换前显式 `close()` + 置 `None`；恢复登录窗时若发现 `_login_window` 已存在则只 `show / raise / activateWindow`，避免新建。

## 五、关键设计思路与取舍

1. **不做 JWT 自动续期**：与用户在 v1.1.1 需求阶段明确达成的取舍。理由：
   - 自动续期等价于"长期 token"，与 §9.2 PFS 精神冲突；
   - 用户希望"安全 > 便利"，到期 = 退出更直观可控；
   - 已通过"登录有效期下拉"把控制权交给用户。
2. **ECDH 续约不写 QSettings**：续约可能在并发请求触发下高频发生；session_id / session_key 本就不持久化（§9.2 第 6 条）；故 `resync_session()` 不调用 `_save_session()`。
3. **单飞续约用 Condition 而非简单锁**：等待方需要在续约完成后被唤醒，而不是排队等下一个独立续约；Condition + 标志位是标准实现。
4. **续约只发生 1 次**：避免服务端持续异常时的请求风暴。第二次仍 401 直接抛 `ApiError`，由调用页的"网络错误"路径处理。
5. **流接口续约只在建连阶段**：一旦帧流开始读取，session_key 已被服务端 generator 持有；中途换密钥救不回该流，故仅对 `requests.request(...)` 这次系统调用做续约保护，后续逐帧 `parse_stream_frame` 失败按网络错误处理（StreamProxy 现有逻辑会让 FFmpeg 下次 Range 触发自动恢复）。
6. **`_logout_in_flight` 在 `MessageBox.exec()` 之前抢占**：`exec()` 是阻塞但 Qt 内部仍跑事件循环，60s 定时器可能再次触发 `_check_token_expiry`；先置标志再弹窗，避免出现"两个登录已过期对话框堆叠"。
7. **`local_session_max_seconds` 不随登出清除**：它是用户偏好（与"上次连接的服务端地址"性质相同），跨会话保留。
