> 版本：v1.10.7　角色：cross-platform-desktop　类型：**代码 BUG 快速修复**（`AGENTS.md §7.5.3`）
> 基线：`文档记录/需求文档/v1.10.0.md` §本机终端、`文档记录/设计文档/v1.10.0.md` §3.7
> 上一版结论：`文档记录/测试报告/v1.10.6.md` §11（v1.10.6 只补了诊断日志与前端监听，**未修掉黑屏**）

## 1. 问题与根因

**现象**（v1.10.6 发布包，KVM 真机 Windows 10 22H2 实测）：远程连接 → 本机配置 → 打开，
tab 显示绿点「已打开」，终端区域**全黑、无 banner、无提示符**，键盘输入无回显；
`app.log` 只有

```text
[src.services.local_terminal_service] 本机终端启动：shell=…\powershell.exe args='' cwd=''
[WARNING] pywinpty spawn 不接受 cwd/env，降级为仅命令
[src.services.local_terminal_service] 本机终端已启动（pywinpty）：…\powershell.exe
[src.components.terminal_host] 终端通道已连接：sid=…
```

之后**没有任何异常、没有任何输出**。

**根因（真机 + 官方 wheel 双向取证）**：

| 取证 | 结果 |
| --- | --- |
| 发布包 `_internal\winpty\` 内容 | 只有 `conpty.dll` / `winpty.dll` / `_winpty.cp314-win_amd64.pyd` |
| `pywinpty==3.1.2` 官方 wheel 内容 | 另有 **`OpenConsole.exe`（1.09MB）**、**`winpty-agent.exe`（2.63MB）** |
| 客机进程树 | JFLove 下只有 `conhost.exe`，**没有 `powershell.exe`** 子进程 |
| 把两个 exe 复制进已安装目录后重启 | 终端立刻出 `Windows PowerShell` banner + `PS C:\…>`，`echo` 回显正常 |
| 删掉两个 exe 再重启 | 又回到全黑（`.xterm-rows` 只剩一个空格） |

→ PyInstaller 只收集了 pywinpty 的 DLL/`.pyd`，**没收集它的两个运行时助手 exe**；ConPTY 因此起不来，
`PTY.spawn()` **返回 `False` 而不抛异常**，旧实现忽略返回值并打印"已启动"，
前端于是显示绿点、画面全黑。

**调用契约也一并错着**（`pywinpty 3.x` `_winpty.PTY.spawn`）：

```python
spawn(appname: str, cmdline: str|None = None, cwd: str|None = None, env: str|None = None) -> bool
# appname = 可执行文件路径（不是整条命令行）
# env     = "K=V" 以 \0 分隔的字符串（传 dict → TypeError，正是日志里那条 WARNING 的来源）
```

旧实现把整条命令行当 `appname` 传、`env` 传 dict，靠 `except TypeError` 降级，
代价是 **cwd / env 配置被静默丢弃**。

## 2. 改动内容

| 文件 | 改动 |
| --- | --- |
| `jflove-desktop/build.py` | 新增 `WINPTY_DATA_FILES`、`winpty_data_args()`、`assert_winpty_bundled()`；Windows 分支把两个助手 exe 以 `--add-data <src>;winpty` 打进包；pyinstaller 成功后**复查产物**（缺文件 → 构建失败） |
| `jflove-desktop/src/services/local_terminal_service.py` | `_open_windows()` 按契约调用 `spawn(appname, cmdline, cwd, env)` 并**检查返回值**（False → `RuntimeError`）；新增 `_winpty_cwd()`（不存在则回退主目录）、`_winpty_env()`（`K=V\0` 串；无自定义变量传 `None` 继承） |
| `jflove-desktop/tests/test_winpty_bundle_v1_10_7.py` | 新增 8 条回归用例（Linux 可跑）：打包参数、缺文件 fail、产物复检、`run_pyinstaller` 传参、spawn 契约（appname/cmdline/cwd/env）、`env=None` 分支、**spawn 返回 False 必须抛错** |
| `version.json` + 9 处派生 | 1.10.6 → 1.10.7（`scripts/sync_version.py`） |

**为什么门禁要在"构建后"再查一遍**：`--add-data` 参数写对、产物里却没有（被清理/被忽略）时，
安装包照样能出、程序照样能启动，只有打开本机终端才全黑 —— 只有查产物拦得住。
同理，`assert_winpty_bundled` 在 `prepare_output_name()` 改名（`JFLove` → `JFLove-new`）之后调用，
用的是被改写后的 `APP_NAME`，指向真实产物目录。

## 3. 与旧实现的逻辑对比

| 场景 | 旧实现 | 新实现 |
| --- | --- | --- |
| 打包 | 只收 dll/pyd，漏两个 exe | 显式收，产物缺文件即构建失败 |
| spawn 参数 | 整条命令行当 `appname`；`env` 传 dict → TypeError → 降级 | `appname` 传 exe、`cmdline` 传参数、`cwd` 绝对目录、`env` 传 `K=V\0` 串 |
| cwd / env 配置 | 静默丢弃 | 真正生效（`env` 无自定义时传 `None` 继承） |
| spawn 返回 False | 忽略，打印"已启动" → 前端绿点黑屏 | 抛 `RuntimeError` → `local_term.session_failed` → tab 显示失败原因 |
| 打包回归 | 无 | 8 条用例（含反向用例） |

## 5. 已知边界 / 未覆盖

1. **Windows 真机复验需等 CI 产物**：PyInstaller 不能交叉编译，本机（Linux）出不了
   `JFLove-1.10.7-win64-setup.exe`；打通 CI 后在 `scripts/verify/vm-win.sh up` 的
   KVM 真机上装包复验本机终端（banner + `echo` 回显）。
2. **一过性残留**：关闭本机终端标签页后 `conhost.exe` 仍挂在 JFLove 下（shell 进程本身会退出）。
   属既有小问题，不在本次范围；如需清理，后续把 `LocalSession.close()` 改成调用 raw PTY
   实际存在的 `cancel_io()`（raw `PTY` **没有** `close()`，现有 `self._pty.close()` 一直抛
   `AttributeError` 并被吞掉）。
3. **cwd 含 `~`**：Windows 下 `os.path.expandvars` 不展开 `~`，配置里请填绝对路径
   （留空自动回退用户主目录）。
