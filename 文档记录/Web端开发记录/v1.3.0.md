## 三、技术实现要点

### 3.1 加密栈

| 环节 | 实现 | 验证 |
|------|------|------|
| X25519 ECDH | `SubtleCrypto.generateKey({name: 'X25519'})` | ✅ 5 测试通过 |
| HKDF-SHA256 | `SubtleCrypto.deriveBits({name: 'HKDF', hash: 'SHA-256'})` | ✅ |
| ChaCha20-Poly1305 | `@noble/ciphers` `chacha20poly1305`（12B nonce） | ✅ 加解密互逆 |
| 流式帧 | 自研 `stream-frame.ts` | ✅ |

### 3.2 关键设计决策

| 决策 | 理由 |
|------|------|
| `chacha20poly1305` 而非 `xchacha20poly1305` | 与 Python `cryptography` 的 ChaCha20-Poly1305 使用 12B nonce，`xchacha20poly1305` 需要 24B nonce，不兼容 |
| 同步页面降级 | 浏览器安全沙箱限制，不支持本地文件系统双向同步 |
| session_key 仅存内存闭包 | 对标桌面端 `_session_store: dict`，页面关闭即清除 |
| 不使用 `Authorization` header | 遵循 §9.3.9，JWT 通过加密 body 的 `token` 字段传递 |

### 3.3 响应式布局实现

- PC 端（≥1024px）：`DesktopLayout`（侧边栏 240px + 主内容区）
- 移动端（<1024px）：`MobileLayout`（主内容区 + 底部 TabBar 56px）
- 通过 `useMediaQuery('(min-width: 1024px)')` 实时检测，`AppLayout` 自动切换

### 7.4 后端配合改动（用户授权，仅 1 处全局通用改动）

> 说明：早期尝试修改 6 个 controller 路由为 GET+POST 双方法的方式已**整体回滚**
> （`git checkout` 还原，后端仅保留本方案 B 的 1 处 middleware 改动）。

**方案 B（2026-08-02，用户明确授权）：** 后端 `jflove-server/src/utils/middleware.py`
的 `decrypt_request_body` 增加支持：**请求体为空时从 URL query 读取加密信封**
（`?nonce=...&ciphertext=...`）。作用与兼容性：

- Web 端浏览器 GET 无法携带 body（fetch/XHR 均丢弃），只读接口改用真 GET + URL
  query 传**密文信封**，服务端在 body 为空时从 query 读取，逻辑与 body 路径完全一致。
- 桌面端 / 移动端继续 body 传参，**不受任何影响**（body 非空时仍走原逻辑）。
- 安全性：query 中仅携带 ChaCha20-Poly1305 密文（nonce + ciphertext 均 Base64），
  不含任何明文业务参数，符合 §9.1.4；错误响应仍走全局加密 handler，白名单不变。

```text
git diff --stat jflove-server/
 jflove-server/src/utils/middleware.py | 16 ++++++++++++++--
 1 file changed, 14 insertions(+), 2 deletions(-)
```

**Web 端配套改动（本方案）：**

- `http-client.ts`：`get()` 改用 `getQueryEncrypted`（fetch 真 GET + `?nonce=&ciphertext=`）；
  `downloadStream()` 改用 fetch GET + query（保持流式 `ReadableStream` 逐帧解密）；
  移除 XHR GET+body 方案；GET 的 401 续约后重走 `getQueryEncrypted`
- `file-service.ts`：`listFiles` 改用 `httpClient.get`（修复误用 POST 导致 405，文件列表空白）
- `disk-service.ts`：`browseDirs` 改用 `httpClient.get`（修复误用 POST 导致 405）
- `server-history-service.ts`：新增 `normalizeServerUrl`（无协议地址自动补全 `http://`，
  避免请求发往当前站点）；`auth-store.keyExchange` 统一规范化
- `tests/utils/http-client.test.ts`：GET 用例适配 fetch + query 信封断言

**复验结果：** 后端重启后浏览器全链路通过——登录/磁盘列表/文件浏览/流式预览/笔记列表与
读取/设置页/权限配置（删除列）/管理面板/同步/传输；`tsc` 0 / `eslint` 0 / `vitest` 35 通过。
