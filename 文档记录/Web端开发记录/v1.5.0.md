## 修复 1：Mermaid「显示不全 / 导出不全 / 类图排版错乱」

- **发现日期**：2026-09-12
- **来源**：用户使用反馈 —— 「web 端 mermaid 显示还是显示不全，即使下载出来的图片也是不全的」；
  另一张截图显示类图的 `用户` 框里没有成员，`+int id` / `+string name` / `+登录()` 画在框外并与边标签重叠
- **影响范围**：`jflove-web`（桌面端 / APP 未动，用户要求逐端推进）

### 现象与根因

| 现象 | 根因 |
| --- | --- |
| 类图外框只按标题高度画，成员/方法文字跑到框外 | **`src/index.css` 里一条无障碍规则**：`@media (prefers-reduced-motion: reduce) { * { transition-duration:.01ms!important } }`。当该偏好生效时，引擎在**几何尚未落定**时就去测量，写出错误的节点尺寸与 `viewBox` |
| ER / 流程图 / 状态图文字被裁（ER 下裁 40px、流程图右裁 63px） | 同上（同一根因的另一种表现） |
| **下载出来的图片也不全** | 导出写盘的就是屏幕上那份 SVG 字符串，`viewBox` 错 ⇒ 导出必然同样不全 |
| 饼图标题上裁 2px（无 CSS 干扰时仍存在） | 尺寸归一化**曾经是死代码**：它在 SVG 字符串还没插进容器时就去 `querySelector('svg')`，永远返回 `null`，重新测量从未生效 |

**关键取证**（`设计预览/probe_reduced_rule_which.mjs`，在页面里原地改写该规则后逐条对照）：

| 规则状态 | 类图 | ER 图 | 流程图 |
| --- | --- | --- | --- |
| 两条声明都在（原状） | 框装不下 1 个 / 文字被裁 2 段 | 被裁 5 段 | 被裁 3 段 |
| **只留 `animation-duration`** | ✅ 全好 | ✅ | ✅ |
| **只留 `transition-duration`** | ❌ 同样坏 | ❌ 同样坏 | ❌ 同样坏 |
| 整条去掉 | ✅ 全好 | ✅ | ✅ |

⇒ 元凶是 **`transition-duration: .01ms !important`** 这一条。
**无头浏览器默认报告 `prefers-reduced-motion: reduce`**，所以此前所有无头测试都带着这个干扰，
这也是它一度被误判成「mermaid 引擎缺陷」的原因。

### 修复内容

| 文件 | 改动 |
| --- | --- |
| `src/index.css` | 过渡冻结改为 `*:not(svg):not(svg *)`：**HTML UI 仍尊重减动效偏好，SVG 子树豁免**（第三方渲染引擎依赖过渡计时决定节点几何）；注释内写明完整取证与"别再改回去"的理由 |
| `src/utils/mermaid/renderer.ts` | 渲染后处理改为**先插 DOM 再量**（修掉死代码）；`fitSvgToContent` 改为元素级（直接设 `viewBox`/`width`/`height`、去内联 `max-width`）并按实测内容**只放不缩**；新增 `serializeSvg`（`XMLSerializer`，保证导出串可独立打开）；`PIPELINE_VERSION` 纳入缓存键 |
| `src/utils/mermaid/matrix.ts` | 新增自实现的 2×3 矩阵工具（不依赖 `DOMMatrix`/`DOMPoint`，便于单测与旧引擎） |
| `src/utils/mermaid/config.ts` | `htmlLabels` 保持 `false`；把"为什么必须是 false / 为什么不要改成 true"的证据写进注释 |
| `tests/utils/mermaid-geometry.test.ts` | 新增 17 条单测（内容量测、只放不缩、viewBox 损坏兜底、量测异常不抛错、调用顺序契约，以及"reduced-motion 规则必须豁免 SVG""不得引入标签转换层"两条**防回退**断言） |

### 一个被推翻的中间结论（记录以免重犯）

排查中途曾判定「类图排版是 mermaid 11.16.0 在 `htmlLabels:false` 下的引擎缺陷、配置无解」，
并据此选定「路线 A：改用 `htmlLabels:true` + 把 `foreignObject` 转成 SVG `<text>`」，
实现到一半时发现前提不成立 —— 真实原因是上面那条 CSS。**路线 A 已整体回退**，理由：

- 前提错：不需要 HTML 标签来拿到正确排版；
- 代价大：`htmlLabels:true` 时引擎算出的 `viewBox` 会**膨胀约 10 倍**（实测 class 2788×2788），
  需要额外的"收缩 viewBox"能力（收缩比放大风险高）；
- 风险高：转换层要处理字号自校准、折行、对齐、背景块，且实测踩到
  `inverse(getCTM())` 在离屏容器里含页面偏移（坐标偏 30 万）这类隐蔽陷阱；
- 收益为零：`htmlLabels:false` 产物是**纯 SVG**（无 `foreignObject`），安全清洗 / 导出 /
  桌面端渲染全部天然成立。

### 对其它端的提示（本轮未动）

- 三端各自的 `mmNormalizeSize` 思路相同；桌面端实测 `svg.getBBox()` 会被辅助线污染
  （时序图返回 2000 高），移植时需采用本轮的"文字全计入 + 图形按量级筛"规则；
- 若桌面端 / 移动端的样式里也有"全局冻结过渡/动画"这类写法，同样会让引擎几何错乱 ——
  建议按 `prefers-reduced-motion` 的**两种取值各测一遍**（无头环境默认是 `reduce`）。

## 修复 2：「插入图表」插入的 ER 图必报语法错误

- **发现日期**：2026-09-12（用户第二次反馈：「最后插入的 ER 图还是有语法错误」）
- **影响范围**：`jflove-web` 笔记编辑器 —— **「插入图表」里的 ER 图 100% 复现**
- **关键点**：**模板常量本身是正确的**。缺陷在插入逻辑里，所以
  「从源码抽模板字符串再渲染」这类验证**永远发现不了**（上一轮就是这么漏掉的）。

### 根因

`NoteEditPage.tsx::insertMarkdown` 用 `|` 当**光标占位符**，并且**无条件**把插入文本里的
第一个 `|` 当占位符：

```ts
const replacement = insert.includes('|') ? insert.replace('|', selected) : insert;
```

而 ER 图模板的正文里**本来就有** `|` —— mermaid 的 ER 关系语法是 `||--o{`。
用户在没有选中任何文字时点「ER 图」，`selected` 是空串，`replace('|', '')`
**把第一根竖线删掉了**：

```
期望（模板）：用户 ||--o{ 会话 : 拥有
实际（插入）：用户 |--o{ 会话 : 拥有     ← 只剩一根竖线
```

mermaid 只认 `||--o{`，于是报
`Parse error on line 2: erDiagram 用户 |--o{ 会话 : 拥有 ... got '|'`。

**为什么只有 ER 图中招**：7 个模板里只有 ER 图的正文含 `|`（流程图用的是 `B -- 是 --> C`）。

### 修复内容

| 文件 | 改动 |
| --- | --- |
| `src/utils/markdown-insert.ts`（新增） | 抽出纯函数 `planInsertion(template, selected, useCursorMarker)`：**默认原样插入**（`useCursorMarker = false`），只有显式开启才把**第一个** `|` 当光标落点。顺带把这段逻辑从页面组件里抽出来，使其可被单测覆盖（原来藏在组件里、零覆盖） |
| `src/pages/NoteEditPage.tsx` | `insertMarkdown(template, useCursorMarker = false)` 改用 `planInsertion`；工具栏按钮调用点显式传 `true`，**图表模板调用点不传**（原样插入）；注释与 `ToolbarButton` 接口说明写清"占位符约定只对工具栏按钮成立" |
| `tests/utils/markdown-insert.test.ts`（新增） | 13 条单测，含：7 个模板**逐字**插入（无选区/有选区两种）、ER 图必须含 `||--o{`、**旧实现确实会改坏**的反向断言（证明测试不空转）、工具栏占位符仍正常、调用契约（图表模板不得走占位符解析） |

### 教训

**"模板字符串对"不等于"插入进去的内容对"。** 验证必须走**用户真实路径**
（点按钮 → 读编辑区 → 看预览），只在源码层面比对常量会把整类
"插入 / 转义 / 占位符"缺陷漏干净。见 `.claude/skills/LESSONS.md` L25。
