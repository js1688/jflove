## 2. 进度条终态口径（D15 / AC-256）

### 2.1 根因

`taskProgress()` 把 `status === 'success'` 的判断放在字节 / 项数之后：

```ts
// 修复前
if (task.bytes_total > 0) return clamp(...);
if (task.item_total > 0) return clamp(...);
if (task.status === 'success') return 100;
```

成功任务只要 `bytes_total > 0` 就永远按估算字节算，与桌面端同源缺陷。

### 2.2 修复

```ts
if (task.status === 'success') return 100;   // 产品口径：不按估算值回退
if (task.bytes_total > 0) return clamp(...);
if (task.item_total > 0) return clamp(...);
return 0;
```

页面侧（与设计 §4.1 的差异说明）：

- 设计写「页面无需改渲染逻辑」，但 v1.8.0 的 Web 卡片**只在 active 状态渲染进度条**，
  成功任务即使 `taskProgress()=100` 也看不到 100%。为满足 AC-256「页面成功任务显示 100%」，
  改为**所有状态都渲染进度条**（与桌面端一致），成功任务固定满格；
- `taskProgressText()` 成功态追加 `· 100%`，让纯文本也读得出口径。

## 3. 服务器目录选择器（D14 / AC-257）

- 与桌面端**独立实现**（不共享组件），交互与接口契约一致；
- 创建磁盘：`initialPath = createPath`（空 = 服务端 roots 第一项）；
- 编辑：`initialPath = editPath`；
- 「上级」用服务端 `parent`；「根目录」用 `roots[0]`；roots 快捷按钮；
- 错误：`toast.error('加载服务器目录失败', message)` + 弹窗内错误态 + 重试；
- 请求：`diskService.browseServerDirs` → `http-client.ts` 加密 query 信封，
  **URL 只出现 `nonce` / `ciphertext`**，不出现明文路径。

## 6. 已知限制

1. 浏览器安全模型不允许选择用户本机目录；本版只做**服务端远端目录**选择。
2. 单次最多 2000 条，超限提示进入更具体路径，不做分页。
3. 浏览器实机验证使用临时后端 + 本机 Edge；未在真实 https 域名下复测（同源代理行为一致）。
