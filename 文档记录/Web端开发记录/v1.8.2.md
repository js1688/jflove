## 2. F37.6 管理端超时设置

### 2.1 字段与范围（与服务端 `offline_download_service.validate_config_value` 一致）

| UI 标签 | 配置键 | 默认 | 前端允许范围 |
|---|---|---|---|
| 解析总超时（秒） | `offline_download_analyze_timeout_s` | 90 | 30~180 |
| 连接超时（秒） | `offline_download_connect_timeout_s` | 15 | 5~30 |
| 读取超时（秒） | `offline_download_read_timeout_s` | 60 | 15~120 |

- 读写完全复用既有 `config-service.ts`：`GET /api/v1/config` 读取、`PUT /api/v1/config` 逐项写入
  （key + value，全部走 `http-client.ts` 加密信封与 JWT）。
- 页面本身在 `/admin/system`（`RequireAdmin` 守卫），非管理员页面不可见；接口侧仍由服务端
  `_require_admin` 返回 403，前端不新增任何权限判断分支。
- 保存时先做前端整型 + 范围校验，**任一项越界即整体不提交**并提示
  「解析总超时（秒）需为 30~180 的整数」；合法值交给服务端二次校验。
- 默认值仅在 `GET /config` 未返回该键时补齐；已落库值按实际展示。

### 2.2 与桌面端 / 移动端

三端各自维护 `config-service` 常量（设计 §8 R6 的既定做法），键名与范围统一由本文件第 2.1 节表格约束；
Web 端不引用桌面端工程。

## 3. C1 目录选择器 `limit`

- 后端 `GET /api/v1/virtual-disks/server-dirs` 响应新增 `limit`（`SERVER_DIR_LIMIT`）。
- `ServerDirListing.limit` 为可选字段：旧服务端不返回时，选择器回落常量 2000；
  新服务端返回时按 `limit` 渲染「目录过多，仅显示前 N 项，请进入更具体的路径。」。
- 不改请求参数（不向服务端传上限），只消费响应，保持向后兼容。

## 5. 与上一版本的差异 / 取舍

| 项 | v1.8.1 | v1.8.2 |
|---|---|---|
| 离线下载数字项 | 4 项（并发 / 体积 / 项数 / 图片数） | 7 项（+ 解析 / 连接 / 读取超时） |
| 选择器上限文案 | 硬编码「2000」 | 取响应 `limit`，缺省回落 2000 |
| 接口 | `server-dirs` 无 `limit` | 消费新增的 `limit`（不改请求） |

取舍：超时范围校验在前端只做「前置拦截 + 中文提示」，最终以服务端 400 为准，
避免两端范围常量漂移时前端放行非法值。

## 6. 已知限制

1. 选择器仍不分页：超过服务端上限时仅提示进入更具体路径。
2. 浏览器实机使用临时空库 + 本机 Edge；未在真实 HTTPS 域名下复测（同源代理行为一致）。
3. 超时实际生效范围（L1/L2/L3 预算、出站连接/读取）由后端负责，本记录只覆盖 Web 端配置读写。
