# v1.4.0 Web 端开发记录：MSE 主路径边下边播 + 媒体修复开关

## 一、变更概述

Web 端边下边播从 **Service Worker 流式代理** 切换为 **MSE（MediaSource）主路径**，任意 HTTP/HTTPS（内网/公网）环境均可边下边播；新增管理员「系统设置」页配置服务端媒体修复开关（默认关闭）。

| 文件 | 变更类型 | 说明 |
|------|---------|------|
| `src/utils/stream-frame.ts` | 修改 | `StreamMeta` 支持 `stream_mode`/`range_start_seconds`；`openEncryptedStream` 增加时间 range 参数 |
| `src/utils/media-source-player.ts` | 修改 | 升级为 MSE 主路径：byte/time 双模式 + time 流 seek 按时间重拉 |
| `src/pages/FilePreviewPage.tsx` | 修改 | 移除 SW，回退链简化为 MSE → Blob 完整下载 |

## 二、详细变更

### 2.1 `stream-frame.ts`

- `StreamMeta` 扩展：`stream_mode?: 'byte' | 'time'`、`range_start_seconds?: number`；`file_size/range_start/range_end` 改为可选（time 模式无）。
- `openEncryptedStream` 新增第 7 个可选参数 `rangeStartSeconds`（秒），payload 加密字段 `range_start_seconds`（默认 0）。
  - 初始请求同时携带字节 range 与时间 range，服务端根据文件状态返回 byte（健康）或 time（需修复）meta。

### 2.2 `media-source-player.ts`（MSE 主路径）

- 重写 `playWithMSE`：
  - **双模式**：读取 meta 后判定 `stream_mode`；byte 走字节 range 顺序流，time 走时间 range 修复流。
  - **seek**：time 修复流监听 `video.seeked`，按 `currentTime` 重新 `openEncryptedStream(rangeStartSeconds=target)` → 清空 SourceBuffer → 重建 append；byte 流走 MSE 原生已缓冲 seek（不远程重拉）。
  - 保留首帧 append 快速失败检测（普通 MP4 非 fMP4 回退 Blob）。
  - 保留 codec 探测（fMP4/WebM/MP3/FLAC/OGG 等）。

### 2.3 `FilePreviewPage.tsx`

- 移除 `openStreamUrl/closeStreamUrl` 与 SW 分支。
- 回退链：**MSE 主路径 → 完整下载 Blob 兜底**（`isMSEAvailable` + `playWithMSE`；失败再 `downloadRaw` → Blob URL）。

### 2.4 删除 SW

- 删除 `src/utils/stream-proxy.ts`、`src/sw/index.ts`。
- `vite.config.ts`：移除 `swDevPlugin` 与 `build.rollupOptions` 双入口，单入口输出。
- `main.tsx`：移除 `registerStreamProxy()` 与 `syncStreamSession()`。
- `auth-store.ts`：移除 `syncStreamSession()`（登录后）与 `clearStreamProxySession()`（登出）。

### 2.5 管理员「系统设置」（`AdminSystemPage.tsx`）

- 路由 `/admin/system`（RequireAdmin 守卫）；PC 侧边栏与移动端设置页加入口。
- 功能：
  - **启用媒体修复**（总开关）：`media_repair_enabled`，默认关闭，即点即存；
  - **允许重编码降级**：`media_repair_allow_transcode`，默认关闭（总开关关闭时禁用）；
  - **修复并发数**：`media_repair_max_concurrent`，1~8 或留空自动（总开关关闭时禁用）。
- 调用 `configService.getConfig()`（GET）/ `updateConfig(key, value)`（PUT），写后立即生效、无需重启。

## 三、调用的后端接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `GET /api/v1/files/stream` | GET | 加密帧流；请求体新增可选 `range_start_seconds`；meta 帧新增 `stream_mode` |
| `GET /api/v1/config` | GET | 读取全部配置（admin），响应 `{config: {k:v}}` |
| `PUT /api/v1/config` | PUT | 写入 `media_repair_enabled` / `media_repair_allow_transcode` / `media_repair_max_concurrent`（admin） |

## 四、与上一版本的逻辑差异

| 维度 | v1.3.x | v1.4.0 |
|------|--------|--------|
| 边下边播主路径 | Service Worker 流式代理（仅 HTTPS/localhost） | **MSE 主路径**（HTTP/HTTPS 均可用） |
| 回退链 | SW → MSE → Blob（三层） | **MSE → Blob（两层）** |
| 损坏/非流式文件 | 无法播放 | 服务端修复流（time 模式）实时修复后可播 |
| seek | SW 原生 206 seek | MSE：time 修复流按时间重拉；byte 流走原生已缓冲 seek |
| 管理员配置入口 | 无 | `/admin/system` 系统设置（媒体修复开关） |
| 构建 | 双入口（index + sw.js） | 单入口（无 sw.js） |

## 五、设计取舍

| 决策 | 说明 |
|------|------|
| 统一 MSE 主路径 | 摆脱 SW 安全上下文限制，HTTP/HTTPS/内网/公网一致；代价是 MSE 对 seek 需自行管理 |
| time 修复流 seek 按时间重拉 | 每次 seek 服务端 `-ss` 重新修复（每次实时计算，符合"不落盘"约束），缓冲重建后续播 |
| byte 流不远程重拉 | 健康文件字节↔时间映射不可知，走 MSE 原生已缓冲 seek；非主场景从简 |
| 开关即点即存 + 并发数按钮保存 | 减少并发请求；写后服务端缓存失效即生效 |
| 删除 SW 代码 | 简化工程（无 SW 注册/生命周期/会话同步），单入口构建 |
