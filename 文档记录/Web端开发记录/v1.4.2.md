# v1.4.2 Web 端开发记录：播放纯净化 + 修复中心 + MSE 前向 seek

## 一、变更概述

| 编号 | 变更 | 说明 |
|------|------|------|
| WEB-1 | **MSE 播放器纯 byte 化** | `media-source-player.ts` 删除 time 模式全部逻辑（timestampOffset / 代际计数 / -ss 重拉 / MediaSource.duration 恒完整时长）；仅保留 byte 流 append 管线 |
| WEB-2 | **byte 模式前向 seek 按需重拉（AC-3）** | MP4 家族文件拖到未缓冲区域：按「目标时间/总时长 × 文件大小」估算字节偏移 → 取 init 段（0~moov 结束）+ 自估算偏移起的数据（扫描 moof 分片边界）→ 重建 SourceBuffer append → 定位到目标；重拉失败保持顺序下载渐进到达（不劣化） |
| WEB-3 | **损坏播放引导（AC-1）** | 播放/下载失败且错误含 `[MEDIA_NEEDS_REPAIR]` → 「该文件已损坏，无法在线播放 + 立即修复」按钮 → 调 create API → 提示去修复中心 |
| WEB-4 | **右键「修复损坏媒体」** | 文件浏览右键菜单新增（仅音视频；要求 canWrite 且 canDelete 并存）；结果 toast 3.5s 自动消失 |
| WEB-5 | **修复中心页面（新增）** | `/repair` 路由 + 双布局导航（PC 侧边栏「修复中心」/ 移动底部 Tab「修复」）；全平台共享任务列表 + 2.5s 轮询 + 按状态操作（取消/验证播放/覆盖[重点二次确认]/删除产物/删除记录）；只读账号按钮禁用 |
| WEB-6 | **验证播放** | `previewTarget` 扩展 `repairTaskId`；`playWithMSE` 透传 → `/stream?repair_task_id` 加密流播放产物 |
| WEB-7 | **管理面板改造** | 移除「启用媒体修复」总开关；改为「离线媒体修复」配置（重编码开关 + 并发数） |
| WEB-8 | **磁盘模型扩展** | `VirtualDisk` 新增 `can_delete`（服务端 v1.4.2 起返回） |

## 三、关键设计取舍

1. **前向 seek 字节估算 + moof 边界扫描**：不引入完整 demuxer——估算偏移后逐字节扫描 `moof`（校验前 4 字节 size 合法），命中即从该分片起 append（init 段单独拉取）。落到目标附近（误差 < 1 个分片）。扫描失败/非 MP4 格式保持顺序下载渐进到达（v1.4.1 既有行为，不劣化）。
2. **删除 time 逻辑而非保留兼容**：服务端 v1.4.2 恒返回 byte 流，time 分支成为死代码；整体删除让播放器回到 v1.4.0 之前的简单模型。
3. **修复引导走统一错误码**：415 detail 前缀 `[MEDIA_NEEDS_REPAIR]` 经 http-client 解密透传到页面层，预览页与下载回退链都能识别（不只 MSE 路径）。
4. **验证播放复用 previewTarget**：修复中心设置 `repairTaskId` 后跳转预览页，MSE 播放器透传参数，零新增播放管线。

## 六、BUG 修复（代码审查 S-2）

> 标签：BUG 修复（Phase 5 代码审查发现，修复后复验）

- **S-2（严重）**：`media-source-player.ts::seekTo` 先 abort 旧流后 `consumeGeneration++`——旧 consume 循环因 abort 抛错时 generation 仍相等 → 误判失败 → `fail()` → `cleanup()` 清空 video.src，**一次前向拖拽即摧毁整个播放**。修复：① `seekTo` 首行递增代际；② 重拉任一步失败（moov/moof 定位失败、网络错误）→ `rebuildFromStart(target)` 全流重建兜底（「失败不劣化」承诺成立）；③ 目标落在分片缝隙（分片起点晚于目标）→ 定位到 `buffered.start` 最近可用分片。复验：vitest 53 passed + tsc/lint 0。
