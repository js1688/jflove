## 1. BL-3：响应解密失败 → `ApiError(502)`（AC-B3）

### 1.1 改前的问题（BACKLOG BL-3 原文）

`src/utils/http-client.ts` 的两条加密请求路径，把「**响应解密失败**」和「网络故障」**混在同一个 `catch` 里**：

```ts
// 改前（POST/PUT/DELETE 路径，与 GET query 路径同型）
const respJson = await response.json();
const decrypted = decryptEnvelope(sessionKey, respJson.nonce, respJson.ciphertext);
return JSON.parse(new TextDecoder().decode(decrypted)) as T;
} catch (e) {
  ...
  throw new ApiError(0, `网络错误：${e instanceof Error ? e.message : String(e)}`);   // ← 解密失败落到这里
}
```

结论（BACKLOG 定性）：**会抛错、非静默降级**（安全语义没有问题），但用户看到「网络错误」，
真实原因是「解密失败」（会话密钥不匹配 / 响应被篡改），**排查方向被带偏**。

### 1.2 改法（对齐桌面端口径）

桌面端在 v1.5.1 修复 M-4 时已落地同一口径（`jflove-desktop/src/utils/http_client.py:53` `_is_envelope()`
+ `:244` `raise ApiError(502, "响应解密失败（会话密钥不匹配或响应被篡改）")`）。Web 端本次对齐：

| 落点 | 改动 |
| --- | --- |
| `src/utils/http-client.ts`（新增，紧接 `baseUrl()`） | `isEnvelope(body)`：**只判形状**（`nonce` / `ciphertext` 均为 `string`），不尝试解密 |
| 同上 | `decryptResponse<T>(sessionKey, body)`：<br>① 形状**不是**信封 → **原样返回**（明文白名单路径不误伤）；<br>② 形状**是**信封但解密失败 → `throw new ApiError(502, '响应解密失败（会话密钥不匹配或响应被篡改）')` |
| `encryptedRequest()`（POST/PUT/DELETE） | 三行内联解密 → **一行** `return decryptResponse<T>(sessionKey, await response.json());` |
| `getQueryEncrypted()`（GET + URL query 信封） | 同上（**第二条路径同样改造**，不是只改一处） |

**关键语义（写进代码注释，防误读）**：`502` 是**客户端合成**的状态码（服务端此刻的状态是 `200`），
语义是"本次会话隧道这一侧出了故障"，**不要**理解为"服务端返回了 502"。

**安全合规**：错误文案**不含** `nonce` / `ciphertext` / 密钥材料（安全宪法 §9.4.13）；
未新增加密原语、未下发 `session_key`、未引入网络出口（§9.5.15-17）。

### 1.3 新增用例（`tests/utils/http-client.test.ts`，**+3**）

| # | 用例 | 判据 |
| --- | --- | --- |
| 1 | `BL-3 POST：200 + 解不开的信封 → ApiError(502)，文案不含 nonce/ciphertext` | 用**另一份会话密钥**造信封（形状合法、本会话解不开）→ `status === 502`；`detail` 含「响应解密失败」且**不含** `nonce` / `ciphertext`；**不得**是 `0` |
| 2 | `BL-3 GET：200 + 解不开的信封 → ApiError(502)`（URL query 信封路径同判定） | GET 路径同样断言 `{ status: 502, detail: '响应解密失败（会话密钥不匹配或响应被篡改）' }` |
| 3 | `BL-3 边界：200 + 明文 body（非信封形状）→ 直返成功，不误伤明文白名单路径` | 响应为明文 JSON（`/api/v1/auth/admin-exists` 形态）→ **直返成功**，不抛 502 |

> 第 3 条即 AC-B3 的「明文白名单路径不误伤」判据；第 2 条是我方额外覆盖（设计只点名了 POST 型路径，但 GET query 路径是**另一处**同型缺陷）。
