# v1.4.1 Web 端开发记录：视频播放 BUG 修复

## 一、变更概述

本次为纯代码 BUG 快速修复（版本号不变），不改变任何接口字段。Web 端共修复 4 个问题：

| 编号 | 现象 | 根因 | 修复 |
|------|------|------|------|
| BUG-1 | 非 fMP4 的 MP4 打开后无限等待、不报错、不播放 | Chrome MSE 对 moov 在尾部的普通 MP4 不报错只等待 | 首帧主动判定 `isFmp4Init`，非 fMP4 立即回退完整下载 |
| BUG-2 | 修复流 codec 声明与实际音轨不匹配 → MSE 回退下载 | TS 等重封装 fMP4 音频 esds 缺 DecoderSpecificInfo，服务端解析 codec 只含视频 | codec 串补全：`avc1` 且无 `mp4a` 时补 `mp4a.40.2` |
| BUG-3 | faststart MP4（moov 前置但无 mvex）MSE 卡死 | faststart≠fMP4，MSE 需 moov+mvex | `isFmp4Init` 要求 moov 内含 mvex，否则回退下载 |
| BUG-4 | 视频时长未知、无法拖进度、点击进度条播放失败 | ① fMP4 `empty_moov` 无时长信息；② seek 重建后旧 consume 把 `ended/endOfStream` 写到新流；③ seek 重建归零播放头并把时长改成剩余时长 | ① 用 meta.duration 显式设 `MediaSource.duration`；② consume 代际计数；③ seek 改为 `SourceBuffer.timestampOffset`，不重建 MediaSource |
| BUG-5 | seek 后旧流仍占服务端修复并发槽，新流排队失败 | Web 只 `frames.return()` 未真正 cancel 旧 fetch，服务端 ffmpeg 未终止 | 每流独立 AbortController，seek 前 abort 旧流 |
| BUG-6 | 开发模式（StrictMode）初始播放间歇性卡死 | effect 双跑产生两个 playWithMSE 实例争用同一 `<video>` | effect 异步播放逻辑 `setTimeout(0)` 延迟到双跑完成后；`<video>`/`<audio>` src 改为非受控 |

## 二、详细变更

| 文件 | 变更类型 | 说明 |
|------|---------|------|
| `src/utils/stream-frame.ts` | 修改 | `StreamMeta` 新增 `duration?: number`（time 模式完整时长，供 MSE 设时长） |
| `src/utils/media-source-player.ts` | 修改 | ① `isFmp4Init` 要求 moov+mvex；② codec 串补全 mp4a；③ `MediaSource.duration` 恒为完整时长；④ seek 用 `timestampOffset` 不重建 MediaSource；⑤ consume 代际计数；⑥ 每流独立 AbortController；⑦ 支持外部 AbortSignal |
| `src/pages/FilePreviewPage.tsx` | 修改 | ① effect 异步播放逻辑 `setTimeout(0)` 防 StrictMode 双跑竞态；② `<video>`/`<audio>` src 改为非受控，避免与 MSE 命令式 src 冲突 |

### 2.1 `isFmp4Init` 判定修正

- 原：首个非 ftyp box 为 `moov` 即认为 fMP4。
- 现：`moov` 内必须能找到 `mvex` box 才返回 true；先见 `mdat` 或 moov 无 mvex 均返回 false → 回退完整下载。
- 与服务端 `media_probe._moov_at_front` 判定规则保持一致。

### 2.2 codec 串补全

- 服务端 `meta.codec` 对 TS 重封装出的 fMP4 可能只含视频轨（音频 esds 缺 DecoderSpecificInfo）。
- 修复：`raw.includes('avc1') && !raw.includes('mp4a')` 时追加 `, mp4a.40.2`，避免 `addSourceBuffer` 因「实际含音频轨但 codecs 未声明」被 Chrome 拒绝。

### 2.3 时长 / seek 修复

- **时长**：初始打开与每次 seek 后，均将 `mediaSource.duration` 设为 meta 的 `duration`（完整时长），**不随 seek 缩减**，保证进度条总时长恒定。`empty_moov` 的 fMP4 moov 不含时长信息，必须显式设置，否则进度条未知、无法 seek。
- **seek（timestampOffset 方案）**：不重建 MediaSource（避免 currentTime 归零、总时长被改成剩余时长），而是移除旧 SourceBuffer、新建一个 SourceBuffer 并用 `timestampOffset = target` 把服务端「0 基准」的新流映射到 `[target, 完整时长]` 时间轴；随后等首个媒体分片 append 完成后再把播放头定位到 target。
- **seek 竞态**：`consume` 引入 `consumeGeneration` 代际计数，旧代际退出时不再写 `ended/endOfStream`，修复「seek 后新流被旧流提前 endOfStream」的播放失败。
- **旧流取消**：每流独立 AbortController，seek 替换流时 abort 旧流，使服务端立即终止旧 ffmpeg、释放修复并发槽，避免新流排队失败。
