### 8.1 v1.5.0 文档存在仓库无法佐证的结论（已更正）

- `代码审查报告/v1.5.0.md:726` 与 `测试报告/v1.5.0.md:700` 称 M-4 **已修**（并点名 `_is_envelope()` 与"strict xfail 已转正"），但：`git log --oneline -- jflove-desktop/src/utils/http_client.py` 只有初始提交；`git grep -n _is_envelope` 在 `src/` 下 0 命中；被引用的 `test_v150_security_envelope.py`、`test_security_client_authorization.py`、`test_v150_main_window_shell.py`、`设计预览/*.mjs` **在本仓库全历史（所有分支与 tag）0 命中**；实测桌面端基线为 **78**（非文档里的 228/490）。
- **处置**：按 `LESSONS.md` L21 在**两份 v1.5.0 文档末尾追加事后更正**（保留原文 + C-1~C-4 + 可复现命令），原文对应行加 `⚠ 已被 v1.5.1 复审推翻` 标注；流程改进写入 `项目管理记录/v1.5.1.md §7`。

### 8.2 版本号单一来源违规（发布期发现并修复）

桌面端 Web UI（QtWebEngine 承载的前端工程）的 `jflove-desktop/ui/src/config/constants.ts` 里的 `APP_VERSION` **不在** `sync_version.py` 的位置表中，而它**用户可见**（`LoginPage.tsx:283` 页脚、`SettingsPage.tsx:256` 关于页）⇒ 1.5.1 构建出来界面会显示 v1.5.0；`build.py` 的"版本一致性校验"因复用同一张不完整的表而**不会发现**。
**处置**：加入位置表（正则与 web 端同款）→ 同步清单由 7 处变 **8 处**；`--check` 现在覆盖它（`build.py` 构建前会调用，故今后漂移会被拦住）；本地桌面端产物**已重建**并实测包内为 1.5.1。

### 8.3 两次本地构建的"外层退出码 = 1"（环境性，非构建失败）

- 两次真实构建（`-m all` / `-m desktop`）的外层作业退出码均为 1，但其汇总都打印 `[ok] … 成功`、产物齐全、内容已逐项实测；
- 反证：`build.py` 自身的成功路径实测为 **0**（用假模块走通 `main()` 的诊断脚本）；stderr 噪声探针（小 / 1.7 MB / 带 `2>&1`）三组均返回 **0**；
- 结论：与本环境"**Windows 下被强制清理的进程树会呈现 `exit code: 1`（无信号标记），应视为中断而非命令失败**"一致（这两次恰好是派生大量子进程的 PyInstaller / Gradle / Flutter 构建）。
- **处置**：不以外层退出码判定构建成败，改用**产物存在性 + 包内内容 + sha256**；发布产物以 CI 为准。

### 8.4 测试资产隔离缺陷（v1.5.0 即存在，已修）

`test_stream_v1_1_0.py::Test安全宪法流式预览` 依赖他类副作用创建的用户 ⇒ 单独运行会假失败（401）。已把用户创建搬进 session 作用域 fixture（`conftest.py::no_perm_session`），三粒度前后对照 + 两组反向对照已实测（详见 `测试报告/v1.5.1.md §8.5`）。
