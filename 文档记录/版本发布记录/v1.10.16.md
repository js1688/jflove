## 1. 发布范围

1. **密钥只发一次**：首轮 publickey 已被服务器接受（`partial`，且服务器另列出 `password` /
   `keyboard-interactive`）时**不再回退重发 publickey**。v1.10.15 多发的那一次会让网关把它当成
   「还差一把密钥」，把「请输入账号密码」误报成「请提供第二把私钥」（用户报错①）。
2. **回退门槛改为「服务器没给下一步」**：`ssh-rsa`（RSA-SHA1）回退只在首轮裸失败或只列
   `publickey` 时触发；`rejected` 与「已给出其它因子」都不回退；已进入旧式模式不重复进入。
3. **按服务器实际列表补齐**：`password` → `keyboard-interactive` → `publickey`，中途换列表以新的为准；
   `keyboard-interactive` 不再要求本地有密码（网关把第二因子放在 `Password:` 提示里时代答）。
   修复用户报错②「账号密码没有被服务器接受」（实际第二因子只在键盘交互）。
4. **同一凭据不重复打**：`password` 被拒后换下一个公布过的因子，不再原地重试。
5. **诊断行加「认证序列」**：`认证序列=publickey→password`，文案据此指明哪个凭据没被接受并给出下一步。
6. 服务端 / Web / App **仅版本号同步**；数据库 **无 DDL**。

### 用户可见变化

- 旧网关（一把 RSA 私钥 + 账号密码）连接时，认证序列与 WinSCP 一致：`密钥一次 → 密码一次`。
- 失败时的报错直接指出是「登录密码不对」还是「服务器还要别的因子」，不再是「需两把私钥」。

> 版本切换：Windows VM 由 v1.10.15 覆盖安装到 v1.10.16（注册表 `DisplayVersion` 校验通过）。
> **回验过程发现并修复的工具缺陷**（`scripts/verify/windows_vm.py`，不属产品代码）：
> `guest_ip()` 原先取「`domifaddr --source agent` 第一行 ipv4」，QGA 刚上线时该命令常先返回回环
> （或完全为空），导致拿到 `127.0.0.1` / 空值，Windows E2E 在本轮连跑三次都停在「未取到客机 IP」。
> 已改为**轮询 + 跳过 Loopback / `127.*` / 优先非链路本地**，修复后稳定返回 `192.168.122.150`，E2E 一次通过。
>
> **环境坑**：本机 `/tmp` 是 tmpfs（16G）。一次性下载 3 个 CI 产物（约 537MB）后写满，
> bash 工具自身要往 `/tmp` 写结果文件，于是**所有 bash 调用（含 `rm`）全部失败**，形成无法自救的死锁；
> 后被系统 tmpfiles 清掉才恢复。后续回验改为「按需单个下载 + 用完即删」。

## 6. 回滚方式

- 桌面端 / App / Web：回退到 `v1.10.15` 的 Release 资产与镜像
  （`ghcr.io/js1688/jflove-{server,web}:1.10.15`），数据库无需回滚（本版无 DDL）。
- 服务端：`docker compose` 里把镜像 tag 从 `1.10.16` 改回 `1.10.15` 重启即可。
- 桌面端回退到 v1.10.15 后，「密钥一次 + 密码一次」的旧网关会重新出现
  「需两把不同私钥」误报（v1.10.15 会在密钥被接受后多发一次 publickey）。
