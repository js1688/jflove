## 2. 生产库表结构同步（§5.1.1 三关全部通过）

### 2.1 变更内容

| 表 | 变更 | 原因 |
| --- | --- | --- |
| `sessions` | `session_id`：去掉**列级 UNIQUE**；新增部分唯一索引 `sessions_session_active_uidx ... WHERE deleted_at IS NULL` | 软删除保留历史行，而列级 UNIQUE 不区分是否删除 ⇒ 同一会话二次登录 / refresh 续期必然撞约束 → 500 |

> 与 v1.5.0 `users.username` 是**同一类建模错误**，本次用同一套办法修正。

### 2.2 三关核对

| 关卡 | 命令 | 结果 |
| --- | --- | --- |
| ① 代码 → dev | `check_db_schema.py` 内置前置检查 | 发现 2 处差异（sessions DDL、缺索引）→ 跑 `init_db()` 迁移 dev → 复验一致 |
| ② dev → prod | `check_db_schema.py` | 发现同样 2 处差异 → `--align` 对齐 |
| ③ 复验 | `check_db_schema.py`（`--align` 后自动重跑） | ✅ **退出码 0「结构一致」** |

### 2.3 反向验证（工具可信度，依据 LESSONS L15–L17）

| 输入 | 期望 | 实测 |
| --- | --- | --- |
| prod 的 `sessions` 缺 `jwt_token_hash` 列（坏数据） | 必须拦住 | ✅ 退出码 **1** |
| prod 与 dev 结构完全等价（纯格式差异） | 必须放行 | ✅ 退出码 **0** |

### 2.4 数据完整性

对齐前后 `users=0 / sessions=0` 未变（prod 保持空库，符合 §5.1.3）。
对齐工具自动备份：`jflove-db/jflove-prod.db.bak-align-20261128-173550`。

### 2.5 交付脚本

| 文件 | 说明 |
| --- | --- |
| `jflove-db/migrate-1.10.26.sql` | 幂等升级；只重建表结构，**不触碰业务数据**，主键 id 原样保留 |
| `jflove-db/rollback-1.10.26.sql` | 回滚 DDL；**脚本内写明回滚前必须先跑的冲突检查 SQL** 与两种清理办法（物理删历史行 / 改名保留痕迹） |

**已实测**：迁移保数据、幂等（连跑 3 次只迁 1 次）、不清理冲突时回滚**被拒**
（`UNIQUE constraint failed`，与脚本警告一致）、清理后回滚成功且 id 保留。
