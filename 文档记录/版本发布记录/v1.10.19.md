# JFLove v1.10.19 版本发布记录

> 版本：1.10.19｜发布日期：2026-11-20｜角色：devops
> 发布方式：**GitHub Actions 云端构建 + Release**（本地不打包）
> 前序版本：1.10.18｜加密协议：**X-Encrypted-Stream: v1**（未变；无接口 / 原语 / DDL 变更）
> 通道：`AGENTS.md §7.5.3` 代码 BUG 快速修复
> 依据：用户提供的第三方客户端 **Debug 2 日志**（标准流程的直接证据）

## 1. 发布范围

1. **认证严格按 RFC 4252 的 authlist 推进**：先发 `none` 取初始方法列表；每轮只在
   「服务器列出的方法」与「本地能提供的能力」的交集里选一个发送；**绝不发送未列出的方法**。
2. **修复核心缺陷**：服务器列出 `password` 而连接未存密码时，改为**弹框索取并用
   `password` 方法发送**。此前弹框输入只流向 keyboard-interactive 回调，
   用户的正确密码**从未以服务器允许的方法发出去过** —— 这是连不上的真正原因。
3. **删除非标准兜底**：v1.10.16/18 中「服务器没列 keyboard-interactive 也发一次」的启发式整体移除。
4. **去第三方客户端品牌化**：产品代码与用户文案中的客户端名称全部改为协议术语
   （`grep -rn "WinSCP" jflove-desktop/src jflove-desktop/ui/src jflove-server/src` = 0）。
5. 保留（均为通用能力，与具体主机无关）：`ssh-rsa`(RSA-SHA1) 回退、跳板链、主机指纹、诊断行。

服务端 / Web / 移动端 **仅版本号同步**；数据库 **无 DDL**。

### 用户可见变化

- 只配私钥、服务器要求账号密码时：连接会弹框，输入后**按服务器要求的方式**提交（此前从未提交成功）。
- 弹框 / 字段提示改为「服务器要求继续认证（SSH password 方法）」这类协议术语。
- 报错明确区分「没收到输入」「账号密码不对」「服务器仍要求密钥」，不再把问题归咎于私钥。

## 6. 回滚方式

- 桌面端 / App / Web：回退到 `v1.10.18` 的 Release 资产与镜像，数据库无需回滚（本版无 DDL）。
- 服务端：`docker compose` 把镜像 tag 从 `1.10.19` 改回 `1.10.18` 重启即可。
- 回退到 v1.10.18 后的已知退化：
  - 服务器列 `password` 而本地无密码时，弹框输入的密码**不会被发送**，认证必然失败；
  - 可能向服务器发送其未列出的 `keyboard-interactive`；
  - 用户文案中出现第三方客户端名称。
