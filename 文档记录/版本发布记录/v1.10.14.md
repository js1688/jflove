## 1. 发布范围

1. **旧服务器 `ssh-rsa` 主机密钥握手**：`paramiko` 固定 `4.0.0`（5.0 起移除 `ssh-rsa`/RSA-SHA1
   与 SHA-1 KEX）；现代算法（Ed25519/ECDSA/rsa-sha2）仍默认优先。
2. **旧服务器公钥认证**：首次 `publickey` 失败后，仅在 RSA 私钥且服务器未声明只支持 SHA-2 时，
   自动临时改用 `ssh-rsa` 重试一次；现代服务器首次成功，不回退。
3. **诊断文案**：区分「认证方式选错」与「私钥被拒」；`no acceptable host key` /
   `no acceptable kex algorithm` 翻成中文；日志记录远端版本/主机密钥类型/KEX/认证方法（不含凭据）。
4. 服务端 / Web / App **仅版本号同步**；数据库 **无 DDL**。

## 6. 回滚方式

- 桌面端 / App / Web：回退到 `v1.10.13` 的 Release 资产与镜像
  （`ghcr.io/js1688/jflove-{server,web}:1.10.13`），数据库无需回滚（本版无 DDL）。
- 服务端：`docker compose` 里把镜像 tag 从 `1.10.14` 改回 `1.10.13` 重启即可。
- 桌面端回退到 v1.10.13 后，旧服务器 `ssh-rsa` 兼容能力会消失（适用于回滚后只连现代服务器）。
