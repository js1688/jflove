# JFLove v1.10.18 版本发布记录

> 版本：1.10.18｜发布日期：2026-11-20｜角色：devops
> 发布方式：**GitHub Actions 云端构建 + Release**（本地不打包）
> 前序版本：1.10.17｜加密协议：**X-Encrypted-Stream: v1**（未变；无接口 / 原语 / DDL 变更）
> 通道：`AGENTS.md §7.5.3` 代码 BUG 快速修复（用户选择「发布 1.10.18（走 CI）」）
> 用户反馈证据：v1.10.17 实测日志 —— 同一网关四次连接得到四种结果
> （`认证序列=publickey→password` 报「密钥被拒」/ `publickey→keyboard-interactive` 失败 /
> `认证序列=publickey` 无弹框 / `首轮结果=failed`）

## 1. 发布范围

1. **键盘交互弹框不再依赖认证方式**：以前只有「密码 / 密码 + OTP / 密码 + 密钥」才会在
   「服务器要密码但本地无密码」时改走键盘交互；选「密钥」时直接放弃（用户看到「弹框都不出现」）。
   现在只要**有私钥**就会弹框询问，与 WinSCP「先用密钥、连上后弹框要密码」一致。
2. **密钥已通过时不再误报「私钥被拒」**：密码 / 键盘交互失败后服务器若把 authlist 交回
   `publickey`，旧文案会说「服务器未接受当前密钥（私钥）」把用户引去反复换私钥。
   现在按 `key_accepted` 判定，明确说明「私钥本身没有问题，是后续账号密码未通过」。
3. **弹框空输入可辨识**：弹框超时（约 60 秒）或没点「确定」时，文案直接说
   「没有收到你输入的账号密码」，不再与「密码填错」混为一谈。
4. **防御性改动**：SSH 实现缺 `auth_interactive` 时抛出可读错误而非 `AttributeError`。

服务端 / Web / 移动端 **仅版本号同步**；数据库 **无 DDL**。

### 用户可见变化

- 认证方式选「密钥」，服务器要求账号密码时**会弹框**（以前不弹，只能靠改配置碰运气）。
- 失败时能分清三种情况：**没收到输入** / **输入的账号密码不对** / **私钥真的被拒**。
- 不再因为一句「服务器未接受当前密钥」去反复换私钥（用户实测被误导过）。

## 6. 回滚方式

- 桌面端 / App / Web：回退到 `v1.10.17` 的 Release 资产与镜像，数据库无需回滚（本版无 DDL）。
- 服务端：`docker compose` 里把镜像 tag 从 `1.10.18` 改回 `1.10.17` 重启即可。
- 回退到 v1.10.17 后的已知退化：
  - 认证方式选「密钥」时服务器要密码 → **不弹框**、直接报配置提示；
  - 密码 / 键盘交互失败后可能误报「服务器未接受当前密钥（私钥）」；
  - 弹框超时与密码错误无法区分。
