# v1.0.0 版本发布记录

JFLove 首个正式版本：基于端到端应用层加密的私有文档与笔记管理系统。

## 修订历史

| 修订序号 | 时间 | 内容 | 镜像 sha256 |
|---|---|---|---|
| 初次发布 | 2026-05-04 09:09 | 首发 docker 镜像 + 桌面端 PyInstaller 包；DB 仅支持 `/data` 单一挂载点 | `378efdc5c3a226b03816a7d1defeb3c9d1924a98e0cdcdc9c2404ca6b6149330` |
| **修订 1** | **2026-05-04 19:42** | **新增 `/storage` 物理大容量磁盘挂载点；entrypoint 启动时打印挂载状态；支持单盘与多盘两种挂载形态** | **`381b0a1278745ac337104a4e59845b2c408c23994aa8944b7b27bcb4cbc56203`** |

> **修订 1 动机**：初版镜像未约定物理盘挂载点，服务端添加虚拟磁盘时只能选容器内目录（小容量、销毁丢失）。修订后用户可通过 `-v /mnt/big-disk:/storage` 把宿主机大盘挂入容器，虚拟磁盘 `real_path` 填 `/storage` 即可让文件落到物理盘。本次修订**未改业务源代码**，仅调整镜像构建配置（`Dockerfile` + `entrypoint.sh`）；客户端无需任何修改。
>
> **是否要新增版本号**：严格按语义化应升 `v1.0.1`；但镜像未推送任何远端仓库，沿用 `v1.0.0` 重发是用户决定。如本次修订后镜像已被外部使用，下次类似变更应新开版本号。

## 七、部署步骤

### 7.1 jflove-server（Docker）

镜像约定两个挂载点：

| 挂载点 | 用途 | 不挂载时的退化行为 |
|---|---|---|
| `/data` | SQLite 业务数据库持久化 | 用镜像内置空表 DB（容器销毁数据丢失，仅演示） |
| `/storage` | 物理大容量磁盘挂载点；服务端添加虚拟磁盘时 `real_path` 填 `/storage` 或其子目录 | 服务端只能选容器内目录（小、易丢失），不推荐生产 |

容器启动时 entrypoint 会自动打印两个挂载点的状态、`/storage` 子目录列表、可用空间。

#### 模式 A：单大盘 + 持久化 DB（**生产推荐**）

```bash
mkdir -p /opt/jflove/data

docker run -d \
    --name jflove-server \
    -p 8989:8989 \
    -v /opt/jflove/data:/data \
    -v /mnt/big-disk:/storage \
    --restart=always \
    jflove-server:1.0.0
```

之后管理员在桌面端「添加虚拟磁盘」时，`real_path` 填 `/storage`，文件会保存到宿主机 `/mnt/big-disk`。

#### 模式 B：多块物理盘并行使用

```bash
mkdir -p /opt/jflove/data

docker run -d \
    --name jflove-server \
    -p 8989:8989 \
    -v /opt/jflove/data:/data \
    -v /mnt/disk-a:/storage/disk-a \
    -v /mnt/disk-b:/storage/disk-b \
    --restart=always \
    jflove-server:1.0.0
```

添加虚拟磁盘时 `real_path` 分别填 `/storage/disk-a`、`/storage/disk-b`，对应不同的物理盘；entrypoint 启动日志会自动列出所有 `/storage` 子目录，便于核对。

#### 模式 C：演示 / 临时用（**容器销毁数据丢失**）

```bash
docker run -d \
    --name jflove-server \
    -p 8989:8989 \
    --restart=always \
    jflove-server:1.0.0
```

不挂载 `/data` 与 `/storage`，所有数据保存在镜像内置位置；容器销毁后数据全部丢失。仅适合演示。

#### SELinux 系统（Fedora / RHEL / Rocky）

启用 SELinux 时挂载需加 `:Z` 后缀，否则容器报 `Permission denied`：

```bash
docker run -d \
    --name jflove-server \
    -p 8989:8989 \
    -v /opt/jflove/data:/data:Z \
    -v /mnt/big-disk:/storage:Z \
    --restart=always \
    jflove-server:1.0.0
```

#### 通用：自定义端口与监听地址

```bash
docker run -d \
    --name jflove-server \
    -p 18989:8989 \
    -v /opt/jflove/data:/data \
    -v /mnt/big-disk:/storage \
    -e JFLOVE_HOST=0.0.0.0 \
    -e JFLOVE_PORT=8989 \
    --restart=always \
    jflove-server:1.0.0
```

## 八、回滚预案

### 8.1 服务端回滚

```bash
# 1. 停止现行容器
docker stop jflove-server && docker rm jflove-server

# 2. 切回上一版本（v1.0.0 是首发，没有上一版本 → 等价于完全卸载）
docker rmi jflove-server:1.0.0

# 3. 数据库回滚（仅在确认 schema 不兼容时执行）
sqlite3 /opt/jflove/data/jflove-prod.db < 第四节给出的回滚 SQL
```

### 8.2 桌面端回滚

无需特殊步骤：直接停用旧版 `JFLove` 可执行文件即可（每次发布的 PyInstaller 包都是单文件、互不依赖）。

### 8.3 紧急关停（任意阶段）

```bash
docker stop jflove-server
```

服务停止后客户端会立即失败；此时 session_key 仅在内存中存在，**容器一旦销毁所有 session 即失效**（前向保密）。

## 十、加密协议版本声明

- 当前协议版本：`X-Encrypted-Stream: v1`
- 帧格式：`[4 字节 BE 长度 N] [12 字节 nonce] [N 字节密文+16 字节 Poly1305 tag]`
- 明文分片大小：64 KB（`STREAM_PLAINTEXT_CHUNK_SIZE`）
- KDF：HKDF-SHA256，盐 `b"jflove-v1"`，输出长度 32 字节
- AEAD：ChaCha20-Poly1305
- 密钥交换：X25519 ECDH 临时密钥（每次会话新派生，前向保密）

本版本未升级帧格式，`X-Encrypted-Stream: v1` 即首发版本；后续若升级到 v2，必须在对应版本发布记录中列出向后兼容策略。
