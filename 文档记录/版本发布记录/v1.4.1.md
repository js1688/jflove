# v1.4.1 版本发布记录：视频播放修复（时长 + seek）

## 一、版本信息

| 模块 | 版本 | 变更 |
|------|------|------|
| jflove-server | **1.4.1** | 媒体探测失败回退 byte、ffmpeg 可用性修复；TS 伪装 MP4 强制转 AAC；faststart MP4 判定修正；init 段补读；**fMP4 mvhd duration 改写（供播放器显示总时长）** |
| jflove-web | **1.4.1** | MSE 非 fMP4 回退下载 + 下载进度；MSE 时长/seek 修复（timestampOffset + 非受控 src + 防竞态） |
| jflove-desktop | **1.4.1** | StreamProxy time 修复流声明 Accept-Ranges，使 QMediaPlayer 可拖拽 seek |
| jflove-app | **1.4.1** | StreamProxy time 修复流声明 Accept-Ranges，使 ExoPlayer 可拖拽 seek |

> 接口契约不变（`stream_mode` / `range_start_seconds` / meta 帧字段均不变），桌面/移动端仅 StreamProxy 一处改动。

### 修复明细（迭代内追加，均在 v1.4.1 范围内）

| 编号 | 现象 | 根因 | 修复 |
|------|------|------|------|
| BUG-4 | TS 伪装 .mp4（0x47 同步字节）无法 MSE 播放 | 源为 MPEG-TS 流，Chrome MSE 不识别 | ffmpeg 修复流 `-c:a aac` 强制转码音频 + 输出 fMP4 |
| BUG-5 | 修复后无声音 / 报 codec 不识别 | 某些源 mp4a 无 DecoderSpecificInfo | `_mp4a_codec` 回退 `mp4a.40.2` + Web codec 串补全 |
| BUG-6 | faststart MP4（moov 前置但无 mvex）MSE 卡死 | faststart≠fMP4，MSE 需要 moov+mvex | 服务端 `_moov_at_front` 要求 mvex；Web `isFmp4Init` 同判定，非 fMP4 回退下载 |
| BUG-7 | 视频时长未知、无法拖进度、点击进度条播放失败 | fMP4 `empty_moov` 无时长信息；seek 后旧流退出把 endOfStream 写到新流 | Web 用服务端 meta.duration 设 `MediaSource.duration`；consume 代际计数防竞态 |
| BUG-8 | 初始播放间歇性失败（空 codec / ftyp-only init 段） | ffmpeg 把 ftyp 与 moov 分两次写出，首块 `read` 只拿到 28 字节 ftyp → `parse_fmp4_codec` 解析为空 | 服务端 `_read_fmp4_init` 累加读取直到出现 moov（上限 4MB） |
| BUG-9 | seek 后旧流仍占服务端修复并发槽，新流排队超时失败 | Web 只 `frames.return()` 未真正 cancel 旧 fetch | Web 每流独立 AbortController，seek 前 abort 旧流；seek 改用 `SourceBuffer.timestampOffset` 保持总时长恒定、播放头不归零；`<video>` src 改为非受控避免与 MSE 命令式 src 冲突 |
| BUG-10 | 桌面/移动端 time 修复流无总时长、拖拽进度条无效 | empty_moov 的 mvhd duration=0 播放器拿不到时长；HEAD 不声明 Accept-Ranges 播放器认为不可 seek | 服务端改写 mvhd duration 提供总时长；两端 StreamProxy 声明 Accept-Ranges 使播放器可 seek |

> BUG-4/5/6/8/10 在服务端镜像中生效；BUG-7/9 在 Web 中生效；BUG-10 的客户端部分（Accept-Ranges）在桌面端 1.4.1 / 移动端 1.4.1 中生效。

## 七、部署步骤（用户侧）

### 服务端（192.168.100.5）

```bash
# 1. 推送镜像（本机 docker push 到仓库，或在 NAS 上重新构建）
docker tag jflove-server:1.4.1 <仓库>/jflove-server:1.4.1
docker push <仓库>/jflove-server:1.4.1

# 2. NAS 上拉取并重启（注意保留 -v /data 与 /storage 挂载）
docker pull <仓库>/jflove-server:1.4.1
docker rm -f jflove-server  # 先停旧容器
docker run -d --name jflove-server -p 8989:8989 \
  -v /opt/jflove/data:/data \
  -v /mnt/big-disk:/storage \
  --restart=always jflove-server:1.4.1
```

### Web 端

```bash
docker tag jflove-web:1.4.1 <仓库>/jflove-web:1.4.1
docker push <仓库>/jflove-web:1.4.1
# NAS 上
docker pull <仓库>/jflove-web:1.4.1
docker rm -f jflove-web
docker run -d --name jflove-web -p 18080:80 --restart=always jflove-web:1.4.1
```

### 部署后验证

1. 浏览器访问 Web，打开普通 MP4：应能**回退完整下载并显示「下载中 x%」后正常播放**（BUG-1 生效）。
2. 管理面板开启「媒体修复」后，普通 MP4 / MKV 应能**边下边播**（BUG-2/BUG-3 生效，ffmpeg 可用）。
3. 若 ffmpeg 仍不可用，修复开关开启后也**不再报 415**，自动回退 byte + 下载播放（BUG-2 兜底）。
4. TS 伪装 .mp4（「损坏的」视频）：开启媒体修复后应能**边下边播且有声**（BUG-4/BUG-5 生效）。
5. 修复流播放时进度条应**显示总时长、可拖拽 seek**；点击进度条跳转后应从目标点继续播放，不再「播放失败」（BUG-6/BUG-7 生效）。
