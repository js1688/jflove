## 1. 发布范围

**桌面端终端：粘贴重复 + 粘贴/输入卡顿。**

用户 2026-11-22 反馈（Linux 端，要求一并排查 Windows）：

1. 远程 SSH / 本机终端**按一次 Ctrl+V 会粘贴两次**；
2. 远程 SSH / 本地终端**输入时有明显延迟和卡顿**。

### 1.1 根因（全部有实测证据，详见开发记录 §2）

| # | 根因 | 关键证据 |
| --- | --- | --- |
| 1 | `attachCustomKeyEventHandler` 返回 `false` **只拦 xterm 自己的 keydown**，浏览器默认粘贴照样执行 ⇒ 一次按键走两条路 | 同机 A/B：去掉 `preventDefault()` → 2 条 input 帧；加上 → 1 条 |
| 2 | QtWebEngine 里 `navigator.clipboard.readText()` **永久 pending**，旧实现每次粘贴先白等满 500ms 才回退桥 | 实测 `TIMEOUT@3001ms`；用户侧感受即"每次粘贴卡半秒" |
| 3 | 输出写屏绑在 `requestAnimationFrame` 上；页面被判隐藏时 **rAF 1 秒 0 帧** | `{"vis":"hidden","raf":0,"mc":295747}` |
| 4 | `applyFit` 每次都重跑整套候选测量（同步布局） | 源码级单测锁定幂等守卫 |
| 5 | 反后台化 flags 原来只注入 Windows | Linux 一并注入（单测锁定） |

### 1.2 修复

1. **粘贴单一路径**：命中自定义分支即 `event.preventDefault()`（复制三分支 + 粘贴一支），
   保住 `ctrl` / `ctrlShift` / `smart` 三种模式的既有语义；
2. **剪贴板桥优先**：桌面端（桥就绪）直接走 Python 桥（同步 IPC），
   浏览器 API 只在无桥时兜底；`withTimeout` 用哨兵区分"超时"与"空剪贴板"，
   超时后记忆"该宿主不可用"，不再反复白等；
3. **输出调度不依赖 rAF**：新增 `ui/src/utils/terminal-schedule.ts`，
   用 `MessageChannel` 宏任务合帧（无 `MessageChannel` 时退化为 `setTimeout`），
   消除"页面隐藏 ⇒ 输出堆死 ⇒ 恢复时一次性灌入/丢数据"；
4. **`applyFit` 幂等**：容器尺寸 + 字号 + 自适应开关未变则直接返回；
5. **Linux 反后台化**：`--disable-backgrounding-occluded-windows` /
   `--disable-renderer-backgrounding` / `--disable-background-timer-throttling`
   三平台统一注入；`CalculateNativeWinOcclusion` 仍限 Windows。

服务端 / Web / 移动端 / 官网 **仅版本号同步**；数据库 **无 DDL**。

### 1.3 ⚠ 证据边界（对外表述必须遵守）

「rAF 掉到 1.5fps / 按键 2~4 秒」那组数据来自**无合成器的 Xvnc/Xvfb**。
在同一用户真实桌面（Wayland + XWayland `:0`，DPR=2）上，同一探针测得
**keydown → 画面 6–25ms、rAF 稳定 60fps**，**未能复现秒级延迟**。

因此本版的准确表述是：

- **已修复且可量化**：粘贴两次（A/B 实证）、每次粘贴固定 500ms 白等（实测）；
- **已修复的确定性缺陷**：页面被判隐藏时终端输出断流（rAF=0 实测），
  影响"最小化到托盘再恢复"场景；
- **未定位的剩余体感差异**：记入台账 T-1，下个版本在真实负载下长时段采样。

## 8. 回滚方式

本版为纯客户端渲染层修复，**无服务端/数据库变更**：

- 服务端 / Web：无新接口、无 DDL，回滚到 v1.10.21 镜像即可；
- 桌面端：重装 v1.10.21 安装包（用户配置与本地库结构未变，可原地回退）；
- 若仅需回退"剪贴板桥优先"行为：恢复 `ui/src/utils/clipboard.ts` 中先试浏览器 API 的顺序
  （不建议——会把 500ms 白等重新带回来）。
