## 1. 发布范围

**多步 SSH 认证共用一条 `ssh-userauth` 会话。**

用户那台网关（`SSH-2.0-UNLAWFUL ENTRY…`，要求「公钥 + 账号密码」两因子）从 v1.10.13 到
v1.10.20 八个版本都连不上，而 WinSCP 与用户自己的 JSch（Java）代码都能连。

根因（报文级实测）：`paramiko` 的 `Transport.auth_publickey` / `auth_password` /
`auth_interactive` **每调用一次就新建 `AuthHandler` 并重发一次
`SSH_MSG_SERVICE_REQUEST("ssh-userauth")`**。该网关把「新的服务请求」当作**认证进度重置**：

```text
publickey    → partial：允许 password     （公钥这一步过了）
重发服务请求 → 网关清掉「公钥已通过」
password     → 网关认为公钥还没过 ⇒ 拒绝，只列 publickey
```

表现就是「密码明明正确却被拒，服务器仍要求 `publickey`」。

本版：

1. 新增 `_AuthChannel`：复用同一个 `AuthHandler`，首步开服务、后续只发
   `SSH_MSG_USERAUTH_REQUEST` —— 整次认证只开**一条** userauth 会话；
2. 报文组装复用 paramiko 自己的算法协商与签名逻辑（不自行实现签名/编码）；
3. `ssh-rsa`(RSA-SHA1) 回退走同一条会话；只对真实 `paramiko.Transport` 生效，
   测试替身与既有用例零改动；
4. 顺带对齐前端：「密码 + 密钥」允许**密码留空**（与服务端 `ssh_service` 同口径）。

服务端 / Web / 移动端 **仅版本号同步**；数据库 **无 DDL**。

### 用户可见变化

- 那台网关：认证方式「密码 + 密钥」、**密码栏可留空**，连上后弹框输入账号密码即可连通。
- 其他服务器：**行为不变**（只是少发了若干次无用的服务请求）。
