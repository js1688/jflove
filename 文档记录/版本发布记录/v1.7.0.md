## 四、生产库 DDL（升级 + 回滚）

### 4.1 升级

```bash
sqlite3 jflove-prod.db < jflove-db/migrate-v1.7.0.sql
```

幂等；只新增表与索引，**不触碰业务数据**。内容：

```sql
CREATE TABLE IF NOT EXISTS file_changes (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    disk_id      INTEGER NOT NULL,
    rel_path     TEXT    NOT NULL,
    op           TEXT    NOT NULL,
    is_dir       INTEGER NOT NULL DEFAULT 0,
    size         INTEGER NOT NULL DEFAULT 0,
    mtime        REAL    NOT NULL DEFAULT 0,
    content_hash TEXT    NOT NULL DEFAULT '',
    created_at   TEXT    NOT NULL,
    updated_at   TEXT    NOT NULL,
    deleted_at   TEXT
);
CREATE INDEX IF NOT EXISTS file_changes_disk_id_idx ON file_changes(disk_id);
CREATE INDEX IF NOT EXISTS file_changes_rel_path_idx ON file_changes(rel_path);
```

### 4.2 回滚

```bash
sqlite3 jflove-prod.db < jflove-db/rollback-v1.7.0.sql
```

**回滚前冲突检查**：本表只存变更日志，删除不影响业务文件与用户数据；但会丢弃变更历史，
旧客户端的 `since_rev` 失效后会回退到全量对账（`scan`），功能不受影响、只是变慢。

```sql
-- 可选：确认记录量（不阻断）
SELECT COUNT(*) FROM file_changes;
```

## 六、镜像部署（本版重点）

### 6.1 服务端

```bash
# 1) 升级前先备份生产库
cp /data/jflove-prod.db /data/jflove-prod.db.bak-$(date +%Y%m%d-%H%M)

# 2) 执行迁移（新增 file_changes 表）
sqlite3 /data/jflove-prod.db < jflove-db/migrate-v1.7.0.sql

# 3) 拉取并重启
docker pull ghcr.io/js1688/jflove-server:1.7.0
docker stop jflove-server && docker rm jflove-server
docker run -d --name jflove-server --restart=always \
  -p 8989:8989 \
  -v /data:/data \
  -v /storage:/storage \
  ghcr.io/js1688/jflove-server:1.7.0

# 4) 冒烟
curl -s http://127.0.0.1:8989/health
```

## 七、已知限制（如实登记）

1. **Linux 桌面挂载未实现**：本版只有 Windows CfAPI；Fedora 上仍是应用内挂载视图（台账 BL-1）。
2. **CfAPI 回调整文件读入内存**：大文件（几百 MB 以上）内存占用高，后续改按范围流式。
3. **移动端后台保活未接 WorkManager**：App 被杀后不自动备份（BL-4）。
4. **Android 真机未验证**：相册权限、厂商 ROM 后台行为需真机验收。
5. **挂载路径只读**：不提供「在挂载目录编辑后回传」；「固定到本地」未单独实现（AC-108 未达）。
