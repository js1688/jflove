## 1. 发布范围

1. **旧服务器 ssh-rsa 三步认证链**：回退后**保持 ssh-rsa 签名直到本轮认证结束**；
   服务器「部分认证」后仍要求 `publickey` 时补一轮继续用 ssh-rsa；`publickey` 上限 3 次。
   修复用户 `Maverick_SSHD` 型服务端（首轮 rsa-sha2 被拒 → ssh-rsa 验签成功但要求继续 → 补一轮完成）。
2. **回退门槛解除**：`server-sig-algs` 不再作为是否回退的条件；回退时摘掉该扩展，
   避免 paramiko 抛 `Unable to agree on a pubkey algorithm`。
3. **认证诊断行**：失败信息追加 `诊断：远端=…；主机密钥=…；KEX=…；服务器签名算法=…；
   本次签名算法=…；私钥=…；首轮结果=…；ssh-rsa 回退=…`（不含凭据），会话失败条完整显示 + 复制详情。
4. **二次密钥认证文案**：明确指向「两把不同私钥」而不是 `authorized_keys`；
   多跳认证失败带 `跳板 N / 目标 + host:port`。
5. 服务端 / Web / App **仅版本号同步**；数据库 **无 DDL**。

## 6. 回滚方式

- 桌面端 / App / Web：回退到 `v1.10.14` 的 Release 资产与镜像
  （`ghcr.io/js1688/jflove-{server,web}:1.10.14`），数据库无需回滚（本版无 DDL）。
- 服务端：`docker compose` 里把镜像 tag 从 `1.10.15` 改回 `1.10.14` 重启即可。
- 桌面端回退到 v1.10.14 后，旧网关（`Maverick_SSHD` 型）的三步认证链会失效
  （v1.10.14 在回退后立即恢复 rsa-sha2、且 `publickey` 只试 2 次）。
