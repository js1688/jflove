# JFLove v1.10.17 版本发布记录

> 版本：1.10.17｜发布日期：2026-11-20｜角色：devops
> 发布方式：**GitHub Actions 云端构建 + Release**（本地不打包）
> 前序版本：1.10.16｜加密协议：**X-Encrypted-Stream: v1**（未变；无接口 / 原语 / DDL 变更）
> 通道：`AGENTS.md §7.5.3` 代码 BUG 快速修复（用户明确要求新版本号 1.10.17）
> 用户反馈证据：WinSCP 对照日志 —
> `使用公钥"imported-openssh-key"进行认证。` → `Further authentication required` → 输入密码即连上

## 1. 发布范围

1. **第二因子走键盘交互的网关照常支持**：服务器 authlist 只列 `password`、真正的第二因子在
   keyboard-interactive 里问密码（WinSCP 的「Further authentication required」）时，客户端在
   `password` 认证被拒后**自动补一次键盘交互**并由弹层收集密码。用户此前无论把密码填到
   「账号密码」还是「私钥口令」都不可能成功——两个都走错通道。
2. **消除密钥重发死循环**：密钥被服务器接受后，即使 authlist 又交回 `publickey` 也**不再重发**
   （除旧网关 ssh-rsa 合法补签名）。此前形成 `publickey→password→publickey→password→publickey`。
3. **`key_accepted` 判定收紧**：仅 `status == "ok"` 视为密钥被接受；`rejected` 不再误判。
4. **密码可留空**：密钥类认证（密钥 / 密码 + 密钥 / 密码 + OTP）在保存时允许不填账号密码，
   连接时弹层补——这类网关在保存阶段本来就拿不到密码，不再逼用户瞎填。
5. **口令状态不再谎报**：服务端新增 `has_passphrase`（只回布尔），表单据此显示
   「已设置，留空不修改」或「私钥未加密则留空」。此前用 `has_private_key` 推断，
   只要存过私钥就永远显示「已设置」，用户误以为库里有幽灵口令。
6. 服务端仅新增布尔派生字段与一处校验放宽；**无 DDL**。

### 用户可见变化

- 那台 Maverick 网关：**密码栏留空**保存 → 连接时弹出「服务器要求继续认证 / Password:」→ 输入
  WinSCP 里用过的那个密码 → 即可连上。
- 编辑连接时，「私钥口令」不再因为存过私钥就显示「已设置」。
- 失败报错不再劝你「改用密码 + OTP」（本版已自动处理），并带上 `认证序列=` 便于排查。

## 6. 回滚方式

- 桌面端 / App / Web：回退到 `v1.10.16` 的 Release 资产与镜像
  （`ghcr.io/js1688/jflove-{server,web}:1.10.16`），数据库无需回滚（本版无 DDL）。
- 服务端：`docker compose` 里把镜像 tag 从 `1.10.17` 改回 `1.10.16` 重启即可。
- 回退到 v1.10.16 后的已知退化：
  - 第二因子走键盘交互的网关会重新连不上（报「账号密码没有被服务器接受」）；
  - 编辑连接时口令框会重新谎报「已设置」；
  - 密钥被拒后可能再次出现 `publickey→password→publickey→…` 的重复序列。
