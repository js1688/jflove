# v1.1.3 版本发布记录

## 一、发布概述

本版本在 v1.1.2 基础上，为文档管理页面新增「重命名」与「移动到…」两项写操作，并实现磁盘级写权限感知。具体改动：

- **服务端（jflove-server）**：新增 `POST /api/v1/files/rename`、`POST /api/v1/files/move` 接口；`GET /api/v1/files/disks` 新增 `can_write` 字段（向后兼容）；全部接口走加密信封通道，路径参数权限校验严格。
- **桌面端（jflove-desktop）**：右键菜单扩展重命名/移动/删除；新增 `MoveTargetDialog` 懒加载目录树；`_can_write` 状态随磁盘切换实时更新，无写权限时三项写操作均禁用。

## 八、部署步骤与启动命令

### 8.1 服务端 Docker 部署

#### 方式一：挂载外部数据库（生产推荐）

```bash
docker run -d \
  --name jflove-server \
  -p 8989:8989 \
  -v /opt/jflove/data:/data \
  -v /mnt/big-disk:/storage \
  --restart=always \
  jflove-server:1.1.3
```

说明：
- `/opt/jflove/data` ：SQLite 数据库持久化目录（首次自动从镜像内空表结构初始化）
- `/mnt/big-disk` ：大容量磁盘挂载点（可选，创建虚拟磁盘时使用）
- `--restart=always` ：Docker 启动（含宿主机重启）时自动重启容器

#### 方式二：使用镜像内置数据库（演示/测试）

```bash
docker run -d \
  --name jflove-server \
  -p 8989:8989 \
  --restart=always \
  jflove-server:1.1.3
```

注意：容器销毁后数据丢失，仅用于临时演示。

#### 从 v1.1.2 升级

```bash
# 1. 停止旧容器
docker stop jflove-server && docker rm jflove-server

# 2. 加载新镜像（如已 push 到仓库则 docker pull）
# docker pull your-registry/jflove-server:1.1.3

# 3. 用新镜像启动（-v 挂载路径与之前保持一致）
docker run -d \
  --name jflove-server \
  -p 8989:8989 \
  -v /opt/jflove/data:/data \
  -v /mnt/big-disk:/storage \
  --restart=always \
  jflove-server:1.1.3
```

无数据库结构变更，挂载目录下的 `jflove-prod.db` 可直接复用，无需手动迁移。

### 8.2 桌面端部署

将 `build/dist/JFLove` 分发到目标 Linux 机器，赋予执行权限直接运行：

```bash
chmod +x JFLove && ./JFLove
```

## 十一、回滚预案

### 服务端回滚到 v1.1.2

```bash
# 停止 1.1.3 容器
docker stop jflove-server && docker rm jflove-server

# 回滚到 v1.1.2 镜像
docker run -d \
  --name jflove-server \
  -p 8989:8989 \
  -v /opt/jflove/data:/data \
  -v /mnt/big-disk:/storage \
  --restart=always \
  jflove-server:1.1.2
```

注：本版本无数据库表结构变更，回滚无需 DDL 回滚脚本，挂载目录下的数据库文件可直接复用。

### 桌面端回滚

保留旧版 `JFLove` 二进制，替换新版即可。

### 向后兼容说明

- v1.1.2 桌面端连接 v1.1.3 服务端：原有功能完全兼容；新的 rename/move 接口在旧桌面端不可见，不影响使用。
- v1.1.3 桌面端连接 v1.1.2 服务端：rename/move 请求会 404，右键菜单操作将提示失败；其他功能不受影响。
