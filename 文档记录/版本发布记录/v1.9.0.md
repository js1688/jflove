## 4. 生产库 DDL（升级 + 回滚）

**本版本无服务端表结构变更**，因此不需要迁移/回滚 SQL。

发布前核对证据：

```text
$ jflove-server/venv-linux/bin/python scripts/check_db_schema.py
前置检查：dev 库 vs 当前程序代码的表结构 → dev 库与当前代码一致 ✓
dev / prod 表结构核对 → 结构一致 ✓（发布前检查通过）
历史遗留表（不参与比对、不会复制到 prod）：[dev] notes_permissions
exit=0
```

回滚：服务端无 DDL 需要回滚；但本版协议为 **强制异步合并**，回滚必须四端与服务端**一起回退**到旧版本，
不允许只回退服务端或只回退某个客户端（旧客户端 init 会被 409 提示升级）。

## 5. 升级说明（用户可见）

1. **四端与服务端必须同批次升级到 1.9.0**；旧客户端连接新服务端时 init 会返回 409「请升级客户端」。
2. 断点续传保障期默认 24 小时；管理员可在「系统设置 → 存储与临时文件」调整（同时决定清理保护期）。
3. 超过保障期的分片会被自动清理；客户端重试时从头上传且不报错。
4. 文件列表/对账不再显示 `.` 开头条目；程序临时目录不可通过文件管理接口访问。
5. 弱服务端（如 N2840/8GB）建议启用「弱服务端模式」（合并并发 1 / 上传并发 2 / 分片 512KB）。

## 6. 回滚方案

- 代码/镜像：四端与 GHCR 镜像统一回退到上一版本（v1.8.4）与对应 tag；
- 数据库：无 DDL/无业务表变化，无需数据回滚；
- 临时文件：回退后旧代码会忽略 `.jflove-tmp`（文件列表仍会显示旧隐藏项，需重新部署 1.9.0 或用清理脚本处理）。
