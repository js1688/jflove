# v1.10.8 设计：桌面端终端底座重建

> 角色：designer　日期：2026-11-15　版本：v1.10.8
> 基线：`文档记录/设计文档/v1.10.0.md` §3.4（终端通道）、§3.7（本机终端）
> 需求：`文档记录/需求文档/v1.10.8.md`

## 1. 结论先行

v1.10.0 的终端分层（Python 持有 PTY/SSH、渲染层只有 xterm + 一条本机 WebSocket）是**对的**，不改。
要动的是三处**契约**：

| 契约 | 旧 | 新 | 为什么 |
| --- | --- | --- | --- |
| 终端能力探测 | 交给 xterm 内置处理 | **渲染层前置 DECRQM 兼容层** | xterm 6.0.0 生产包该路径必抛异常，且异常会让写队列永久卡死 |
| 会话与 DOM 的生命周期 | 组件生命周期 = 会话生命周期 | **会话生命周期 = 标签生命周期**（xterm/WS 存模块级注册表） | 路由切换/标签切换都不该重建终端 |
| 输出下发 | 每个 chunk 一帧 | **16ms 合并一帧** + 8MB 上限 | TUI 每帧几十个 chunk，逐条发会把 GUI 线程拖垮 |

## 2. 组件与数据流

```
┌─────────────── 渲染层（QtWebEngine / React）───────────────┐
│ SessionPage（标签/工具条/状态栏）                          │
│   └─ TerminalView ── 取用 ──▶ runtimes: Map<sessionId, RT> │
│         │                      ├─ xterm 实例（可自愈重建） │
│         │                      └─ WebSocket（可自愈重连）  │
│         └─ DECRQM 兼容层 / 复制粘贴 / 字号 / 状态节流      │
└───────────────────────────┬────────────────────────────────┘
                            │ ws://127.0.0.1:<port>/term/<sid>?token=…
┌───────────────────────────▼────────────────────────────────┐
│ TerminalHost（Qt 主线程）                                   │
│   feed(bytes) ─▶ 待发缓冲 ─(16ms)─▶ 一条二进制帧            │
│   文本帧：exit（退出）/ 上行 input·resize·close·redraw       │
└───────────────────────────┬────────────────────────────────┘
                            │
              ┌─────────────▼─────────────┐
              │ LocalSession / SshSession │  TERM/色彩、SIGWINCH、退出码
              └───────────────────────────┘
```

## 3. 关键设计点

### 3.1 DECRQM 兼容层（`ui/src/utils/xterm-decrqm.ts`）

- xterm 的 CSI handler 派发是**后注册者先执行**（`EscapeSequenceParser` 从数组尾部往前），
  因此在我们自己的 handler 里 `return true` 即可完全屏蔽内置坏实现；
- 回复按 DECRPM 规范 `CSI [?]m;status$y`，status ∈ {0 未识别, 1 置位, 2 复位, 3 永久置位, 4 永久复位}；
- 状态值从 `term.modes` / `term.buffer.active.type` 推导，保证与渲染层真实状态一致。

### 3.2 会话级运行时注册表（`TerminalView.tsx`）

- `runtimes: Map<sessionId, SessionRuntime>`；组件挂载时"接管" DOM（`host.appendChild(runtime.wrapper)`），
  卸载时只 `removeChild`，**不 dispose**；
- 标签关闭（`store.closeTab`）→ `SessionPage` 调 `disposeOrphanTerminals(aliveIds)` 显式回收；
- 为什么不用"路由 keep-alive"：会牵动整个路由架构，且终端生命周期本来就该绑定标签。

### 3.3 写队列看门狗与自愈

xterm 的 `WriteBuffer` 遇到解析异常会**永久卡死**（`_bufferOffset` 不前进、不再调度）。
兜底策略：`write(data, callback)` 记录"待确认时间"，5s 未被确认即认为卡死 →
丢弃旧 xterm、在同一个 `wrapper` 里新建一个（WS 不动）→ 发 `redraw` 让远端整屏重绘。

### 3.4 不做历史回放（设计决策，含反例）

第一版设计过"Python 侧保留 256KB 输出、重连回放"。真机证伪：
回放会让终端重新应答字节流里的能力查询（DA1/OSC10/OSC11），应答进 shell 被回显，
形成自我污染。**结论：宁可让 TUI 自己重绘，也不回放原始字节。**

### 3.5 控制终端（POSIX）

`pty.openpty()` 后子进程必须 `setsid()` **且** `ioctl(slave, TIOCSCTTY)`：
没有控制终端就没有前台进程组，`Ctrl+C`（0x03）不会产生 SIGINT，`Ctrl+Z` 也不会挂起。

### 3.6 终端类型与字体

- `TERM` 缺省/`dumb` → `xterm-256color`；补 `COLORTERM=truecolor`、`TERM_PROGRAM=JFLove`；
  profile 的 `env_json` 拥有最终否决权；
- `lineHeight 1.25` + 无外层 padding：单元格高度按字体度量计算，中文回退字体偏大；
  同一窗口由 137×22 提升到 135×24。**注意这不只是美观**：dsh TUI 在 ≤21 行会画丢输入框内容行
  （tmux 交叉验证同样现象）。

## 4. 安全与合规（对照 `AGENTS.md §9`）

- 终端通道仍只绑 `127.0.0.1`，每会话随机 token，`hmac.compare_digest` 校验；
- 渲染层仍无网络出口，WS 只连本机回环；凭据不进入渲染层（本设计未新增凭据路径）；
- 剪贴板读写登记进 `MAIN_THREAD_METHODS`（`QClipboard` 非线程安全）；
- 日志不记录终端内容（仅尺寸、长度、状态）。
