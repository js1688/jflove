# JFLove 1.1.0 技术设计文档

## 0. 与 v1.0 的差异概述

本版本只在**流式预览**一个功能方向上扩展，所有 v1.0 的设计均保持不变。

| 项 | v1.0 | v1.1.0 |
|---|---|---|
| 视频/音频预览 | 整文件写临时文件，交 QMediaPlayer 播放 | 本地 HTTP 代理边下边播，内存缓冲，不落盘 |
| 大文本/日志预览 | 整文件加密下载到内存后显示 | 流式分块拉取，首屏 ≤3s，支持跳转任意位置 |
| 预览协议 | `X-Encrypted-Stream: v1`（无 Range） | `X-Encrypted-Stream: v2`（加密 body 携带 Range） |
| 服务端接口 | `GET /api/v1/files/preview`（全量） | 新增 `GET /api/v1/files/stream`（Range 支持） |
| 本地临时文件 | 视频/音频写 tmpfile | 全部格式均不写磁盘 |
| 客户端版本兼容 | — | 硬升级：v1.0 桌面端不兼容 v1.1.0 流式端点 |

## 1. 架构决策记录

### 决策 1：新增 `/api/v1/files/stream` 端点（不复用 download）

选择方案 B：新增独立端点。

- download 语义是"拿走一份副本落盘"，stream 语义是"边传边播、关闭即丢"；两者责任不同，不应合并
- 测试覆盖独立，不影响 v1.0 已有的 download 行为

### 决策 2：Range 参数走加密 body（不用 HTTP Range header）

选择方案 B：Range 字段（`range_start` / `range_end`）嵌入加密 JSON body。

- HTTP `Range` header 对 MITM 可见，字节偏移能反推"用户拖到了文件 50%"——侧信道与 §9 隐私优先冲突
- 与现有 GET 接口风格统一（`requests.get(url, json=encrypted_payload)`）

### 决策 3：保持 64KB 明文帧大小

- v1.0 已有 `STREAM_PLAINTEXT_CHUNK_SIZE = 64 * 1024`，100 Mbps 下传输 1 帧 < 5ms，远低于 3s 阈值
- 帧大小固定 → 客户端 seek 时可精确计算帧边界：第 N 帧明文起点 = N × 64 KB

### 决策 4：媒体播放用本地 HTTP 代理（`StreamProxy`）

选择方案 B：桌面端在 `127.0.0.1` 起临时 HTTP 服务，`QMediaPlayer` 指向该本地 URL。

- 完全不落盘（§4.2 要求）
- QMediaPlayer 原生支持 HTTP Range，拖进度自动触发新的 Range 请求
- 本地代理只 listen loopback，URL 含一次性随机 token，生命周期与预览窗口绑定

### 决策 5：协议版本升级到 v2

响应头 `X-Encrypted-Stream: v2` 标记 Range 流式协议，便于回滚与故障排查。

## 2. 服务端设计

### 2.1 新端点：`GET /api/v1/files/stream`

#### 2.1.1 鉴权方式

- 明文白名单之外 → **加密信封**（§9.1）
- 请求头必须携带 `X-Session-ID`
- 加密 body 内含 `token` 字段（JWT，ES256）
- 权限校验：调用 `permission_service.check_disk_permission(user_id, disk_id, "read")`

#### 2.1.2 请求体（解密后 JSON）

```json
{
  "token": "<JWT>",
  "disk_id": 1,
  "path": "videos/",
  "filename": "movie.mp4",
  "range_start": 0,
  "range_end": -1
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| token | string | JWT 令牌 |
| disk_id | int | 虚拟磁盘 ID |
| path | string | 文件所在目录（磁盘内相对路径） |
| filename | string | 文件名 |
| range_start | int | 请求字节起点（含），0 = 文件开头；负数表示从末尾倒数（如 −524288 = 最后 512KB） |
| range_end | int | 请求字节终点（不含），−1 = 文件结尾 |

#### 2.1.3 参数规范化（服务端）

```text
file_size = os.path.getsize(real_path)

effective_start = range_start if range_start >= 0 else max(0, file_size + range_start)
effective_end   = range_end   if range_end   >= 0 else file_size

effective_start = clamp(effective_start, 0, file_size)
effective_end   = clamp(effective_end,   effective_start, file_size)
```

#### 2.1.4 响应格式（`StreamingResponse`）

响应头：
```
X-Encrypted-Stream: v2
Content-Type: application/octet-stream
```

响应体为帧序列：

```
┌─────────────────────────────────────────────────────┐
│ Frame 0 — 元数据帧（Metadata Frame）                 │
│  [4B 大端 length][12B nonce][ChaCha20-Poly1305 密文] │
│  明文 JSON：{                                         │
│    "type": "meta",                                   │
│    "file_size": <total_file_size>,                   │
│    "range_start": <effective_start>,                 │
│    "range_end": <effective_end>,                     │
│    "content_type": "<mime_type>"                     │
│  }                                                   │
├─────────────────────────────────────────────────────┤
│ Frame 1..N — 数据帧（Data Frame）                    │
│  [4B 大端 length][12B nonce][ChaCha20-Poly1305 密文] │
│  明文：最大 64KB 的原始文件字节                       │
│  最后一帧可能 < 64KB                                 │
└─────────────────────────────────────────────────────┘
```

> 帧格式与 v1 相同（`[4B length][12B nonce][ciphertext+16B tag]`），v2 只增加了元数据帧和 Range 请求语义。客户端用同一个 `parse_stream_frame()` 函数解密。

#### 2.1.5 文件不存在 / 被删除时的错误帧

若文件在传输中途被删除，服务端发送一个错误帧后关闭连接：

```json
{ "type": "error", "code": "FILE_NOT_FOUND", "message": "文件不存在或已被删除" }
```

正常打开时文件不存在，直接返回加密的错误响应（HTTP 404，与现有机制一致）。

#### 2.1.6 内容类型推断（服务端）

```python
import mimetypes
content_type, _ = mimetypes.guess_type(filename)
if content_type is None:
    content_type = "application/octet-stream"
```

#### 2.1.7 加密规范自查

- [x] 路径参数：仅含 disk_id（整数），无业务敏感信息
- [x] 请求 body 走 `decrypt_request_body`
- [x] 响应走 `StreamingResponse + encrypt_stream_chunk`（每帧独立 nonce）
- [x] 错误通过 `HTTPException` 抛出，被全局 handler 加密
- [x] 响应头不含 filename / 路径
- [x] 日志中 filename 截断，不记录路径全文

### 2.2 服务端流式生成器（伪代码）

```python
async def _stream_range_generator(
    real_path: str,
    session_key: bytes,
    effective_start: int,
    effective_end: int,
    file_size: int,
    content_type: str,
):
    # 帧 0：元数据
    meta = json.dumps({
        "type": "meta",
        "file_size": file_size,
        "range_start": effective_start,
        "range_end": effective_end,
        "content_type": content_type,
    }).encode()
    yield encrypt_stream_chunk(session_key, meta)

    # 帧 1..N：数据
    try:
        with open(real_path, "rb") as f:
            f.seek(effective_start)
            remaining = effective_end - effective_start
            while remaining > 0:
                chunk_size = min(STREAM_PLAINTEXT_CHUNK_SIZE, remaining)
                chunk = f.read(chunk_size)
                if not chunk:
                    break
                yield encrypt_stream_chunk(session_key, chunk)
                remaining -= len(chunk)
    except FileNotFoundError:
        error_frame = json.dumps({
            "type": "error",
            "code": "FILE_NOT_FOUND",
            "message": "文件不存在或已被删除",
        }).encode()
        yield encrypt_stream_chunk(session_key, error_frame)
```

> 服务端流生成器中的 `open/seek` 操作是同步 I/O，需在 `asyncio.get_event_loop().run_in_executor(None, ...)` 中执行，或使用 `anyio.to_thread.run_sync`，避免阻塞 FastAPI 事件循环。

### 3.2 视频/音频：`StreamProxy`

#### 3.2.1 架构

```
PreviewDialog
  │
  ├─── 创建 StreamProxy(disk_id, path, filename, file_service)
  │      ├── 绑定 127.0.0.1:随机端口
  │      ├── 生成一次性 token（UUID4）
  │      └── 启动 HTTPServer 线程
  │
  └─── QMediaPlayer.setSource(QUrl("http://127.0.0.1:{port}/{token}"))

QMediaPlayer → [HTTP GET / Range请求] → StreamProxy._handle()
                                          │
                                          ├── 解析 Range header
                                          │   (bytes=X-Y)
                                          ├── 调用 file_service.stream_range(
                                          │     disk_id, path, filename,
                                          │     range_start=X, range_end=Y+1)
                                          │   返回: (meta, frame_iter)
                                          ├── 读 meta.file_size
                                          ├── 响应 206 Partial Content
                                          │   Content-Range: bytes X-Y/total
                                          │   Accept-Ranges: bytes
                                          └── 逐帧解密 → 写入响应体
```

#### 3.2.2 `StreamProxy` 关键行为

**启动**：
```python
class StreamProxy:
    def __init__(self, disk_id, path, filename):
        self._token = str(uuid.uuid4()).replace("-", "")
        self._server = HTTPServer(("127.0.0.1", 0), self._make_handler())
        self._port = self._server.server_address[1]
        self._thread = threading.Thread(target=self._server.serve_forever, daemon=True)
        self._active_response = None   # 当前进行中的 requests.Response
        self._lock = threading.Lock()

    @property
    def url(self) -> str:
        return f"http://127.0.0.1:{self._port}/{self._token}"

    def start(self):
        self._thread.start()
```

**处理请求**：
```python
def _handle_get(self, handler):
    # 1. 验证 token
    if handler.path.lstrip("/") != self._token:
        handler.send_error(403); return

    # 2. 解析 Range header
    range_header = handler.headers.get("Range", "")
    range_start, range_end_inclusive = _parse_range_header(range_header)
    # range_end 在请求体里是 exclusive，Range header 是 inclusive，+1 转换

    # 3. 向服务端发流式请求
    meta, frame_iter = file_service.stream_range(
        disk_id, path, filename,
        range_start=range_start,
        range_end=range_end_inclusive + 1 if range_end_inclusive >= 0 else -1,
    )

    # 4. 响应头
    handler.send_response(206 if range_header else 200)
    handler.send_header("Content-Type", meta["content_type"])
    handler.send_header("Accept-Ranges", "bytes")
    if range_header:
        end = range_end_inclusive if range_end_inclusive >= 0 else meta["file_size"] - 1
        handler.send_header(
            "Content-Range",
            f"bytes {meta['range_start']}-{end}/{meta['file_size']}"
        )
    handler.end_headers()

    # 5. 逐帧写入（可被 close() 中断）
    for plaintext in frame_iter:
        if self._closed:
            break
        handler.wfile.write(plaintext)
```

**关闭**：
```python
def close(self):
    self._closed = True
    with self._lock:
        if self._active_response:
            self._active_response.close()   # 终止 requests 流，断开与服务端的 TCP
    self._server.shutdown()                 # 停止 HTTPServer
    # 内存中的 frame buffer 随对象销毁
```

#### 3.2.3 `file_service.stream_range()`

```python
def stream_range(disk_id, path, filename, range_start, range_end):
    """
    向 jflove-server GET /api/v1/files/stream 发请求，
    返回 (meta: dict, frame_iter: Iterator[bytes])
    meta 包含 file_size / content_type / range_start / range_end
    frame_iter 逐帧 yield 已解密的明文字节
    """
    resp = http_client.stream_request(
        "GET", "/api/v1/files/stream",
        payload={
            "disk_id": disk_id,
            "path": path,
            "filename": filename,
            "range_start": range_start,
            "range_end": range_end,
        },
        stream=True,
    )
    # 读第一帧（元数据帧）
    meta_bytes = _read_one_frame(resp)
    meta = json.loads(meta_bytes.decode())
    if meta.get("type") == "error":
        raise StreamError(meta["code"], meta["message"])

    def _frame_iter():
        for raw_frame in _iter_frames(resp):
            plaintext = parse_stream_frame(raw_frame, session_manager.session_key)
            frame = json.loads(plaintext) if plaintext.startswith(b"{") else None
            if frame and frame.get("type") == "error":
                raise StreamError(frame["code"], frame["message"])
            yield plaintext

    return meta, _frame_iter()
```

> **注意**：`_frame_iter()` 是一个惰性生成器，只在 `StreamProxy._handle_get()` 消费时才实际读取网络数据。关闭代理时 `response.close()` 会让生成器的 `next()` 抛出 `ConnectionError`，由 proxy 捕获后静默退出。

#### 3.2.4 内存缓冲上限

`StreamProxy` 不自行缓冲帧——`frame_iter` 拿到一帧就写给 QMediaPlayer，QMediaPlayer 自身的解码缓冲区负责平滑播放。

因此客户端内存峰值约为：QMediaPlayer 内部缓冲（通常 2~8 MB）+ 当前解密帧（64 KB）。

若用户频繁拖进度，每次拖动会触发 QMediaPlayer 发出新的 Range 请求 → proxy 终止旧请求 → 发起新请求 → 服务端 seek 到新位置。旧请求的 TCP 连接被 `response.close()` 立即释放。

#### 3.2.5 网络抖动处理

`stream_range()` 内部用 `requests.get(stream=True, timeout=(连接超时 5s, 读取超时 30s))`。

代理检测到 `requests` 读取超时（30 秒内无数据）：
1. 发出 `stream_error` 信号（含错误描述）
2. `PreviewDialog` 收到信号 → 弹错误对话框「连接已断开，请重试」→ 关闭预览窗口

短暂抖动（< 读取超时）期间，`frame_iter` 的 `next()` 阻塞等待，QMediaPlayer 的播放缓冲会逐渐耗尽然后进入 stalled 状态（显示加载图标），网络恢复后自动继续——这正是 §4.1.3 故事 D 要求的行为。

### 3.3 文本/日志：`StreamTextLoader`

#### 3.3.1 目标行为

| 操作 | 期望 |
|---|---|
| 打开文件 | 3 秒内首屏可见（加载前 512KB） |
| 向下滚动 | 接近底部时自动追加下一块 |
| 跳转到末尾 | 3 秒内显示（加载最后 512KB，使用 `range_start=-524288`） |
| 关闭预览 | 立即停止传输，释放内存 |

#### 3.3.2 架构

```
StreamTextLoader
  ├── _loader_thread: QThread（在后台调用 file_service.stream_range）
  ├── chunk_ready(bytes) signal → UI 线程 append 到 QPlainTextEdit
  ├── error(str) signal → 错误对话框
  └── _cancel: threading.Event（set 即停止 _loader_thread）

_StreamTextView（QDialog 中的 QPlainTextEdit）
  ├── scrolled_near_bottom() → 触发加载下一块
  └── jump_to_end() → 重置 loader，从 range_start=-524288 重新加载
```

#### 3.3.3 分块策略

- 每次请求 `range_size = 524288`（512 KB）的字节段
- 解码时按 UTF-8 解码，后缀截断不完整多字节字符（`errors="ignore"` 兜底）
- `QPlainTextEdit` 持有的文本上限：8 MB（超出时截断前面内容，保留最新 6 MB）

#### 3.3.4 跳转到末尾

```python
def jump_to_end(self):
    self._cancel.set()        # 停止当前加载
    self._text_view.clear()   # 清空缓冲
    self._start_loading(range_start=-524288, range_end=-1)
```

#### 3.3.5 内存释放

关闭对话框时 `closeEvent` 调用 `loader.cancel()` → `_cancel.set()` → 后台线程退出 → 服务端 TCP 连接关闭 → `frame_iter` 生成器被 GC → 所有帧内存释放。

### 3.5 PreviewDialog 关闭逻辑

```python
def closeEvent(self, event):
    # 停止媒体播放
    if hasattr(self, "_media_player"):
        self._media_player.stop()
        self._media_player.setSource(QUrl())

    # 关闭代理（媒体）/ 取消加载（文本）
    if hasattr(self, "_stream_proxy"):
        self._stream_proxy.close()
    if hasattr(self, "_text_loader"):
        self._text_loader.cancel()

    super().closeEvent(event)
```

关闭序列保证：
1. `QMediaPlayer.setSource(QUrl())` → 停止向代理发 Range 请求
2. `proxy.close()` → 中止代理到服务端的连接 → 服务端生成器退出 → 带宽/CPU 释放
3. 整个过程 < 1 秒（§4.1.4）

## 5. 加密接口规范（v2 新增部分）


## 6. 安全宪法合规（§9 自查）

| 条款 | 合规情况 |
|---|---|
| §9.1.1 加密通道是默认值 | `/files/stream` 在明文白名单之外，全程加密 |
| §9.1.2 文件传输端到端加密 | `StreamingResponse + encrypt_stream_chunk`，每帧独立 nonce |
| §9.1.3 错误响应加密 | HTTPException 全局 handler 覆盖 |
| §9.1.4 URL 不携带业务参数 | Range 在加密 body，URL 无 query string |
| §9.3 JWT 走加密 body | ✓ |
| §9.3 路径参数权限校验 | 无新路径参数；disk_id 在 body 内校验权限 |
| §9.4 响应头无敏感字段 | 无 Content-Disposition / filename |
| §9.5 加密原语复用 | 复用 `encrypt_stream_chunk` / `parse_stream_frame` |
