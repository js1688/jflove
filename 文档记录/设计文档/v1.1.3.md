## 4. API 接口设计

### 4.1 接口总览

| 路径 | 方法 | 说明 | 明文白名单 | 路径参数 | 加密策略 |
|---|---|---|---|---|---|
| `/api/v1/files/rename` | POST | 重命名文件或目录 | 否 | 无 | ChaCha20-Poly1305 信封 |
| `/api/v1/files/move` | POST | 移动文件或目录 | 否 | 无 | ChaCha20-Poly1305 信封 |

> 两个接口均无路径参数，不存在路径参数权限绕过风险；磁盘归属校验在 body 解密后的 disk_id 上进行。

---

### 4.2 POST `/api/v1/files/rename` — 重命名

#### 4.2.1 安全标注

| 项 | 值 |
|---|---|
| 明文白名单 | 否（走加密信封） |
| 路径参数 | 无 |
| 加密信封策略 | 请求体 `decrypt_request_body`；响应体 `encrypt_response` |
| 错误响应 | 经全局加密 handler，detail 不 echo 完整路径 |
| 鉴权 | JWT 从加密 body 的 `token` 字段读取 |
| 权限校验 | `check_disk_permission(db, user_id, disk_id, "write")` |

#### 4.2.2 请求体（加密后字段）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `token` | string | 是 | JWT 令牌 |
| `disk_id` | int | 是 | 虚拟磁盘 ID |
| `path` | string | 是 | 目标文件/目录的当前相对路径（含名称，例如 `"docs/old_name.txt"`） |
| `new_name` | string | 是 | 新名称（**纯名称**，不含路径分隔符，例如 `"new_name.txt"`） |

#### 4.2.3 响应体（加密后字段）

| 字段 | 类型 | 说明 |
|---|---|---|
| `message` | string | `"已重命名"` |

#### 4.2.4 错误码

| HTTP 状态码 | detail | 触发条件 |
|---|---|---|
| 401 | 缺少认证令牌 / 令牌无效 | JWT 缺失或过期 |
| 403 | 无写入权限 | 用户对该磁盘无 write 权限 |
| 400 | 非法名称 | `new_name` 为空、含 `/`、`\`、为 `.` 或 `..` |
| 400 | 路径非法 | `path` 路径穿越检测失败 |
| 404 | 路径不存在 | `path` 指向的文件/目录不存在 |
| 409 | 目标名称已存在 | 同目录下已有同名文件/目录 |

#### 4.2.5 服务端逻辑

```
1. decrypt_request_body → 提取 token / disk_id / path / new_name
2. _get_user → 解析 JWT
3. check_disk_permission(write)
4. _get_disk_path(disk_id) → base
5. target = _safe_join(base, path)          # 防路径穿越
6. 校验 new_name：非空、不含 /\、不为 . 或 ..
7. parent_dir = os.path.dirname(target)
8. new_target = os.path.join(parent_dir, new_name)
9. _safe_join(base, new_name_rel)            # new_target 也在 base 内（理论上同 parent_dir 就在内，但仍需验证）
10. 若 target == new_target → return {"message": "已重命名"}（静默跳过）
11. 若 os.path.exists(new_target) → raise HTTPException(409)
12. os.rename(target, new_target)
13. encrypt_response({"message": "已重命名"})
```

### 4.3 POST `/api/v1/files/move` — 移动

#### 4.3.1 安全标注

| 项 | 值 |
|---|---|
| 明文白名单 | 否（走加密信封） |
| 路径参数 | 无 |
| 加密信封策略 | 请求体 `decrypt_request_body`；响应体 `encrypt_response` |
| 错误响应 | 经全局加密 handler，detail 不 echo 完整路径 |
| 鉴权 | JWT 从加密 body 的 `token` 字段读取 |
| 权限校验 | `check_disk_permission(db, user_id, disk_id, "write")` |

#### 4.3.2 请求体（加密后字段）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `token` | string | 是 | JWT 令牌 |
| `disk_id` | int | 是 | 虚拟磁盘 ID |
| `src_path` | string | 是 | 被移动的文件/目录相对路径（例如 `"docs/file.txt"`） |
| `dst_dir_path` | string | 是 | 目标**目录**的相对路径（例如 `"archive"`；根目录传 `""`） |

#### 4.3.3 响应体（加密后字段）

| 字段 | 类型 | 说明 |
|---|---|---|
| `message` | string | `"已移动"` |

#### 4.3.4 错误码

| HTTP 状态码 | detail | 触发条件 |
|---|---|---|
| 401 | 缺少认证令牌 / 令牌无效 | JWT 缺失或过期 |
| 403 | 无写入权限 | 用户对该磁盘无 write 权限 |
| 400 | 路径非法 | src_path 或 dst_dir_path 路径穿越检测失败 |
| 400 | 目标目录与当前目录相同 | src 和 dst 解析后父目录相同（静默跳过亦可，服务端选择返回 400 让客户端处理） |
| 400 | 目标目录是源目录的子目录 | 移动目录到自身子目录（循环嵌套） |
| 404 | 源路径不存在 | src_path 指向的文件/目录不存在 |
| 404 | 目标目录不存在 | dst_dir_path 不是一个存在的目录 |
| 409 | 目标位置已存在同名项 | dst_dir_path 下已有与 src_path 同名的文件/目录 |

#### 4.3.5 服务端逻辑

```
1. decrypt_request_body → token / disk_id / src_path / dst_dir_path
2. _get_user → 解析 JWT
3. check_disk_permission(write)
4. _get_disk_path(disk_id) → base
5. src_abs = _safe_join(base, src_path)         # 防路径穿越
6. dst_dir_abs = _safe_join(base, dst_dir_path) # 防路径穿越
7. 若 src_abs 不存在 → raise 404
8. 若 dst_dir_abs 不存在 或 不是目录 → raise 404
9. src_parent = os.path.dirname(src_abs)
   若 src_parent == dst_dir_abs → return 400（静默跳过由客户端负责，服务端统一 400）
10. 若 src 是目录：检查 dst_dir_abs 是否以 src_abs + os.sep 开头 → raise 400（循环嵌套）
11. name = os.path.basename(src_abs)
    new_abs = os.path.join(dst_dir_abs, name)
12. 若 os.path.exists(new_abs) → raise 409
13. os.rename(src_abs, new_abs)                  # 同磁盘内，OS 层原子操作
14. encrypt_response({"message": "已移动"})
```

#### 5.2.2 重命名对话框（内联，使用 `QInputDialog`）

```
1. 弹出 QInputDialog.getText()，预填当前名称，全选
2. 用户取消 → 跳过
3. new_name.strip() == "" → InfoBar 提示「名称不能为空」
4. new_name == old_name → 跳过
5. new_name 含 / \ 或 == "." 或 == ".." → InfoBar 提示「名称包含非法字符」
6. 调用 Worker(file_service.rename_file, disk_id, rel_path, new_name)
7. 成功 → _refresh() + InfoBar.success("已重命名")
8. 失败 → InfoBar.error(e)
```

客户端校验（步骤 3~5）仅作快速提示，服务端会二次校验。

#### 5.2.3 移动对话框（新增 `MoveTargetDialog` 类）

`MoveTargetDialog` 是一个 `QDialog`，包含：

- **标题**：「选择目标目录」
- **目录树** `QTreeWidget`：
  - 根节点「/（根目录）」，data = `""`
  - 懒加载：展开节点时才请求子目录（`itemExpanded` 信号）
  - 树项仅展示目录，不展示文件
  - 被移动的源目录本身不可选（灰色 + 禁用）
- **底部按钮**：`PrimaryPushButton("确认移动")` + `PushButton("取消")`
- `get_selected_path() -> str | None`：返回用户选定的目录相对路径

展开子目录流程：

```
1. itemExpanded(item) → 若 item 未曾展开过（标记 _loaded=False）
2. Worker(file_service.list_files, disk_id, item_path) 只取 is_dir=True 的项
3. 加载完成后追加子节点；若无子目录，留空（叶节点）
4. 标记 item._loaded = True
```

点击「确认移动」流程：

```
1. 若无选中项 → 提示「请选择目标目录」
2. 获取 selected_path = selected_item.data(0, Qt.UserRole)
3. 若 selected_path 与当前目录相同 → dialog.accept()（客户端静默跳过，不发请求）
4. else → 调用 Worker(file_service.move_file, disk_id, src_rel_path, selected_path)
5. 成功 → dialog.accept() + _refresh() + InfoBar.success("已移动")
6. 失败 → InfoBar.error(e)（在 dialog 内部显示，不关闭弹窗）
```

#### 5.2.4 写权限状态维护

在 `FilePage` 中新增 `_can_write: bool = False`。

在 `_on_disks_loaded` 中，磁盘切换时：
- 管理员角色（已从 session 中读取）：`_can_write = True`
- 普通用户：调用 `file_service.list_accessible_disks` 的返回结果中追加 `can_write` 字段（服务端 `/files/disks` 接口扩展，见 5.3）。

#### 5.2.5 写权限判断的服务端接口扩展（minor）

`GET /api/v1/files/disks` 响应的每个磁盘项增加 `can_write: bool` 字段，供桌面端决定是否启用写操作按钮。

这是对现有接口的**向后兼容扩展**（仅新增字段，原有字段不变）。

## 6. 安全方案

### 6.1 路径穿越防护

服务端两个新接口均使用现有 `_safe_join(base, rel)` 函数校验所有路径参数。`_safe_join` 已通过 v1.1.0 测试报告中的路径穿越专项测试，无需修改。

特别对 `rename` 接口：`new_name` 是纯名称，服务端额外校验：
- 不能为空字符串
- 不能包含 `/` 或 `\`（Windows 路径分隔符）
- 不能为 `.` 或 `..`（相对路径跳转）

### 6.2 循环嵌套防护（移动接口）

防止「把目录 A 移动到 A 的子目录 B」：

```python
if os.path.isdir(src_abs):
    # dst_dir_abs 必须不以 src_abs + os.sep 开头
    if dst_dir_abs.startswith(src_abs + os.sep) or dst_dir_abs == src_abs:
        raise HTTPException(status_code=400, detail="目标目录是源目录的子目录")
```

### 6.3 加密合规

两个新接口均遵循安全宪法 §9：

- 请求体走 `decrypt_request_body`
- 响应体走 `encrypt_response`
- 错误响应经全局 handler 加密
- 日志不记录完整路径（仅记录 disk_id 和操作结果）
- 不在响应头暴露 filename

### 6.4 权限校验

两个接口均检查 `write` 权限，与 `make_dir`、`delete_file` 保持一致。无权限时服务端返回 403，客户端灰色按钮是附加的 UX 保护，不作为唯一防线。
