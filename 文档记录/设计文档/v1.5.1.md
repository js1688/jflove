## 2. 品牌资产一致性设计（#1，AC-1/2/3）

### 2.1 单一真相

品牌美术资产 = **猫猫 logo**（用户认可的基准）。当前它只有一份物理副本，位于桌面端工程内：

```
jflove-desktop/ui/public/logo-64.png   (7 040 B)
jflove-desktop/ui/public/logo-128.png  (24 151 B)
jflove-desktop/ui/public/logo-256.png  (82 519 B)
```

**两端是独立工程**，所以 Web 端**复制**一份到自己的 `public/`（不做软链、不跨工程引用、不共享构建配置）：

```
jflove-web/public/logo-64.png | logo-128.png | logo-256.png   （新增，与桌面端同字节）
```

> 为什么不用"改桌面端去引用 Web 端"或抽公共目录：两端在 CI/打包上互相独立（`web-frontend/SKILL.md` 边界约束），跨工程引用会让任一端的构建依赖另一端的目录结构。**"同一美术资产的副本 + 哈希校验"**是本项目已验证的跨端一致性做法（对照 v1.5.0 的三端图表模板"逐字一致 + 校验脚本"）。

### 2.2 替换点

| 文件 | 现状 | 目标 |
|------|------|------|
| `jflove-web/src/layouts/DesktopLayout.tsx:99-101` | `<span className="logo-mark"><Icon name="shield" …/></span>` | `<img src="./logo-128.png" alt="" aria-hidden="true" className="h-8 w-8 shrink-0 rounded-[10px] object-cover" />`（与桌面端 `ui/src/layouts/DesktopLayout.tsx:101-106` 逐属性一致） |
| `jflove-web/src/pages/LoginPage.tsx:111-112` | `<span className="logo-mark mx-auto !h-14 !w-14 !rounded-2xl"><Icon name="shield" size="xl" …/></span>` | 同款 `<img>`，保留原有尺寸类（`h-14 w-14 rounded-2xl`），保持登录页版式不变 |

- 相对路径 `./logo-*.png` 与桌面端现有写法一致（Vite `base` 配置下两端各自成立）。
- `Icon.tsx` 的 `shield` 条目**保留**（其他地方可能在用；删除图标会牵连无关文件）；只改这两处**使用点**。

### 2.3 可执行判据（把约束绑到命令，**LESSONS.md L12**）

新增根级脚本 `scripts/check_logo_sync.py`：

- 逐一比较 `jflove-web/public/logo-{64,128,256}.png` 与 `jflove-desktop/ui/public/logo-{64,128,256}.png` 的 **sha256**；
- 任一侧缺文件或哈希不一致 → 打印差异明细，**退出码 1**；全部一致 → 退出码 0；
- **反向验证**（`LESSONS.md` L17）：把任一文件的 1 个字节改掉后必须返回 1（并在交付记录里写出该反向验证的实际输出）。

## 3. 系统设置契约对齐（#2，AC-4/5）

### 3.1 契约事实（本设计的唯一依据）

| 层 | 事实 | 证据 |
|----|------|------|
| 服务端 | `media_repair_allow_transcode` **已无人读取**；键保留在库中不删 | `media_repair_service.py:11-13`、`settings.py:30` |

| Web 端 UI | 已按"废弃"处理，不读不写 | `jflove-web/src/services/config-service.ts:11-13` |

> ⚠ 这正是 `LESSONS.md` **L34**（"抄另一个端的客户端代码前，必须对着服务端契约逐项核对"）的实例：**客户端之间的不一致会把错误互相传染**。本次以**服务端契约为准**收敛，而不是让 Web 端去对齐桌面端的残留 UI。

### 3.2 设计

1. **桌面端**删除「允许重编码降级」开关：删除 `AdminSystemPage.tsx` 中的开关块（`:111-125`）、`allowTranscode` 状态、`toggleTranscode` 处理函数、以及说明文案里"重编码为无损修复失败时的降级手段"这半句；
2. **桌面端** `ui/src/services/config-service.ts` 删除 `allowTranscode` 键常量，注释措辞与 Web 端 `config-service.ts:11-13` **对齐**（两端都说明"该键已废弃、前端不再读写"）；
3. **Web 端**不改界面，仅确认其注释与桌面端一致（如措辞不同则统一）；
4. 服务端**不动**（键保留在库中）；
5. **PoC 断言同步**（E5）：`jflove-desktop/poc/login-shell/test_headless.py` 中与该开关相关的四段（`:1155` 常量、`:1172` 文本断言、`:1186-1205` 点击与轮询、`:1243-1250` 还原）必须一并移除，并把"页面**不含**该文案"作为新的断言方向。

   > 为什么必须改 PoC：它是一道"可执行的门禁"。留着它，下次谁跑这个脚本都会得到一个**与设计相反的失败**；而如果为了让脚本通过又把开关加回来，就等于让门禁把错误锁死（`LESSONS.md` L11、L12）。

### 3.3 验收口径

- 全仓 UI 源码中 `允许重编码降级` **零命中**（判据：`grep -rn "允许重编码降级" jflove-web/src jflove-desktop/ui/src` 无输出）；
- 两端系统设置页可见配置项集合一致（均为「修复并发数」一项）。

## 4. 笔记编辑页改版设计（#4，两端同源）

### 4.1 布局（改后）

```
┌────────────────────────────────────────────────────────────────┐
│ PageHeader：[← 返回]  文件名             [编辑|分屏|预览] [大纲][保存] │  ← 工具栏新增「大纲」开关
├──────────────────────────────────┬─────────────────────────────┤
│ 编辑区（分屏/编辑模式）           │  预览区                      │  右侧大纲栏（可折叠）
│ textarea                          │  .markdown-body             │  ▸ 一级标题
│                                   │                             │    ▸ 二级标题
└──────────────────────────────────┴─────────────────────────────┘
```

- 大纲栏从**底部**（`<details>`）移到**右侧**，与预览区**并列**（feasible：容器 `flex min-h-0 flex-1`）；
- 尺寸：固定 `w-56`（224px）+ `shrink-0` + `border-l border-line-subtle` + `overflow-y-auto`，栏内条目沿用现有样式（缩进 `(level-1)*16px`、`text-[13px] text-muted hover:text-fg-brand`）；
- 标题行 `px-4 py-2`，与既有面板风格一致；**不新增色值、不硬编码品牌色**（沿用 v1.5.0 令牌体系）。

### 4.2 显示与折叠规则

| 条件 | 行为 |
|------|------|
| `viewMode === 'preview' \|\| 'split'` 且 `headings.length > 0` | 显示大纲栏（默认**展开**） |
| `viewMode === 'edit'` 或 `headings.length === 0` | 不显示大纲栏（编辑时给全宽；无标题时栏内无内容可展示） |
| 用户点击工具栏「大纲」按钮 | 展开/折叠切换；折叠时按钮处于 `data-on` 态 |
| 折叠状态 | 仅组件内存状态（**不持久化**，避免新增存储面；下次进入页面回到默认展开） |

> 说明：`viewMode === 'edit'` 时不显示大纲，是因为大纲跳转依赖预览区 DOM（`document.querySelector('.markdown-body')`），编辑模式下预览区不存在，展示一个点了没反应的栏不如不展示。

### 4.3 默认模式判定（AC-9/10/11）

**不能用"路由是否带 new 标记"**（E9：新建与打开既有笔记共用 `notes/:noteId`，且新建是先建空文件再跳转），因此采用**内容驱动**规则：

```
进入页面：
  viewMode 初值 = 'edit'             // 加载期间不显示空预览，避免"闪一下空预览"（Web 端硬约束 3 的同源思想）
  loadNote(filename) 成功后（仅首次、且用户未手动切换过）：
      content.trim() !== '' ? setViewMode('preview')   // 已有内容 → 预览
                            : setViewMode('edit')      // 空笔记（新建）→ 编辑
  用户手动切换过模式 → userSwitchedRef = true，此后任何自动判定都不再改写 viewMode
```

- 用 `useRef` 记录"本次 filename 是否已判定过"，**避免自动保存触发的 store 变化再次改写用户模式**；
- **"手动优先"的作用域＝当前 filename**（R5-T2 口径补充）：手动切换后把该 filename 记进 ref，同一篇内不再自动改写（AC-11）；切到另一篇笔记时按该篇内容重新判定（AC-9/AC-10）。实现即 `useRef<string | null>`（记"手动切换过的文件名"），**不是**全局布尔 —— 全局布尔会导致"先手动切过一次，之后打开任何有内容的笔记都停在编辑模式"；
- 既有"图表跳到源码"逻辑（`NoteEditPage.tsx:254`：预览态下切到分屏）**保持不变**——它属于"用户主动点击图表"的显式意图；
- 自动保存、离开确认、`beforeunload` 等逻辑**零改动**。

### 4.4 大纲栏的数据来源

沿用现有 `headings`（`useMemo`，`^#{1,3}\s` 解析、≤3 级）与 `handleOutlineClick`（按文本匹配 `h1,h2,h3` 后 `scrollIntoView`）。本次**不新增**标题解析规则、不加滚动联动高亮（避免过度设计，且滚动联动在窄栏里价值有限）。

### 4.5 两端同源判据（AC-15）

`jflove-web/src/pages/NoteEditPage.tsx` 与 `jflove-desktop/ui/src/pages/NoteEditPage.tsx` **改动后必须逐字节一致**（当前 E8 已证实一致）：

- 施工顺序：先在 Web 端改完并自测通过，再把**同一份文件**同步到桌面端 `ui/`（不做第二遍手写）；
- 判据命令：两端文件 sha256 相同（写入测试报告与开发记录）。

## 5. 桌面端媒体浮层生命周期与几何同步（#3）

### 5.1 缺陷定位（对应 E10~E13）

| 现象 | 根因 |
|------|------|
| 关闭窗体后播放框"停留在原地" | `WebShell.hide_to_tray()` 只隐藏主窗；浮层是**独立顶层窗口**，没有任何人隐藏它（E11） |
| 拖动主窗后画面消失、音频继续 | 浮层几何**只**由渲染层的 `setRect()` 驱动；主窗移动时视口内 rect 不变、渲染层不会上报，且全仓无 `moveEvent/resizeEvent` 去重算屏幕坐标 → 浮层停在旧位置（E10/E12）；音频由 `QMediaPlayer` 独立播放，故"音频继续" |

### 5.2 设计

#### 5.2.1 `MediaOverlay`（`src/ui/media_overlay.py`）新增两个主线程方法

| 方法 | 语义 | 要点 |
|------|------|------|
| `refresh_geometry()` | 按**当前** `_rect` + 主窗当前位置重算屏幕矩形 | 幂等；`_fullscreen` 为真时**直接返回**（不把全屏浮层拉回小矩形）；`_rect` 为空或 `visible=false` 时返回；内部仍调 `_apply_geometry()`（复用既有"CSS px == Qt 逻辑 px"口径与 `mapToGlobal`，**不新增 dpr 换算**，见 E10 与 L33 的口径纪律） |
| `on_shell_hidden()` | 主窗隐藏（最小化到托盘）时同步隐藏浮层 | `self.window.hide()` → 调 `_force_repaint()`（**必须**：原生窗口隐藏后 Chromium 不会重绘，`LESSONS.md` L40 / E13）；**不停止播放**（保持托盘后台语义）；`self._rect` 不清空（恢复窗口时可直接贴合） |

> 复用而非另写：`refresh_geometry()` 只是"外部触发的一次 `_apply_geometry()`"，避免出现第二套坐标计算。

#### 5.2.2 `WebShell`（`src/ui/web_shell.py`）新增主窗几何事件与注入点

```python
def attach_overlay(self, overlay) -> None:      # main.py 在创建浮层后调用
    self._overlay = overlay                     # 仅保存引用，不做任何直接调用

def moveEvent(self, event):                     # 拖动主窗
    super().moveEvent(event)
    self._schedule_overlay_refresh()

def resizeEvent(self, event):                   # 缩放主窗
    super().resizeEvent(event)
    self._schedule_overlay_refresh()

def hide_to_tray(self):                         # 既有方法，补一行
    overlay = getattr(self, "_overlay", None)
    if overlay is not None:
        overlay.on_shell_hidden()
    self.hide()                                 # 原有行为不变
    ...
```

- **不引入定时轮询**（性能要求）：只在 `moveEvent`/`resizeEvent` 时触发；
- **合并同一帧的多次事件**：`_schedule_overlay_refresh()` 用 `QTimer.singleShot(0, ...)` + 一个 `_overlay_refresh_pending` 标志，把一次拖动产生的连续事件收敛成"事件循环末尾一次刷新"。
  > 为什么延迟一帧：Windows 拖动过程中 `moveEvent` 可能在窗口几何**尚未最终生效**时到达，`mapToGlobal` 会拿到旧坐标（表现为"画面滞后一格/抖一下"）。延迟到当前事件循环之后取坐标，可拿到最终几何（**待真机验证**：见 §7 风险表）。
- **`hide_to_tray` 在 `closeEvent`/托盘菜单两条路径上都会被走到**，故只需在此一处补挂（托盘"显示窗口"→ `restore_from_tray()` 无需改：浮层会在下一次 `setRect`/`refresh_geometry` 时重新贴合；为稳妥，`showEvent` 也可调用一次 `refresh_geometry()`）。

_shell.attach_overlay(overlay)     # 新增：主窗几何事件 → 浮层重贴合 / 主窗隐藏 → 浮层隐藏

### 5.3 边界与不变式

1. 全屏态优先：`refresh_geometry()` 在全屏时不得改变浮层几何；
2. 浮层隐藏后必须触发一次强制重绘（否则浮层遮挡区域的像素残留 —— 用户此前已反馈过同类现象，`_force_repaint` 已有实现，复用即可）；
3. 播放状态与浮层可见性**解耦**：关窗只隐藏窗口，不 `stop()`、不清 `_rect`、不 `setSource(QUrl())`；
4. 退出应用（托盘「退出」）路径不变（`quit_application` → `QApplication.quit()`）；
5. 渲染层（JS）**零改动**：桥方法名、参数、事件名全部不变（`src/bridge/media.py` 不动）；
6. **全屏优先 vs 尊重渲染层（已裁决：全屏优先，2026-10-10 用户确认）**：四维状态表里有一格是"`_kind` 有 + 全屏 + `rect.visible=false`"——
   恢复分支**忽略** `visible=false` 直接 `showFullScreen()`（口径＝"全屏是用户的显式点击意图，布局派生信号不得把它拉回来"）；
   非全屏路径仍尊重 `visible=false`（保持 `_shell_hidden=True` 等下一次有效上报）。
   **实现零改动**（当前代码即此口径：`media_overlay.py:329-333` 全屏分支不判 `visible`，`:334-337` 非全屏分支判它）；
   真机项 V-15 仅用于确认观感。
