# v1.1.6 设计文档：同步配置客户端本地化存储

## 一、背景与问题

### 1.1 现状

[`sync_configs`](jflove-server/src/models/database.py:67-83) 表的全部字段（含 `local_path`、`auto_sync`、`sync_interval`、`name`、`enabled`）都存储在服务端数据库中。客户端通过 [`/api/v1/sync/configs`](jflove-server/src/controllers/sync_controller.py:34-52) 系列接口进行 CRUD。

### 1.2 核心矛盾

不同客户端安装在不同机器上，其本地同步目录 (`local_path`) 各不相同。当前所有客户端共享同一份服务端同步配置，导致：

- 客户端 A 的 `local_path` 会被客户端 B 覆盖
- 客户端 A 想开启自动同步 (`auto_sync=true`)，客户端 B 可能想关闭
- `sync_interval`、`name`、`enabled` 等偏好设置无法按客户端独立

### 1.3 目标

**服务端完全移除 `sync_configs` 表及相关接口**，同步配置全部由客户端本地存储管理，不同客户端相互独立、互不影响。snapshot 接口改为直接传 `disk_id + remote_path` 参数。

---

## 二、架构决策

### 2.1 核心决策：服务端不再存储任何同步配置

| 决策 | 理由 |
|---|---|
| 服务端完全移除 `sync_configs` 表 | 同步配置本质上是客户端偏好（本地路径、自动开关、间隔），服务端无需知晓 |
| snapshot 接口改为传 `disk_id + remote_path` | 不再依赖 config_id 定位远端目录，直接通过磁盘+路径参数访问 |
| touch 接口移除 | `last_synced_at` 改为客户端本地追踪，服务端不需要此信息 |
| 客户端 `sync_configs.json` 存储全部配置 | 与 v1.1.5 的 `session.json` / `server_history.json` 风格一致 |

### 2.2 存储职责划分

```

│  ✅ 权限校验逻辑 — 不变（check_disk_permission）     │
│                                                   │
│  新 snapshot 接口：POST /api/v1/sync/snapshot      │
│  参数：disk_id + remote_path（加密 body 内）        │

┌──────────────────────────────────────────────────┐

│  storage/sync_configs.json                        │

│  │ {                                          │  │
│  │   "configs": [                             │  │
```

### 2.3 为什么不再需要服务端 config ID

| 旧依赖 | 新方案 |
|---|---|
| `snapshot` 需要 `config_id` 查找 `disk_id + remote_path` | 客户端直接传 `disk_id + remote_path` |
| `touch` 更新服务端 `last_synced_at` | 客户端本地记录 `last_synced_at` |
| `delete` 软删除服务端配置 | 无需服务端操作，仅删本地 JSON |
| `PUT` 更新服务端配置 | 无需服务端操作，仅改本地 JSON |

**服务端不再需要知道"哪个用户有哪些同步配置"**。服务端只需：
1. 验证用户对 `disk_id` 的读权限（snapshot 接口）
2. 根据 `disk_id + remote_path` 递归扫描返回文件清单

## 三、服务端变更设计

### 3.1 移除的接口（6 个 → 1 个）

| 旧接口 | 去向 |
|---|---|
| `GET /api/v1/sync/configs` | ❌ 移除 |
| `POST /api/v1/sync/configs` | ❌ 移除 |
| `PUT /api/v1/sync/configs/{id}` | ❌ 移除 |
| `DELETE /api/v1/sync/configs/{id}` | ❌ 移除 |
| `GET /api/v1/sync/configs/{id}/snapshot` | → 改为 `POST /api/v1/sync/snapshot` |
| `POST /api/v1/sync/configs/{id}/touch` | ❌ 移除 |

### 3.2 新接口：`POST /api/v1/sync/snapshot`

**用途**：递归扫描指定磁盘子目录，返回文件清单供客户端 diff。

**不在明文白名单中**，走 ChaCha20-Poly1305 加密信封。

```
POST /api/v1/sync/snapshot

请求体（加密前）：
{
  "token": "<JWT>",
  "disk_id": 1,
  "remote_path": ""           // 磁盘内子目录，空串=根目录
}

响应体（加密前）：
{
  "files": [
    {"path": "photo1.jpg", "size": 102400, "modified_at": 1716300000.0},
    {"path": "subdir/doc.txt", "size": 512, "modified_at": 1716200000.0}
  ]
}
```

| 条件 | 状态码 |
|---|---|
| 正常 | 200 |
| disk_id 不存在 | 400 |
| 无读权限 | 403 |
| 鉴权失败 | 401 |
| 加密格式错误 | 400 |

### 3.3 鉴权逻辑

```python
async def get_snapshot(request, db):
    body = await decrypt_request_body(request)
    user = await _get_user(request, db, body)
    disk_id = int(body.get("disk_id") or 0)
    remote_path = body.get("remote_path", "").strip().strip("/")

    # 1) 磁盘存在性
    disk = await virtual_disk_repository.find_by_id(db, disk_id)
    if not disk:
        raise HTTPException(400, "虚拟磁盘不存在")

    # 2) 路径越界防护
    _safe_join(disk["real_path"], remote_path)

    # 3) 权限校验（admin 免检）
    if user["role"] != "admin":
        if not await check_disk_permission(db, user["id"], disk_id, "read"):
            raise HTTPException(403, "对目标磁盘没有读取权限")

    # 4) 递归扫描（逻辑与旧 list_remote_snapshot 一致）
    files = _scan_directory(disk["real_path"], remote_path)

    return encrypt_response(session_id, {"files": files})
```

### 3.6 `sync_controller.py` 新结构

```python
router = APIRouter(prefix="/api/v1/sync", tags=["同步"])

@router.post("/snapshot", summary="获取远端目录快照")
async def get_snapshot(request: Request, db=Depends(get_db)):
    """递归扫描指定磁盘子目录，返回文件清单（加密传输）"""
    body = await decrypt_request_body(request)
    user = await _get_user(request, db, body)
    try:
        files = await sync_service.list_remote_snapshot(
            db, user["id"], user["role"],
            int(body.get("disk_id") or 0),
            body.get("remote_path", ""),
        )
    except PermissionError as e:
        raise HTTPException(status_code=403, detail=str(e))
    except ValueError as e:
        raise HTTPException(status_code=400, detail=str(e))
    return encrypt_response(
        request.headers.get("X-Session-ID", ""), {"files": files}
    )
```

### 3.7 §9 安全宪法合规自查（服务端）

| 检查项 | 结果 |
|---|---|
| 接口是否在明文白名单中 | ❌ 不在白名单，走加密信封 ✅ |
| 路径上是否有可枚举 ID | ❌ 无路径参数——接口改为 `POST /snapshot`，参数全在加密 body 中 ✅ |

| 响应是否走 `encrypt_response` | ✅ |
| 错误是否通过 `HTTPException` 抛出 | ✅ 全局 handler 自动加密 |
| 权限校验 | ✅ `check_disk_permission` 校验读权限 |
| 是否在 URL 上携带业务参数 | ❌ `remote_path` 在加密 body 中 ✅ |
| 响应头无敏感元数据 | ✅ |

## 四、桌面端变更设计

### 4.1 本地存储文件

**路径**：`{USER_DATA_DIR}/storage/sync_configs.json`

```json
{
  "configs": [
    {
      "id": "a1b2c3d4",
      "name": "照片备份",
      "local_path": "/home/alice/Photos",
      "disk_id": 1,
      "remote_path": "",
      "auto_sync": true,
      "sync_interval": 300,
      "enabled": true,
      "last_synced_at": null
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | 本地唯一标识（UUID 或自增序号），用于引擎 timer 和 UI 行定位 |
| `name` | str | 用户起的别名 |
| `local_path` | str | 本地目录绝对路径 |
| `disk_id` | int | 远端虚拟磁盘 ID |
| `remote_path` | str | 磁盘内子目录相对路径 |
| `auto_sync` | bool | 是否启用自动同步 |
| `sync_interval` | int | 自动同步间隔秒数（≥30） |
| `enabled` | bool | 是否启用此配置 |
| `last_synced_at` | str | 最近同步完成时间 (ISO)，客户端本地记录 |

### 4.2 核心流程

```mermaid
flowchart TD
    subgraph 创建同步配置
        A1[用户填写表单] --> A2[客户端本地校验]
        A2 --> A3[生成本地唯一 id]
        A3 --> A4[写入 sync_configs.json]
        A4 --> A5[刷新 UI + sync_engine.reload]
    end

    subgraph 编辑同步配置
        B1[用户修改表单] --> B2[更新 sync_configs.json]
        B2 --> B3[刷新 UI + sync_engine.reload]
    end

    subgraph 删除同步配置
        C1[用户确认删除] --> C2[从 sync_configs.json 移除]
        C2 --> C3[刷新 UI + sync_engine.reload]
    end

    subgraph 同步执行
        D1[trigger_sync] --> D2[从本地 JSON 读配置]
        D2 --> D3[扫描本地目录 local_path]
        D3 --> D4[POST /api/v1/sync/snapshot<br>disk_id + remote_path]
        D4 --> D5[计算 diff]
        D5 --> D6[提交上传/下载任务]
        D6 --> D7[更新本地 last_synced_at]
    end
```

### 4.3 `sync_service.py` 重构

**核心变更**：所有操作仅读写本地 JSON 文件，不再调服务端（snapshot 除外）。

```python
import json
import os
import uuid
from datetime import datetime, timezone
from src.config.settings import LOCAL_STORAGE_DIR
from src.utils.http_client import http_client
from src.utils.logger import get_logger

logger = get_logger(__name__)
_SYNC_CONFIGS_FILE = os.path.join(LOCAL_STORAGE_DIR, "sync_configs.json")

# ── 本地文件读写 ──────────────────────────────

def _read_local_configs() -> list[dict]:
    if not os.path.exists(_SYNC_CONFIGS_FILE):
        return []
    try:
        with open(_SYNC_CONFIGS_FILE, "r", encoding="utf-8") as f:
            data = json.load(f)
        return data.get("configs", []) if isinstance(data, dict) else []
    except Exception as e:
        logger.warning("读取 sync_configs.json 失败：%s", e)
        return []

def _write_local_configs(configs: list[dict]) -> None:
    os.makedirs(os.path.dirname(_SYNC_CONFIGS_FILE), exist_ok=True)
    tmp = _SYNC_CONFIGS_FILE + ".tmp"
    with open(tmp, "w", encoding="utf-8") as f:
        json.dump({"configs": configs}, f, ensure_ascii=False, indent=2)
    os.replace(tmp, _SYNC_CONFIGS_FILE)

# ── CRUD ─────────────────────────────────────

def list_configs() -> list[dict]:
    """获取本地全部同步配置"""
    return _read_local_configs()

def create_config(
    name: str, local_path: str, disk_id: int,
    remote_path: str = "", auto_sync: bool = False,
    sync_interval: int = 300,
) -> str:
    """创建同步配置（仅写本地），返回本地 id"""
    cfg_id = uuid.uuid4().hex[:8]
    configs = _read_local_configs()
    configs.append({
        "id": cfg_id,
        "name": name,
        "local_path": local_path,
        "disk_id": disk_id,
        "remote_path": remote_path,
        "auto_sync": auto_sync,
        "sync_interval": sync_interval,
        "enabled": True,
        "last_synced_at": None,
    })
    _write_local_configs(configs)
    return cfg_id

def update_config(
    config_id: str, name: str, local_path: str,
    disk_id: int, remote_path: str, auto_sync: bool,
    sync_interval: int, enabled: bool,
) -> None:
    """更新同步配置（仅写本地）"""
    configs = _read_local_configs()
    for c in configs:
        if c["id"] == config_id:
            c.update({
                "name": name, "local_path": local_path,
                "disk_id": disk_id, "remote_path": remote_path,
                "auto_sync": auto_sync, "sync_interval": sync_interval,
                "enabled": enabled,
            })
            break
    _write_local_configs(configs)

def delete_config(config_id: str) -> None:
    """删除同步配置（仅删本地）"""
    configs = _read_local_configs()
    _write_local_configs([c for c in configs if c["id"] != config_id])

# ── 远端快照 ─────────────────────────────────

def get_remote_snapshot(disk_id: int, remote_path: str) -> list[dict]:
    """
    获取远端目录快照（递归扫描）。
    :returns: 文件清单 [{path, size, modified_at}, ...]
    """
    resp = http_client.post("/api/v1/sync/snapshot", {
        "disk_id": disk_id,
        "remote_path": remote_path,
    })
    return resp.get("files", [])

# ── touch 本地化 ─────────────────────────────

def touch_synced(config_id: str) -> None:
    """标记同步完成（更新本地 last_synced_at）"""
    configs = _read_local_configs()
    now = datetime.now(timezone.utc).isoformat()
    for c in configs:
        if c["id"] == config_id:
            c["last_synced_at"] = now
            break
    _write_local_configs(configs)
```

## 五、兼容性分析

### 5.1 向后兼容

| 场景 | 行为 |
|---|---|
| 旧客户端 (v1.1.5) 连新服务端 (v1.1.6) | 旧客户端调 `GET /configs` → 404（路由已移除），所有同步功能不可用。**必须升级** |
| 新客户端 (v1.1.6) 连旧服务端 (v1.1.5) | 新客户端 `POST /snapshot` → 404（旧服务端无此路由）。**必须同步升级** |

**结论**：v1.1.6 是 breaking change，要求服务端和客户端**同步升级**。

### 5.2 数据迁移

- 服务端 `sync_configs` 表直接 DROP，不保留旧数据
- 客户端从零开始创建同步配置（旧服务端配置中的 `local_path` 本来就是错误共享的）
- 已同步到远端的文件不受影响——远端文件仍在 `virtual_disks` 对应目录中
