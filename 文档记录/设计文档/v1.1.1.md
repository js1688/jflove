## 0. 与 v1.1.0 的设计差异

| 项 | v1.1.0 设计 | v1.1.1 设计 |
|---|---|---|
| JWT 过期时间 | 客户端读 JWT `exp` 字段 | 改为 `min(JWT exp, 用户在登录界面选择的最大本地有效期)`，UI 可配置 |
| 客户端会话计时器到期处理 | 直接弹"登录已过期" + 退出登录，无并发保护 | 引入 `_logout_in_flight` 互斥标志 + 单例登录窗，保证仅触发一次 |
| HTTP 401 处理 | 一律抛 `ApiError`，UI 弹"登录已过期" | 区分两类：JWT 类 → 触发登出（仅一次）；ECDH 类 → `http_client` 内部静默重做 key-exchange + 重发原请求 |
| 流式接口（`stream_request`）401 处理 | 直接抛错，导致视频/预览中断弹窗 | 同样走 ECDH 自动续约路径（重做 key-exchange 后 FFmpeg 下次 Range 自然成功） |
| 登录界面 | 服务器地址 / 用户名 / 密码 | 新增"登录有效期"下拉选择（含默认值 1h、记忆上次选择） |
| `session_manager` 字段 | 已有 token / username / role / token_expires_at 等 | 新增 `local_session_max_seconds`（用户选择，持久化到 QSettings） |
| 服务端代码 | n/a | **不变更** |

## 1. 系统架构（变更点）

整体仍是「桌面端 ── HTTPS（端到端加密信封） ── 服务端」单端单进程架构，本版本不引入新进程、新组件、新依赖。

变更视图（仅桌面端）：

```
┌─────────────────────────────── jflove-desktop ───────────────────────────────┐
│                                                                              │
│  LoginWindow ──┬──► auth_service.do_key_exchange()                           │
│      │ (新增) │      └──► auth_service.login()                               │
│      │ ▼      │                                                              │
│      │ 登录有效期下拉                                                          │
│      │ → session_manager.local_session_max_seconds                           │
│      │ → QSettings 持久化                                                     │
│      ▼                                                                       │
│  MainWindow                                                                  │
│   ├─ token 计时器 (60s) ─┐                                                    │
│   │   到期判定 = min(JWT exp, key_exchange_time + local_max)                  │
│   │   触发: _request_logout()  ← 互斥保护，只触发一次                          │
│   │                                                                          │
│   └─ 一切 HTTP 都走                                                           │
│       └─► HttpClient.{post,get,put,delete,stream_request,download_*}         │
│            ├── 收到 401 → 用 detail 区分                                      │
│            │     "会话不存在或已过期" → ECDH 类 → 静默续约 + 重试              │
│            │     "令牌无效或已过期"   → JWT 类  → 通知登出 + 抛 ApiError      │
│            │     其他 401              → 抛 ApiError                          │
│            └── 静默续约：通过 _ecdh_resync_lock 单飞防止并发重复               │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 核心模块职责

#### `HttpClient`（关键改造）

新增私有方法 `_send_with_resync(do_request)`：

- 接收一个无参函数 `do_request()`，返回 `(status_code, response_or_raise_payload)`；
- 调用 `do_request()`，若得到 401 且解密 detail 含 `"会话不存在或已过期"` / `"缺少 X-Session-ID 请求头"`，进入静默续约：
  - 抢 `_ecdh_resync_lock`（threading.Lock，类级单飞）；
  - 拿到锁的线程实际调用 `auth_service._resync_session()`；其他线程等待该次续约完成；
  - 续约完成后**所有等待线程各自调用一次 `do_request()` 重发**（每个线程持有自己的请求句柄，重发时使用新的 session_key / session_id）；
- 该自动重试**只发生 1 次**；第二次仍 401 / 出错 → 直接抛 `ApiError`；
- 若 401 且 detail 含 `"令牌无效或已过期"` / `"缺少认证令牌"` 等 JWT 类，则不续约，直接抛 `ApiError(401, detail)`，由 UI 主线程的 token 计时器或调用方决定是否触发登出。

`stream_request` 同款套路：先尝试 `do_request()`，若返回 401 且 detail 是 ECDH 类，关闭旧 response、续约、再发一次。

`download_stream` / `download_to_file` 仅对**首次请求建连阶段**做续约重试；一旦开始接收帧（HTTP 200 已建立流），后续读取帧失败不再续约（这种情况服务端 generator 已开启，session_key 已被使用，单纯换密钥也不会救回该流，应该让上层进度回调感知失败）。

#### `auth_service._resync_session()`

新私有函数，只做"静默重建加密通道"：

```python
def _resync_session() -> None:
    """
    静默重新执行 X25519 密钥交换。
    成功后 session_manager.session_id / session_key 被替换为新值；
    JWT (token) / username / role 等保持不变。
    用于 http_client 在收到 ECDH 类 401 时自动续约，对用户透明。
    """
```

注意：

- 这是**会话级**续约，不刷新 JWT；
- **不**调用 `_save_session()` 重写 QSettings（避免高频 IO，且 session_id 本就不持久化）；
- 失败时抛 `ApiError`，由调用方决定后续。

新增控件：`ComboBox` "登录有效期"，挂在密码框下方。
- 数据源：`LOCAL_SESSION_TTL_OPTIONS = [(1800, "30分钟"), (3600, "1小时"), (7200, "2小时"), (14400, "4小时"), (28800, "8小时")]`；

#### `MainWindow`

```python
# session.py
def effective_expire_at(self) -> float:
    """返回 token 真实失效时间（Unix 秒）：min(JWT exp, key_exchange_time + local_max)"""
    candidates = []
    if self.token_expires_at:
        candidates.append(self.token_expires_at)
    if self.local_session_max_seconds and self.key_exchange_time:
        candidates.append(self.key_exchange_time + self.local_session_max_seconds)
    return min(candidates) if candidates else 0.0
```

def _on_logout_requested(self) -> None:

#### 主流程 `main.py`（单实例保护）

```python
class _AppController:
    """单实例持有当前活动的 LoginWindow 或 MainWindow，确保两者不同时存在"""

    def __init__(self, app):
        self._app = app
        self._login: Optional[LoginWindow] = None
        self._main: Optional[MainWindow] = None

    def show_login(self):
        if self._main is not None:
            self._main.close()
            self._main.deleteLater()
            self._main = None
        if self._login is None:
            self._login = LoginWindow()
            self._login.login_succeeded.connect(self.show_main)
        self._login.show()
        self._login.raise_()
        self._login.activateWindow()

    def show_main(self, role: str):
        if self._login is not None:
            self._login.close()
            self._login.deleteLater()
            self._login = None
        if self._main is None:
            self._main = MainWindow(role=role)
            self._main.logout_requested.connect(self.show_login)
        self._main.show()
```

入口处取代裸的"if 已登录就 new MainWindow else new LoginWindow"流程。

## 6. 安全方案

### 6.1 与 §9 安全宪法的对照

| 条款 | 本期是否触动 | 处置 |
|---|---|---|
| §9.1 通信加密默认值 | 否 | 沿用 v1.1.0 的加密信封 |
| §9.2 PFS / X25519 | 是（更频繁地刷新） | 静默续约仍走临时密钥对，**不**引入长期密钥；旧 session_key 被覆盖即销毁 |
| §9.3 鉴权与权限 | 是（401 处理逻辑变化） | JWT 仍只在加密 body；ECDH 类 401 走续约不绕过任何权限校验 |
| §9.4 不暴露内容 | 否 | 不动 |
| §9.5 加密原语清单 | 否 | 不引入新原语 |

### 6.2 静默续约的具体安全约束

1. **只在收到 ECDH 类 401 时触发**——服务端 detail 是确定字符串 `"会话不存在或已过期，请重新交换密钥"` 或 `"缺少 X-Session-ID 请求头"`；其他 401 一律不触发。
2. **每次请求最多续约 1 次**——避免无限续约循环。第二次仍失败 → `ApiError` 上抛。
3. **续约由 `threading.Lock` 单飞**——多线程同时遇到 ECDH 401 时只会发起一次 `key-exchange`，其他线程等待结果后用新 session_key 重发自己原本的请求。
4. **续约不改 JWT**——即使续约 5 次，JWT 仍可能在原定时间过期；用户感知到的"会话期"仍由 JWT 决定。
5. **续约失败的兜底**——`ApiError` 抛回 UI；UI 现有的"网络错误"提示路径处理（不弹"登录已过期"）。

### 6.3 单飞与重入风险评估

`HttpClient._send_with_resync` 设计：

```python
class HttpClient:
    _ecdh_resync_lock = threading.Lock()
    _ecdh_resync_inflight = False  # 当前是否有线程正在续约

    def _try_resync(self) -> bool:
        """尝试续约。已在续约中的线程会等待并复用结果。返回是否续约成功。"""
        with self._ecdh_resync_lock:
            if self._ecdh_resync_inflight:
                # 等待持有者完成
                # 实际实现用 Condition + flag，简化此处
                ...
                return True/False
            self._ecdh_resync_inflight = True
        try:
            auth_service._resync_session()
            return True
        except Exception as e:
            logger.warning("ECDH 静默续约失败: %s", e)
            return False
        finally:
            with self._ecdh_resync_lock:
                self._ecdh_resync_inflight = False
                # 唤醒等待者
```

实际代码用 `threading.Condition` 实现"持有者发起、其他人等"模式。

### 6.4 视频流（`StreamProxy`）的特殊处理

`StreamProxy._ProxyHandler` 内部调用 `file_service.stream_range`，进而走 `http_client.stream_request`。`stream_request` 已经具备 401 自动续约能力，因此：

- 服务端重启 → 下一次 FFmpeg 触发 Range → `stream_request` 收到 401（ECDH 类）→ 续约 + 重试 → 200 → FFmpeg 收到帧继续播放；
- 用户感知到的最坏情况：≤2s 卡顿；不弹"登录已过期"。

JWT 在播放过程中真过期时（≥ 1h 默认），`stream_request` 收到 401（JWT 类）→ 不续约直接抛 → `_ProxyHandler` 写 500 给 FFmpeg → 视频报错；与此并行的是 `MainWindow._token_timer` 检测到 `effective_expire_at` 已过 → 走唯一登出流程，弹一次提示。

## 8. 错误处理与可观测性

### 8.1 日志要求

- 静默续约触发 / 成功 / 失败：INFO 级别，**不输出 session_key / token**；
- JWT 类 401：保持 v1.1.0 行为（INFO，"JWT token 已过期，自动退出登录"）；
- ECDH 类 401：新增 INFO 日志 "检测到加密会话失效，触发静默续约（请求路径=%s）"；
- 续约失败兜底：WARNING "静默续约失败：%s"。

### 8.2 用户提示

- 静默续约期间不弹任何对话框 / Toast；
- 登录过期：仅 `MainWindow._check_token_expiry` 弹一次 `MessageBox`；
- 续约最终失败 → 上抛的 `ApiError` 由调用页（如 FilePage、SyncPage）现有"网络错误"显示路径处理（InfoBar 错误提示）。

## 10. 风险与回退

### 10.1 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 静默续约 vs JWT 过期的并发竞争 | 用户在 JWT 边界时间触发请求，可能两条路径同时走 | JWT 类与 ECDH 类的判定基于服务端 detail 字符串，互斥；`_logout_in_flight` 进一步保证只走一次登出 |
| `MessageBox.exec()` 期间的事件循环 | 弹窗期间其他 401 仍可能触发 | `_logout_in_flight` 早于 `MessageBox.exec()` 设置，后续触发被忽略 |
| `LoginWindow` / `MainWindow` 单例切换时未释放 | 内存泄漏 / 双窗口 | `_AppController` 显式 `close()` + `deleteLater()` |
| ECDH 续约时多个等待线程同时唤醒发请求 | 续约后瞬时请求高峰 | 等待线程各自只发自己原本的请求，无放大 |

### 10.2 回退方案

- 改动仅落在 `jflove-desktop`，回退 = 把 `1.1.1` 桌面端包替换为 `1.1.0` 包；
- 服务端无需操作；
- 用户重新登录后即可继续使用。
