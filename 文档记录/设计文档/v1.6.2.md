## 3. 关键机制设计

### 3.1 DS-49 关框时机（修"点了完全没反应"）

**缺陷形态**（真机已证，`r21`）：关框挂在弹框容器的 `pointerup` **捕获**阶段 ⇒ React 在 `pointerup` 之后、`click` 之前同步提交 ⇒ 被点按钮被卸载 ⇒ Chromium **不派发**这次 `click` ⇒ 按钮的 `onClick` 永不执行。

**修法（本设计的硬口径）**：

1. 关框委托从 `onPointerUpCapture` **整体搬**到容器的 `onClick`（**冒泡阶段**）。
2. **判定逻辑一字不改**（保持 AC-76 语义）：
   - 从 `event.target` 向上找最近的 `[data-toolbox-item]` 得到归属项 id；
   - `menuStaysOpenAfter(itemId)` 为真（`sql` / `font`）⇒ **不关**；
   - 目标不是 `<button>`（`<input>` / `<select>`）⇒ **不关**（用户在配置，不丢上下文）；
   - 目标按钮 `disabled` ⇒ **不关**（用户什么也没得到）；
   - 其余 ⇒ `setMenuOpen(false)`。
3. **为什么冒泡阶段就能保证动作先执行**：React 的事件派发路径是 `target → … → 容器`，被点按钮自己的 `onClick` 必然先于容器 `onClick` 执行 ⇒ 关框永远发生在动作之后；而且此时事件已派发完毕，卸载 DOM 不再影响这次点击。
4. **守门判据**（写进用例）：把关框搬回 `onPointerUpCapture` 的注入式变异 ⇒ 至少 5 条用例（`lines`/`case`/`base64`/`json`/`diff`）必须**变红**。
5. **测试形状的硬要求**（E-4 的直接产物）：工具箱点击类用例**必须**把 `pointerdown` / `pointerup` / `click` 放进**三个独立 `act` 边界**（= 真实浏览器的三个 task）；沿用"同一个 `act` 里三连发"的写法**测不出**本缺陷。

**不改的东西**：`Esc` 关闭（`window` 捕获）、点弹框外部关闭（`document` `pointerdown` 捕获）、`toolbox` / `diff` 的一次性 `panelRequest` 通路。

### 3.2 DS-50 动作可见反馈（治"作用文字不明显"）

**问题**：动作生效了，但正文变化可能在视口外；且执行后只 `setMessage(null)`，用户没有任何正面反馈。

**设计**：

1. `ScratchEditorSession` 扩展（`ScratchEditorHost.tsx`）：
   ```ts
   export interface ScratchSetTextOptions {
     /** 把**首个差异位置**滚进视口并把光标放过去（"变化看得见"） */
     revealFirstChange?: boolean;
   }
   interface ScratchEditorSession {
     setText(next: string, options?: ScratchSetTextOptions): void;
     /** 选中并滚动到一个区间（跨标签搜索"点结果跳过去"用） */
     revealRange(from: number, to: number): void;
   }
   ```
   - `setText`：`current === next` ⇒ **直接 return**（不产生无意义历史/事务）；需要揭示时用
     `firstDifferenceIndex(current, next)` 取首个差异码点位置，随同一次事务 `dispatch({ changes, selection:{anchor:pos}, scrollIntoView:true })`
     （CM6 的位置即 UTF-16 码元偏移，与 `String#length` 同口径）。
   - `revealRange`：夹取到 `[0, doc.length]`，`selection = {anchor: from, head: to}` + `scrollIntoView: true` + `focus()`。
2. 工具箱纯变换的统一入口加**结果文案**：
   ```ts
   runTransform(transform, { label: string; unit: 'lines' | 'chars' })
   ```
   - 结果 = 输入 ⇒ 提示 `已${label}（无变化）`，**不写回**；
   - 否则写回并提示 `已${label}（<行数|字符数>）`，例：`已排序（12 行）`、`已 Base64 编码（96 字符）`；
   - 异常 ⇒ 既有中文兜底文案（**不得**英文异常原文上屏）。
3. `sql` / `xml` 的美化/压缩/格式化同样给结果文案（含行数）。
4. **类型门禁的 title 说明**：所有因**文档类型**而禁用的动作按钮（弹框内的「表格视图」「树形视图」「预览」「分屏」，以及工具栏顶部的 5 个视图按钮）必须带**中文 `title`**（如「仅 CSV / TSV 可用」「仅 JSON 文档可用」「仅 Markdown 文档可用」）。
5. **文案唯一真相**：结果文案的构造只有一处实现（`describeApplied(label, unit, count)`），用例断言"含数字 + 中文动词"。

### 3.3 DS-51 对比覆盖层的定位祖先（治"只有一条缝"）

**缺陷形态**：工具栏根元素带 `relative` ⇒ 其子节点 `absolute inset-0`（diff 覆盖层）的包含块是**工具栏**（一行高）；而 `EditorPanel.tsx:155-157` 的契约要求定位祖先是面板根元素。工具箱弹框 `absolute top-full` 又**恰好**需要工具栏这一层。

**修法（DOM 结构）**：

```tsx
<div className="flex flex-wrap items-center gap-1 …">      {/* 根：static（不再是定位祖先） */}
  <div className="relative flex min-w-0 flex-1 flex-wrap items-center gap-1">
    {/* 语言下拉 / 视图按钮 / 工具箱开关 */}
    {menuOpen && <div className="absolute top-full left-0 z-40 …">…12 项…</div>}
  </div>
  {tab.readOnly && <span>只读</span>}
  {message && <span role="status">…</span>}
  {/* 覆盖层挂在**根元素**下 ⇒ 包含块 = 最近的定位祖先 = EditorPanel 根（relative） */}
  {overlayOpen && <div className="absolute inset-0 z-30">…</div>}
</div>
```

- 工具箱弹框的 `w-full min-w-[420px]` 仍相对"内容层"（几乎等于工具栏宽度）⇒ 外观不变、右侧不会被 `EditorPanel` 的 `overflow-hidden` 裁掉；
- 覆盖层（对比 / 跨标签搜索）成为根元素的子节点 ⇒ 铺满**整个编辑面板**（含工具栏与状态栏区域），符合"覆盖层"语义；
- **判据**：真机 `r22` 量几何 —— 覆盖层高度 ≥ 编辑面板内容区高度 × 90%；注入式变异（把 `relative` 挪回根元素）⇒ 该断言必红。

### 3.4 DS-52 外壳右击菜单（编辑器区中文、别处不弹）

**为什么在外壳（Python）而不是渲染层**：渲染层处在 `file://` 非安全上下文 ⇒ `navigator.clipboard` 不可用 ⇒ **渲染层做不出剪切/复制/粘贴**；要做得靠桥新增剪贴板能力，直接违反 `AGENTS.md §9.6` 的能力面最小化（且 v1.6.1 已把"外壳读写剪贴板"作为**观察项**登记为 BL-62，本版**不再扩大**）。⇒ 用 Qt 的 `WebAction`（Chromium 自己的编辑动作）在外壳侧组菜单。

**实现**：

1. **纯函数 spec（可单测，是判据的落点）**：
   ```python
   def context_menu_spec(is_content_editable: bool, edit_flags: int) -> list[tuple[str, str, bool]] | None:
       """返回 [(中文文案, WebAction 名, 是否可用), ...]；None = 该上下文不弹菜单。
       分隔符用 ('-', '', False)。"""
   ```
   - **弹与不弹的判定**（唯一口径）：
     `is_content_editable` **或** `edit_flags & (CanPaste|CanUndo|CanRedo|CanCut|CanDelete) != 0` ⇒ 弹；
     否则（普通页面背景 / 只读预览 / 表格 / 树形，只有 `CanCopy` / `CanSelectAll`）⇒ **不弹**。
     —— 前者覆盖 CM6 正文与 `<input>`/`<textarea>`；后者保证"别处那份没用的菜单"不再出现。
   - **菜单项（顺序即 UI 顺序）**：撤销 / 重做 / ─ / 剪切 / 复制 / 粘贴 / ─ / 全选；可用性逐项由对应 `EditFlag` 决定。
     ⚠ **不含「删除」**（2026-10-16 实现期裁决）：Qt 6 的 `QWebEnginePage.WebAction` **不暴露 Delete**
     ⇒ 只能靠 `runJavaScript("document.execCommand('delete')")`，那会新增"外壳 → 渲染层执行 JS"的能力面
     （本模块此前零 `runJavaScript`）⇒ **宁可不做这一项**；"删掉选中的内容"由「剪切」覆盖。
     注：`EditFlag.CanDelete` 仍参与"是否可编辑上下文"的判定（见下一条），只是不再对应菜单项。
   - **不出现的项**：`Back` / `Forward` / `Reload` / `Save page` / `View page source` / `Inspect` / `Copy image` / `Download link` …（Chromium 标准菜单里那些与桌面应用无关的项，一律不组进菜单）。
2. **Qt 侧**（`DropAwareWebView`）：
   ```python
   def contextMenuEvent(self, event) -> None:
       spec = context_menu_spec(...)          # 从 page().lastContextMenuRequest() 取两个输入
       if spec is None:
           event.accept()                      # 不弹菜单
           return
       menu = QMenu(self)
       for label, action_name, enabled in spec: 新建 QAction(中文) → trigger 时 page().triggerAction(WebAction[action_name])
       menu.exec(event.globalPos())
   ```
   - 覆写 `contextMenuEvent` ⇒ `QWebEngineView` 的**默认（英文）菜单不再被创建**；
   - 用**自建 QAction**（不直接复用 page 的 action 对象）⇒ 改文案不会污染页面自身动作（`LESSONS.md` L39 的同类教训：不要依赖组件库对菜单对象的所有权语义）；
   - `lastContextMenuRequest()` 只在处理右击期间有效 ⇒ 取值与建菜单**必须在同一个 `contextMenuEvent` 里完成**。
3. **测试**：`jflove-desktop/tests/test_v162_context_menu.py` 用**替身 request**（鸭子类型：`isContentEditable()` / `editFlags()`）测纯函数：
   - 可编辑 ⇒ 有菜单且**全部文案为中文**（正则：0 命中 `[A-Za-z]{3,}` 的英文单词表）；
   - 不可编辑且仅有 Copy/SelectAll ⇒ **返回 `None`**；
   - 0 命中浏览器导航项关键词；
   - 可用性随 `edit_flags` 变（无 `CanPaste` ⇒ 粘贴禁用）。
4. **真机**（`r22`）：正文右击 ⇒ 出现中文菜单；标签条右击 ⇒ 不出现菜单；登录页输入框右击 ⇒ 出现中文菜单。

  **迁移期不破坏既有调用**：`requestPanel(kind, tabId, itemId?)` 第三参可选，既有 3 处调用点不改也能编译（`view.toolbox` / `view.diff` 传 `undefined`）。

### 3.6 DS-54 跨标签页搜索 / 替换

**1）纯逻辑模块**（`utils/scratch/search-across-tabs.ts`，零依赖、零 DOM）：

```ts
export interface SearchOptions { regex: boolean; caseSensitive: boolean; wholeWord: boolean }
export interface TextHit { from: number; to: number; line: number; lineText: string }
export interface TabHits { tabId: string; title: string; hits: TextHit[] }
export const MAX_HITS_PER_TAB = 500;
export const MAX_HITS_TOTAL = 2000;

export function buildSearchPattern(query: string, options: SearchOptions): RegExp | null;  // 非法正则 ⇒ null
export function findHits(text: string, pattern: RegExp, limit = MAX_HITS_PER_TAB): TextHit[];
export function replaceAllLiteral(text: string, pattern: RegExp, replacement: string): { text: string; count: number };
export function lineIndexAt(text: string, offset: number): number;   // 1 基行号
export function lineTextAt(text: string, offset: number): string;    // 该行原文（供结果列表摘要）
```

口径：
- `buildSearchPattern`：`regex` 为假 ⇒ `query` **转义**后当成字面量；`wholeWord` ⇒ 两侧 `\b`；`caseSensitive` 为假 ⇒ 加 `i` 标志；**总是加 `g`**（`findHits` / `replaceAllLiteral` 都要靠 `lastIndex` 前进）。
- `findHits`：**零长度匹配必须手动前进 `lastIndex`**（否则死循环）；超过 `limit` 截断并在返回值之外由调用方提示"命中过多"。
- `replaceAllLiteral`：用 `String.prototype.replace` 的**回调形式**按字面插入替换文本（**不展开 `$1` 反向引用**），回调里计数 ⇒ 计数与替换**同源**、不可能不一致；面板上**明写**这一口径。
- 行号/行文本：一次线性扫描预计算行首偏移表，避免每次命中都从 0 扫全文（10 标签 × 1 MB 的性能目标 AC-92 第 9 条）。

**2）面板组件**（`components/scratch/CrossTabSearchPanel.tsx`，覆盖层，与 `DiffView` 同一挂载手法）：

- props：`{ tabId: string; onClose: () => void }`；
- 状态：`scope: 'tab' | 'all'`（**默认 `'tab'`**）、`query`、`replacement`、`options`、`results`、`message`、`confirmAll`；
- 数据来源：`useScratchStore(s => s.tabs)` + `getScratchEditorSession(id)`（**只读已挂载会话**）；
- 收集范围：`scope === 'tab'` ⇒ 仅 `tabId`；否则全部 `mounted` 且 `getScratchEditorSession(id) !== null` 的标签页；
- 未挂载提示：`tabs.length - searchable.length > 0` ⇒ 中文说明（AC-94）；
- 结果列表：按标签页分组（标题 + 命中数），每条命中显示 `行号：行文本`（命中段高亮）；
- 点击命中 ⇒ `setActiveTab(tabId)` + `session.revealRange(from, to)`；
- 「替换当前」⇒ 对当前选中命中的标签页做单点替换（用 `findHits` 定位后按 `from/to` 精确替换，**不用全局 replace**，避免误伤其它命中）；
- 「全部替换」⇒ **就地二次确认条**（不弹原生/嵌套对话框，便于自动化判据）→ 逐标签页 `replaceAllLiteral` + `setText` → 文案 `已替换 N 处`;
- 每次操作后**重跑一次搜索**（用于"替换后再搜 = 0 命中"的判据）。
- **零桥调用**：本组件只 import `scratch-store` / `ScratchEditorHost` / 纯逻辑模块 ⇒ AC-96 天然成立（用例用"桥替身一旦被调用即失败"再证一遍）。

**3）入口**：工具箱第 1 项新增按钮「跨标签搜索」；`toolbox.search` 快捷键仍 = 打开 CM6 面板（默认当前标签页，行为不变）。
