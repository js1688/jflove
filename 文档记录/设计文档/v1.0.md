# JFLove 1.0 技术设计文档

## 1. 系统架构设计

### 1.1 整体架构

JFLove 采用客户端-服务端架构，客户端为桌面应用，服务端为后端 API 服务。系统分为以下层次：

- **客户端层**：PySide6 桌面应用，负责用户界面、文件管理、笔记编辑。
- **服务端层**：FastAPI 后端服务，负责业务逻辑、数据存储。
- **数据层**：SQLite 数据库，存储用户、会话、配置。

架构图（文字描述）：
```
[客户端 (PySide6)] <--- HTTPS (加密) ---> [服务端 (FastAPI)]
     |                                           |
     | (本地文件系统)                            | (服务端文件系统)
     v                                           v
[本地存储]                                   [SQLite DB]
```

### 1.2 模块划分

- **文档管理模块**：文件系统操作、目录浏览、大文件分片上传/下载、断点续传、多格式文件预览。
- **传输任务管理模块**：客户端集中调度上传/下载任务，限制并发数、提供进度面板与取消能力。
- **笔记本管理模块**：md 文件操作、编辑器集成、实时预览。
- **安全模块**：会话密钥交换、数据加密、身份验证。
- **配置模块**：系统设置、目录配置。

### 1.3 技术栈选择

- **后端**：
  - 框架：FastAPI (异步支持，高性能)
  - 数据库：SQLite (轻量级，存储用户、会话、配置)
  - 认证：PyJWT (JWT 令牌)
  - 密码哈希：bcrypt (用户密码哈希存储)
  - 加密：cryptography (ChaCha20-Poly1305 对称加密，ECDH X25519 非对称密钥交换，HKDF 密钥派生，ES256 JWT 签名)
  - 文件系统：os, pathlib (操作服务端磁盘)
  - 日志：logging (内置模块)
  - 异步：asyncio

- **前端（桌面）**：
  - 框架：PySide6 (Qt for Python)
  - HTTP 客户端：requests (同步请求)
  - 加密：cryptography (同后端)
  - Markdown 编辑：QTextEdit（等宽字体）+ markdown 库
  - Markdown 预览：QTextBrowser（Qt 原生）+ 自定义 GitHub 风格 CSS（QTextDocument 支持的 CSS 2.1 子集）
  - 代码高亮：pygments（纯 Python，无 JS / 无浏览器）
  - 图表：Mermaid 块降级显示为带标签的源码框（QTextBrowser 不支持 JS，
    无法原地渲染图表；用户可复制源码到 mermaid.live 等外部工具可视化）
  - 多媒体：QtMultimedia + QtMultimediaWidgets（视频/音频预览）
  - SVG：QtSvgWidgets
  - UI 组件：PySide6-Fluent-Widgets (Material Design 风格)
  - 日志：logging

- **通信协议**：HTTPS + 自定义加密层
- **部署**：pyinstaller 打包客户端，服务端通过 pyinstaller 部署

## 2. 数据库设计

### 2.1 设计原则

- 所有表包含固定字段：id (主键，自增整数)、created_at (创建时间)、updated_at (更新时间)、deleted_at (软删除时间)
- 使用 snake_case 命名
- 无外键约束（根据项目规范）
- 支持软删除

### 2.2 核心表结构

#### users 表（用户表）
- id: INTEGER PRIMARY KEY
- username: TEXT UNIQUE (用户名)
- password_hash: TEXT (密码哈希)
- role: TEXT (角色：admin/user)
- enabled: BOOLEAN (是否启用)
- notes_disk_id: INTEGER (笔记存储虚拟磁盘 ID，可为 NULL)
- notes_path: TEXT (笔记存储目录在磁盘内的相对路径，空字符串表示磁盘根目录)
- created_at: DATETIME
- updated_at: DATETIME
- deleted_at: DATETIME

#### virtual_disks 表（虚拟磁盘表）
- id: INTEGER PRIMARY KEY
- name: TEXT (虚拟磁盘名称，如"文档库"、"备份")
- real_path: TEXT (服务端真实磁盘路径)
- created_by: INTEGER (创建者用户 ID，仅管理员)
- created_at: DATETIME
- updated_at: DATETIME
- deleted_at: DATETIME

#### user_permissions 表（用户权限表）
- id: INTEGER PRIMARY KEY
- user_id: INTEGER (普通用户 ID)
- virtual_disk_id: INTEGER (虚拟磁盘 ID)
- can_read: BOOLEAN (是否可读)
- can_write: BOOLEAN (是否可写)
- can_delete: BOOLEAN (是否可删除)
- created_at: DATETIME
- updated_at: DATETIME
- deleted_at: DATETIME

#### sessions 表（会话表）
- id: INTEGER PRIMARY KEY
- user_id: INTEGER
- session_id: TEXT UNIQUE (会话标识符，UUID，用于关联内存中的会话密钥)
- jwt_token_hash: TEXT (JWT 令牌哈希，用于吊销校验)
- expires_at: DATETIME (过期时间)
- created_at: DATETIME
- updated_at: DATETIME
- deleted_at: DATETIME

> **注意**：会话密钥（session_key）为临时密钥，仅存储于服务端内存（dict: session_id → session_key），不落库。服务重启后所有客户端需重新进行密钥交换。

> **设计变更（v1.x）**：原 `notes_permissions` 表已移除。所有登录用户均可使用笔记功能，每个用户的笔记目录由 `users.notes_disk_id` + `users.notes_path` 字段独立配置，互相不可见，因此不需要单独的笔记权限表。历史 `notes_permissions` 表在已部署的实例中保留（不再读写），不影响新部署。

#### config 表（系统配置表）
- id: INTEGER PRIMARY KEY
- key: TEXT (配置键，如 'notes_disk_id', 'admin_created')
- value: TEXT (配置值)
- created_at: DATETIME
- updated_at: DATETIME
- deleted_at: DATETIME

#### sync_configs 表（同步配置表）

记录每个用户配置的「本地目录 ↔ 远端虚拟磁盘子目录」映射关系。一个用户可以有多条配置；软删除仅取消映射，不影响实际文件。

- id: INTEGER PRIMARY KEY
- user_id: INTEGER (所属用户 ID)
- name: TEXT (用户起的别名)
- local_path: TEXT (客户端本地目录绝对路径)
- disk_id: INTEGER (远端虚拟磁盘 ID)
- remote_path: TEXT (磁盘内子目录相对路径，根目录为空串)
- auto_sync: INTEGER (是否启用自动同步，0/1)
- sync_interval: INTEGER (自动同步间隔秒数，最小 30，默认 300)
- last_synced_at: TEXT (最近一次同步完成时间，可为 NULL)
- enabled: INTEGER (配置是否启用，0/1)
- created_at: DATETIME
- updated_at: DATETIME
- deleted_at: DATETIME
- 索引：sync_configs_user_id_idx (user_id)

## 3. API 设计

### 3.1 设计原则

- RESTful 风格
- 使用 JWT 认证
- 所有请求/响应加密
- 遵循 OpenAPI 规范
- 版本控制：/api/v1/

### 3.2 核心 API 接口

#### 认证相关
- POST /api/v1/auth/init-admin：首次创建管理员账号
- POST /api/v1/auth/login：用户登录，返回 JWT 令牌
- POST /api/v1/auth/refresh：刷新令牌
- POST /api/v1/auth/key-exchange：会话密钥交换

#### 文档管理
- GET /api/v1/files/list?path={path}：获取指定路径下的文件/目录列表（检查权限）
- POST /api/v1/files/upload/init：初始化上传会话，参数：path, filename, file_size, total_chunks, file_hash(SHA256)，返回 upload_id
- POST /api/v1/files/upload/chunk：上传单个分片，参数：upload_id, chunk_index, chunk_data
- POST /api/v1/files/upload/complete：合并分片完成上传，参数：upload_id
- DELETE /api/v1/files/upload/{upload_id}：取消上传，清理临时分片
- GET /api/v1/files/download?path={path}：下载文件（检查权限）
- POST /api/v1/files/mkdir：创建目录，参数：path
- DELETE /api/v1/files?path={path}：删除文件/目录（检查权限）
- GET /api/v1/files/preview?path={path}：获取文件预览（文本/图片）

#### 笔记管理
- GET /api/v1/notes/list：获取笔记目录下的 .md 文件列表（检查权限）
- GET /api/v1/notes/read?filename={filename}：读取 md 文件内容（检查权限）
- POST /api/v1/notes/write：写入 md 文件，参数：filename, content（检查权限）
- DELETE /api/v1/notes?filename={filename}：删除 md 文件（检查权限）
- POST /api/v1/notes/rename：重命名 md 文件，参数：old_name, new_name（检查权限）
- GET /api/v1/notes/disk-config：获取当前用户笔记目录配置，返回 disk_id、path、disks
- PUT /api/v1/notes/disk-config：设置笔记目录，参数：disk_id、path（磁盘内子目录相对路径）

#### 虚拟磁盘目录浏览
- GET /api/v1/virtual-disks/{id}/browse：列出磁盘内指定路径下的子目录，参数：path（相对路径），所有已登录用户可调用，用于笔记目录选择

#### 用户管理（仅管理员）
- POST /api/v1/users：添加普通用户，参数：username, password
- GET /api/v1/users：获取用户列表
- DELETE /api/v1/users/{id}：删除用户
- PUT /api/v1/users/{id}/password：修改用户密码
- PUT /api/v1/users/{id}/enabled：启用/禁用用户

#### 虚拟磁盘管理（仅管理员）
- GET /api/v1/virtual-disks：获取虚拟磁盘列表
- POST /api/v1/virtual-disks：添加虚拟磁盘，参数：name, real_path
- DELETE /api/v1/virtual-disks/{id}：删除虚拟磁盘
- PUT /api/v1/virtual-disks/{id}：编辑虚拟磁盘

#### 权限管理（仅管理员）
- GET /api/v1/permissions/users/{user_id}/disks：获取用户的磁盘权限
- POST /api/v1/permissions/users/{user_id}/disks/{disk_id}：设置用户磁盘权限
- DELETE /api/v1/permissions/users/{user_id}/disks/{disk_id}：删除用户磁盘权限

#### 系统配置
- GET /api/v1/config：获取系统配置
- PUT /api/v1/config：更新配置

#### 同步配置（每用户私有）
- GET /api/v1/sync/configs：列出当前用户的所有同步配置
- POST /api/v1/sync/configs：创建一条同步配置，参数：name, local_path, disk_id, remote_path, auto_sync, sync_interval
- PUT /api/v1/sync/configs/{id}：更新同步配置（全字段，含 enabled 开关）
- DELETE /api/v1/sync/configs/{id}：软删除同步配置（**不会**删除任何实际文件）
- GET /api/v1/sync/configs/{id}/snapshot：获取远端目录的递归文件清单（用于客户端做 diff），返回 path/size/modified_at
- POST /api/v1/sync/configs/{id}/touch：标记一次同步完成，更新 last_synced_at

### 3.3 加密机制

- **会话密钥交换**：使用 ECDH X25519 生成临时公私钥对，双方交换公钥后通过 HKDF-SHA256 派生 32 字节会话密钥。
- **数据加密**：使用 ChaCha20-Poly1305 对称加密，每次请求生成随机 16 字节 nonce，密文携带 nonce 和认证标签。
- **JWT 签名**：ES256 算法，服务端持有 EC 私钥签发，客户端验证公钥。
- **传输**：HTTPS（TLS 1.2+）+ 应用层加密双重保护。

### 3.4 接口加密规范

加密请求格式（适用于所有需应用层加密的接口）：

```json
{
  "nonce": "<16字节随机数，base64编码>",
  "ciphertext": "<ChaCha20-Poly1305加密后的原始JSON Body，base64编码>"
}
```

加密响应格式相同，客户端用会话密钥解密后得到原始 JSON。

| 接口 | 是否需要应用层加密 | 说明 |
| ---- | ------------------ | ---- |
| POST /api/v1/auth/key-exchange | **否** | 密钥交换本身，会话密钥尚未建立，仅靠 HTTPS 保护公钥传输 |
| POST /api/v1/auth/init-admin | **是** | 包含管理员密码，必须加密 |
| POST /api/v1/auth/login | **是** | 包含用户凭证，必须加密 |
| POST /api/v1/auth/refresh | **是** | 包含 JWT 令牌，必须加密 |

| POST /api/v1/files/upload/init | **是** | 包含文件路径、文件名，加密保护 |
| POST /api/v1/files/upload/chunk | **是** | 文件内容分片，加密保护（chunk_data 单独加密） |
| POST /api/v1/files/upload/complete | **是** | 包含上传会话信息，加密保护 |
| DELETE /api/v1/files/upload/{upload_id} | **是** | 加密保护 |
| GET /api/v1/files/download | **是** | 响应体为加密文件分片数据 |
| DELETE /api/v1/files | **是** | 包含路径信息，加密保护 |
| GET /api/v1/files/preview | **是** | 响应包含文件内容，加密保护 |
| POST /api/v1/files/mkdir | **是** | 加密保护 |
| GET /api/v1/notes/list | **是** | 加密保护 |
| GET /api/v1/notes/read | **是** | 响应包含笔记内容，加密保护 |
| POST /api/v1/notes/write | **是** | 包含笔记内容，加密保护 |
| DELETE /api/v1/notes | **是** | 加密保护 |
| POST /api/v1/notes/rename | **是** | 加密保护 |
| POST /api/v1/users | **是** | 包含用户密码，必须加密 |
| GET /api/v1/users | **是** | 加密保护 |
| DELETE /api/v1/users/{id} | **是** | 加密保护 |
| PUT /api/v1/users/{id}/password | **是** | 包含新密码，必须加密 |
| PUT /api/v1/users/{id}/enabled | **是** | 加密保护 |
| GET /api/v1/virtual-disks | **是** | 加密保护 |
| POST /api/v1/virtual-disks | **是** | 包含服务端真实路径，加密保护 |
| DELETE /api/v1/virtual-disks/{id} | **是** | 加密保护 |

### 3.5 密钥交换流程

#### 初次连接密钥交换

```text
客户端                                          服务端
  |                                               |
  |  1. 生成 X25519 临时公私钥对                   |
  |     client_priv, client_pub                   |
  |                                               |
  |  POST /api/v1/auth/key-exchange               |
  |  { "client_public_key": "<base64>" }          |
  | --------------------------------------------> |
  |                                               |  2. 生成 X25519 临时公私钥对
  |                                               |     server_priv, server_pub
  |                                               |
  |                                               |  3. 计算共享密钥
  |                                               |     shared = ECDH(server_priv, client_pub)
  |                                               |
  |                                               |  4. 派生会话密钥
  |                                               |     session_key = HKDF-SHA256(shared, salt="jflove-v1")
  |                                               |
  |                                               |  5. 生成 session_id (UUID)
  |                                               |     内存存储: session_id → session_key
  |                                               |
  |  { "server_public_key": "<base64>",           |
  |    "session_id": "<uuid>" }                   |
  | <-------------------------------------------- |
  |                                               |
  |  6. 计算共享密钥                               |
  |     shared = ECDH(client_priv, server_pub)    |
  |                                               |
  |  7. 派生会话密钥（与服务端一致）               |
  |     session_key = HKDF-SHA256(shared, salt="jflove-v1")
  |                                               |
  |  8. 内存存储 session_id 和 session_key         |
  |     销毁 client_priv                           |
  |                                               |
  |  后续所有请求携带:                              |
  |  Header: X-Session-ID: <uuid>                 |
  |  Body:   { nonce, ciphertext }（加密内容）      |
  | --------------------------------------------> |
```

#### 密钥刷新流程

触发条件：用户主动刷新、会话超时策略触发。

```text
客户端                                          服务端
  |                                               |
  |  1. 生成新的 X25519 临时公私钥对               |
  |                                               |
  |  POST /api/v1/auth/key-exchange               |
  |  Header: X-Session-ID: <旧 session_id>        |
  |  Body: 加密({ "client_public_key": "<base64>", "refresh": true })
  | --------------------------------------------> |
  |                                               |  2. 用旧 session_key 解密请求
  |                                               |  3. 生成新服务端公私钥对
  |                                               |  4. 派生新 session_key
  |                                               |  5. 生成新 session_id
  |                                               |  6. 内存中删除旧 session_id
  |                                               |
  |  明文响应（公钥本身不敏感）:                   |
  |  { "server_public_key": "<base64>",           |
  |    "session_id": "<新 uuid>" }                |
  | <-------------------------------------------- |
  |                                               |
  |  7. 派生新 session_key                        |
  |  8. 更新内存中的 session_id 和 session_key    |
  |  9. 旧密钥立即失效                             |
```

#### 会话密钥安全要求

- 客户端和服务端的 X25519 私钥用完即销毁，不持久化。
- `session_key` 仅存于内存，服务端重启所有客户端须重新交换。
- 每个 `nonce` 全局唯一，服务端校验 nonce 不重复（防重放攻击）。
- 会话密钥默认有效期 24 小时，可通过系统配置调整强制刷新频率。

## 4. 安全设计

### 4.1 认证与授权

- 用户名密码登录，密码使用 bcrypt 哈希。
- JWT 令牌，有效期 1 小时，支持刷新。
- 角色权限：admin 可管理所有，user 仅个人数据。

### 4.2 数据加密

- 静态数据：敏感字段加密存储。
- 传输数据：所有 API 请求/响应加密。
- 会话密钥：每次连接重新生成，不重用。

### 4.3 其他安全措施

- 输入验证：防止 SQL 注入、XSS。
- 日志记录：所有操作记录到 logs/ 目录。
- 异常处理：全局异常处理器，记录错误但不泄露敏感信息。

## 5. 性能与可扩展性设计

### 5.1 性能优化

- 异步处理：FastAPI asyncio 支持并发请求。
- 分片上传：大文件按 1 MB 分片，避免一次性占用大量内存。
- 流式下载：客户端 `download_to_file` 边下边写到本地 `.part` 临时文件，避免大文件全量入内存，下载完成后原子重命名为目标文件。
- 字节级进度回调：上传 SHA256 校验阶段、上传分片阶段、下载阶段均按字节上报进度，UI 不会因为单分片过大而出现"长时间无反馈"。
- 传输任务管理器：客户端单例 `TransferManager` 维护上传/下载任务队列，最多并发 3 个；多余任务进入 PENDING 队列等待调度，结束后自动启动下一个。
- 文件系统缓存：客户端缓存目录结构，减少请求。
- 索引：数据库索引优化查询。
- 文件操作安全：限制访问路径，防止目录遍历攻击。

### 5.2 可扩展性

- 模块化设计：易添加新功能，如云存储集成。
- 配置化：通过配置文件调整目录路径、权限。
- 未来扩展：支持多用户目录隔离、文件版本控制、远程备份。

### 5.3 客户端传输任务管理器设计

#### 5.3.1 架构概览

```text
┌─────────────┐  submit_upload/   ┌──────────────────┐
│  file_page  │ submit_download   │ TransferManager  │
│  (UI)       │ ────────────────▶ │  (单例 QObject)  │
└─────────────┘                   └────────┬─────────┘
                                           │ task_added /
                                           │ task_updated /
                                           │ task_removed
                                           ▼
                                  ┌──────────────────┐
┌─────────────┐  显示/取消        │  transfer_page   │
│  navigation │ ◀──────────────── │   (UI 任务面板)  │
└─────────────┘                   └──────────────────┘
                                           │
                  调度（最多 3 并发）        │
                                           ▼
                                  ┌──────────────────┐
                                  │ _TransferWorker  │
                                  │ (QThread, 1/任务)│
                                  └────────┬─────────┘
                                           │ 调用
                                           ▼
                                  ┌──────────────────┐
                                  │  file_service    │
                                  │ upload_file/     │
                                  │ download_file    │
                                  └──────────────────┘
```

#### 5.3.2 核心数据结构

- `TransferTask`: 单个任务的数据对象，字段包括 `id / kind(UPLOAD|DOWNLOAD) / filename / disk_id / rel_path / local_path / file_size / transferred / status / error / created_at / finished_at`
- `TaskStatus` 枚举：`PENDING / HASHING / RUNNING / COMPLETED / FAILED / CANCELLED`

#### 5.3.3 调度规则

- `MAX_CONCURRENT = 3`，上传与下载共享配额
- 提交任务后 → 默认状态 `PENDING` → `_try_dispatch()` 决定是否立即启动
- 当前进行中数（`HASHING + RUNNING`）小于上限时，按照创建顺序挑选下一个 `PENDING` 任务启动
- 任意 worker 进入终态（`COMPLETED / FAILED / CANCELLED`）后立即触发新一轮 `_try_dispatch`

#### 5.3.4 信号通信

- `task_added(TransferTask)` —— 新任务被加入
- `task_updated(task_id: str)` —— 状态/进度变化（UI 通过 `task_id` 反查最新对象）
- `task_removed(task_id: str)` —— 任务被清除（"清除已完成"）

#### 5.3.5 取消语义

- 进行中任务：worker 设置 `_cancelled=True`，下一次分片或字节边界检查时退出；上传会 `DELETE /upload/{upload_id}` 清理服务端临时分片，下载会删除本地 `xxx.part` 临时文件
- 等待中任务：直接置为 `CANCELLED`，不会被调度执行

#### 5.3.6 进度反馈

- 上传分两阶段，回调签名 `(done_bytes, total_bytes, phase)`：
  - `phase="hashing"` —— SHA256 校验阶段
  - `phase="uploading"` —— 分片上传阶段
- 下载阶段固定 `phase="downloading"`，按字节流式上报
- 每次进度回调通过 worker 的 `progress` 信号转发到 `TransferManager._on_progress`，再 emit `task_updated` 让 UI 更新

### 5.4 客户端多格式预览组件设计

#### 5.4.1 组件位置

`src/components/preview_dialog.py` 提供 `PreviewDialog`，由 `file_page._preview_file()` 创建并 exec()。

#### 5.4.2 文件类型识别

按扩展名分类，识别函数 `_detect_kind(filename) -> {"image", "svg", "video", "audio", "markdown", "text", "other"}`：

| 类型 | 扩展名集合 |
| ---- | ---------- |
| image | png / jpg / jpeg / gif / bmp / webp / tiff / tif / ico |
| svg | svg |
| video | mp4 / mkv / avi / mov / webm / flv / wmv / m4v / mpg / mpeg / ts / 3gp |
| audio | mp3 / wav / ogg / flac / m4a / aac / wma / opus |
| markdown | md / markdown / mdown / mkd |
| text | txt / log / json / xml / yaml / ini / csv / 常见编程语言源码 |
| other | 其他类型，提示用户改用下载 |

#### 5.4.3 数据获取策略

- 图片 / SVG / Markdown / 文本：调用 `file_service.get_preview_bytes()`，整体加载到内存（限制 500 MB）
- 视频 / 音频：调用 `http_client.download_to_file()` 流式写入到本地临时文件（`tempfile.mkstemp`，保留原扩展名），再通过 `QUrl.fromLocalFile()` 喂给 `QMediaPlayer` 播放

#### 5.4.4 预览控件

| 类型 | 控件 |
| ---- | ---- |
| image | `_ImageView`（QScrollArea + QLabel + QPixmap，超大图按 1920×1080 缩放后可滚动查看） |
| svg | `_SvgView`（`QSvgWidget`） |
| markdown | `_MarkdownView`（`markdown` 库渲染为 HTML，支持 `fenced_code / tables / toc / nl2br` 扩展，QTextBrowser 显示） |
| text | `_TextView`（QTextBrowser 等宽字体，UTF-8/GBK 兜底解码） |
| video | `_MediaView`（`QMediaPlayer + QVideoWidget`，含播放/暂停、停止、进度条、时长显示、音量滑块） |
| audio | `_MediaView`（同 video，但视觉用 `ProgressRing` 替代 video widget） |

#### 5.4.5 跨平台兼容性

- `QtMultimedia` 是 PySide6 标准模块，但实际播放依赖各平台底层后端：
  - **Windows**：MediaFoundation（系统自带）
  - **macOS**：AVFoundation（系统自带）
  - **Linux**：GStreamer，需安装 `gst-plugins-good` / `gst-plugins-bad` / `gst-plugins-ugly` / `gst-libav`，否则无法播放
- 模块采用 try/except 导入 `QtMultimedia`、`QtSvgWidgets`，缺失时降级为友好提示而非崩溃
- 临时文件使用 `tempfile.mkstemp` 保留原扩展名，关闭对话框时通过 `QTimer.singleShot(200ms)` 延迟删除（给 Windows 文件句柄释放时间）

#### 5.4.6 资源清理

- `closeEvent` 触发 `_MediaView.stop_and_release()` 停止播放并清空 `setSource(QUrl())`
- 临时文件通过 `_safe_remove(path)` 静默删除，失败仅记录日志

### 5.5 目录同步架构设计

#### 5.5.1 整体架构

```text
┌──────────────────┐  CRUD/snapshot/touch   ┌────────────────────┐
│  sync_page (UI)  │ ────────────────────▶  │  sync_controller   │
└────────┬─────────┘                        │  (FastAPI 路由)    │
         │                                  └─────────┬──────────┘
         │ trigger_sync / reload_configs              │
         ▼                                            ▼
┌──────────────────┐                        ┌────────────────────┐
│   sync_engine    │                        │   sync_service     │
│ (单例 QObject)   │                        │ + sync_config_repo │
└────────┬─────────┘                        └─────────┬──────────┘
         │                                            │
         │ _SyncRunWorker (QThread)                   │ os.walk
         ▼                                            ▼
┌──────────────────┐  submit_upload/download  ┌────────────────────┐
│ transfer_manager │ ◀──────────────────────  │ 远端 disk.real_path│
└──────────────────┘  (复用文件传输框架)      │ + remote_path 子树 │
                                              └────────────────────┘
```

#### 5.5.2 同步算法（双向、增量、不删除）

```text
1. LocalIndex  = recursive_scan(local_path)         # {rel: (size, mtime)}
2. RemoteIndex = GET /api/v1/sync/configs/{id}/snapshot
3. for rel in (LocalIndex.keys ∪ RemoteIndex.keys):
       l = LocalIndex.get(rel)
       r = RemoteIndex.get(rel)
       if l and not r:                              → 提交 UPLOAD
       elif r and not l:                            → 提交 DOWNLOAD
       else:
           if abs(l.mtime - r.mtime) <= 2.0:        → 跳过（容差）
           elif l.mtime > r.mtime:                  → 提交 UPLOAD（覆盖）
           else:                                    → 提交 DOWNLOAD（覆盖）
4. POST /api/v1/sync/configs/{id}/touch
```

#### 5.5.3 删除安全约束（产品强制）

- 客户端 `sync_engine` **永远不会**调用 `DELETE /api/v1/files`
- 服务端 `sync_controller` 不暴露任何"按 sync 配置删除文件"的接口
- 本地缺失文件 → 触发 DOWNLOAD（即"自动恢复"），不会反向删除远端
- 远端缺失文件 → 触发 UPLOAD（即"自动补回"），不会主动删除本地
- 删除入口：仅文档管理页 → `file_controller.delete_file` → 该接口要求显式 disk + path，不参与同步流

#### 5.5.4 并发与调度

- 每个开启 `auto_sync` 的配置在客户端拥有独立的 `QTimer`（间隔 = `sync_interval` 秒）
- `sync_engine._running_ids` 集合防止同一配置并发执行
- 单次同步在独立 `QThread`（`_SyncRunWorker`）中运行，不阻塞 UI
- 上传/下载任务最终交给 `transfer_manager`（默认 3 并发）执行，因此多个同步任务的传输操作可共享同一并发上限

#### 5.5.5 远端递归扫描

- 服务端 `sync_service.list_remote_snapshot()` 用 `os.walk(base)` 递归遍历
- 用 `_safe_join` 防目录遍历攻击；远端目录尚未存在时返回空清单（首次同步会自动创建）
- 单文件 stat 异常仅日志告警跳过，不中断扫描
- 客户端按 `path` 字段建立 `dict[str, dict]` 索引，与本地索引取并集做 diff

#### 5.5.6 权限校验

- `sync_service.create_config / update_config` 强制要求当前用户对目标磁盘**同时**具备读+写权限（普通用户）
- `list_remote_snapshot` 校验读权限
- `transfer_manager` 提交的具体上传/下载任务由 `file_controller` 在写盘/读盘时再次校验权限（双层防御）

### 5.6 Markdown 预览组件设计

#### 5.6.1 组件位置与技术栈

`src/components/markdown_view.py` 提供 `MarkdownView`（`QTextBrowser` 子类）。同时在笔记管理页（实时分栏预览）和文档管理页 `PreviewDialog` 的 `_MarkdownView` 中复用，渲染逻辑统一。

技术栈选择：

- **Markdown → HTML**：`markdown` 库 + `tables` / `nl2br` / `sane_lists` 扩展
- **代码高亮**：`pygments`（纯 Python，BSD-3，约 5 MB）— `HtmlFormatter(noclasses=True)` 输出 inline-style HTML，QTextBrowser 直接吃
- **Markdown 渲染容器**：`QTextBrowser`（Qt 原生）

#### 5.6.2 为什么不用 QWebEngineView

最初尝试过 `QWebEngineView` 路线（搭配 mermaid.js + highlight.js），但实测在 PySide6 6.11 + Qt 6.10 + Wayland + Python 3.14 组合下，鼠标 hover 经过预览面板时会触发 `PySide::getWrapperForQObject` segfault（PYSIDE-2700 系列已知 bug，上游未修）。core dump 显示崩溃路径：`QGuiApplicationPrivate::processEnterEvent` → `QQuickWidget::event` → `QQuickDeliveryAgentPrivate::sendHoverEvent` → PySide6 wrapper lookup → SIGSEGV。

权衡稳定性 / 自包含 / 用户对"不下载第三方"的明确诉求，最终选择 QTextBrowser 方案：

- ✓ Qt 原生组件，跨平台稳定，零崩溃
- ✓ 完全自包含，无任何 JS 资产、无网络依赖、无 Chromium 运行时
- ✗ 无法原地渲染 Mermaid 图表（QTextBrowser 不执行 JS）

#### 5.6.3 渲染管线

```text
markdown 源文本
  ↓ (1) 抽取 ```mermaid 块 → 占位符 @@JFLOVE_MERMAID_n@@（避免被当普通代码块）
  ↓ (2) 抽取其他代码块（带语言标识）→ 占位符 @@JFLOVE_CODE_n@@
  ↓ (3) 标题前注入 <a id="hN"> 锚点（与大纲面板顺序对齐）
  ↓ (4) markdown 库（tables / nl2br / sane_lists）→ HTML 主体
  ↓ (5) 还原 mermaid 占位 → <p class="mermaid-label">📊 标签</p> + <pre class="mermaid-block">源码</pre>
  ↓ (6) 还原代码块占位 → pygments 高亮 inline-style HTML
  ↓ (7) 套 HTML 模板（嵌入 QTextBrowser 兼容的 CSS）
  ↓
QTextBrowser.setHtml(html)
```

#### 5.6.4 自包含 / 无外部依赖

- 不需要任何 JS / CSS 资产文件
- 不连接任何 CDN / 网络
- PyInstaller 打包只需把 `pygments` 打入即可（pip 自动处理），无额外步骤
- 渲染输出脱机抓包验证：HTML 中无 `file://` / `jsdelivr` / `cdnjs`，全部为 inline 内容

#### 5.6.5 排版样式

内置 CSS 限定为 QTextDocument 支持的 CSS 2.1 子集，避开 `border-radius` / `flex` / `:hover` / 媒体查询等不支持的属性：

- 字体栈：`PingFang SC / Microsoft YaHei / Segoe UI / Arial`，覆盖中英文
- 标题：H1/H2 带下边线，主色 `#1f2328`
- 代码块：浅灰底（`#f6f8fa`）+ 边框 + 等宽字体
- 引用块：左侧 4px 蓝灰色条 + 浅底
- 表格：边框完整 + 表头浅底色
- Mermaid 块：黄色提示条 + 浅黄底代码框，明确告诉用户这是图表源码

#### 5.6.6 Mermaid 降级展示

- 用占位符避开 markdown 库 fenced_code 处理
- 还原为「醒目标签 + 源码框」组合：
  - `<p class="mermaid-label">📊 Mermaid 图表（QTextBrowser 不支持 JS，下方显示源码，可复制到 mermaid.live 可视化）</p>`
  - `<pre class="mermaid-block">{HTML 转义后的源码}</pre>`
- 用户体验：在笔记内**写** mermaid 完全正常（笔记页支持 ` ```mermaid `）；预览时看到带颜色提示的源码框；要可视化时复制到外部 mermaid 渲染工具

#### 5.6.7 代码高亮（pygments）

- 通过 `get_lexer_by_name(lang)` 按语言标识精确选择 lexer；无标识时 `guess_lexer(code)` 根据内容猜测
- `HtmlFormatter(style="default", noclasses=True)` 把样式以 `<span style="...">` inline 写入，QTextBrowser 直接渲染（QTextDocument 不支持外部 stylesheet 中的 class 选择器）
- 失败保护：lexer 找不到 / pygments 异常时降级为普通 `<pre>{escape(code)}</pre>`

#### 5.6.8 锚点跳转

- 注入 `<a id="h0">`、`<a id="h1">`...，N 为标题在文档中的顺序索引
- 大纲面板点击时调用 `MarkdownView.scroll_to_anchor("hN")`
- 实现：直接调用 `QTextBrowser.scrollToAnchor()`（Qt 内置）

#### 5.6.9 编辑器适配

- 笔记编辑器使用等宽字体（Cascadia Code / JetBrains Mono / Menlo / Consolas），自动 fallback
- `setTabStopDistance(28)` 让 Tab 缩进更紧凑，便于代码 / mermaid 编写
- 编辑器内容变化触发 400ms 防抖，重新调用 `set_markdown(text)`

### 5.7 跨平台中文输入法（IME）支持

#### 5.7.1 平台差异概览

| 平台 | IME 工作机制 | Qt 配置 |
| ---- | ------------ | ------- |
| Linux Wayland | text-input-v3 协议（Qt 6 内置 wayland 模块直接对接 fcitx5/ibus 的 wayland-frontend） | `QT_IM_MODULE=wayland` |
| Linux X11 + IBus | IBus 桥接插件（PySide6 venv 自带 `libibusplatforminputcontextplugin.so`） | `QT_IM_MODULE=ibus` |
| Linux X11 + Fcitx5 | Fcitx5-Qt6 桥接插件（PySide6 venv **未自带**，需系统级 fcitx5-qt6 包） | `QT_IM_MODULE=fcitx` |
| Windows | Win32 / TSF 系统级 IME，Qt 自动桥接 | 无需配置 |
| macOS | NSTextInputClient 系统级 IME，Qt 自动桥接 | 无需配置 |

#### 5.7.2 自动检测与回退

`src/utils/input_method.py` 的 `setup_input_method()` 必须在 `QApplication` 之前调用，按以下优先级决定 `QT_IM_MODULE`：

```text
1. 非 Linux（Windows/macOS）→ 不动，使用系统原生 IME
2. 当前 QT_IM_MODULE 在 PySide6 venv 中可用？
   - "wayland" + 当前是 Wayland 会话 → 保留
   - 名字命中 PySide6 自带的 platforminputcontexts/ 插件 → 保留
   是 → 不动
3. 当前 IM 不可用：
   - Wayland 会话 → 切换到 "wayland"（Qt 6 内置，走 text-input-v3）
   - X11 + ibus 守护进程在跑 + ibus 插件可用 → 切换到 "ibus"
   - 否则保留原值，仅打 warning 日志（用户需手动安装系统 fcitx5-qt6 等）
```

#### 5.7.3 PyInstaller 打包要点

- **Linux**：PyInstaller 会自动收集 PySide6 自带的 `platforminputcontexts/` 插件目录（包含 ibus 桥接 + Compose 处理）。Wayland 用户依赖系统的 fcitx5-wayland-frontend；X11 + Fcitx5 用户需要系统额外安装 fcitx5-qt6 包。这些都是 OS 级依赖，不是项目能内嵌的
- **Windows**：原生 IME 不需要 Qt 插件，无需任何额外配置；用户只要在系统设置里开启中文输入法就能在我们的应用中使用
- **macOS**：同 Windows，原生 IME 自动工作；本项目暂未在 macOS 验证，但代码路径已预留（`setup_input_method()` 在非 Linux 平台直接 return）

#### 5.7.4 用户配置矩阵（基于 PySide6 venv 自带插件）

| 用户场景 | 我们做什么 | 用户需要做什么 |
| -------- | ---------- | -------------- |
| Linux Wayland + fcitx5 | 自动设 `QT_IM_MODULE=wayland` | 安装 `fcitx5-wayland-frontend` 包 |
| Linux Wayland + ibus | 自动设 `QT_IM_MODULE=wayland` | 默认即可（ibus 1.5.30+ 自带 wayland 支持） |
| Linux X11 + fcitx5 | 保留原 `fcitx`，打 warning | 安装 `fcitx5-qt6` 包，或改用 IBus |
| Linux X11 + ibus | 自动设 `QT_IM_MODULE=ibus` | 无需操作 |
| Windows | 不动 | 系统设置中启用中文输入法 |
| macOS | 不动 | 系统偏好设置中启用中文输入源 |
