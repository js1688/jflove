## 0. 与 v1.1.1 的设计差异

| 项 | v1.1.1 设计 | v1.1.2 设计 |
|---|---|---|
| `JWT_EXPIRE_HOURS` | 默认 1 小时，`create_token` 使用此常量计算 exp | 默认仍为 1 小时；新增 `JWT_EXPIRE_MAX_SECONDS = 28800`（8 小时硬上限） |
| `create_token(user_id, username, role)` | 仅按默认 TTL 签发 | 新增可选参数 `ttl_seconds: int \| None = None`，给定时按该 TTL 签发；超出上下限时 clamp |
| `auth_service.login` | 三参数（db, username, password, session_id） | 新增可选参数 `requested_ttl_seconds: int \| None = None`，从加密 body 透传到 `create_token` |
| 登录接口 `/api/v1/auth/login` 加密 body | `{"username", "password"}` | 新增可选字段 `requested_ttl_seconds`（向后兼容，缺省走默认 1h） |
| 登录响应 | `{"token", "role", "username", "user_id", "expires_in"}` | 字段不变；`expires_in` 自然反映本次签发的 TTL |
| 桌面端 `auth_service.login(local_max_seconds=)` | local_max_seconds 仅写入 `session_manager.local_session_max_seconds`，不传给服务端 | 同时作为 `requested_ttl_seconds` 传给服务端登录请求 |
| 登录页布局 | 8 行垂直堆叠（拥挤） | 6 行：标签+下拉同行、按钮同行 |
| 服务端 `session_repository.create` 的 `expires_at` | 始终用 `JWT_EXPIRE_HOURS` 计算 | 与 JWT 实际 TTL 保持一致（用 create_token 实际使用的秒数）|

### 2.2 服务端核心改造

#### `jwt_utils.create_token(... ttl_seconds=None)`

```python
from src.config.settings import (
    JWT_ALGORITHM,
    JWT_EXPIRE_DEFAULT_SECONDS,  # 默认 3600
    JWT_EXPIRE_MAX_SECONDS,      # 上限 28800
)

JWT_EXPIRE_MIN_SECONDS = 60  # 最小 60s，硬性下限


def create_token(
    user_id: int,
    username: str,
    role: str,
    ttl_seconds: int | None = None,
) -> tuple[str, int]:
    """
    签发 JWT 令牌，返回 (token, 实际使用的 TTL 秒数)。

    :param ttl_seconds: 客户端请求的 TTL（秒）。
                        - None：使用默认值 JWT_EXPIRE_DEFAULT_SECONDS
                        - 给定：clamp 到 [JWT_EXPIRE_MIN_SECONDS, JWT_EXPIRE_MAX_SECONDS]
    """
    if ttl_seconds is None:
        effective = JWT_EXPIRE_DEFAULT_SECONDS
    else:
        effective = max(JWT_EXPIRE_MIN_SECONDS,
                        min(int(ttl_seconds), JWT_EXPIRE_MAX_SECONDS))
    now = datetime.now(timezone.utc)
    payload = {
        "sub": str(user_id),
        "username": username,
        "role": role,
        "iat": now,
        "exp": now + timedelta(seconds=effective),
    }
    return jwt.encode(payload, _PRIVATE_PEM, algorithm=JWT_ALGORITHM), effective
```

返回值改为 `(token, effective_seconds)` 二元组，方便 `auth_service.login` 用同一个 effective 算 `expires_at`，避免两边算两遍出现轻微偏差。

#### `auth_service.login(db, username, password, session_id, requested_ttl_seconds=None)`

```python
async def login(
    db, username, password, session_id, requested_ttl_seconds: int | None = None,
) -> dict:
    ...
    token, effective_ttl = create_token(
        user["id"], user["username"], user["role"],
        ttl_seconds=requested_ttl_seconds,
    )
    expires_at = (
        datetime.now(timezone.utc) + timedelta(seconds=effective_ttl)
    ).isoformat()
    ...
    return {
        "token": token,
        "role": user["role"],
        "username": user["username"],
        "user_id": user["id"],
        "expires_in": effective_ttl,
    }
```

`refresh_token` **本期保持不变**（仍按默认 TTL 签发），原因：刷新接口客户端目前不主动调用（v1.1.1 已决定不做 JWT 自动续期）；本期不扩大改动范围。

#### `auth_controller.login`

```python
async def login(request: Request, db: ...):
    body = await decrypt_request_body(request)
    username = body.get("username", "").strip()
    password = body.get("password", "")
    requested_ttl_seconds = body.get("requested_ttl_seconds")
    session_id = request.headers.get("X-Session-ID", "")
    if not username or not password:
        raise HTTPException(status_code=400, detail="用户名和密码不能为空")
    # requested_ttl_seconds 类型校验：允许 int / 字符串数字 / None
    if requested_ttl_seconds is not None:
        try:
            requested_ttl_seconds = int(requested_ttl_seconds)
        except (TypeError, ValueError):
            requested_ttl_seconds = None  # 非法值视为不传，走默认
    try:
        result = await auth_service.login(
            db, username, password, session_id, requested_ttl_seconds,
        )
    except ValueError as e:
        raise HTTPException(status_code=401, detail=str(e))
    return encrypt_response(session_id, result)
```

设计取舍：**非法 TTL 值（字符串、负数、超出范围）一律 clamp 或回退默认**，**不向客户端报 400**。理由：

1. 容错：网络字节抖动 / 旧客户端 / 伪造请求都不应该把登录接口拒绝；
2. 安全：clamp 到上限就是最严苛行为，不需要用户感知；
3. 简化：客户端 v1.1.1 不带此字段，服务端必须容忍 None。

## 4. API 接口

### 4.1 `POST /api/v1/auth/login`（修改）

#### 安全宪法 4 项标注

| 项 | 值 |
|---|---|
| 是否在明文白名单 | 否（与 v1.1.1 一致，仍走加密信封） |
| 路径参数归属/角色校验 | 无路径参数 |
| 加密信封策略 | 普通 JSON 走 ChaCha20-Poly1305 信封；错误响应也加密 |
| 错误响应 | 通过 `HTTPException` 抛出，全局 handler 加密 |

#### 请求体（加密 body 解密后）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名 |
| `password` | string | 是 | 明文密码 |
| `requested_ttl_seconds` | int | **可选**（v1.1.2 新增）| 客户端请求的 JWT 有效期（秒）。允许范围 `[60, 28800]`。超出/非法值由服务端 clamp 或回退默认 3600 |

#### 响应体（加密后）

| 字段 | 类型 | 说明 |
|---|---|---|
| `token` | string | JWT |
| `role` | string | 用户角色 |
| `username` | string | 用户名（回显） |
| `user_id` | int | 用户 ID |
| `expires_in` | int | **本次签发的实际 TTL（秒）**，反映 clamp 后的真实值 |

#### 错误码

| 状态码 | 触发条件 | detail |
|---|---|---|
| 400 | 用户名 / 密码为空 | "用户名和密码不能为空" |
| 401 | 用户名密码错误 / 账号禁用 | "用户名或密码错误" / "账号已被禁用" |

不为非法 TTL 单独抛错——非法值一律 clamp 或回退默认。

## 6. 安全方案

### 6.1 §9 安全宪法对照

| 条款 | 是否触动 | 处置 |
|---|---|---|
| §9.1 通信加密默认值 | 否 | login 仍走加密信封 |
| §9.2 PFS / X25519 | 否 | 不引入长期密钥 |
| §9.3 鉴权 | 部分（JWT TTL 变长）| 仍只走加密 body 的 token；TTL 受服务端硬上限约束 |
| §9.4 不暴露内容 | 否 | 不动 |
| §9.5 加密原语 | 否 | 不引入新原语 |

### 6.2 长 TTL 引入的额外考虑

**8 小时 vs 1 小时：JWT 被盗后的暴露窗口扩大 8 倍**。安全策略：

1. **上限受控**：`JWT_EXPIRE_MAX_SECONDS = 28800`，运维可调，但用户/客户端无法绕过；
2. **本地强制更严**：用户在 UI 选 30 分钟时，即使 JWT 是 30 分钟有效，行为完全等价，不会被"本地上限"无意识缩短或延长；
3. **登出仍走 logout** 接口（沿用 v1.1.1）：用户主动退出时立即吊销 sessions 表记录，不依赖 JWT 自然过期；
4. **不引入 JWT 自动续期**：仍由用户登录界面显式选择，避免"长期 token"形态。

### 6.3 兼容性

| 客户端 | 服务端 | 行为 |
|---|---|---|
| v1.1.2 | v1.1.2 | 完整功能：用户选 8h 真生效 8h |
| v1.1.2 | v1.1.1 | 旧服务端忽略 `requested_ttl_seconds` 字段，签 1h JWT；客户端的 `effective_expire_at = min(JWT exp, 用户上限)` = 1h；体验回退到 v1.1.1 |
| v1.1.1 | v1.1.2 | 客户端不带 `requested_ttl_seconds`，服务端走默认 1h；行为与 v1.1.1 一致 |
| v1.1.0 | v1.1.2 | 同上 |

无破坏性升级。

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| 客户端不带 `requested_ttl_seconds` | 服务端走默认 1h |
| 客户端带 `requested_ttl_seconds = 0 / 负数` | clamp 到下限 60s |
| 客户端带 `requested_ttl_seconds = 9999999`（超出上限）| clamp 到上限 28800s |
| 客户端带非整数（字符串数字、null、非数字字符）| 数字字符串可解析则按数字 clamp；其他视为 None 走默认 |
