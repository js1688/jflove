# JFLove v1.9.1 设计文档（存储配置精简 + 文案对齐）

> 需求：[`文档记录/需求文档/v1.9.1.md`](../需求文档/v1.9.1.md)
> 版本：v1.9.1

## 1. 配置键收敛（服务端唯一真相）

| 键 | 状态 | 默认值 | 范围 | 含义 |
| --- | --- | --- | --- | --- |
| `upload_cleanup_enabled` | 保留 | `1` | `0/1` | 自动清理总开关（只管定时任务） |
| `upload_resume_ttl_hours` | 保留 | `24` | 1~168 | 临时文件期限：续传有效期 + 所有临时文件清理保护期 |
| `upload_cleanup_interval_minutes` | 保留 | `60` | 5~1440 | 清理检查间隔 |
| `upload_cleanup_client_types` | 遗留（不再读取） | — | — | 行为固定为「全部类型」 |
| `upload_orphan_ttl_hours` | 遗留（不再读取） | — | — | 行为固定 = `upload_resume_ttl_hours` |
| `upload_max_sessions_per_user` | 遗留（不再读取） | — | — | 固定 8 |
| `upload_merge_concurrency` | 遗留（不再读取） | — | — | 固定 1 |
| `upload_chunk_concurrency` | 遗留（不再读取） | — | — | 固定 2 |

- `UPLOAD_CONFIG_DEFAULTS` 只含 3 个保留键（GET 只下发这 3 个默认值）；
- `UPLOAD_LEGACY_KEYS` 仍参与 `validate_config_value`，旧客户端 PUT 不报错、但运行时不读取；
- 旧库中已有的遗留键行保留、不删除（不在发布时触发结构/数据变更）。

## 2. 清理入口语义拆分

| 入口 | 函数 | 开关关闭时 |
| --- | --- | --- |
| 定时任务（`_upload_cleanup_loop`） | `run_auto_cleanup(db)` | 跳过，返回 `enabled=false` |
| 管理员「立即清理」（`POST /api/v1/config/cleanup`） | `run_cleanup(db)` | **仍执行**，返回 `enabled=true` + 统计 |

清理目标不变（安全硬约束 D31 保持）：上传会话与临时目录、旧 `.jflove-download` / 统一根 `offline/`
任务目录、合并残留 `.jflove-*.part`；只删程序自产、固定命名、位于允许根内的对象。

## 3. 三端 UI

| 元素 | 形态 |
| --- | --- |
| 卡片标题 | 存储与临时文件 |
| 说明 | 清什么 + 期限含义 + 关闭后仍可手动清理 + 不删正常文件（三端同一份文案） |
| 开关 | 自动清理临时文件 |
| 数字项 1 | 临时文件期限（小时）1~168 |
| 数字项 2 | 清理检查间隔（分钟）5~1440 |
| 按钮 | 保存（仅写 2 个数字项）/ 立即清理 |
| 删除 | 客户端类型多选（含「未知」）、孤儿保留期、会话上限、合并/分片并发、弱服务端模式 |

文案基线（三端逐字一致，仅手势词按平台写「右键」/「长按」）：

> 自动清理程序自产的临时文件（上传分片与会话残留、离线下载残缺目录、合并残留）。临时文件期限同时决定断点续传有效期与清理保护期；到期后安全删除，客户端下次从头上传。关闭自动清理后，「立即清理」仍可手动执行一次。只删除程序自产、固定命名的文件，不会动你的正常文件。

「离线媒体修复」说明（App 对齐桌面/Web）：

> 损坏媒体经「修复中心」手动离线修复（在文件管理中长按文件选「修复损坏媒体」发起）。并发数 1~8，或留空按服务器 CPU 核数自动推导。配置存于服务端、三端共享，修改后立即生效。

## 4. 安全

- 无新增接口、无新增路径参数、加密信封与鉴权不变（§9 安全宪法无触发点）；
- 删除配置项不改变清理的文件白名单与命名正则；「立即清理」仍要求管理员 JWT。
