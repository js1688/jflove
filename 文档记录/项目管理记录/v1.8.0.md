# JFLove v1.8.0 项目管理记录

> 版本目标：让服务端学会「自己上网取东西」——网址分析 → 可下载项清单 → 下载到**账号自己的**磁盘目录（三端可见）
> 范围：`jflove-server`（核心）+ `jflove-desktop` + `jflove-web` + `jflove-app`（只读）
> 管理角色：pmo（Phase 7）
> 前序交付：需求 / 设计 / 四端开发记录 / 代码审查 / 测试报告 / 人工体验（UAT）均已完成
> 发布方式：**真实发布**（用户 2026-10-22 裁决）→ 推 `main` + tag `v1.8.0`，由 GitHub Actions 构建并创建 Release

## 4. 关键决策与最终裁决

| 决策点 | 最终结论 | 推翻过程摘要 | 原因 | 生效位置 |
|---|---|---|---|---|
| **D9 存放位置归谁** | **每个账号一份自己的默认目录**，必须在该账号有 write 权限的磁盘；无可写磁盘 ⇒ 不可用 | 早期方案是「管理员配置一个全局共享目录」，2026-10-20 第 4 轮被推翻 | 全局目录等于管理员替所有人决定落点，且越权风险大 | 需求 §1.1 口径修订、§3.3；设计 §2.7；`offline_download_settings` |
| **D10 记录可见性** | 任务 / 清单 / 配置**一律按账号隔离**，管理员也看不到别人的；他人 `task_id` 一律 **404** | 初版只对 `media_repair_tasks` 隔离，本版扩展到离线下载三表 | 隐私默认值；404 优于 403（不泄露存在性） | 需求 §3.9；设计 §2.7；`test_task_list_and_detail_are_isolated` |
| **D11 总开关默认值** | **默认开启**；保留管理员应急关闭；**Web / 桌面 / 移动端「系统设置」三端都要有开关** | 原设计「默认关 + 仅后端配置」，UAT 问题 #1 暴露「三端都没 UI，用户无法开启」→ 2026-10-21 用户裁决翻转 | 开箱即用优先；熔断仍由管理员掌控 | 需求 §0.2 D11、§3.6；设计 §2.6.1；`OFFLINE_CONFIG_DEFAULTS`、三端 `AdminSystemPage` |
| **移动端能力范围** | **只读**（列表 / 详情 / 进度），不提供创建 / 勾选 / 取消 / 重试 | 讨论过「三端全功能」，用户 D6 口径定为只读 | 移动端创建流程（勾选 200 张图）体验差且成本高 | 需求 §1.4、F27.5；设计 §5 |
| **加密图片站点** | 不引入站点专用解密器；服务端如实报「图片内容无法识别（可能经过站点加密）」 | UAT 问题 #2 排查发现目标站点在前端 AES 解密图片 | 为单个站点写解密器＝不可维护的军备竞赛，且涉及内容合规灰区 | 后端记录 UAT #2；`content_invalid` 文案 |
| **解析器更新方式（I-6）** | **随服务端版本升级**，禁止运行时在线自更新 | 曾设想「解析器热更新」以应对站点改版 | 供应链风险：运行时拉代码＝远程执行入口 | 需求 §1.4、设计 I-6 |
| **UAT 构建方式** | `workflow_dispatch`（ref=`main`），**禁止打 tag** | — | `v*` tag 会触发 `release.yml` 建 Draft Release，等于提前进入 P8 | `文档记录/人工体验记录/v1.8.0.md` §2；LESSONS L58 |
| **UAT 期间版本号** | 三轮修复**不新开版本号**，仍 1.8.0，用 commit SHA 区分轮次 | — | 代码 BUG / 体验缺口不构成新版本 | UAT 记录 §2.1~§2.3 |
| **本期发布方式** | **真实发布**：本地不打包，push main → tag → CI 构建 + Draft Release | 备选「仅本地构建」被用户否决 | 产物与哈希以 CI 为准，便于追溯与开源分发 | 本文件 §11 |

> **废弃方案检索确认**：「管理员配置一个全局共享目录」只以「已被推翻 / 现行口径」形式出现在需求 §1.1 与本节；
> 「总开关默认关」在需求中已改为 D11 默认开启，代码 `OFFLINE_CONFIG_DEFAULTS`（`offline_download_service.py:1341`）已为 `"1"`，无 `"0"` 残留。

## 8. 与上一版本差异

| 维度 | v1.7.0 | v1.8.0 |
|---|---|---|
| 文件来源 | 只能由客户端上传 | **新增**服务端按网址主动抓取并落盘 |
| 服务端网络方向 | 仅被动接收 | **新增出站**（服务端 → 互联网），仅 `outbound_http` 可直接出网，逐跳 SSRF 复检 |
| 新增入口 | 无 | 桌面端 / Web 端「离线下载」页；移动端**只读**「离线下载中心」 |
| 数据库 | `media_repair_tasks` / `file_changes` 等 | **新增** `offline_download_tasks` / `offline_download_items` / `offline_download_settings` + 4 索引 |
| 配置 | 媒体修复开关 / 并发 / 重编码 | **新增**管理员级：总开关（默认开）/ 深度分析 / 并发 / 体积与项数上限；**账号级**：默认目录 |
| 依赖 | fastapi / aiofiles / imageio-ffmpeg | **新增**站点解析与媒体抓取依赖（含可选无头浏览器运行时，`WITH_BROWSER`） |
| 移动端 | 相册备份 | 相册备份（修复数量统计 / Wi-Fi 恢复即扫 / 去重）+ 离线下载只读 |
| UAT 反馈闭环 | — | 问题 #1（默认开 + 三端开关）、问题 #2（超时 / 图片污染）均修复并复验 |
