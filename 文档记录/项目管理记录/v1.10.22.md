## 下个版本候选台账

> 本节是技术债 / 下个版本候选的**唯一去处**（`AGENTS.md §8.3`）。每条带证据 + 建议 + 验收判据。

### T-1 终端输入「体感卡顿」的剩余差异未定位

- **证据**：
  - 用户真实桌面（Wayland + XWayland `:0`，DPR=2）实测 keydown → 画面 **6–25ms**、rAF 稳定 60fps，
    **无法复现秒级延迟**（`文档记录/测试报告/v1.10.22.md` §5）；
  - 同一探针在无合成器 Xvnc 上可复现 rAF **1.5fps** / 按键 **2~4 秒**（`§5.1`）。
- **判断**：本版已修掉两个**可量化**主因（粘贴两次、粘贴固定 500ms 白等）；
  但用户"输入卡顿"的其余部分可能来自其日常负载（多终端标签、TUI 刷新率、系统负载、GPU 合成路径）。
- **建议做法**：
  1. 在用户真实环境加**长时段采样**（≥10 分钟、含 dsh/TUI、多标签），落地一份
     `keydown → ws.send → 下行 → 画面` 四段耗时直方图；
  2. 对比"仅 1 标签 / 6 标签 / 大输出中"三档，确认是否存在随标签数线性增长的成本；
  3. 若确认是 xterm DOM 渲染开销，评估切换 `@xterm/addon-webgl`（当前项目只用 `xterm-dom-renderer`）。
- **验收判据**：真实桌面连续使用 ≥10 分钟，`input-latency` 探针 P95 < 50ms。

### T-2 `min-rows` 实机用例失败（存量）

- **证据**：
  ```
  FAIL min-rows —— 恢复窗口后未回到用户字号：{"dims":"135×26","font":"⌥ 字号 13→13（自适应）","warn":false}
  ```
  - `git stash` 回 HEAD `05187c9` 后同一用例**同样 FAIL**；
  - 仅移除 v1.10.22 新增的 `applyFit` 幂等守卫后**同样 FAIL**。
- **建议做法**：排查 `applyFit` 在"窗口由矮变高"时为何没有把字号还原
  （`lastFitKey` 随尺寸变化会变，理论上应重算 ⇒ 问题应在候选挑选或 `fit.fit()` 的取整）；
  并对 `readAutoFitRows()` 关闭分支补一条实机用例。
- **验收判据**：`node scripts/verify/desktop_terminal_e2e.mjs --only min-rows` 退出码 0。

### T-3 `copyText` 的浏览器路径在 QtWebEngine 上仍会白等 500ms

- **证据**：`ui/src/utils/clipboard.ts::copyText` 仍先 `writeThroughBridge`，
  失败才走浏览器 API + 500ms 超时；桌面端桥恒可用，**实践中走不到该分支**，
  但代码上这条"白等"路径没删。
- **建议做法**：与 `readClipboardText` 对齐——桥不可用才尝试浏览器 API。
- **验收判据**：单测覆盖"桥就绪时 `writeText` 一次都不被调用"。
