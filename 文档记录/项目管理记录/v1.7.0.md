## 4. 关键决策与最终裁决

| 决策点 | 最终结论 | 推翻过程摘要 | 原因 | 生效位置 |
|---|---|---|---|---|
| 是否做标准协议出口（WebDAV/SMB） | **不做**，只为自己客户端服务 | 最初设想"开放协议管理"，后确认与端到端加密冲突 | 保 E2E、不改安全宪法 | 需求 D1 |
| 本地缓存形态 | **明文落盘** | 讨论过"本地也加密" | 否则系统程序打不开 | 需求 D2 |
| 挂载粒度 | **目录级、多挂载点互不暴露** | — | 最小暴露面 | 需求 D3 |
| app 端范围 | **只做相册备份** | 讨论过"应用内云盘"，判定与文件管理重复后收回 | 移动端高频需求是相册 | 需求 D6 / D7 |
| Web 端范围 | **只删同步面板** | — | 该页本就不提供服务 | 需求 D8 |
| 版本拆分 | **全部进 v1.7.0** | 我方曾建议拆 v1.7.0 / v2.0.0，用户明确不拆 | 用户决策 | 需求 D9 |
| 系统级挂载（CfAPI） | **Windows 已实现并实测**；Linux FUSE 待换设备 | 设计阶段计划 CfAPI 优先；实现阶段先用 POC 验证三步判据（注册→占位→水合），再集成 `mount_vfs.py` | 先用探针排除结构体/参数陷阱，避免把未验证的驱动塞进应用 | 审查 S-2 / 本文 R-1 |
| 占位创建路线 | **真实文件 → `CfConvertToPlaceholder(DEHYDRATE)`**（非 `CfCreatePlaceholders`） | `CfCreatePlaceholders` 在本机持续返回 `ERROR_CLOUD_FILE_INVALID_REQUEST`，改用 Convert 路线一次通过 | 少踩参数坑，且官方推荐等价 | `mount_vfs.py::add_file` |

### 10.2 Fedora 上继续的步骤

1. **环境**：装 Python 3.14 + `venv-linux`、Flutter（`FLUTTER_HOME`）、Node/pnpm；`pip install -r requirements.txt`。
2. **先跑门禁**：`python scripts/sync_version.py --check`、`python scripts/check_db_schema.py`（退出码必须 0）、`pytest`（server / desktop）。
3. **Linux FUSE（BL-1）**：
   - 新增 `LinuxFuseMount`（`fusepy` 或 `pyfuse3`），与 `WinCfapiMount` 同级；
   - 接 `mount_sync_service.enable_vfs` / `sync_placeholders`，上层不改；
   - 判据：FUSE 挂载目录读取未缓存文件 → 触发下载 → 内容与远端一致。
4. **移动端（BL-4）**：`python build.py -m app` 出 APK → 真机开相册备份 → 拍照 → 传输页出现任务、远端出现文件；再补 `workmanager` 周期任务。
5. **服务端联调**：本地 `uvicorn` 或 Docker 起 v1.7.0，三端连同一实例。
6. **发布**：确认后按 `AGENTS.md §7.3 Phase 8` 选「真实发布」（打 tag 走 CI）或继续本地构建。
