## 1. 本版本的流程缺口（用户发现，必须先记下来）

v1.10.8 首轮交付（提交 `677cb0a`）**漏了两个强制节点**：

| # | 缺口 | 后果 | 违反的规则 |
| --- | --- | --- | --- |
| G1 | **没写 PMO 记录**（Phase 7 整个跳过） | 版本范围/任务/风险没有台账，事后无法复盘 | `AGENTS.md §7.1`（Phase 7 必过）、§7.5.3（快速通道只允许跳 1/2/7，且这里的"跳 7"从未被批准） |

| G3 | **Windows 以"本地构建不出安装包"为由跳过** | 用户明确要求"拉 CI 产物下来验证，有问题继续修"——本轮没有做 | 验证标准 §5 `desktop-windows` 行 + §9（跳过只认 probe/命令输出） |

**根因（流程层，不是技术层）**：Phase 8 第 0 步写的是"**先问用户**：真实发布 or 仅本地构建"。
无人值守时"问不到"，就默认降级成"仅本地构建"，把一条**不可跳过的验收链**（tag → CI → Windows 真机）
降级成了"本地跑通就算发布"。§7.5.3 的快速修复通道又允许"跳过 Phase 7"，进一步放大了这个洞。

## 4. 决策与风险

| 决策点 | 结论 | 说明 |
|---|---|---|
| 版本号 | 1.10.8（递增而非复用 1.10.7） | 必须重新出包，版本号要能区分旧包/新包 |
| 回放历史输出 | **不做** | 真机证伪：回放会触发终端应答 TUI 查询，污染 shell |
| 默认快捷键 | `smart` | Ctrl+C 在终端里必须能中断（安全） |
| 默认行数 | 22 → 24 行 | dsh TUI 在 ≤21 行会画丢输入框内容行（tmux 交叉复现） |
| Windows 验证口径 | **必须用 CI 当前 tag 安装包** | 本地构建不出 Windows 包；用旧包/缓存包一律无效（验证标准 §4） |

风险台账：

| 风险 | 影响 | 缓解 |
|---|---|---|
| CI 构建失败（Windows/Linux） | 无发布产物 | 看 run 日志逐项修；不修改版本来"绕过" |
| Draft Release 资产是草稿态（需鉴权下载） | Windows e2e 无法直连 Release URL | 用 API 下载资产 → 本机 http 服务 → `URL=` 注入 |
| VM 启动/网络异常 | Windows 无法验证 | `vm-win.sh status`/`shot` 取证；如实记"未覆盖（原因）"，不冒充通过 |
| 真机暴露新 BUG | 需要再出包 | 按 §7.5.3 修复 → 递增版本 → 重新 tag；**不移动已发布 tag** |
