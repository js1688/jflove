## 7. 流程改进建议（可执行，供后续版本落地）

1. **测试数字必须可复现**：报告里的"N passed"只能来自**仓库内可执行命令**或 **CI 日志**；发布/测试报告开头加一条"证据可复现声明"（文件存在 + 命令 + 退出码）。
2. **引用上一版"已修/已通过"前先验证**：确认该用例文件真实存在且能跑（文件存在 + 退出码双重判据），否则按"未修"处理。
3. **关键行为结论以代码行号为唯一判据**：本轮出现过两名子代理对同一段代码描述**方向相反**（全屏恢复分支是否尊重 `visible=false`），最终靠 `media_overlay.py:323-343` 行号裁决 + 就地更正文档。
4. **门禁必须自带反向验证并接入 CI**：`--self-test` 已成为两个门禁的标配（本轮修掉 M-1/M-2 后新增）；本版本已接入 `ci-guards.yml`。
5. **"改文档 ≠ 改代码"**：任何"已修"结论必须同时给出**代码位置 + 可执行的失败用例**，禁止只写结论。
6. **真机项显式挂账**：无头环境无法验证的像素/几何项，一律列成清单并标注"未验证"，不得用 DOM 断言冒充。
7. **写仓库配置文件不要用 PowerShell 的 `Set-Content -Encoding utf8`**：本轮编排者在预览版本号时被它写进 **UTF-8 BOM**，`sync_version.py` 当场 `JSONDecodeError: Unexpected UTF-8 BOM`（`version.json` 首字节 `EF BB BF`）。已用 `UTF8Encoding($false)` 修复并 `git checkout` 恢复到与 HEAD 逐字节一致。
   → 规则：**JSON/配置一律用 Python 写**（`Path.write_text(json.dumps(..., separators=(',',':')), encoding='utf-8')`），或显式 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`；改完用 `前 4 字节 == 7B 22` 自检（与 `LESSONS.md` L42「子进程/编码必须显式指定」同源）。

### 9.4 一个环境性观察（不是构建失败）

两次真实构建作业（`-m all` 与 `-m desktop`）的**外层作业退出码都是 1**，但：

- 构建脚本自身的成功路径实测退出码为 **0**（用假模块走通 `build.py::main()` 诊断：`main() 正常返回，退出码 = 0`）；
- 两个作业的汇总都打印 `[ok] … 成功`，且产物齐全、内容已逐项验证；
- 对照探针：stderr 噪声（小 / 1.7 MB 大 / 带 `2>&1`）三组均返回 **0**。

⇒ 与本环境"**Windows 下被强制清理的进程树会呈现 `exit code: 1`（无信号标记），应视为中断而非命令失败**"一致；这两次恰好是派生大量子进程（PyInstaller / Gradle / Flutter）的构建。
**处置**：不以外层退出码判定构建成败，改用**产物存在性 + 包内内容 + sha256** 作为判据（已在 §9.1 执行）。
