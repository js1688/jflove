# v1.1.1 项目管理记录

## 一、版本目标与范围概述

**版本目标**：修复桌面端"会话频繁过期"体验问题，分别处理两类 401（JWT 过期 / ECDH 加密会话失效）。

**用户痛点**：在线预览视频时频繁弹出"会话已过期"，被强制踢回登录页，无法持续使用。

**根因（v1.1.0 已存在但未暴露）**：

1. JWT 默认 1 小时硬编码，到期没有续期逻辑，定时器一发现过期就直接弹窗 + 退出登录；
2. 服务端 `_session_store` 重启即清空，但客户端不会自动重新做密钥交换；
3. `http_client` 对 401 没有自动恢复能力，所有 401 都直接抛 `ApiError` → UI 表现为"会话过期"。

**范围**：

- 桌面端 `jflove-desktop`（核心改动）
  - JWT 过期时间在登录界面提供 UI 配置项，默认仍为 1 小时；超时严格踢出，确保只产生一次"过期"提示与一个登录窗口；
  - ECDH 会话失效时自动重新交换密钥并透明重试当前请求，用户无感知（含视频流）；
  - HTTP 401 分类处理：JWT 类直接登出，ECDH 类自动续。
- 服务端 `jflove-server`：**评估后无需改动**（refresh / key-exchange 接口在 v1.1.0 已就绪；JWT 1h 默认值已满足）。
- 数据库：无表结构变更。

**版本策略**：补丁版本（PATCH），桌面端单端升级即可，服务端二进制不动。

## 四、风险与应对

| 风险 | 影响 | 状态 | 处置结果 |
|---|---|---|---|
| ECDH 自动续约与并发请求竞争（多线程同时拿到 401） | 重复 key-exchange 浪费请求 | ✅ 已闭环 | `HttpClient._try_resync_ecdh` 用 `Lock + Condition` 实现单飞；testing 5 线程并发用例验证仅触发 1 次实际续约 |
| JWT 自动续期被误开启会引入"长期 token"风险 | 违反 §9.2 | 🛡️ 决策落定 | 全程不做 JWT 自动续期；到期 = 退出登录；用户登录有效期 UI 配置满足体验诉求 |
| 视频流式接口（StreamProxy 长连接）期间发生 ECDH 失效 | 视频突然中断 | ✅ 已闭环 | `stream_request` 走 `_send_with_auto_resync`；续约后 FFmpeg 下次 Range 自然恢复，仅 ≤2s 卡顿 |
| 弹窗与登录窗口重复出现（两次过期检测、两个登录进程） | 体验问题，用户明确反馈 | ✅ 已闭环 | `MainWindow._logout_in_flight` 在 `MessageBox.exec()` 之前抢占；`main.py` 单实例切换；testing 2 用例验证 |
| 改动点位于鉴权 + 加密信封链路，回归风险高 | 核心链路 | ✅ 已闭环 | 测试报告 §四：安全 5 大类共 25+ 用例全部通过；服务端 0 改动，二进制完全兼容 |
