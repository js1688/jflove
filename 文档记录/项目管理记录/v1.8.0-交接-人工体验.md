## 4. UAT 问题 #1（待修）

### 4.1 现象与根因

- 现象：Web「离线下载 → 新建任务」红色提示 **“离线下载功能已关闭 / 管理员尚未开启”**；
  管理员进「系统设置」只看到「离线媒体修复」，**没有离线下载开关**。
- 根因：
  1. 需求/设计规定 `offline_download_enabled` **默认关**、管理员级；
  2. 后端有该配置键、`GET/PUT /api/v1/config` 和默认值，但 **Web / 桌面 / 移动三端都没有配置 UI**；
  3. 全新部署（无该 config 行）走默认 `0`，用户无从开启，只能改库或直接调加密接口。
- 结论：**不是代码写错，而是需求默认值不合理 + 管理端配置 UI 缺失**。

### 4.2 用户裁决（2026-10-21 18:06）

- **默认开启**（开箱即用，谁都能用）；
- 保留管理员**应急关闭**能力；
- **Web + 桌面 + 移动端** 三端管理端都要有该配置。

### 4.5 实现要点

1. **后端默认改 1** 只影响“从未写过该键”的库；已有 `0` 行仍保持关闭（尊重显式配置）。
2. 三端 UI 读 `GET /api/v1/config`（管理员），未落库的键用后端默认值（`OFFLINE_CONFIG_DEFAULTS`）。
3. 开关保存走现有 `updateConfig`（加密 PUT，管理员校验不变）；保存后**立即生效**，无需重启。
4. 三端入口文案保持不变：真被管理员关闭时，离线页仍显示原提示（AC-200 语义保留）。
5. 需求/设计文档同步：默认值 `关 → 开`，并写明“管理端系统设置可应急关闭”。
