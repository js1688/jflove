## 三、涉及文件与改动详情

### 3.1 `src/config/settings.py`

**修改前**：

```python
JWT_EXPIRE_DEFAULT_SECONDS = 3600   # 1 小时
JWT_EXPIRE_MAX_SECONDS = 28800       # 8 小时

```

**修改后**：
```python
JWT_EXPIRE_DEFAULT_SECONDS = 86400   # 1 天
JWT_EXPIRE_MAX_SECONDS = 2592000     # 30 天
JWT_EXPIRE_MIN_SECONDS = 60
```

### 3.2 `src/services/file_service.py`

#### 3.2.1 `rename_file()` — 补 `_safe_join` 校验

原实现中，`rename_file` 先校验 `new_name`，再调用 `_safe_join` 组装路径，但对 `path` 参数本身缺少 `_safe_join` 校验。v1.1.4 补上：

```python
# 新增：路径穿越防护
src_abs = _safe_join(base_dir, path)
```

其中 `_safe_join` 在路径不存在时返回 `None`，后续逻辑将其当作「不存在」处理，与 `move_file` 保持一致。

#### 3.2.2 `move_file()` — 抛 `FileNotFoundError`

原实现中，`_safe_join` 返回 `None` 后统一走 `ValueError`：

```python
if not src_abs:
    raise ValueError("源路径不存在")
```

修改为：

```python
if not src_abs:
    raise FileNotFoundError("源路径不存在")
```

`FileNotFoundError` 在控制器层单独捕获并映射为 404：

```python
except FileNotFoundError as e:
    raise HTTPException(status_code=404, detail=str(e))
```

其他 `ValueError`（空名称、非法字符、循环嵌套等）仍映射为 400。

### 3.3 `src/controllers/file_controller.py`

## 五、关键设计思路与取舍

### 5.1 默认 TTL 改为 1 天而非 7 天

桌面端登录界面新增三个选项：「1 天」「7 天」「30 天」。默认勾选 7 天，但客户端不传 `requested_ttl_seconds` 时，服务端走 `JWT_EXPIRE_DEFAULT_SECONDS = 86400`（1 天）。原因：

- 向后兼容老客户端（v1.1.3 及之前版本），它们不传此字段且安全策略上预期较短有效期；
- 如果老客户端更新到 v1.1.4 服务端但不传 TTL，默认值从 1 小时变为 1 天仍是合理让步；
- 客户端勾选/传参后才升级到 7 天选项。

### 5.2 `FileNotFoundError` vs `ValueError` 的分层

| 异常 | 场景 | HTTP 状态码 | 语义 |
|---|---|---|---|
| `ValueError` | 空名称、非法字符、循环嵌套 | 400 | 参数格式错误 |
| `FileNotFoundError` | `_safe_join` 返回 None（路径不存在） | 404 | 资源不存在 |
| `PermissionError` | 无写权限 | 403 | 权限不足 |
| `FileExistsError` | 目标名称已存在 | 409 | 资源冲突 |

这种分层使 API 的 HTTP 语义更准确，也方便客户端侧根据状态码精准提示用户。

### 5.3 不引入新的配置项

原有 `JWT_EXPIRE_DEFAULT_SECONDS` / `JWT_EXPIRE_MAX_SECONDS` / `JWT_EXPIRE_MIN_SECONDS` 三个常量的语义足够表达「按天选项」的需求，仅修改值即可。不新增 `JWT_EXPIRE_OPTIONS` 等字典配置，保持简单。
