# v1.1.2 后端开发记录

## 一、本次完成的功能与改动点

| # | 改动 | 文件 |
|---|---|---|

## 二、API 接口变更

### `POST /api/v1/auth/login`

| 字段 | v1.1.1 之前 | v1.1.2 |
|---|---|---|
| 请求 `username` | 必填 string | 必填 string（不变） |
| 请求 `password` | 必填 string | 必填 string（不变） |
| 请求 `requested_ttl_seconds` | — | **新增可选 int**：客户端请求的 JWT 有效期（秒）；服务端 clamp 到 [60, 28800]；缺失/非法时使用默认 3600 |
| 响应 `token` | string | string（不变） |
| 响应 `role` / `username` / `user_id` | 不变 | 不变 |
| 响应 `expires_in` | — | **新增 int**：本次签发的实际 TTL（clamp 后的真实秒数） |

按设计文档 §4.1 安全宪法 4 项标注：

| 项 | 值 |
|---|---|
| 是否在明文白名单 | 否（仍走加密信封） |
| 路径参数归属/角色校验 | 无路径参数 |
| 加密信封策略 | 普通 JSON ChaCha20-Poly1305；错误响应也加密（沿用全局 handler） |
| 错误响应 | `HTTPException` 抛出，由 `main.py` 全局 handler 加密 |

### 其他接口

- `/api/v1/auth/refresh`：行为不变（仍按默认 1h 签发新 token）；调用方改造为接收 `create_token` 新返回值
- 其他业务接口（files / notes / sync 等）：完全不动

## 七、与上一版本（v1.1.0 服务端基线）的差异

| 项 | v1.1.0 | v1.1.2 |
|---|---|---|
| OpenAPI 版本 | 1.1.0 | 1.1.2 |
| `JWT_EXPIRE_HOURS` | 直接控制签发 | 派生常量，实际签发由 `JWT_EXPIRE_DEFAULT_SECONDS` 等三个常量控制 |
| `create_token` 签名 | 3 参数，返回 token | 4 参数（含 ttl_seconds），返回 (token, effective_ttl) |
| `auth_service.login` 签名 | 4 参数 | 5 参数（含 requested_ttl_seconds） |
| `/login` 请求字段 | username / password | + requested_ttl_seconds（可选） |
| `/login` 响应字段 | token / role / username / user_id | + expires_in |
| 数据库 / 加密协议 / 帧格式 | — | 完全不变 |

向后兼容性：
- v1.1.1 桌面端连 v1.1.2 服务端：客户端不带 `requested_ttl_seconds` → 服务端走默认 1h
- v1.1.0 桌面端连 v1.1.2 服务端：同上
