## 2. 修改前后逻辑对比

### 2.1 F36 合并

**修改前**（v1.8.1）：

```python
if protocol == "m3u8":      # 播放列表自带音轨
elif protocol == "mpd_segments":  # 用 variant_id 的 | 后半段合并
else:                        # 直链：只下 source_url ⇒ 无音轨
```

**修改后**：

```python
needs_aux = kind == "video" and aux_url and protocol not in ("m3u8", "mpd_segments")
if needs_aux:
    video = 下载主轨（直链/HLS/DASH）
    audio = _fetch_aux_audio(aux_url)   # 后缀 .m3u8/.mpd/直链
    ffmpeg -protocol_whitelist file,crypto -i video -i audio \
           -map 0:v:0 -map 1:a:0 -c copy -y merged_av.mp4
    ffprobe 断言 audio + video，否则 merge_failed
```

- 进度：主轨字节上报后，音轨按「主轨已完成 + 音轨」累计。
- 临时文件仍在 `.jflove-download/<task_id>/`，成功后 `os.replace`。
- 产物文件名用 `mp4` 扩展（`_final_name` 传入覆盖 ext），避免 `m4a` 命名。

### 2.2 F37 超时

| 项 | 修改前 | 修改后 |
|---|---|---|
| 解析总预算 | 30s 硬编码，不可配 | 默认 90s；`offline_download_analyze_timeout_s`（30–180） |
| 连接/读取 | 10s / 30s 硬编码 | 默认 15s / 60s；两个 config 键（5–30 / 15–120） |
| 解析重试 | 无 | `net_timeout` / `network_error` 且耗时 < 50% 预算 ⇒ 退避 2s 重试 1 次 |
| 超时结果 | 全部丢弃，任务 failed | 已抓到的清单项落库并 `ready`（`level=partial` + warning）；一项都没有才 failed |
| 文案 | 「分析总预算超时」 | 「解析超时（Ns），可稍后重试或让管理员调大解析超时」 |

**实现边界（如实记录）**：超时发生在 L1/L2 并发等待期间（两者都未返回）时没有可保留的项，仍按失败处理；要覆盖该段需改逐任务 `asyncio.wait`，列入后续增强。

### 2.3 C1

`list_server_dirs` 返回 `limit: SERVER_DIR_LIMIT`；`truncated` 语义不变。

## 7. 安全自查（§9.7）

- 无新增路径参数；无新增明文白名单；
- `aux_url` 下载仍经 `OutboundClient`（SSRF/重定向校验），ffmpeg 只读本地文件且带 `-protocol_whitelist file,crypto`；
- 新增配置仅管理员可写，越权 403；
- 日志只记 `task_id` / 错误码，不记录 URL/路径/文件名；
- 未引入新算法/密钥/KDF。
