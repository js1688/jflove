## 2. 数据库

### 2.1 DDL

```sql
CREATE TABLE IF NOT EXISTS file_changes (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    disk_id      INTEGER NOT NULL,
    rel_path     TEXT    NOT NULL,
    op           TEXT    NOT NULL,              -- upsert / delete
    is_dir       INTEGER NOT NULL DEFAULT 0,
    size         INTEGER NOT NULL DEFAULT 0,
    mtime        REAL    NOT NULL DEFAULT 0,
    content_hash TEXT    NOT NULL DEFAULT '',
    created_at   TEXT    NOT NULL,
    updated_at   TEXT    NOT NULL,
    deleted_at   TEXT
);
CREATE INDEX IF NOT EXISTS file_changes_disk_id_idx ON file_changes(disk_id);
CREATE INDEX IF NOT EXISTS file_changes_rel_path_idx ON file_changes(rel_path);
```

**为什么没有唯一索引**：同一路径允许多条历史记录（append-only 日志）。若加唯一索引，
就会与 `AGENTS.md §5.2` 的软删除约定冲突（见 `backend/SKILL.md`「数据库变更硬约束」第 1 条）。

## 3. 接口

### 3.1 `POST /api/v1/files/journal`

拉取增量变更。

- 明文白名单：否；加密：`decrypt_request_body` + `encrypt_response`
- 鉴权：JWT（body `token`）+ `check_disk_permission(read)`；admin 免检
- 路径参数：无（`disk_id` / `prefix` 均在加密 body）

请求：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `token` | string | 是 | JWT |
| `disk_id` | int | 是 | 虚拟磁盘 ID |
| `prefix` | string | 否 | 子目录前缀（空 = 根） |
| `since_rev` | int | 否 | 上次最大 rev（默认 0） |
| `limit` | int | 否 | 默认 500，最大 2000 |

响应：

| 字段 | 类型 | 说明 |
|---|---|---|
| `changes` | array | `rev` / `path` / `op` / `is_dir` / `size` / `mtime` / `hash` |
| `latest_rev` | int | 本次最大 rev |
| `has_more` | bool | 是否还有更多 |
| `reset_required` | bool | 为真时客户端应改走全量对账 |

### 3.2 `POST /api/v1/files/scan`

全量对账（只 stat，不读内容），分页。

- 请求：`disk_id` / `prefix` / `cursor` / `limit`（默认 2000，最大 5000）
- 响应：`entries[]`（`path` / `is_dir` / `size` / `mtime`）/ `next_cursor` / `has_more` / `latest_rev`
- 鉴权与加密同 3.1

### 3.3 兼容性

- `POST /api/v1/sync/snapshot` **保留**（过渡期），本版未改动其行为。
- `complete_upload(upload_id, db=None)` 的 `db` 为可选参数：不传时与旧版行为完全一致。

## 4. 关键取舍

| 取舍 | 结论 | 理由 |
|---|---|---|
| `rev` 语义 | 用 `file_changes.id`（全局单调） | 客户端只记一个整数；AUTOINCREMENT 删除不回收号 |
| 前缀匹配 | `substr(rel_path, 1, n) = prefix + '/'` | 大小写敏感、边界精确，`photos` 不会误匹配 `photos2` |
| 范围隔离 | SQL 过滤 + Python 二次断言 | 防御深度（AC-112） |
| journal 写失败 | 只记 warning，不影响主操作 | 文件已落盘，日志失败不能回滚用户操作 |
| 清理策略 | 保留最近 10 万条（由调用方传参） | 防表无限增长；老游标失效时用 `reset_required` 兜底 |
| 分片清理 | 24h + 不在内存会话 | 服务重启后内存会话丢失，残留目录需回收 |
| 目录删除 | 删除前先 `_collect_tree` | 删除后无法再遍历，必须提前收集 |
