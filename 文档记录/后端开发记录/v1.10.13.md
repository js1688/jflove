# 后端 v1.10.13（远程连接凭据清空语义）

> 分类：**接口语义补齐**（配合桌面端 v1.10.13「凭据清空」）
> 来源：用户反馈「密码填错后无法清空；留空 = 不修改」
> 范围：仅 `jflove-server/`；无新增表/列/DDL，无接口新增（沿用 `/api/v1/ssh/connections/update`）

## 1. 问题与根因

`ssh_service.update_connection` 旧语义：

- `password` / `private_key` / `passphrase` 缺省或空串 = **不修改**；
- `clear_password` / `clear_private_key` 已支持，但桌面端表单从未发送；
- **口令单独修改/清空没有通道**：只有在提交了新私钥时才写 `passphrase`，用户把「私钥口令」填错了也改不回来。

## 2. 本版改动

| 字段 | 语义 |
| --- | --- |
| `clear_password` | 写 `password = ""`（保持不变） |
| `clear_private_key` | 写 `private_key = ""` 且 `passphrase = ""`（保持不变） |
| `clear_passphrase`（新增） | 只写 `passphrase = ""`，保留私钥 |
| `passphrase`（非空） | 未提交新私钥时允许单独更新口令 |
| 新私钥 + `clear_passphrase` | 口令写空（清空优先） |
| 不传任何 `clear_*` 且凭据为空 | 仍表示「不修改」（旧客户端/旧表单不回归） |

实现位置：`src/services/ssh_service.py::update_connection`。

## 3. 测试

新增 `tests/test_ssh_clear_credentials_v1_10_13.py`（5 条）：

1. `clear_password` 后 `password == ""`，其它凭据不变；
2. `clear_private_key` 后私钥与口令都为空；
3. `clear_passphrase` 后口令为空、私钥保留；
4. 只提交 `passphrase` 时口令单独更新；
5. 不传 `clear_*` 时空串仍不修改（旧语义不回归）。

全量：`jflove-server/venv-linux/bin/python -m pytest tests/ -q` → **467 passed, 48 skipped**；
`flake8 src/ tests/ --max-line-length=99` → 退出码 0。

## 4. 兼容性与安全

- 向后兼容：旧客户端不传清空标志时行为不变。
- 没有新增路由/鉴权路径；凭据仍按账号隔离，清空只写当前 `user_id` 的记录。
- 响应/日志不输出凭据原文；`clear_*` 只影响目标列。
