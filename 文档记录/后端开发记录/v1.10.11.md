# v1.10.11 后端开发记录：远程连接新增「密码 + 密钥」双因素认证方式

> 版本：v1.10.11　角色：backend　类型：**功能缺口修复**（`AGENTS.md §7.5`）
> 触发：用户实测反馈（2026-11-17）——网关需要「登录密码 + 私钥 + 私钥口令」同时生效
> 影响模块：仅 `jflove-server/src/services/ssh_service.py` 与对应单测；**无数据库 DDL**

## 1. 背景

v1.10.0 的远程连接只支持三种认证方式：`password` / `publickey` / `password_keyboard`。
用户实际使用的网关（WinSCP 配置）是「用户名 + 登录密码 + 私钥文件 + 私钥口令」，
属于 SSH 双因素认证（`AuthenticationMethods publickey,password` 或 `password,publickey`），
现有模型无法表达，客户端也就无法把两道口令一起用上。

服务端只做**配置存档**，不建立 SSH 连接（`文档记录/设计文档/v1.10.0.md` §2.3），
因此本版只需放开认证方式取值并补齐新建校验。

## 2. 改动

`src/services/ssh_service.py`：

1. `AUTH_TYPES` 增加 `password_publickey`：

   ```python
   AUTH_TYPES = ("password", "publickey", "password_keyboard", "password_publickey")
   ```

2. `normalize()` 新建校验：
   - `password_publickey` 必须同时提供密码与私钥；
   - `publickey` 仍只要求私钥；
   - `password` / `password_keyboard` 仍只要求密码。

3. `auth_type` 在数据库里是 `TEXT NOT NULL DEFAULT 'password'`，**无 CHECK 约束**：
   本版无表结构变更、无迁移脚本、无生产库对齐动作。

## 3. 接口契约

| 字段 | 说明 |
| --- | --- |
| `auth_type` | 新增取值 `password_publickey`；旧值语义不变 |
| `password` | 登录密码；`password_publickey` 时必填（新建） |
| `private_key` | 私钥文本。桌面端「选择文件…」时由 Python 读取文件内容后提交，服务端只存字符串、不解析；`password_publickey` 时必填（新建） |
| `passphrase` | 私钥口令；可为空（私钥未加密时） |

凭据仍按 D37 明文列存储、不返回列表接口；`connections/get` 才返回原文，安全口径未变。

## 5. 兼容性

- 旧客户端不认识 `password_publickey` 时无法创建该类型，但读取旧类型不受影响；
- 新客户端读旧配置：`publickey` + 已存在密码时，客户端会按双因素尝试（见桌面端开发记录 §2.2）；
  旧配置若存的是本机路径，桌面端仍做兼容解析，但**新保存的连接只存内容**；
- App 端本轮未同步支持（模块边界），桌面端配置的该类型在 App 端会按密码方式失败。
