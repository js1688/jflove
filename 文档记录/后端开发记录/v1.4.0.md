# v1.4.0 后端开发记录：媒体修复服务（损坏/非流式媒体在线播放）

## 二、详细变更

### 2.1 `src/utils/media_probe.py`（新增）

- `get_ffmpeg_exe()`：懒加载 imageio-ffmpeg 内置二进制；不可用时返回 None（调用方降级为不修复）。
- `probe_media(file_path)`：用 `ffmpeg -hide_banner -i` 解析 stderr，返回 `{available, has_stream, duration_ok, fatal}`（**无 ffprobe**，故用 ffmpeg -i 探测）。
- `_moov_at_front(file_path)`：解析 MP4 头部 box 结构——首个非 `ftyp` box 为 `moov` → 可流式；为 `mdat` → moov 在尾部，需修复（避免"小文件读全导致 b'moov' 必命中"的误判）。
- `is_mse_friendly` / `needs_repair` / `is_repair_supported_extension`：按扩展名分类 + probe 结果判定。

### 2.2 `src/services/media_repair_service.py`（新增）

- `is_repair_enabled` / `is_transcode_enabled` / `get_concurrent_limit`：读 `config` 表（经 config_service 内存缓存，写后立即生效）。
- `ensure_playable(db, file_path, filename)`：返回播放模式：
  - 开关关 / ffmpeg 不可用 / 健康文件 → `{"mode": "byte"}`（原文件字节 range，零处理）
  - 需修复媒体（有音/视频流）→ `{"mode": "time"}`（ffmpeg 管道）
  - **非媒体文件**（非媒体扩展名且无流）→ `{"mode": "byte"}`（修复开关不影响普通文件下载/预览）
  - 媒体扩展名但无法解析 → `{"mode": "error"}`（415，提示下载）
- `stream_repaired_frames(...)`：异步生成器，帧 0 = meta（`stream_mode="time"`），随后启动 ffmpeg `-c copy` 重封装 fMP4 → stdout 管道 → 逐块 `encrypt_stream_chunk` 加密。`-c copy` 启动即失败且允许转码时降级重编码。
- **动态并发**：整数计数 + 50ms 轮询（`asyncio.Semaphore` 值不可改、`Condition` 需 await 不适用于生成器 finally，故用同步计数）；每次获取读最新上限 → 配置变更立即生效。
- **进程回收**：`_kill_proc_sync`（同步 kill，可在 GeneratorExit 中调用）+ `_reap_proc`（正常路径 wait）；无输出超时强制终止。

### 2.3 `src/controllers/file_controller.py`（修改）

`stream_file` 在权限/路径校验后插入 `ensure_playable` 决策：

```
修复前：get_stream_range → _build_range_stream_generator（字节 range）→ 返回
修复后：get_stream_range → ensure_playable
        ├─ byte  → _build_range_stream_generator（原文件字节 range，行为不变）
        ├─ time  → stream_repaired_frames（ffmpeg 管道，时间 range）
        └─ error → 415 加密错误响应
```

- 请求体新增可选字段 `range_start_seconds`（修复流专用，秒）。
- meta 帧新增 `stream_mode: "byte" | "time"`（byte 模式沿用旧格式，无该字段时为默认 byte，向后兼容）。

### 2.4 `src/services/config_service.py`（修改）

```
修复前：get_all 每次读库
修复后：模块级 _cache 缓存全量配置；get(key, default) 读缓存；update 写库后 invalidate_cache()
```

`invalidate_cache()` 供测试复位；保证管理员 C 端改配置后下一次请求立即生效、无需重启。

## 四、关键设计取舍

| 决策 | 取舍说明 |
|------|---------|
| 不写盘管道直出 | ffmpeg `-f mp4 pipe:1`（frag_keyframe+empty_moov）stdout 管道；零磁盘占用，内存与文件大小无关；代价是修复流只能按**时间 range**（`-ss`），字节 range 失效 |
| ffmpeg 探测（无 ffprobe） | imageio-ffmpeg 仅内置 ffmpeg；改用 `ffmpeg -i` 解析 stderr 判断 has_stream/duration/fatal |
| 动态并发用"计数+轮询" | `Semaphore` 值不可改无法即时生效；`Condition` 在生成器 finally/GeneratorExit 中需 await 会报错；整数计数 + `asyncio.sleep(0.05)` 轮询在弱并发下开销可忽略 |
| 同步 kill + 异步 wait | 客户端中断（GeneratorExit）时 finally 只能同步操作；kill 确保无孤儿，asyncio child watcher 自动 waitpid 回收无僵尸 |
| 非媒体文件回退 byte | 修复开关只针对媒体；`.bin/.txt/.zip` 等无流文件在开关开启时仍走原文件流，避免影响普通下载/预览 |
| 无缓存、每次实时修复 | 服务器内存/磁盘有限（用户决策）；每次 seek 重新 `-ss` 修复，秒级可接受 |
