## 2. 为什么 #2 不是"后端补能力"

用户 issue #2 的原始诉求是"Web 端补上「允许重编码降级」开关"。核实服务端契约后确认：

- `jflove-server/src/config/settings.py:30` 仅**保留常量定义**（键不删）；
- `jflove-server/src/services/media_repair_service.py:11-13` 明确写明：`media_repair_enabled`（实时修复总开关）与
  `media_repair_allow_transcode`（重编码子开关）**任何代码不再读取**，播放与修复行为均不受其影响（v1.4.2 hotfix）。

即：**该开关在服务端已无对应行为**。因此若在 Web 端补开关，只会把两端一起对齐到一个失效交互上
（对照 `.agents/skills/lessons/LESSONS.md` L34：客户端之间的不一致会把错误互相传染）。
最终裁定（用户 2026-10-10 确认）为：**删除桌面端的僵尸开关**，以服务端契约为准收敛。
若将来要恢复"重编码降级"能力，那是一个**新功能**（需要独立需求 + 设计 + ffmpeg 降级链路），不在本版本范围。
