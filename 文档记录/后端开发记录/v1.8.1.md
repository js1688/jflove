## 2. 新增接口：`GET /api/v1/virtual-disks/server-dirs`（S2/S3）

### 2.1 用途与边界

添加 / 编辑虚拟磁盘时，「服务端真实路径」过去只能手输绝对路径（需求取证 E-6）。
磁盘此时**尚未创建**，无法复用「虚拟磁盘内子目录浏览」接口
（`GET /api/v1/virtual-disks/{disk_id}/browse`），因此新增一个**管理员只读**的服务器目录浏览接口。

硬边界（需求 I-2 / F35.3）：

- **仅管理员**：普通用户 403，无 token 401；
- **只列目录**：不返回文件名、文件内容、文件大小；
- **不跟随文件**：`entry.is_dir()` 过滤；隐藏目录（`.` 开头）不返回；
- **路径不进 URL 明文**：`token` / `path` 都在加密 query 信封里；
- **错误 detail 不回显完整路径**（`§9.4`）。

### 2.2 契约

| 项 | 内容 |
|---|---|
| 方法 / 路径 | `GET /api/v1/virtual-disks/server-dirs` |
| 鉴权 | 管理员（`_require_admin` → `auth_service.get_current_user` + `role == "admin"`） |
| 加密 | 请求：GET query 信封（`decrypt_request_body` 的 query 通道）；响应：`encrypt_response` |
| 明文白名单 | **不在** `main.py::_PLAIN_PATHS`（仅 `/health`、`/api/v1/auth/key-exchange`、`/api/v1/auth/admin-exists`） |
| 路径参数 | **无**（`path` 在加密 body 内） |

**请求字段**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `token` | string | 是 | 管理员 JWT 令牌 |
| `path` | string | 否 | 绝对路径；留空 = 取 `roots` 第一项 |

**响应字段**（加密信封内）

| 字段 | 类型 | 说明 |
|---|---|---|
| `path` | string | `os.path.normpath` 规范化后的当前绝对路径 |
| `parent` | string \| null | 上一级绝对路径；根目录 / Windows 盘符根为 `null` |
| `dirs` | array | `[{name, path}]`，按名称 `casefold()` 排序，最多 `SERVER_DIR_LIMIT = 2000` 条 |
| `roots` | array | `[{name, path}]`，本机常见起点，去重且只保留真实存在的目录 |
| `truncated` | bool | 子目录数超过上限时为 `true`（客户端提示「目录过多，请进入更具体的路径」） |

**roots 生成规则**（`_server_roots()`）

| 平台 | 候选起点 |
|---|---|
| POSIX | `/`、`/storage`、`/data`、`~` |
| Windows | 各存在的盘符根（`A:\` ~ `Z:\`）+ `~` |

- 统一 `os.path.normpath` + `os.path.normcase` 去重；不存在的目录不返回；
- 展示名取路径最后一段，根目录回退为路径本身（`/` → `/`）。

**错误码**

| 状态 | 场景 | detail |
|---|---|---|
| 401 | 缺少 / 无效令牌 | `get_current_user` 的中文提示 |
| 403 | 非管理员 | 「仅管理员可操作」 |
| 403 | 目录无权限（`PermissionError`） | 「无权限访问该目录」 |
| 400 | `path` 不是绝对路径 | 「路径必须是绝对路径」 |
| 404 | 目录不存在 | 「目录不存在」 |
| 404 | 一个 roots 都没有（极端环境，`path` 留空时） | 「没有可访问的目录」 |

> 403 的两种语义（非管理员 / 目录无权限）**故意保持同一个状态码、不同文案**，
> 不把「无权限」混成 404 —— 否则客户端会误判为「目录被删」而反复创建。

### 2.3 代码位置

| 文件 | 改动 |
|---|---|
| `jflove-server/src/services/virtual_disk_service.py` | 新增 `SERVER_DIR_LIMIT`、`ServerDirError`、`_server_roots()`、`list_server_dirs()` |
| `jflove-server/src/controllers/virtual_disk_controller.py` | 新增 `GET /server-dirs`（注册在 `/{disk_id}` 系列路由**之前**，避免被路径匹配吞掉） |
| `jflove-server/tests/test_virtual_disk_server_dirs_v1_8_1.py` | 新增 10 条单测 |

实现要点：

1. 路径先做 `os.path.isabs` 校验，再 `normpath`；`isdir` 校验存在性；
2. `os.scandir` 内逐项 `entry.is_dir()`；`OSError` 单项失败静默跳过，不中断整页；
3. 达到上限立即 `break` 并置 `truncated=True`（不先收集再截断，避免超大目录占内存）；
4. `PermissionError` 只包住 `scandir` 上下文，转 403；
5. 日志不打印 `path`（`§9.4` 第 14 条），controller 也不 echo 原始路径。

## 5. 安全自查（`AGENTS.md §9.7`）

- [x] **请求是否解密**：`_require_admin` → `decrypt_request_body`（query 通道）。

- [x] **是否返回文件流**：否。

- [x] **日志是否记录用户内容**：不记录 `path`。
- [x] **是否新增长期密钥 / 静态盐 / 写死对称密钥**：否。

## 6. 已知限制与后续

1. **管理员可见服务器目录结构**：仅在管理员权限下、且只列目录；管理员本就能注册任意磁盘路径，
   风险已在需求 R-2 / 设计 §10 记录，Phase 5 审查需复核。
2. **单次上限 2000 条**：超限只返回前 2000 条并置 `truncated`，客户端应提示进入更具体路径。
3. **不做路径白名单**：管理员可按需浏览任意可访问目录；不返回文件内容，故不构成读写越权。
4. **`server.sh smoke` 不含加密链路**：已在上文说明，Phase 6 用三端实机补齐。
