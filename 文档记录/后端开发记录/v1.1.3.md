## 三、涉及文件与改动详情

### 3.1 `src/services/file_service.py`

#### 3.1.1 `list_accessible_disks` — 新增 `can_write` 字段

**修改前**（返回 `{id, name}`）：
```python
return [{"id": d["id"], "name": d["name"]} for d in all_disks if d["id"] in readable]
```

**修改后**（返回 `{id, name, can_write}`）：
```python
perm_map = {p["virtual_disk_id"]: dict(p) for p in perms}
for d in all_disks:
    p = perm_map.get(d["id"])
    if p and p.get("can_read"):
        result.append({"id": d["id"], "name": d["name"],
                       "can_write": bool(p.get("can_write", False))})
```

> **关键细节**：`permission_repository.get_disk_permissions` 返回 `sqlite3.Row`，不支持 `.get()`，需先 `dict(p)` 转换。

#### 3.1.2 新增 `rename_file()`

```
入参: db, user_id, role, disk_id, path, new_name
校验顺序:
  1. write 权限（admin 跳过）
  2. new_name 非空、不含 / 或 \、不为 . 或 ..
  3. _safe_join(base, path) — 路径穿越防护
  4. target 必须存在
  5. 静默跳过：target == new_target
  6. FileExistsError：new_target 已存在 → 409（控制器层处理）
  7. os.rename(target, new_target)
日志: INFO "文件/目录已重命名: disk_id=xx"（不记录路径）
```

#### 3.1.3 新增 `move_file()`

```
入参: db, user_id, role, disk_id, src_path, dst_dir_path
校验顺序:
  1. write 权限（admin 跳过）
  2. _safe_join(base, src_path)、_safe_join(base, dst_dir_path) — 路径穿越防护
  3. src_abs 存在
  4. dst_dir_abs 存在且是目录
  5. 静默跳过：src_parent == dst_dir_abs（同一目录）
  6. 循环嵌套防护（仅 src 为目录时）：
     dst_dir_abs == src_abs 或 dst_dir_abs.startswith(src_abs + os.sep) → ValueError → 400
  7. 目标同名：os.path.exists(new_abs) → FileExistsError → 409（控制器层处理）
  8. os.rename(src_abs, new_abs)
日志: INFO "文件/目录已移动: disk_id=xx"（不记录路径）
```

### 3.2 `src/controllers/file_controller.py`

新增两个路由函数 `rename_file` 和 `move_file`，均遵循安全宪法：

- `body = await decrypt_request_body(request)` 解密入参
- 从 `body.get("token")` 取 JWT，不走 Authorization header

## 五、关键设计思路与取舍

### 5.1 `os.rename` 的原子性

在同一文件系统内，Linux/macOS 的 `os.rename` 是原子操作。由于虚拟磁盘要求在同一 Docker 挂载卷内操作，可以保证重命名和移动的原子性，无需引入临时文件或事务。

### 5.2 `FileExistsError` 与 `ValueError` 的分层

- `ValueError`：参数层面的错误（空名称、非法字符、路径不存在、循环嵌套）→ 400 Bad Request
- `FileExistsError`：业务层面的冲突（目标已存在）→ 409 Conflict

两种异常语义清晰，控制器层分别捕获并映射到合适的 HTTP 状态码。

### 5.3 `list_accessible_disks` 的 `sqlite3.Row` 问题

原函数使用集合推导 `{p["virtual_disk_id"] for p in perms if p["can_read"]}`，通过下标访问，不用 `.get()`，所以没有问题。新版需要同时读取 `can_read` 和 `can_write` 两个字段，改为 `dict(p)` 转换后再用 `.get()` 操作，向后安全。

### 5.4 移动同目录静默跳过

当 `src_parent == dst_dir_abs` 时，`os.rename(src, dst/name)` 实际等效于 `os.rename(src, src)`，即不做任何事。为了响应语义清晰，服务层提前判断并直接 return，不发起多余的系统调用。
