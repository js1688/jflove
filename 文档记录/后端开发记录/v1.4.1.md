# v1.4.1 后端开发记录：视频播放 BUG 修复

## 一、变更概述

服务端共修复 5 个问题：

| 编号 | 现象 | 根因 | 修复 |
|------|------|------|------|
| BUG-4 | TS 伪装 .mp4 无法 MSE 播放 | 源为 MPEG-TS 流，Chrome MSE 不识别 | ffmpeg 修复流 `-c:a aac` 强制转码音频 |
| BUG-5 | 修复后无声音 | mp4a 无 DecoderSpecificInfo | `_mp4a_codec` 回退 `mp4a.40.2` |
| BUG-6 | faststart MP4（moov 前置无 mvex）MSE 卡死 | faststart≠fMP4 | `_moov_at_front` 要求 mvex |
| BUG-8 | 初始播放间歇性失败（空 codec / ftyp-only init 段） | ffmpeg 把 ftyp 与 moov 分两次写出，首块 read 只拿到 28 字节 ftyp | `_read_fmp4_init` 累加读取直到出现 moov |
| BUG-10a | 桌面/移动端 time 修复流无总时长 | empty_moov 的 mvhd duration=0，QMediaPlayer/ExoPlayer 拿不到时长 | `patch_mvhd_duration` 改写 mvhd duration |

### 2.1 init 段补读（BUG-8）

- **根因**：`_read_pipe_chunk` 每次最多读 64KB，但 ffmpeg 可能先 flush 28 字节 ftyp、再 flush moov。
  若首块只拿到 ftyp，`parse_fmp4_codec` 找不到 moov → codec 为空 → 客户端
  `addSourceBuffer('video/mp4; codecs=""')` 失败 → 回退完整下载（间歇性）。
- **修复**：`_read_fmp4_init` 循环补读直到 `b"moov" in data` 或达到 4MB 上限，
  确保 meta 帧的 `codec` 与 init 段完整。正常情况（moov 已在首块）零额外开销。

### 2.2 mvhd duration 改写（BUG-10a，本轮新增）

- **根因**：`empty_moov` 流式输出的 fMP4 其 moov/mvhd 的 duration 为 0（实时流无法预知
  总字节），QMediaPlayer / ExoPlayer 从容器拿不到时长 → 进度条 0-0 不可拖。
- **修复**：`patch_mvhd_duration` 在 moov 内定位 mvhd，按「秒 × timescale」改写 duration
  字段（ver=0 为 4 字节、ver=1 为 8 字节）。初始流写完整时长，seek 流写剩余时长
  （`duration - range_start_seconds`）。meta 帧的 `duration` 字段保持完整时长不变（供
  桌面/移动端线性 seek 映射用）。
