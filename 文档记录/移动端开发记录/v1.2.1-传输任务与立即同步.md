# jflove-app 传输任务与立即同步功能开发记录

> 基于 v1.2.1 版本的补充开发（无版本号变更，属功能补全）

## 概述

补齐移动端两个缺失的桌面端功能：
1. **传输任务可视化** — 文件下载/上传时创建传输任务，全局底部浮窗展示进度
2. **同步管理 - 立即同步按钮** — 同步配置卡片上添加"立即同步"按钮，实时反映同步状态

---

## 变更详情

### 1. 传输任务浮窗全局化

**背景**：此前 `TransferFloatingCard` 仅放在 `HomePage` 的 `Stack` 中，用户导航到文件/笔记/同步/设置页面时看不到传输进度。

**变更**：
- `lib/app.dart`：将 `TransferFloatingCard` 从 `HomePage` 移到 `_AppScaffold` 的 `Stack` 中，使其在所有底部导航页面底部可见
- `lib/pages/home/home_page.dart`：移除 `TransferFloatingCard` 相关代码

| 文件 | 变更 |
|------|------|
| `lib/app.dart` | 引入 `TransferFloatingCard`，在 `_AppScaffold` 的 `Scaffold.body` 中包裹 `Stack`，底部放置 `TransferFloatingCard` |
| `lib/pages/home/home_page.dart` | 移除 `import` 和 `TransferFloatingCard` + `Positioned`，简化 body 为纯 `SingleChildScrollView` |

### 2. 传输服务增强

**背景**：此前 `TransferService.submitDownload()` 只读取流不保存文件，`submitUpload()` 是空壳。

**变更**：
- `lib/services/transfer_service.dart`：重写 `submitDownload` 和 `submitUpload`，增加并发控制、任务队列、取消支持

| 改进点 | 之前 | 之后 |
|--------|------|------|
| 下载 | 只读取流更新进度，不保存文件 | 创建 `File` + `IOSink` 写入本地，边收边写，进度实时更新 |
| 上传 | 空壳，标记为 completed | 分片读取本地文件，Base64 编码后通过 `encryptedPost` 上传，跟踪进度 |
| 并发控制 | 无 | 最大 3 个并发任务，超额任务排队等待 |
| 取消支持 | 仅改状态，不中止实际传输 | 添加 `_cancelledTasks` Set，任务执行中检查取消标志，取消后清理不完整文件 |
| 统计方法 | `switch` 语法错误（`case A \|\| B`） | 修正为正确语法（`case A:` `case B:`） |

### 3. 文件页下载使用传输任务

**背景**：此前 `_downloadFile` 直接调用 `FileService.download()` 写入文件，用户看不到下载进度。

**变更**：
- `lib/pages/files/disk_browser_page.dart`：`_downloadFile` 改为调用 `TransferService.submitDownload()`，创建传输任务并由 `TransferFloatingCard` 展示进度

### 4. 同步管理 - 立即同步按钮

**背景**：桌面端同步配置表格每行有「立即同步」按钮，移动端 `_SyncConfigCard` 缺少此功能。

**变更**：
- `lib/pages/sync/sync_page.dart`：
  - `_SyncConfigCard` 从 `StatelessWidget` 重构为 `ConsumerStatefulWidget`
  - 添加 `onSyncNow` 回调 + 同步按钮（`Icons.sync`）
  - 同步中显示 `CircularProgressIndicator`，结束后显示结果文字
  - 监听 `SyncEngineService.eventStream`，实时反映 `SyncStarted` / `SyncProgress` / `SyncFinished` / `SyncError` 事件
  - 状态文字 3~5 秒后自动清除
