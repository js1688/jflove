## 2. 关键实现

### 2.1 导航
- `_AppScaffold._routes` 与 destinations 一一对应：
  `/files`、`/notes`、`/transfer`、`/offline`、`/album`、`/settings`；
- `/offline/new`、`/files/:diskId` 等子页仍在 Shell 外（进入后隐藏底部栏）。

### 2.2 相册同步活动
- `AlbumBackupPhase { idle, checkingRemote, scanning, uploading }`；
- `scanAndUpload()` 在开始/每 250ms/结束时发布 `AlbumBackupActivity`（阶段、已处理/总数、可取消）；
- `cancelScan()` 置位取消标记，扫描循环与失败重试循环在边界退出；
- `init()` 延迟 2s 扫描，避免启动首帧被大相册阻塞。

### 2.3 大视频不卡死
- `TransferService._doUpload` 的 SHA256 改为 `Isolate.run` → `sha256FileSync`；
- 主 isolate 只做文件分片读取 + 加密请求；`_updateTask` 进度最多 5 次/秒；
- 实机验证：300MB `.mp4` 上传期间可切换底部 Tab、页面可滚动，无 ANR。

### 2.4 可发现性
- 文件名无扩展名时用本地文件扩展名补全（`VID_1` → `VID_1.mp4`）；
- 相册页「最近上传」显示文件名/大小/时间；「在文件中查看」直接打开磁盘 + 相册目标根；
- 「复制诊断信息」包含版本/阶段/六类计数/失败样例（不含 token/路径）。

## 4. 已知限制 / 待用户验证

1. 仅云端、无本地文件的视频仍无法上传；现在会显示「文件不可用（可能仅在云端）」而非静默跳过。
2. 300MB 测试文件为「有效 mp4 头 + 补零」用于验证上传链路，不代表播放正确性；真实视频播放由用户素材覆盖。
3. 用户真机上的具体失败需用「复制诊断信息」+ logcat 复核（本次模拟器无云端素材）。
4. 极端低内存设备上 isolate 失败会回退失败态并提示「文件校验失败」。

## 6. 全量核对与展示修正（2026-10-25，版本仍为 1.8.3）

用户反馈「核对远端检查一两百就停」与「同步明细文案挤在一起」，处理如下：

### 6.1 全量核对（不再有 2000 / 30 目录上限）

- 删除 `_maxScanPerRound = 2000` 与 `_maxRemoteDirRequests = 30`：每轮从 0 扫到相册尾部；
- 提交仍限 20 项/轮（避免一次塞爆队列），但**扫描不再因提交上限提前结束**；
- 远端索引跨轮保留 10 分钟（`_remoteIndexFetchedAt`），「全量核对远端」显式清空重建；失败目录下一轮重试；
- **远端优先**：先查远端同名文件，命中即跳过 —— 不再打开本地大视频（避免 photo_manager 缓存复制与重复流量）；
- 同名判定优先于大小（避免重复上传）；代价是「同名但内容变化」的文件会被视为已同步（相机文件名唯一，风险低）。

### 6.2 相册页表单化

- 「同步明细」改为 4 列表格：类型 / 总数 / 已同步 / 待同步（图片、视频两行）；
- 「任务状态」改为标签-数值表单行（待备份/上传中/失败/不在范围/远端跳过）；
- 操作区改为「立即检查并上传」主按钮 + 「重试失败项 / 全量核对远端」双列 + 次级文本按钮；
- 页面底部改为「在文件中查看已上传」整宽按钮 + 「去传输任务查看上传明细」文本按钮，不再挤成一行。

## 7. 远端索引架构修正（2026-10-25，版本仍为 1.8.3）

用户指出「10 分钟内存索引」过于复杂且生命周期不清，裁决改为：

### 7.1 索引存哪

- **本地 SQLite 持久化**（`album_backup.db` v4）：
  - `album_remote_index(disk_id, remote_root, dir, name, size)`：远端文件全量清单；
  - `album_remote_meta(disk_id, remote_root, built_at)`：索引建立时间。
- 服务端**不缓存**、不新增接口，仍复用 `POST /api/v1/files/list` 递归遍历目标根。

### 7.2 何时建立 / 生命周期

| 触发 | 行为 |
|---|---|
| 索引不存在 | 先建立完整索引，**建完才允许上传** |
| 索引超过 10 分钟 | 自动重建（兼顾远端删除自动补传与请求频率） |
| 手动「立即检查 / 全量核对远端」 | 强制重建 |
| 正在上传（有 pending 任务） | **禁止重建**，继续用现有索引，避免覆盖本地已维护索引 |
| 建索引期间 | 不开始上传；任何上传判定为 `deferred`（下轮重试） |
| 列表失败 | 暂停该轮上传并提示，不做 fail-open 盲传 |

### 7.3 上传判定

- 按 `YYYY/MM + 文件名` 查本地索引：
  - 命中 → 直接算已上传，**不读取本地文件流**（大视频不会被复制到缓存）；
  - 未命中（含远端被删除）→ 重新上传；
- 每成功上传一个文件，立即 `upsertRemoteFile` 维护本地索引；
- 相册新增文件：下一轮全量扫描时按索引判断，命中跳过、未命中上传。

### 7.4 UI

- 相册页新增「远端索引：HH:mm 建立 · 最多 10 分钟刷新一次（可手动全量核对）」；
- 「等待远端索引（已暂停）」计数，避免用户误以为卡死。
