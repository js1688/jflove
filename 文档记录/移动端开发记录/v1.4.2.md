# v1.4.2 移动端开发记录：播放纯净化 + 修复中心 + seek 回归修复

## 一、变更概述

| 编号 | 变更 | 说明 |
|------|------|------|
| MOB-1 | **StreamProxy 纯 byte 化** | 删除 time 分支 / `seek()` / `_seekSeconds` / `_seekVersion` / `duration` / `mapRangeToSeconds`；URL 不再带 `?v=`；HEAD 恒声明 `Accept-Ranges: bytes`；新增 `repairTaskId` 透传与 `lastError`（415 错误码解密识别） |
| MOB-2 | **seek 回归修复** | `_seekTo` 恢复 `controller.seekTo()` 原生 seek（v1.4.1 曾无条件重建 controller 重拉流，健康文件拖拽后从头播放）；删除 `_seekOffsetSeconds` / `_fullDurationSeconds` 兑底逻辑 |
| MOB-3 | **Slider 改 `onChangeEnd`** | 松手才触发 seek，修复拖动过程连续重建 controller、多次重拉流的体验问题（v1.4.1 遗留） |
| MOB-4 | **损坏播放引导** | 初始化失败且错误含 `[MEDIA_NEEDS_REPAIR]` → 展示「该文件已损坏，无法在线播放 + 立即修复」按钮 → 调 create API → SnackBar 提示 |
| MOB-5 | **长按「修复损坏媒体」** | 文件列表长按菜单新增（仅音视频；要求 canWrite 且 canDelete 并存，权限不足置灰） |
| MOB-6 | **修复中心页面（新增）** | 底部导航新增「修复中心」；全平台共享任务列表 + 2.5s 轮询 + 下拉刷新 + 按状态操作（取消/验证播放/覆盖[重点二次确认]/删除产物/删除记录）；只读账号按钮禁用 |
| MOB-7 | **验证播放** | `FilePreviewPage` 新增 `repairTaskId` 参数：经代理走 `/stream?repair_task_id` 加密流播放修复产物 |
| MOB-8 | **设置页改造** | 移除「启用媒体修复」总开关；卡片改为「离线媒体修复」，保留重编码开关与并发数（不再依赖总开关状态） |
| MOB-9 | **磁盘模型扩展** | `VirtualDisk` 新增 `canDelete`（服务端 v1.4.2 起返回 `can_delete`） |

## 三、关键设计取舍

1. **seek 回归修复 = 删除 time 逻辑**：v1.4.1 的「重建 controller + 偏移补偿」整体删除，恢复 `seekTo()` 字节 range 原生 seek；时长/进度回归 `controller.value.duration/position`（byte 模式容器自带完整 moov）。服务端 v1.4.2 已无 time 流，两端复杂度同步归零。
2. **损坏识别复用代理错误通道**：`stream_proxy.dart` 在 HTTP 错误时尝试解密信封提取 detail（含 `[MEDIA_NEEDS_REPAIR]`），存入 `lastError`；预览页初始化失败时据此切换「修复引导」UI，无需额外探测请求。
3. **修复入口权限 = canWrite && canDelete**：`VirtualDisk` 扩展 `canDelete`；长按菜单与修复中心操作按钮按写+删并存判定可用性（admin 天然满足；接口 403 兜底）。
4. **Slider 只在松手时 seek**：`onChanged` 为空实现（Slider 必需参数）、`onChangeEnd` 才调 `seekTo`——避免拖动期间数十次 seek 请求（v1.4.1 为重建 controller 重拉流，体验更糟）。
5. **验证播放复用 FilePreviewPage**：`repairTaskId > 0` 时经 StreamProxy 透传参数，服务端流式返回产物（faststart MP4 健康直读），零新增播放管线。

## 五、验证方式（用户侧）

1. `flutter build apk --debug` 安装到 Android。
2. 文件列表长按一个损坏视频 →「修复损坏媒体」→ SnackBar 提示已入队。
3. 底部导航「修复中心」查看进度 → 成功 →「验证播放」预览产物 → 覆盖（二次确认）→ 原位置为修复版。
4. 健康 MP4 拖拽进度条：松手后从目标点继续播放（v1.4.1 回归已修复）。
5. 损坏文件直接预览：弹「立即修复」按钮。
