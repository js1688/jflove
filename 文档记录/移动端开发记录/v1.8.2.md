## 2. F38 相册备份远端去重（#8）

### 2.1 数据流

```
scanAndUpload()
  ├─ 失败项自动重试（attempts < 3）
  ├─ 跨轮游标取候选资源（每页 200，单轮最多访问 2000）
  ├─ 本地记录命中（disk_id + remote_root）→ skip
  ├─ 远端目录 <root>/YYYY/MM 索引（同一轮只请求一次）
  │     ├─ 同名同大小 → markBackedUp（补本地记录）→ skippedExisting++
  │     └─ 列表失败 / 超预算 → 该目录标记不可用（fail-open，按本地记录继续）
  └─ 其余 → submitUpload
```

### 2.2 实现要点

| 项 | 实现 |
|---|---|
| 远端列表 | `FileService.listFiles(diskId, path: <root>/YYYY/MM)`（`GET /api/v1/files/list`，加密 body 带 `disk_id` / `path`） |
| 缓存 | `Map<String, Map<String,int>?>`，键 `diskId:relDir`；扫描开始清空、结束清空；单轮最多 30 个目录请求 |
| 判定 | `is_dir == false && name == asset.filename && size == 本地 length()`；`asset.filename` 与上传文件名同源 |
| 目录不存在 | 服务端对不存在的 `YYYY/MM` 返回「路径不存在或不是目录」，客户端按**空目录**处理（首次备份不应误报「校验不可用」） |
| 真实失败 | 网络 / 权限等异常 ⇒ 该目录索引 `null`，本轮按本地记录继续，`remoteCheckUnavailable=true`，界面提示「远端校验暂不可用」 |
| 记录归属 | 查询 `WHERE disk_id=? AND remote_root=?`；换磁盘/目标目录后旧记录不命中 |
| 目标变更 | `setConfig` 检测到磁盘或 `remote_root` 变化 ⇒ 清空失败记录、游标归零、索引缓存清空（历史资源进入新目标待传队列） |
| 计数 | `skippedExisting` 进入 `AlbumBackupProgress`；设置页/传输页显示「远端已存在跳过 N 项」 |
| 手动入口 | 设置页「重新核对远端」清空索引缓存并再扫一次；「立即检查」手动解锁失败项后扫描 |

### 2.3 安全

- 只对当前配置的 `diskId` 调列表，不遍历 / 不跨账号；
- 复用 `FileService` → `HttpService` 加密 GET，不新增加密实现；
- 远端索引只保留 `name → size`，不写日志；失败原因不含文件名 / 路径；
- 远端校验**只读**，不创建 / 删除 / 移动任何远端文件。

## 3. F39 相册备份扫描健壮性（#12）

### 3.1 单资源隔离

`_handleAsset` 内部逐步隔离并配合调用方的单资源 `try/catch`：

| 步骤 | 失败处理 |
|---|---|
| `asset.file`（平台通道） | `文件不可用（可能仅在云端）`，继续下一个资源 |
| `file.length()` / `size <= 0` | `读取失败`，继续 |
| 远端列表 | 见 F38 fail-open（不记为资源失败） |
| `submitUpload` | `上传失败`，继续 |
| `store.markFailed` 自身 | 再包一层 `try/catch`，只打异常类型日志，绝不冒泡中止整轮 |

扫描级平台异常（如权限查询失败）只记录异常**类型**，不输出文件名。

### 3.2 失败可见与重试

- 失败原因固定中文枚举（`AlbumBackupFailureReason`）：`文件不可用（可能仅在云端）` / `读取失败` / `上传失败` / `上传已取消`；
- `attempts` 入库自增；`attempts >= 3` 暂停自动重试，界面标注「永久不可用 / 暂时失败 · 已尝试 N 次」；
- 每轮扫描先对 `attempts < 3` 的失败项做**一次**自动重试（`findAsset` 找回资源），同一轮内不会重复尝试；
- 「重试失败项」清空失败记录并立即扫描；「立即检查」同样清空失败记录（手动解锁）；
- 设置页「查看失败原因」弹层只显示原因 / 类型 / 次数，不显示文件名或路径。

### 3.3 跨轮游标

- 去掉「每轮固定从 0 扫到 2000」：`_cursorOffset` 内存游标跨轮保留；
- 每页 200，单轮最多访问 2000 个资源；扫到相册尾部回绕到 0；
- 因上传上限（20/轮）提前停止时，游标停在**已检查的最后一个资源之后**，下一轮从该位置继续；
- 大于 2000 张的相册不会永久饿死尾部资源；单测用 2500 张验证两轮扫完并回绕。

### 3.4 计数自洽

`AlbumBackupProgress`：

```
total       = 相册总数（RequestType.common）
outOfScope  = 关闭的图片/视频类型数量（分别用 RequestType.image / video 取数）
done        = 当前 disk_id + remote_root 下已备份数量
failed      = 失败记录数量
pending     = max(0, total - done - failed - outOfScope)
```

设置页同时展示：手机相册总数、已备份、待备份、上传中、失败、不在范围、远端已存在跳过；
满足 `已备份 + 失败 + 不在范围 + 待备份 = 总数`（关闭视频时视频计入「不在范围」）。

## 4. 本地库 v1 → v2（sqflite）

### 4.1 表结构

```sql
-- onCreate(v2)
CREATE TABLE album_backup (
  asset_id    TEXT PRIMARY KEY,
  disk_id     INTEGER NOT NULL,
  remote_root TEXT NOT NULL DEFAULT '',
  remote_path TEXT NOT NULL,
  size        INTEGER NOT NULL,
  backed_at   TEXT NOT NULL
);
CREATE TABLE album_backup_fail (
  asset_id TEXT PRIMARY KEY,
  reason   TEXT NOT NULL,
  attempts INTEGER NOT NULL DEFAULT 0,
  tried_at TEXT NOT NULL
);

-- onUpgrade(1 → 2)
ALTER TABLE album_backup ADD COLUMN remote_root TEXT NOT NULL DEFAULT '';
ALTER TABLE album_backup_fail ADD COLUMN attempts INTEGER NOT NULL DEFAULT 0;
```

### 4.2 老用户升级

- 主键不变（`asset_id`），升级只加列；
- `AlbumBackupService.init()` 调用 `backfillRemoteRoot(diskId, remoteRoot)`：
  `UPDATE album_backup SET remote_root=? WHERE disk_id=? AND remote_root=''`；
- 回填后旧记录在当前目标下继续命中，**不触发全量重传**；
- 换目标目录后旧记录不命中（按设计 F38.2 进入待传队列）；
- 降级不兼容：App 降级会重建本地记录，但远端文件不受影响，最多重新上传一次，可接受。

## 5. F41-C2 分析轮询退避（AC-295）

- `offline_new_task_page.dart` 用单次 `Timer` + 档位表 `[2500, 5000, 10000, 15000, 30000]` 替代固定 2.5s 周期；
- 分析成功后立即查一次详情，之后按档位退避；连续轮询失败仍保留「3 次后落失败态」；
- 失败态新增「重试分析」按钮（保留原「分析」按钮）；
- 回前台时立即补一次详情，后续继续按当前档位退避；离开前台停止轮询。

## 6. 与上一版本（v1.8.1）的差异

| 维度 | v1.8.1 | v1.8.2 |
|---|---|---|
| 相册去重 | 仅本地 sqflite；重装后全量重传 | 远端 `YYYY/MM` 同名同大小跳过 + 本地补记录 |
| 记录归属 | 仅 `asset_id` 主键 | `disk_id + remote_root` 限定；换目标后旧记录不生效 |
| 扫描异常 | `asset.file` / `length()` 在 try 外，异常中止整轮 | 单资源隔离，坏资源只记失败 |
| 失败可见 | 只存 reason，界面不展示 | 中文原因 + 重试次数，可展开查看 |
| 失败重试 | 永久排除，只能手动清标记 | 自动重试 ≤3 次 + 手动解锁 |
| 扫描范围 | 每轮固定 0–1999 | 跨轮游标，>2000 也能扫到尾部 |
| 计数 | 总数 / 已备份 / 上传中 / 失败 | 增加待备份 / 不在范围 / 远端跳过 / 校验状态 |
| 本地库 | version 1 | version 2（`remote_root` / `attempts`） |
| 分析轮询 | 固定 2.5s | 2.5→5→10→15→30s + 「重试分析」 |

## 10. 已知限制

1. 失败记录表没有 `disk_id` / `remote_root` 列（设计只要求加 `attempts`）：换目标时由 `setConfig` 清空失败记录规避旧目标状态污染，未做按目标隔离的失败统计。
2. 远端目录索引单轮最多 30 个目录；超出预算的目录按 fail-open 处理（提交上传），下一轮重新尝试。
3. 「远端已存在跳过 N 项」是**本轮**计数，扫描结束后保留最近一轮结果；重新扫描会刷新。
4. 相册总数 / 分类计数依赖 `photo_manager` 的 `assetCountAsync`，无权限时为 0，界面不报错。
5. iOS / 鸿蒙仍为预留方向，本版只在 Android 验证。
