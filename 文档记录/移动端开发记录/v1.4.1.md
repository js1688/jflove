# v1.4.1 移动端开发记录：time 修复流时长与 seek 修复（UI 兜底方案）

## 一、变更概述

移动端 time 修复流（服务端 ffmpeg 实时生成的 fMP4）存在两个问题：

| 编号 | 现象 | 根因 | 修复 |
|------|------|------|------|
| BUG-10a | 无总时长、进度条范围 0 | ExoPlayer 的 FFmpeg 后端从 moof 推算 duration、忽略 mvhd；流式 fMP4 边下边播拿不到完整时长 | UI 层用 meta.duration 兑底设置进度条，不再依赖 `controller.value.duration` |
| BUG-10b | 拖拽无效 / 拖后空白 | ① time 流声明 `Accept-Ranges` 使 ExoPlayer 进入随机访问模式、chunked fMP4 解包失败；② seek 后同 URL 被 ExoPlayer 复用缓存、不发新请求 | ① time 流不声明 `Accept-Ranges`；② `proxy.seek()` + URL 带递增版本号 `?v=N` 强制重新拉流 |

## 二、根因分析（重要教训，三端通用）

1. **ExoPlayer 的 FFmpeg 后端从 moof 推算 duration，忽略 mvhd duration**。
   服务端改写 mvhd（`patch_mvhd_duration`）对 ExoPlayer 无效——桌面端 QMediaPlayer
   已实测：patch 后 mvhd=5000ms，但 QMediaPlayer 仍报告 5038ms（来自 moof 推算）。
2. **time 流声明 `Accept-Ranges` 有害**：播放器一旦认为可 seek，会进入随机访问
   模式并发字节 Range 探测；对 chunked + empty_moov 的流式 fMP4 直接
   `Demuxing failed`（桌面端 QMediaPlayer 实测复现，ExoPlayer 行为同理）。
3. **同 URL 会被播放器复用缓存**：seek 后若用相同 URL 重建 controller，
   ExoPlayer 不再发 GET，seek 目标无人消费，画面空白。需 URL 带递增版本号。

## 三、详细变更

| 文件 | 变更类型 | 说明 |
|------|---------|------|
| `lib/utils/stream_proxy.dart` | 修改 | 新增 `duration` / `seek()`；`url` 带 `?v=N`；`_handleHead` time 不声明 Accept-Ranges；`_handleGet` time 分支消费 `_seekSeconds` |
| `lib/pages/files/file_preview_page.dart` | 修改 | `_MediaPreviewState` 时长兜底 + `_seekTo` 重建 controller + position 偏移补偿；`_MediaControls` 用完整时长与偏移 |
| `pubspec.yaml` | 修改 | 版本号 1.4.0+4 → 1.4.1+5 |

### 3.1 `stream_proxy.dart`

- `double get duration`：返回 meta.duration（秒），供 UI 显示总时长。
- `void seek(double seconds)`：缓存 `_seekSeconds`（一次性）并递增 `_seekVersion`。
- `String get url`：`.../{token}?v={_seekVersion}`，版本号变化强制 ExoPlayer 重新 GET。
- `_handleHead`：time 模式**不**声明 `Accept-Ranges`（恢复 v1.4.0 行为，避免随机访问模式）。
- `_handleGet` time 分支：优先消费 `_seekSeconds`（UI 主动 seek）；归零后若仍有字节
  Range 则走 `mapRangeToSeconds` 线性映射。

### 3.2 `file_preview_page.dart`

- `_MediaPreviewState._fullDurationSeconds`：`controller.initialize()` 后取 `proxy.duration`。
- `_seekOffsetSeconds`：seek 目标秒，position 显示加偏移映射回绝对时间轴。
- `_seekTo(targetSeconds)`：记录偏移 → `proxy.seek()` → dispose 旧 controller →
  用新 `proxy.url` 重建 `VideoPlayerController.networkUrl` → initialize + play。
- `_MediaControls` 新增 `fullDurationSeconds` / `seekOffsetSeconds` / `onSeek` 参数：
  - 总时长显示用 `fullDurationSeconds`（meta 兑底），不用 `controller.value.duration`；
  - position 显示 = `controller.value.position + seekOffsetSeconds`；
  - Slider 范围 = [0, fullDurationSeconds]。

## 四、已知限制

- time 修复流 seek 后，服务端 `-ss T` 输出的新流时间戳归零，ExoPlayer 的 position
  从 0 开始（copy 模式无法保留绝对时间戳，Web 端用 MSE `timestampOffset` 解决，
  ExoPlayer 无等价能力）。移动端通过 `_seekOffsetSeconds` 偏移补偿把 position 映射回
  绝对时间轴。
- 移动端 Slider 使用 `onChanged` 触发 seek，拖动过程中会连续触发重建 controller，
  可能造成拖动过程多次重拉流；桌面端用 `sliderReleased`（松手才 seek）。
  如体验不佳，后续可改为 `onChangeEnd`。

## 六、验证方式（用户侧）

1. `flutter build apk --debug` 安装到 Android。
2. 打开一个「损坏的」视频，确认：
   - 进度条显示完整总时长；
   - 拖拽后从目标点继续播放（position 显示 = 目标点，不空白、不从头播）。
3. 健康 MP4 也应正常播放、拖拽。
